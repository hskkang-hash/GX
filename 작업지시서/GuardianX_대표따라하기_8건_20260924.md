## ① 지금 — `-old` 컨테이너 셋 결정 (P-297 · 삭제 · 세종 권고 「지운다」)

**왜**: 되돌리기용으로 세워 둔 옛 컨테이너 셋(`gx-celery-e-old` · `gx-celery-e-old-2b` · `gx-gunicorn-e-old-2b`)이 아침 재부팅 셈을 영구히 막고 있다(가장 오래 선 것을 잡는다). 자료는 컨테이너가 아니라 볼륨에 있어 지워도 잃는 것은 없다(영실이 표로 먼저 확인한다).

**하는 법** — Code 세션 입력창에 아래 한 문장을 그대로 붙인다:
```
-old 셋 지워라. 표 먼저(이름·상태·볼륨·크기), docker rm 은 -v 없이. 같은 창에서 gx-celery-e·gx-gunicorn-e 를 로그 상한 붙여 다시 만들어라(창 2b 절차·되돌리기 10분). 끝나면 아침 게이트 다시 세라.
```
두시려면 대신:
```
-old 는 두라. 아침 게이트만 「도는 컨테이너」를 보게 고쳐라. -old 는 손대지 않는다.
```
**확인**: 보고에 「-old 0 · 로그 상한 2/2 · OPS-07-a 초록 · 아침 N/10」 네 수가 있으면 끝.

## ② 지금 — push (P-298 · 영실 손에서 두 번 막힘)

**왜**: 로컬 `turn-q` 가 원격보다 앞서 있다(원격 `709a5aa` · 로컬 `0292092` 이상). Code 환경엔 GitHub 자격이 없어 대표 PC 에서 올려야 한다.

**하는 법** — 시작 → `PowerShell` 입력 → 열기 → 아래 네 줄을 한 줄씩:
```powershell
cd C:\GuardianX\guardianx-source
git status
git log --oneline origin/turn-q..turn-q
git push origin turn-q
```
- 셋째 줄에 **올라갈 커밋 목록**이 뜬다(예: `0292092 …` `7e3e6ab …`). 비어 있으면 이미 올라간 것 — 끝.
- 넷째 줄에서 GitHub 로그인 창이 뜨면 대표 계정으로 로그인(브라우저 창) — 비밀번호를 터미널에 치지 않는다.
- 마지막 줄이 `709a5aa..xxxxxxx  turn-q -> turn-q` 모양이면 성공.
- `rejected`·`denied` 가 보이면 그 화면을 캡처해 세종에게(다음 턴 판정).

**확인**: Code 에 「push 했다」 한 줄 → 영실이 `origin/turn-q == turn-q` 확인해 보고에 적는다.

## ③ 오늘 퇴근 전 — 재부팅 자동화 세 조각 (P-303 · P-285)

**왜**: 아침 10/10 은 「아무도 없는 아침에 서 있다」(S3)의 수인데, 지금은 대표가 손으로 재부팅해야 하고 그날만 센다. 세 조각이 다 있어야 매일 선다.

**조각 1 — 매일 04:30 재부팅(관리자 PowerShell 1줄)**
시작 → `PowerShell` → **마우스 오른쪽 → 관리자 권한으로 실행** → 아래 한 줄:
```powershell
schtasks /Create /TN "GuardianX-DailyReboot" /TR "shutdown /r /t 60 /c GuardianX-daily-reboot" /SC DAILY /ST 04:30 /RU SYSTEM /RL HIGHEST /F
```
`성공: 예약 작업 "GuardianX-DailyReboot"이(가) 생성되었습니다.` 가 뜨면 끝. 확인: `schtasks /Query /TN "GuardianX-DailyReboot"`.

**조각 2 — Docker Desktop 자동 시작**
Docker Desktop 열기 → 오른쪽 위 톱니(Settings) → General → **「Start Docker Desktop when you sign in to your computer」 체크** → Apply & restart.

**조각 3 — 자동 로그인 (결정 · 세종 권고: 켬 + 화면 잠금)**
Docker Desktop 은 Windows 에 **로그인해야** 뜬다. 04:30 재부팅 뒤 로그인 화면에 멈추면 컨테이너 0/10 이다.
- 권고: `Win + R` → `netplwiz` → 「사용자가 이 컴퓨터를 사용하려면 사용자 이름과 암호를 입력해야 함」 **체크 해제** → 확인 → 대표 계정 암호 입력(Windows 창에 · 문서에 적지 않음). 이어서 시작 → 설정 → 개인 설정 → 잠금 화면 → 화면 보호기 설정 → 「다시 시작할 때 로그온 화면 표시」 체크 · 대기 1분 — **부팅 뒤 자동 로그인되고 1분 안에 잠긴다.** 디스크 암호화(BitLocker)는 그대로.
- 원치 않으시면: 조각 1 을 지우고(`schtasks /Delete /TN "GuardianX-DailyReboot" /F`) 출근 직후 손 재부팅 + 로그인을 유지한다. 그 경우 아침 수는 대표가 재부팅한 날만 선다.
- 회사 PC 정책(도메인 가입·MDM)이 있으면 netplwiz 가 막힐 수 있다 — 그때는 세종에게 화면 캡처 1장.

**확인**: 다음 날 아침 Code 보고 첫 줄 「아침 N/10」.

## ④ 이번 주(09-26 까지) — 스테이징 1대 (S5 · 바깥 사용자 0 % 의 뿌리 · PRD §10 ②)

**왜**: 신규 User 가 URL 로 들어오는 것을 대표도 세종도 영실도 아직 한 번도 못 봤다. 모든 RC 문턱 중 이것만 손 밖이고 열한 턴째다.

**하는 법 — 국내 클라우드 VM 1대**(네이버클라우드 · KT클라우드 · 카페24 등 어느 것이나 · 월 대략 5~8만 원대 · 세종 추정)
1. 콘솔 → 서버 생성: **Ubuntu 22.04 LTS · 2vCPU · 8GB · SSD 100GB** · 공인 IP 1개 할당.
2. 방화벽(ACG/보안그룹): **인바운드 22(대표 IP 만) · 80 · 443** 셋만 연다. 나머지 전부 닫음.
3. SSH 키 쌍 생성 → 개인키 파일을 **`C:\GuardianX-vault\staging\gx-stg.pem`** 에 저장(저장소·채팅 0).
4. 도메인: 가이온 DNS(가비아 등) → **A 레코드** `gx-stg.gaion.kr` → 위 공인 IP. (다른 이름도 무방 · 한 줄만 알려주시면 된다)
5. Code 세션에 세 줄:
```
스테이징 왔다. 공인 IP <숫자> · 도메인 gx-stg.gaion.kr · 키 C:\GuardianX-vault\staging\gx-stg.pem. P-302 대로 올려라.
```
영실이 1시간 안에 운영 프로필 그대로 올리고 TLS(Let's Encrypt)를 붙인다. **그날 대표가 브라우저에서 `https://gx-stg.gaion.kr` 로 들어가 로그인하는 것이 CR ① 의 첫 실측**이다.

**대안(VM 이 어려우면)**: 운영 서버 옆 PC 1대 + 사내망 URL + 자체 서명 인증서 — PRD §10 ② 대안 그대로(PR 항목 0.5).

2. 보안 → **앱 비밀번호** → 앱 이름 `GuardianX-SMTP` → 만들기 → **16자리**가 한 번 뜬다.
3. 메모장 → 아래 5줄(값은 대표만 채움) → **`C:\GuardianX-vault\smtp.env`** 로 저장:
```
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=hskkang@gaion.kr
SMTP_PASSWORD=<16자리 · 여기엔 적지 않음>
SMTP_FROM=GuardianX <hskkang@gaion.kr>
```

(다른 메일 서비스면 그 서비스의 SMTP 호스트·포트·앱 비밀번호 — 형식은 같다.)
