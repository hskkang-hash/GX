```

test_write_update_of_another_tenant_row_is_refused   커널 직접 호출 경로
```

래칫은 커널 공개 면 중 **DB 를 바꾸는 것**을 런타임에서 세고, 각각이 probe 에 있거나

### K6 — **모델이 없는 것이 설계입니다**

DA-04 가 못박은 대로 별도 집계 표를 만들지 않았고, `models.py` 가 생기면 시험이 멈춥니다.

**분모가 요구사항입니다.** 미판정(`new`)은 분모가 아닙니다 — 넣으면 **판정을 미루기만
해도 오탐률이 떨어집니다.** 그리고 분모 0 일 때 `rate` 는 `None` 이지 `0.0` 이 아닙니다.
`0.0` 으로 내면 "아직 아무도 판정하지 않았다"가 "오탐이 없었다"로 읽히고,
**U1 의 '월 하락' 이 그것만으로 달성됩니다.**

`usage_snapshot` · `kpi_series` 는 **던집니다.** W4-1 계측 모델이 저장소에 없고
(실측 0건) t0/t1 적재처도 미정입니다. 계측에서 조용한 `0` 은 특히 나쁩니다 —
**아무도 재지 않은 지표가 좋은 지표로 보고되고**, 그 수가 과금 근거(U4)가 됩니다.

### K2 — **실패가 성공처럼 보이지 않는가**

F-10 은 `DeliveryRecord` 의 두 점(`occurred_at → sent_at`)으로 잽니다. **한 행에서**
읽힙니다 — 조인이 필요하면 그 측정은 안 하게 됩니다. 그리고 **실패는 `sent_at=None`**
이라 아무리 빨라도 F-10 을 충족하지 않습니다. 넣었다면 30초 AC 가 실패한 발송으로도

억제는 **발송 이력** 위에서 합니다(K1 은 이벤트 행). 메일 서버가 죽어 못 보낸 알림을

가장 필요한 5분입니다.

수신자 0명은 예외로 올립니다. 빈 목록은 **알림 체계가 꺼진 상태**를 성공으로 보이게 합니다.

## 6. ★ 실측 발견 — **스키마가 마이그레이션만으로 재현되지 않았습니다**

E2E 규약 ①(실 마이그레이션 DB)을 이행하려다 걸렸습니다. 빈 DB 에 `manage.py migrate` 를
돌리면 **죽습니다**:

```
core/logger/migrations/0009_…:17   apps.get_model("multilanguage", "MultiLanguageContent")
LookupError: No installed app with label 'multilanguage'.
```

앱은 `INSTALLED_APPS` 에 **있습니다.** 없는 것은 그 시점의 **마이그레이션 상태**이고,
dj-core 의 `logger/0009` 가 dependency 를 선언하지 않은 탓입니다.
**지금 도는 개발 DB 는 어쩌다 맞는 순서로 적용된 결과였습니다.**

> **계약 6차(2027.1)는 소스 인도이고, 받는 쪽은 빈 DB 에서 시작합니다.**
> 그때 "설치가 안 됩니다"를 듣는 것과 지금 아는 것은 다릅니다.

**되돌린 시도를 남깁니다.** `run_before` 를 선언한 빈 마이그레이션을 만들어 봤고
**빈 DB 에서는 통과했습니다.** 그러나 이미 `logger/0009` 가 적용된 DB(개발·**운영**)에서는
`migrate` 자체가 `InconsistentMigrationHistory` 로 죽고 `--fake` 로도 못 넘습니다 —
**새 환경 하나를 살리려고 도는 환경 전부를 세우는 변경**이라 되돌렸습니다.
운영 DB 에 들어갔다면 그 서버의 `migrate` 가 영구히 막혔을 것입니다.

지금 쓰는 것은 **순서 두 줄**(`user` → `multilanguage` → 나머지)이고, **E2E 시험 DB
생성에만** 끼웠습니다. 스키마 변경 0줄입니다. 근본 해결(dj-core 의 dependency 추가)은
§0.4 금지구역이라 **P-ENV-1 로 적재**했습니다.

**이것은 받침이지 해결이 아닙니다.** 인도 문서의 설치 절차와 CI 에도 그 두 줄이
들어가야 하고, 지금은 시험 경로에만 있습니다. 증거:
`docs/agent/evidence/e2e/migration_from_scratch.md`
