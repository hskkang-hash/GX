## 1. D-299 Zone — E2E-2 3단계가 열렸다

지시하신 설계 그대로입니다. 필드명만 정했고 의미는 유지했습니다.

```
Zone(BaseModel)  # dj-core BaseModel = group FK (D-292 실측 확인 — 마이그 0019 에서 재확인)
  name · kind('camera_group'|'polygon') · cameras M2M(StreamMonitor)
  geometry(JSON, null) · geometry_status('not_implemented'|'ready')
```

**두 잠금이 다른 것을 잠급니다.** 이 대칭이 이번 설계의 핵심이라고 하셨고, 그렇게 만들었습니다.

* `KERNEL_READY = True` — 구역 판정을 **잴 수 있다**. E2E-2 3단계가 열린다.
* `ZONE_POLYGON_READY = False` — 폴리곤은 **선언된 미완성**. 사유가 비면 게이트 exit 1,
  True 로 올리면 `test_f03_polygon_contract_ac` 와 구현이 **둘 다** 있어야 통과한다.

**반대 방향도 잠갔습니다** — 지시에 없던 한 가지입니다. `geometry_status='ready'` 인 Zone 이
DB 에 하나라도 있는데 상수가 False 면, 화면은 폴리곤이 돈다고 믿는데 코드는 미구현입니다.
정적 게이트는 DB 를 못 보므로 `ReadyPolygonDataTest` 가 그쪽을 봅니다. 그리고 그 시험이
**실패할 수 있는지**를 양성 대조로 확인했습니다(D-277).

### 판단 1건 — 결합은 **값이고, 저장된 등급을 덮지 않습니다**

`combine_in_zone` 은 `ZoneCombination(severity='critical', …)` 을 돌려주고 `DetectionEvent.severity`
를 쓰지 않습니다. 이유 둘:

* 덮으려면 K1 공개 면에 **일곱 번째 함수**가 필요합니다. DA-04 §2 가 여섯으로 고정했고,
  계약이 정한 면을 이 규칙 하나 때문에 조용히 넓히지 않았습니다.
* 관측이 실제로 난 등급(`warning`)은 오탐률·이력의 **사실**입니다. 결합이 그것을 덮으면
  나중에 "무엇이 실제로 났는가"를 아무도 못 읽습니다 — D-293 이 `status` 가 `verdict` 를
  덮는 것을 금지한 것과 같은 계열입니다.

결합의 효과는 **누가 받는가**로 나타납니다. E2E-2 4단계가 그것을 잽니다:
`경고 [4] ≠ 심각 [5] · F-03 상향분 [5]`.

**E2E-2 증거** (`docs/agent/evidence/e2e/E2E-2/steps.md`):

```
[E2E-2] 단계 4/4 도달 (계획 4 · 잠김 0)
  OK    1. 수위선 초과 신호 투입                    182.0cm > 150.0cm
```

## 2. D-301 「검사 못함 ≠ 0건 검사」 — 러너가 판정합니다

원칙을 주석으로만 적으면 다음에 추가되는 게이트가 조용히 빠뜨립니다. 그래서 **세 겹**으로 걸었습니다.

1. `inputs <건수> <무엇을> [0건 사유]` — 게이트가 자기가 무엇을 몇 건 보았는지 말합니다.
   0건인데 사유가 없으면 그 자리에서 실패.
2. `run_gate` — 게이트 출력에 `[입력]` 표시가 없으면 **결과가 초록이어도 그 게이트를 실패**시킵니다.
   ★ 출력을 `$(...)` 로 잡지 않고 임시 파일로 받았습니다. 명령 치환은 서브셸이라 PASSED/FAILED
   증가가 부모에 안 남고, 그러면 집계가 조용히 0 이 됩니다 — **이 결정문이 금지한 바로 그 모양**입니다.
3. `scripts/verify_gate_counts.py` — 저장소 밖에서 한 번 더. ALL_GATES 이름마다 함수가 있는가 ·
   게이트마다 inputs 를 부르는가 · 헬퍼가 0건+무사유를 실패시키는가 · 러너의 대조가 남아 있는가.
   자기시험 4건(양성 3 · 음성 1)을 먼저 돕니다.

실측: **게이트 7종 · 건수 출력 지점 9곳 · 전건 exit 0.**

말씀하신 문장은 결정문 본문에 그대로 남겼습니다 —
*"셋 다 재지 않는 동안에는 초록이었습니다."*

## 3. D-302 VIDEO 잠김 사유 — **추정과 다릅니다** (실측)

> **막고 있는 것은 실 스트림 부재가 아니라 배선 부재입니다.**

실측 셋:

* `DetectionEvent.clip_path` — 정의 1건 · **읽기 2곳**(`k1_event._to_view` · `k4_report.services`) ·
  **쓰기 0곳**. 아무도 채우지 않습니다.
* 녹화는 **스트림 단위로 이미 존재**합니다(`/start-record` · `/stop-record` → MinIO `object_path`).
  그러나 그 산출물이 이벤트와 이어져 있지 않습니다.
* 이벤트 시각으로 영상 구간을 찾아 돌려주는 **재생 라우트가 전수 라우트에 0건**입니다.

→ **ZONE 처럼 지금 열 수 없습니다.** 열려면 그 배선을 만들어야 하고, 그 전에 여는 것은
잴 수 없는 것을 재라고 요구하는 일입니다. 다만 SDN 과 성격이 다릅니다 — 이것은 **개발로 풀 수
있는 항목**이지 계약 블로커가 아닙니다. 릴리스 후보에는 넣지 않고 다음 구간 개발 항목으로 두었습니다.

사유는 `LOCKED_CAPABILITIES["VIDEO"]` 본문에 실측 그대로 박았고, 통합시험 결과서가 그것을
자동으로 실어 냅니다.

## 4. FX-5 — **저하 운전은 전부 돕니다. 실호출 파서는 만들지 않았습니다**

### 만든 것

* `backend/adapters/juso/` — 포트 · `AddressResult` · 갈아끼우기 자리 · 타임아웃 2.0s(C-3.3).
  `resolve()` 는 **어떤 경우에도 예외를 던지지 않습니다.** 던지면 부르는 쪽이 감싸야 하고,
  감싸는 코드가 늘면 언젠가 한 곳이 빠집니다 — 그 순간 주소 API 가 이벤트 생성을 끌고 내려갑니다.
* `DetectionEvent.address` / `address_status` (마이그 0020) — 열거 넷.
  **D-290 적용**: `pending`(아직 안 함) 과 `failed`(했는데 실패)를 같은 값으로 두지 않았습니다.
* 알림 본문: `resolved` → 도로명 주소 · `failed` → **"주소 확인 불가(좌표: …)"** ·
  `disabled` → "위치 미상". 상태마다 다른 문장입니다.
* 배선은 **커널이 아니라 `detection_event_bridge`** 에 두었습니다 —
  `verify_layers.py` 금지 ⑤ 가 `kernels/** → adapters/**` 를 막습니다(커널이 외부를 알면
  "타 어댑터로 교체 가능"이 깨집니다). 커널은 받은 것을 적을 뿐입니다. 배치당 1회 호출.

### 만들지 않은 것 — **판단 1건, 승인 요청드립니다**

**juso.go.kr 의 HTTP 구현체를 만들지 않았습니다.** 응답의 필드 이름·중첩 구조·오류 코드를
**실측하지 않았기 때문**입니다. 요청 URL 은 D-298 로 `.env.example` 에 있지만, 응답 스키마는
실호출로만 확인됩니다. D-298 이 그 경우를 못박았습니다 —
*"엔드포인트 미상 항목은 포털 활용신청 상세에서 실측해 채운다. 추정 금지(D-280).
확인 전에는 빈 값으로 두고 **어댑터를 만들지 않는다**."*

SDN 과 정확히 같은 형태로 세웠습니다: `KERNEL_READY=False` + 사유(해소 절차까지 포함) +
DA-05 등록부에 `juso_coord2addr`(`verified: false`) 등재.

> **해소는 개발이 아니라 「키 발급 + 실측 1회」입니다.**
> `GX_JUSO_API_KEY` 를 환경변수에 넣고
> `python scripts/probe_public_data_schema.py --only juso_coord2addr` 를 한 번 돌리면
> `juso_coord2addr_schema.md` 가 생기고, 그다음 남는 일은 **포트 구현 하나**입니다.
> ⚠ juso.go.kr 승인키는 **공공데이터포털 일반키와 별개 계정**입니다(등록부에 명시).

### 정정 고지 1건 — 알림 본문 방침을 한 겹 완화했습니다

`k2_notify._subject_and_body` 의 원래 방침은 *"본문에 개인정보·좌표 원문을 넣지 않는다"* 였습니다.
D-298 의 FX-5 지시(*"'failed' 면 알림에 '주소 확인 불가(좌표: …)'로 나가고"*)가 그 방침을
명시적으로 바꿉니다. **완화 범위를 한 줄로 좁혔습니다**: 조회에 **실패했을 때만** 좌표가 실리고,
성공하면 도로명 주소만 나갑니다. 좌표가 필요한 경우는 주소를 못 얻은 경우뿐이기 때문입니다.
시험이 그 경계를 잽니다(`resolved` 본문에 좌표가 실리면 실패).
