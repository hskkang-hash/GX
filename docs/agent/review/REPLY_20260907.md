## 1. ② 최우선 — **주석 뒤에 열린 문이 있었습니다**

지시대로 순서를 지켰습니다. **코드를 읽어서 답하지 않고 호출했습니다**(D-210).

### ① 분모부터 (D-301) · 술어는 행위로 (D-324)

「없어지면 접근이 넓어지는 데코레이터」만 셌습니다. `csrf_exempt` 는 뺐습니다 —
**주석 처리되면 접근이 좁아지므로** 권한 계열의 반대편입니다.

```
[실측 · scripts/probe_commented_guards.py · 2026-09-07]
  권한 계열 사용 320자리 = 활성 281 + 주석 39     ← 분모
  주석 39자리는 전부 path_permission · 10개 파일
```

### ② ★ 여기서 갈렸습니다 — 「권한」과 「인증」은 같은 이름이 아닙니다

말씀하신 대로 **한 칸에 두면 안 되는 것**이었습니다(D-290).

```
authn_only          24자리   auth= 살아 있음 → 익명 요청은 401
no_authn_no_authz   15자리   ★ 인증 관문 없음 → 익명이 핸들러에 닿는다
```

**한 덩어리로 읽었다면 무엇을 즉시 고치고 무엇을 래칫에 둘지 가를 수 없었습니다.**
이것을 D-337 동음이의 대장에 **네 번째 줄**로 올렸습니다.

### ③ 열려 있었는가 — 15/15 가 401 이 아니었습니다

GET 8자리는 그냥 때렸고, **POST 7자리는 등록된 핸들러를 「도달 표시만 남기는 대체물」로
잠시 바꾸고 때렸습니다 — 본체는 한 줄도 돌지 않았습니다.**
안 때리면 「auth 콜백이 비었으니 열려 있을 것」이라는 **추정**이 되기 때문입니다(D-280).

```
[실측 · 익명 요청 · 수정 전]
  GET  /api/dronehw/.../online-drones                        200  ★ 데이터가 나갔습니다
  GET  /api/terminals/days-of-week                           200  ★
  GET  /api/terminals/terminal-types                         200  ★
  POST /api/operational-data/.../upload-operational-video-드론/로봇   도달 (4자리)
  POST /api/delivery/processing/update-delivery-event        422
  … 그 밖 GET 5자리 400·404·422·500
  → 15/15 가 401 이 아니다 · 그중 3자리가 익명에게 200 과 데이터를 반환
```

> 익명 POST 4자리가 **운행 로그·운행 영상 업로드**입니다. 무게를 낮춰 적지 않습니다.

### ④ 경위 — 아는 것과 모르는 것을 가릅니다 (D-280)

```
[실측] 39자리 전부 blame 이 베이스라인 커밋(4afca2b · 2026-08-13)이다
[실측] 한 자리에 사유가 남아 있다 — api_key_controller.py:54 의 베트남어 주석
       「Tam thoi comment out de test」(= 시험용으로 임시 주석 처리)
[모름] 언제·왜 꺼졌는지. 주석 처리는 **베이스라인 이전 공급자 이력**에서 일어났고
       그 이력은 이 환경에 없다
```

**「임시」가 사유란에 적힌 채 베이스라인을 넘어왔습니다.** 그것이 아는 전부입니다.

### ⑤ 조치 — 고친 것과 미룬 것을 한 칸에 두지 않았습니다

| | 무엇 | 규칙 |

## 2. ★ 곁가지로 하나 더 잡혔습니다 — **캐시가 코드 수정보다 오래 삽니다**

고치고 다시 때렸더니 **2자리가 여전히 200** 이었습니다. 코드는 고쳐졌는데 값이 나갔습니다.

```
[실측] common/universal_optimization.py::UniversalCacheMiddleware
  · 캐시 적중 시 뷰를 부르지 않고 JsonResponse(200) 을 돌려준다  (:872)
  · 캐시 키의 사용자 권한 서명이 익명은 "anon" 이다              (:711)
  → 열려 있던 동안 익명 키로 채워진 항목이 **코드 수정 뒤에도 익명에게 그대로** 나갔다
[실측] cache.clear() 뒤 익명 2xx 0건
```

**원칙으로 올릴 값이 있다고 봅니다: 관문을 고치는 것과 이미 새어 나간 것을 거두는 것은 다른 일입니다.**
그리고 **관문을 재는 시험이 캐시를 재면 안 됩니다** — 회귀 시험은 `X-No-Cache` 로 우회해 때립니다.

> 운영 함의: 같은 일이 운영에 있었다면 **배포만으로는 부족하고 캐시를 비워야** 합니다.
> 개발 환경에서는 비웠습니다. 운영은 불변 제약대로 건드리지 않았습니다.

## 6. ④ F-05 진입면 — **「잇기」가 아니라 「좁히기」였습니다**

착수하면서 판정이 한 겹 내려갔습니다. 지시는 「만들지 말고 이어라」였는데,
**이미 이어져 있었습니다.**

```
[실측 2026-09-07] dj-core 의 CustomJWTAuth 는 X-API-Key 와 Authorization 의
inbound 스킴을 **이미 받는다.** 들어오는 키는 만들 것이 아니라 이미 살아 있었고,
**아무도 그 범위를 정하지 않았다.**

호출로 잰 것 — 키 하나로 F-05 진입면 **7자리 전부에 도달**:
  /events · /deliveries · /dashboard/frame(200) · /events/{id}/clip ·
  ★ /events/{id}/clip/stream · /reports/templates(200) · /settings/{domain}

만료된 키 401 · 비활성 키 401 · 가짜 키 401
→ **인증은 성했습니다. 성하지 않은 것은 범위입니다.**
```

`clip/stream` 이 **계약 11조(영상 반출 · D-306)** 의 자리입니다.
발급된 아무 키나 거기 닿고 있었습니다. 이건 「아직 안 만들었다」가 아니라
**「범위 없이 이미 열어 두었다」**이고, D-334 와 **같은 얼굴**입니다.

### 한 일 — 좁히기 하나

```
backend/common/inbound_api_key.py :: JwtOrInboundKey
  · 라우트마다 들어오는 키를 받을지 **선언하게** 한다
  · ★ 기본값이 거절이다 — 새 라우트가 선언 없이 생기면 키가 닿지 않는다 (D-300 부작위)
  · CustomJWTAuth 를 상속해 **감싸기만** 한다. 고치지 않는다 (§0.4 · D-207)
  · 사유 없는 개방은 생성 시 거부한다 — 「왜 열렸는지 모르는 문」을 만들지 않는다

backend/apps/dsm/api.py — 진입면 11자리 전건이 이 문지기를 지난다.
  들어오는 키가 닿는 곳은 **GET /api/dsm/events 하나뿐**이다 (규약 ③)
```

**규약 다섯을 시험 17건으로 걸었습니다** — 클래스 하나가 규약 하나씩 맡습니다.
⑤ 부작위가 본체이고, **음성 대조**(이벤트 조회에는 들어간다)를 함께 뒀습니다 —
전부 401 이면 그건 「막았다」가 아니라 **「아무것도 안 열렸다」**이기 때문입니다.

### ★ 그래도 절은 올리지 않았습니다

FR-05-3 이 말하는 것은 **「발급·폐기」**이고, 이번에 한 것은 **소비 면의 범위**입니다.
둘은 다른 일입니다. **범위를 좁혔다고 발급·폐기를 만든 것이 아닙니다** —
올리면 그 순간 대장이 거짓말을 시작합니다(D-337 ①과 같은 병).

```
[AC] 절 상태: 구현 27 · 미착수 4 · 잠김 8 · 미측정 0
[AC] 잔여 12절 / 전체 39절 (구현 27 · 69%)   ← ⑨ 변동 없음
```

**⑨ 절 표는 변동 없습니다** [실측]. 이번 턴 산출물이 **기반·게이트·사고 처리·범위 좁히기**여서
계약 절을 갚지 않았습니다. 그것이 사실이고, 좋게 적지 않습니다.

**잠금** [실측]: 총 6건 · **지금 막고 있는 것 4건** (DEV 3 · CONTRACT 1) ·
미룸 2건 (ADMIN 1 팝업키 · **OPS 1 카메라 주소** — 신규).
