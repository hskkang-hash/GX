## 2. ③ 표 ① 임계값 — **계약을 설정으로 어길 수 없게 만들었습니다**

```
[THRESHOLD] 표 ① **5항목** · 코드 하드코딩 임계값 614건 (계약 기능 면 131건)
            event.dedup_window          10 seconds  ← k1_event:DEDUP_WINDOW
            notify.email_timeout        10 seconds  ← k2_notify:FALLBACK_EMAIL_TIMEOUT
  계약고정  notify.max_latency          30 seconds  ← k2_notify:F10_MAX_LATENCY
  계약고정  notify.suppress_window       5 minutes  ← SUPPRESS_WINDOW · NOTIFY_WINDOW
            waterlevel.baseline     (값 없음) cm     ← 읽는 코드 없음
[THRESHOLD] 기준선 614건 · 새 매직 넘버 0건
```

**설계 판정 셋을 보고드립니다.**

**① `contract_fixed` — 지시서에 없던 칸을 하나 더했습니다.**
표를 만들다 이 위험을 봤습니다: *"임계값을 설정 가능하게 만들었다"* 가 곧
**"계약 AC 를 설정 가능하게 만들었다"** 가 됩니다. F-04 「5분」·F-10 「30초」는 우리 취향이
아니라 **계약 인용값**입니다. 표에 두는 이유는 값이 한 곳에 보이게 하기 위해서이지 고치라고
둔 것이 아닙니다. **설정 한 줄로 계약을 어길 수 있으면 그 계약은 코드에서 사라진 것**이므로,
덮어쓰기 시도는 409 로 멈춥니다. 표가 갚으려던 절을 표가 부수지 않게 하는 칸입니다.

**② `waterlevel.baseline` 은 기본값을 지어내지 않았습니다.**
F-02 가 **지점별**이라고 못박았고, 하천 지점마다 범람 수위가 다르므로 전역 기본이라는 것이
성립하지 않습니다. 「기본값 0」은 「기준선이 0cm」로 읽히고, 그러면 **모든 신호가 초과**가
됩니다. 값이 없으면 `ThresholdNotSet` 으로 멈춥니다(D-280 · D-284).

**③ 표 ①도 K5 에 두었습니다.**
지시서는 표 ①을 "L3 커널" 이라고만 하고 번호를 주지 않으셨습니다. 계약 AC 대장이
F-12(수신자·위젯·구역·**임계값**·등급규칙·**API키**)의 커널을 **K5** 로 적고 있어
그대로 따랐습니다. **새 커널 번호를 지어내지 않았습니다**(D-280). 다르게 보시면 판정 주십시오.

강제 도구 — `scripts/verify_threshold_table.py` 가 둘을 봅니다:
**① 대조** 표의 `used_by` 가 가리킨 상수의 값이 표와 같은가(다르면 표는 거짓말하는 문서가 됩니다) ·
**② 래칫** 오늘 614건을 지문으로 잠그고 **새로 태어나는 것만** 막습니다(D-311, 소급 사유 요구 없음).

> ★ 래칫 지문에서 한 번 좁혔다가 반대편이 열린 것을 자기시험이 잡았습니다(D-326).
> 줄 번호를 빼면 코드를 옮겨도 안 흔들리지만 **같은 값이 하나 더 늘어도 안 잡힙니다.**
> 그래서 동일 지문에 **서수**를 붙였습니다 — 옮기는 것은 서수를 안 바꾸고, 늘어나는 것은
> 반드시 새 서수를 만듭니다. 자기시험이 양쪽을 함께 잽니다.

## 3. ④ 표 ② — **섰습니다. 그런데 계약 절은 하나도 갚지 못했습니다**

이것이 이번 회신에서 가장 중요한 보고입니다.

```
[CRED] 표 ② **3건** · 기능 코드가 쓸 수 없는 이름 **1건**
       (술어=capability 기재 + 상태 typed 이상)
  **차단**    DATA_GO_KR_KEY_DECODED   present   비밀키  공공데이터포털 일반 인증키
  쓸 수 있음  JUSO_POPUP_KEY_1         typed     공개키  도로명주소 팝업 API
  쓸 수 있음  JUSO_POPUP_KEY_2         typed     공개키  도로명주소 팝업 API
```

표는 지시하신 대로 섰습니다 — 상태 **5값**(D-328) · `api_type`·`capability` 칸 ·
**값을 담는 칸 자체가 없음**(D-204·D-319) · 마스킹 조회 · 접근 감사 · `verified_at`/`verified_by`
가 손으로 적는 칸이 아니라 **조회 결과**(`refresh_credential`).

**그런데 D-325 가 예상한 두 절(F-05 「API Key 발급·폐기」 · F-12 「API키」)은 갚지 못했습니다.**

```
표 ②    = **나가는** 자격증명 — 우리가 남의 API(juso·포털)를 부를 때 쓰는 키
FR-05-3 = **들어오는** 자격증명 — 남의 App 이 우리 이벤트 OpenAPI 를 부를 때 쓰는 키
```

**방향이 반대입니다.** 둘 다 "API Key" 라고 불려서 같은 것으로 읽혔습니다 —
**이름의 유사성을 같음으로 읽은 것**이고, D-321(재난안전 CCTV: 이름이 우리 도메인과 닮아서)과
D-328(어떤 키인지 묻지 않았다)의 **형제**입니다. 같은 병이 이번으로 세 번째입니다.

그리고 그 판정을 내리는 길에 **바퀴를 하나 발견했습니다** [실측]:

```
core.apikey_account            (dj-core · §0.4 금지구역)      ← 발급·폐기 면이 이미 있다
backend/third_api/views/api_key_controller.py                  ← 그것을 감싼 컨트롤러가 있다
```

다만 **F-05 의 진입면에 연결돼 있지 않고**(이벤트 OpenAPI 는 `CustomJWTAuth` 만 받습니다),
그 컨트롤러의 `@path_permission` 이 **주석 처리돼 있습니다.** 그래서 지금 상태로는 절을
올릴 수 없습니다. **남은 일은 「만들기」가 아니라 「잇기 + 권한 되살리기」**이고,
그 앞에 **이벤트 OpenAPI 의 인증 방식** 판정이 있습니다 — 지금 우리가 고르면 그 선택이 곧
F-05 의 계약이 됩니다(D-280). **판정을 요청드립니다.**

> ★ 표 ②를 만든 것이 헛일은 아닙니다. `verified_at`/`verified_by` 가 진술에서 조회 결과로
> 바뀌었고(D-323), `capability` 가 빈 키를 기능 코드가 만지면 게이트가 멈춥니다(D-328).
> **다만 절 표에서는 0입니다.** 표가 섰다고 절을 올리면 그 순간 대장이 거짓말을 시작합니다.

## 4. ⑤ D-330 카메라 설치 주소 — FX-5 잠금이 **사라졌습니다**

`StreamMonitor` 에 셋을 두었습니다: `install_address` · `install_address_detail` ·
`address_source`(`unset` | `manual`). 알림 위치 한 줄이 이제 이렇게 나갑니다:

```
주소 있음   위치 정문 (서울특별시 중구 세종대로 110)
주소 없음   위치 미상 — 좌표가 기록되지 않았습니다     ← 종전 그대로. D-308 경계를 넓히지 않았습니다
```

**발송은 지연되지 않습니다** — 주소가 없는 카메라의 이벤트도 F-10 상한 안에 발송 기록이
남는 것을 시험이 잽니다(`test_the_address_does_not_delay_sending`).
**보조 정보가 계약 AC 를 인질로 잡지 않게** 하는 것이 이 변경 고유의 위험이었습니다.

`address_source='unset'` 인데 주소만 적힌 행은 **믿지 않습니다** — 두 칸이 한 사실을 다르게
말하는 상태이고, `verify_camera_address.py` 가 그 어긋남 수를 따로 셉니다.

`scripts/verify_camera_address.py` 는 **exit 0** 입니다. 미입력은 운영자가 채우는 값이지
개발이 막는 값이 아닙니다 — 다만 **수가 보여야 채워집니다**(D-301). 이 게이트는 Django 가
필요해 호스트에서는 **exit 2(판정 불가)** 입니다. 컨테이너에서 돌린 첫 실측:

```
[CAM-ADDR] 등록 카메라 **39대** (모수=StreamMonitor 전수 · 술어=install_address 가 비었는가)
[CAM-ADDR] 주소 입력 **0대** · 미입력 **39대** · 어긋남 0대
```

이 개발 DB 기준 **39대 전부 미입력**입니다. 지금 알림은 39대 모두 종전대로 나가고,
그 수가 줄어드는 것이 곧 이 기능이 켜지는 과정입니다.

세 필드는 `verify_dead_fields.DECLARED_UNWIRED` 에 **사유와 함께** 등재했습니다 —
지금 코드에 쓰기가 없다는 것이 사실이고, 그 사실을 숨기지 않았습니다.

## 6. ⑦⑧ 절 표와 잠금 대장 — **두 수가 지시서와 다릅니다**

### 6-1. 절 표 [실측]

```
[AC] 검사 14행 · **절 39개** · 증명 시험 66건
[AC] 절 상태: 구현 **27** · 미착수 **4** · 잠김 8 · 미측정 0
[AC] ★ **잔여 12절 / 전체 39절 (구현 69%)**
```

| | 지시서 예상 | 실측 |
|---|---|---|
| 미착수 | 6 → **2** | 6 → **4** |
| 잔여 | 14 → **10** | 14 → **12** |

차이는 §3 그대로입니다 — 표 ②가 F-05·F-12 의 API키 절 **둘**을 갚을 것으로 보셨으나,
그 둘은 **들어오는 키**이고 표 ②는 **나가는 키**였습니다.

올라간 둘: **F-02 「지점별 기준선 설정」** · **F-12 「임계값」** — 표 하나가 두 절을 갚았습니다.
남은 넷: F-12 「구역」 · F-12 「등급규칙」 · F-05 「API Key 발급·폐기」 · F-12 「API키」.

### 6-2. 잠금 대장 — 지금 막는 것은 **3건이 아니라 4건**입니다 [실측]

```
[BLOCKER] 검사 5건 · 유형별: DEV 3 · CONTRACT 1 · ADMIN 1
[BLOCKER] ★ **지금 막고 있는 것 4건** · 남겨 두었으나 막고 있지 않은 것 1건
[BLOCKER]   (미룸) JUSO_API_KEY — 없앤 것과 미룬 것은 다르다. 지우지 않는다
```

지시서 §4 는 「DEV 2 + CONTRACT 1 = 3건」으로 보셨는데, 그 계산은 **FX-5 가 DEV 잠금 항목으로
대장에 있다**고 전제한 것입니다. 실제 대장의 DEV 3 은 **VIDEO 구간 추출 · ZONE 폴리곤 ·
빈 DB 한 줄 설치**이고, FX-5 는 애초에 ADMIN 한 줄(juso)로만 있었습니다.
그래서 D-330 이 해소한 것은 DEV 잠금이 아니라 **ADMIN 잠금의 사유**입니다.

D-323 대로 세 칸(`blocked_now`·`verified_at`·`verified_by`)을 전건에 넣었고,
D-333 대로 CONTRACT·ADMIN 에 `internal_alternative_considered`·`why_not` 을 넣었습니다.
게이트가 **잠김 총수와 지금 막는 수를 따로** 출력합니다 — 둘이 한 칸에 있으면 D-323 이
무의미해집니다.

> ⚠ 잔사항 하나 [실측]: 이 개발 환경의 시스템 시각이 **2026-08-29** 라서
> `verify_blockers.py` 가 SDN 대기를 「-6일」로 출력합니다. 게이트 결함이 아니라
> 환경 시각 문제이고, 문서 날짜(2026-09-06)와 어긋나 있다는 사실만 적어 둡니다.

### 6-3. D-333 재검토 3종 [실측·판정]

| 자원 | 판정 | 사유 |
|---|---|---|
| 기상특보 | **외부가 낫다** | 특보는 기상청이 발표하는 **공적 사실**이다. 영상으로 강우를 추정하면 그 오탐 책임이 우리에게 온다 |
| 특일(공휴일) | **외부가 낫다** | 대체·임시공휴일은 매년 정부가 정하고 사후 변경된다. 우리 표로 들면 틀린 날 알림 정책이 조용히 틀린다. 다만 실시간 의존이 아니다 |
| 학교 위치 | **필요 없다 → `not_required`** | 고객은 특정 지자체이고 카메라는 D-330 으로 자기 주소를 갖는다. 「F-03 위험구역 자동 제안」은 **계약 AC 가 아니라 우리가 붙인 아이디어**였다 |
