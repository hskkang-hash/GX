# WP-1 착수검토서 — 테넌트 격리 완결 (실제 노출 차단)

**작성** 에이전트 · 2026-08-15 · **정본** tickets v3.1 / WP **2/9** · baseline `4afca2b`
**목표(goal)** group A 토큰으로 group B 데이터에 도달 불가함을 **HTTP 레벨로** 증명
**티켓** W0-12 · W0-14 · W0-13 · W0-11 (4건 / 전부 `ready` · P0 · human_gate 없음)

> **이 검토서의 결론을 먼저 적는다.**
> WP-1 은 티켓 4개가 아니라 **W0-14 하나**다. 나머지 셋은 W0-14 없이는 증명되지 않고,
> W0-14 는 나머지 셋 없이도 대부분의 노출을 막는다. 그리고 **W0-14 의 spec 은 이 저장소와 맞지 않는다**(§3).

## 1. 이 목표가 참이 되려면 무엇이 있어야 하는가

goal 의 무게중심은 **"HTTP 레벨로"** 다. ORM 매니저가 무엇을 하든, 응답 바디에 남의 테넌트 행이
한 줄이라도 있으면 거짓이다. 그래서 증명 단위는 모델이 아니라 **엔드포인트**다.

| # | 있어야 하는 것 | 어느 티켓 | 증명 방법 | 사내망 |
|---|---|---|---|---|
| 1 | 엔드포인트에 group 스코프를 **기본값으로** 주입하는 단일 지점이 존재 | W0-14 ① | 해당 모듈 존재 + 라우트가 그것을 통과 | 불필요 |
| 2 | **누락 탐지 테스트** — 전 라우트가 (a)스코프 통과 or (b)EXEMPT 등재, 아니면 실패 | W0-14 ② | 테스트 실행 | **필요** |
| 3 | EXEMPT 가 인증 불요 엔드포인트로 한정되고 증가 금지 테스트가 걸림 | W0-14 ②③ | 목록 + 테스트 | 불필요(정적) |
| 4 | 적용 현황표가 `evidence/W0-14/coverage.md` 에 존재 | W0-14 ③ | 파일 | 불필요 |
| 5 | 서비스 레이어가 group 을 **임의로 고르지 않는다** | W0-12 | `grep UserGroup.objects.first()` → 0 | 불필요 |
| 6 | 전역 `.objects.first()` 스캔 결과가 `evidence/W0-12/scan.md` 에 기록 | W0-12 ② | 파일 | 불필요 |
| 7 | `created_by IS NULL` 영향 조사표가 `evidence/W0-13/impact.md` 에 존재 | W0-13 ① | 파일 | **필요**(행 수 집계에 DB) |
| 8 | 필터에서 `Q(created_by__isnull=True)` 제거 + `is_system` 대체 | W0-13 ②④ | grep → 0 | 불필요(코드) / **필요**(백필) |
| 9 | dj-core 우회 목록 유무가 `evidence/W0-11/dj-core-findings.md` 에 기록 | W0-11 | 파일 | **필요**(소스 수령) |
| 10 | group A 토큰 → group B 리소스 요청이 **404/빈 목록** | 전체 | `TenantIsolationAPITest` 5건 | **필요** |

**10개 중 6개는 지금 여기서 할 수 있고, 4개가 사내망에 묶인다.**
WP-0(전량 사내망)과 달리 **WP-1 은 구현의 대부분이 오프라인에서 끝난다.** 이것이 지금 WP-1 을 여는 실익이다.

## 3. 전제 검증 — 티켓 spec 과 실측의 차이

> D-210: 지시서의 식별자는 근사치다. 다르면 실측이 우선이고, 차이를 여기 적는다.

**전제가 통째로 틀린 티켓이 있는가?** ☐ 없음 · **☑ 있음 → W0-14 ①②** (아래)

| 티켓 | spec 이 말한 것 | 실측 | 어떻게 처리할 것인가 |
|---|---|---|---|
| **W0-14 ①** | *"DRF: `TenantScopedViewSetMixin` 을 만들고 `get_queryset`/`get_object` 에서 group 강제"* | **이 저장소에 DRF 뷰가 0개다.** `ViewSet` 정의 0 · `APIView` 정의 0 · `from rest_framework` import 0파일. `djangorestframework==3.16.0` 은 `requirements.txt` 에 있으나 `simplejwt` 의 토큰 클래스로만 쓰인다 | **DRF 갈래는 사문(死文)이므로 구현하지 않는다.** spec 의 두 번째 갈래인 **Ninja 의존성 주입**만 구현. 정본은 수정 권한 밖(금지 #11) → AUTHOR-ERROR 로 기록 |
| **W0-14 ②** | *"`config/urls.py` 에서 등록된 전 라우트를 열거"* | `config/urls.py` 에는 라우트가 없다. `include()` 23개가 **18개 `NinjaExtraAPI` 인스턴스**를 마운트하고, 실 엔드포인트는 컨트롤러의 **`@route.*` 466개** | 열거 지점을 **`NinjaExtraAPI` 인스턴스 순회 → `api._routers` → path operations** 로 바꾼다. 결과 수는 같지만 **누락 없이** 센다 |
| **W0-14 ①** | *"`tenant_filters.py` 는 이미 신설돼 있다. 이것을 선택이 아니라 기본값으로 만든다"* | 신설돼 있는 것은 맞다. **그러나 저장소 전체에서 호출처가 0건이다** — 만들어 두고 한 번도 연결하지 않았다 | spec 의 판단이 정확했음을 확인. 다만 "기본값으로 만든다"의 실제 작업량이 **0→466** 이라는 뜻이다 |
| **W0-14 ③** | *"EXEMPT 는 인증 불요 엔드포인트(health, login, 공개 문서)로 한정"* | `@route.*` 466건 중 **`auth=` 미선언이 102건**(21.9%). `@api_controller` 와 `NinjaExtraAPI` 어디에도 전역 auth 기본값이 없다 | **102 를 그대로 EXEMPT 로 넣으면 안 된다.** spec 의 한정 조건과 정면으로 어긋난다 → §6 리스크 1 · §8 결정요청 |
| **W0-12 ①②** | 2지점 지목 | **정확히 2건.** 다른 곳 없음 | 그대로 구현 |
| **W0-12 ③** | *"`.objects.first()` 중 Group/Tenant 성격 모델에 걸린 것 전부"* | 19건. 그중 **관리 커맨드·주석·비테넌트 마스터**가 다수(§4 표) | 성격 분류 후 **테넌트성만** 수정. 분류표를 `scan.md` 에 남긴다 |

## 5. 되돌리기 계획

| 무엇이 잘못될 수 있나 | 어떻게 되돌리나 | 난이도 |
|---|---|---|
| 스코프 주입이 정상 요청을 막는다 | 설정 1개(`TENANT_SCOPE_ENFORCE=False`)로 경고 모드 강등. **코드 되돌림 불필요** | **설정** |
| EXEMPT 목록 판정 착오 | 목록은 단일 파일. 항목 추가/제거는 1줄 | **코드** |

| `is_system` 컬럼 추가 | 역마이그레이션 존재 (`migrate <app> <prev>`) | **스키마** |
| **`created_by` NULL 백필** | **되돌리기 어렵다** | **데이터** |

**되돌릴 수 없는 변경이 포함되는가?** ☐ 없음 · **☑ 있음 → W0-13 ③ 백필 1건**

dry-run 계획: ① `impact.md` 로 모델별 NULL 행 수 집계(읽기 전용, 커밋) → ② 백필 대상·귀속 판정 근거를
`--dry-run` 리포트로 출력해 **먼저 커밋** → ③ 사람 확인 후 실행. **리포트 없이 실행하면 hard_stop(`data-destructive`).**
**이 WP 에서는 ①까지만 하고 ②③은 사내망 방문 이후로 둔다.**

## 8. 사람이 해야 할 것

| # | 무엇 | 왜 사람이어야 하나 | 없으면 어떻게 되나 |
|---|---|---|---|
| **1** | **`auth=` 미선언 102건의 성격 판정 방침** — 전량 인증 필수로 볼 것인가, 앱별로 나눌 것인가 | 미인증 공개가 **의도된 것인지**(파트너 콜백·프록시 등) 코드만 봐서는 판정 불가. 인증을 거는 순간 외부 연동이 끊길 수 있다 | 기본값을 정하면 리스크 1 그대로 — 게이트 착시 |
| **2** | **§0.4 금지구역 라우터에 스코프를 주입해도 되는가** (`terminals` 14 · `delivery` 10 · `orders` 3) | 앱 **파일은 건드리지 않지만** 동작은 바뀐다. §0.4 의 취지("배송 라인은 그대로 둔다")에 닿는다 | 미인증 최다 구간이 통제 밖에 남아 goal 이 거짓 |
| **3** | **WP-1 착수 승인** (이 문서 첫 줄) | 금지 #17 — 승인 전 소스 수정 불가 | 오프라인 구현 6/10 항목이 대기 |
| 4 | 사내망 방문 (WP-0 과 동일 건) | 물리 접속 | 증명 항목 4건(#2·7·9·10) 미충족 |

> 그것이 파트너 연동을 끊으면 `external-commitment` 에 닿는다. **적재만 하고 기본값을 적용하지 않는다.**
