## 1. ② 열린 2자리 — **오늘 닫았습니다**

판정하신 뿌리가 정확했습니다.

> **D-207 이 금지한 것은 그 파일을 수정하는 것이다. 그 경로로 가는 요청을 우리 층에서
> 막는 것은 금지된 적이 없다. 바꿀 것은 게이트가 아니라 막는 자리다.**

순서 ①에서 끝났습니다. **②(앞단)·③(§0.4 예외)는 쓰지 않았습니다.**

```
[실측 2026-09-09 · 익명 · 캐시 우회]
  GET /api/delivery/drone-monitoring/drone-status   200 (17,416 B) → **401** (63 B)
  GET /api/delivery/etri-mock/test-scenarios        200 ( 1,976 B) → **401** (63 B)
  REACHED_WITH_DATA  2 → **0**
  forbidden-zone 게이트: **초록** — backend/delivery 도 dj-core 도 한 줄 안 바뀌었습니다
```

### ★ 자리 판정 하나 — 관문은 **캐시보다 바깥**입니다

`UniversalCacheMiddleware` 안쪽에 두면, 열려 있던 동안 익명으로 채워진 항목이 **관문을 지나지 않고**
그대로 나갑니다. 2026-09-07 에 실제로 있었던 일입니다(고친 뒤에도 2자리가 200).
시험이 미들웨어 **순서 자체를 단언**합니다 — 나중에 누가 옮기면 빨개집니다.

### ③ 전역 기본값 거절 — 같은 한 겹이 덮습니다

승인해 주신 D-343 ③을 이 미들웨어에 함께 실었습니다. 들어오는 키는 **선언 목록**(지금 1자리)
밖에서는 401 입니다 — **§0.4 경로를 포함해서**.

```
[실측] 가짜 키로 때린 결과
  GET /api/dsm/events              401   (허용 목록에 있으나 키가 가짜)
  GET /api/dsm/events/1/clip/stream 401  ← 계약 11조의 자리
  GET /api/terminals/terminals      401  ← 이전에는 키가 닿던 515자리 중 하나
```

★ 목록이 **라우트 선언과 갈리면 시험이 잡습니다.** 한쪽이 열고 다른 쪽이 막는 상태를 막습니다.

> **되돌리기**는 `settings.MIDDLEWARE` 에서 한 줄을 지우는 것입니다. 데이터도 스키마도 안 건드립니다.

**②(배포 앞단)는 걸지 않았습니다.** nginx 설정은 배포 환경마다 갈리고, 여기서 정하면
**그 환경에서만 도는 방어선**이 됩니다. 상용 표 ②에 절로 남겼습니다 — 지시하시면 겁니다.

## 2. ④ 봉투 불일치 — **564 가 아니라 296 이었습니다**

> **술어 재확인: 했습니다. 그리고 첫 술어가 틀렸습니다** (D-350).

처음 `status_code=4xx` 를 훑어 **564건**을 셌습니다. 놀라운 수였고, 그래서 코드를 봤습니다:

```
core/common/base_response.py
    class BaseResponse(JsonResponse):
        def __init__(self, success=True, status_code=200, ...):
            super().__init__(self.results, status=status_code)   ← HTTP 상태가 따라간다
```

**564 중 대부분은 갈리지 않습니다.** 갈리는 것은 **Response 로 감싸지 않고 dict 를 그대로
돌려줄 때**뿐이었습니다. 좁힌 뒤 전수:

| 봉투 상태 | 건수 | 뜻 |
|---|---:|---|
| `clean` | 356 | 갈릴 자리가 없다 |
| `authz_envelope` | **296** | dj-core `path_permission` 이 200 봉투에 403 을 담는다 (§0.4) |
| `promoted` | **11** | F-05 진입면 — 본문의 상태가 HTTP 상태가 된다 |
| `body_status` | **0** | 우리 핸들러가 만든 불일치 — **없습니다** |

**③ F-05 는 래칫에서 빼고 지금 바로잡았습니다.** 전역 승격 플래그는 그대로 꺼 두고
(무증상 실패 후보 21곳 · W0-18 §2-2), **경로로 좁혀** 걸었습니다:

```python
API_CONTRACT_PROMOTE_PATHS = ("/api/dsm/",)   # 전역 플래그가 꺼져 있어도 여긴 승격한다
```

시험이 **양쪽**을 봅니다 — 계약 면은 403 으로 나가고, 래칫 밖 면은 **그대로 200** 입니다.
(전부 승격되면 그건 「좁혔다」가 아니라 「전역을 켰다」입니다.)

## 3. ⑤ 운영 — **복구를 해 봤습니다**

> 「백업 있음」은 절이 아니고 **「복구 성공」이 절이다** — 그 문장대로 만들었습니다.

```
[실측 2026-09-09]
  백업  db_database_guardianx_20260829T134442Z.dump · 4,447,529 B · sha256 기록
  복구  임시 DB restore_check_20260829134640 으로 살렸고, 행 수를 맞췄습니다:
          카메라 39 → 39 · 사용자 103 → 103 · 이벤트 0 → 0 · 클립 0 → 0 · 그룹 0 → 0
  판정  **복구 성공.** 쓴 명령을 그대로 남겼습니다 (evidence/D-354/restore_run.md)
```

**원본은 세 겹으로 지킵니다**: 복구 대상 이름이 원본과 같으면 시작하지 않고,
`restore_check_` 로 시작하지 않으면 거부하고, 끝나면 지웁니다(실패해도).

### ★ 운영 사실 하나를 배웠습니다 — 백업은 **뜨는 자리가 정해져 있습니다**

```
pg_dump: error: aborting because of server version mismatch
detail:  server version: 18.1 · pg_dump version: 17.7
```

앱 컨테이너의 클라이언트가 DB 서버보다 낮았습니다. **아무 데서나 돌리면 안 됩니다.**
매뉴얼에 없으면 운영자가 새벽에 알게 됩니다 — 그래서 「어디서 실행하는가」를 인자로 만들고
(`--via docker:postgres`) 장애 대응 문서에 적었습니다.

### 객체저장은 **미측정입니다** — 그리고 그렇게 적었습니다

`minio.invalid` 에 닿지 못했습니다. **「닿지 못했다」와 「0개다」는 다른 사실**이라 대장에
그대로 적고 미측정으로 뒀습니다(OPS-09).

> ★ **DB 만 살아나면 이벤트 행은 돌아오고 그 이벤트의 영상은 사라집니다.**
> 복구된 시스템이 「영상이 있었다고 말하는 DB」가 됩니다 — 착시 ⑥(스키마)의 운영판입니다.
> 그래서 「복구 성공」을 DB 절과 객체 절로 **쪼갰습니다**.

### 감시 3종 · 장애 대응 1쪽

```
[실측] 신호 7개 · OK 6 · UNKNOWN 1
  OK      db_ping_ms          8.1      한계 500
  OK      cache_alive         True     왕복 5.2ms
  OK      object_store_alive  True     질의가 닿았다 (쓰지 않았다)
  UNKNOWN latest_event_age_min None    이벤트가 한 건도 없다 — 「밀렸다」가 아니라 「비었다」
  OK      unsent_deliveries   0        한계 10
  OK      db_size_gb          0.082    한계 50
  OK      cameras             39
```

`--check` 가 **0 정상 / 1 경보 / 2 판정 불가**로 답합니다. 크론에 걸고 exit 1 을 사람에게 보내면
그것이 경보입니다. **보내는 자리(메일·문자·챗)는 고객 환경마다 달라 여기서 정하지 않았습니다** — OPS-10.

★ 임계값마다 **왜 이 수인가**를 적었습니다. 적을 수 없는 임계값은 임계값이 아닙니다.
★ **UNKNOWN 을 초록으로 세지 않습니다**(D-301).

## 4. ⑥ 성능 1차 측정 — 둘은 쟀고, **하나는 못 잽니다**

> 목표를 먼저 정하지 않았습니다. **먼저 쟀고, 이 수가 출발점입니다**(D-280).

```
[환경 · 실측] CPU 8 · mem 7.7GiB · cgroup cpu.max 100000 · **GPU 없음** ·
              python 3.11 · n=30 · 워밍업 5회 버림 · 트랜잭션 안에서 재고 되돌림

  이벤트 처리 (K1)   p50 12.28ms · p95 13.25ms · 최대 13.62ms
  알림 발송   (K2)   p50  2.89ms · p95  3.42ms · 최대  3.75ms
  동시 스트림 상한   **미측정**
```

**동시 스트림 상한을 못 재는 이유**: RTSP 원본도 AI 서버도 이 환경에 없습니다(`ai.invalid`).
그래서 **「선언된 상한」과 「실제 상한」을 나눠** 적었습니다 —
선언된 값을 실제 값으로 적는 순간 그것이 착시 ①입니다. 잴 수 있으려면:
RTSP 원본 N개 · AI 추론 서버 1대 · 프레임 드롭률·자원·열화 지점 관측.

> ★ **이 수를 영업에 그대로 쓰지 마십시오.** 한 건씩 잰 수입니다.
> F-10 의 30초 대비 여유가 크지만, **초당 몇 건까지 그 30초가 지켜지는지는 다른 측정**입니다
> (PERF-05 · 미측정). 「한 건이 빠르다」를 「많이도 빠르다」로 읽으면 착시 ③입니다.
