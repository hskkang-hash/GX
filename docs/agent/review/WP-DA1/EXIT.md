## 1. ★ 이 WP 가 실제로 만든 것 — 문서 4건이 아니라 **게이트 3개**다

문서는 시간이 지나면 정본과 갈린다. 그래서 이 WP 의 산출물 중 오래 가는 것은 문서가 아니라
**문서와 정본이 갈렸을 때 실패하는 장치**다.

| 게이트 | 무엇을 막나 | 지금 |
|---|---|---|
| `scripts/verify_da01_reuse_paths.py` | DA-01 이 인용한 재사용 경로가 저장소에서 사라지는 것 | **19/19 통과** |
| `scripts/verify_kernel_map.py` | DA-04 §4 매핑표와 `tickets.yaml` 의 `kernel:` 이 갈리는 것 | **커널 6/6 · 통과** |
| `scripts/gen_manifest.py` | 티켓을 넣고 빼면서 ID 가 충돌·유실되는 것 | **77건 대조 통과** |

### 1-1. 게이트 하나를 오늘 더 단단히 했다 (D-258)

`verify_kernel_map.py` 는 K1~K6 만 돌았다. 지시서 v2.2 가 **K7**(컨텍스트 커널)을 예고했으므로,
누군가 `kernel: [K7]` 만 먼저 달면 **이 스크립트는 K7 을 아예 보지 않는다** — 문서에 없는 매핑이
조용히 정본에 남는다. 그것이 이 스크립트가 막으려던 바로 그 상태다(D-227 manifest 유실과 같은 모양).

→ **미지 커널 검사**를 넣었다. 화이트리스트 밖 코드가 정본에 있으면 exit 1.
   주입 시험으로 동작을 확인했다(K7 주입 → 실패 · 되돌림 → 통과).
   DA-05 의 dod (6) 이 "K7 을 문서 표와 스크립트에 **함께** 편입"을 조건으로 못박는다.

## 5. WP-DA2 구조가 승인됐다 (D-259)

월별 증분 릴리스를 그대로 **WP 경계**로 쓴다 — 릴리스 = 검토 지점.
WP-DA2 를 통으로 두면 대표 검토가 3개월에 한 번이 되고, 그것이 v3.0 무인완주가 실패한 모양이다(D-215).

| WP | 시기 | 내용 |
|---|---|---|
| WP-DA2a | 10월 | K1 이벤트 커널 + F-01~03 탐지 확장 + F-05 이벤트 API |
| WP-DA2b | 11월 | SDN 어댑터 F-06~08(Mock→실기) + **K2 알림(DA2-21)** + K6 피드백 |
| WP-DA2c | 12월 | K3 대시보드 프레임 + K4 보고서 엔진 → F-09·11·12 + 검수 |
| WP-DA3 | 2027.1 | 통합시험·최종검수 |
| WP-DA4 | 2027.2~8 | 안정화 + K7 데이터 + F-13/14 |

**착수 조건 3건 (셋 다, 하나라도 빠지면 착수 금지)**:
① WP-2 EXIT(누출 0건) ② 대표 승인(WP 마다 ENTRY) ③ **정적 계층 검사 CI 등재** —
App(L4)이 커널(L3) 모델을 직접 import 하면 실패. DA-04 §5 가 올린 조건을 착수 조건으로 승격했다.
**커널 재사용률을 사람이 세면 항상 90% 가 나오기 때문**이고, 이 규칙이 계약 8조 IP 경계의
코드상 표현이다 — 커널 로직이 App 으로 새면 경계가 코드에서 소멸한다.

**ID 대역**: DA2-1x=a / DA2-2x=b / DA2-3x=c. 기존 ID 집합과 충돌 없음(manifest 75→77 통과).
