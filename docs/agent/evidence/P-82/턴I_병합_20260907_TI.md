## 2. 이 턴의 빨강 넷 — **셋은 새로 보인 것이고 하나는 우리가 만들었다**

### ① 우리가 만든 것 — MinIO 자격증명 없이 서버를 띄웠다
서버를 되세운 직후 `route-alive` 가 **503**(`/api/media-data`)을 냈다. 원인은 제품이
아니라 조율자였다 — 컨테이너에 구워진 값은 `minio.invalid` 라 객체저장소 이름 풀이부터
실패한다. 5분 만에 되세웠고 401(관문이 선 정상 응답)로 돌아왔다.
**영실 오판 +1.** 이 실패 모양은 저장소가 이미 아는 것이었다
(`docs/agent/evidence/TD-COORD/README.md`: 「그 프로세스가 죽지 않았기 때문에 초록이었다」).
**오늘이 그 「죽는 날」이었고, 기동 절차가 문서에 있었기 때문에 5분에 끝났다.**
다음 턴 후보: 그 절차를 **명령으로** 만든다(`scripts/serve_gate_api.sh`).

### ② 익명이 비밀번호를 바꿀 수 있었다 — 차선 S · 조율자 독립 대조
차선 S 가 무관문 쓰기 **10자리**를 찾아 길목(`backend/common/access_gate.py`)에서 닫았다.
조율자는 **그 판정기를 쓰지 않고** 날 HTTP 로, 같은 순간 두 서버에 같은 요청을 던졌다
(없는 id `999999999` 로만 — 아무것도 쓰지 않는다):

```
                                            8000(턴 H 코드)   8400(이번 턴 코드)
POST /api/v1/auth/reset-password-for-user        400      →       401
POST /api/apikey/keys                            500      →       401
```

**400 은 401 이 아니다** — 익명이 핸들러 안까지 들어갔고 본문이 안 맞아 되돌아 나왔을
뿐이다. **500 은 더 나쁘다** — 익명이 API 키 발급 코드까지 닿아 거기서 터졌다.
병합·재기동 뒤 **8000 에서도 둘 다 401** 이다.
★ 턴 H 의 `verify_write_auth` 가 422 를 관문으로 세지 않았다면 이 둘은 영영 안 보였다.

### ③ 앞단 502 — **판정기가 두 턴 동안 눈이 멀어 있었다** (OPS-13a)
OPS-13a 는 턴 D 에 「구현」으로 닫혔고, 그 뒤 판정기가 계속 **회색**이었다.
원인: OPS-07(로그 상한)을 갚느라 앞단 설정을 `access_log /dev/stdout` 으로 바꿨는데
판정기는 여전히 `/var/log/nginx/gx-front.access.log` 를 열고 있었다. 파일이 없으니
「못 쟀다」. **닫힌 절 위에서 판정기가 눈이 멀면 아무도 그것을 모른다.**

읽을 자리를 고쳐(파일 없으면 `docker logs`) 처음으로 다시 쟀다 — **빨강**:

```
앞단 접근로그 13,619줄 · 502 13건 · 정상 200 12,426건 → 0.105%
워커 재활용 61건 · **같은 초의 재활용으로 설명되지 않는 502 가 7건**
앞단이 재시도 138건 중 125건을 되살렸다(손님은 200 을 봤다) · 새어 나간 502 13건
```

★ **이것이 P-84 의 정본 줄 ②**다 — 개발 기계 runserver 수가 아니라 **운영형
인스턴스**(`gx-nginx-e` 앞단 · `gx-gunicorn-e` 뒷단)에서 난 수다. 턴 H 까지 SLA 에
적히던 0.139% 는 개발 기계 수였다.
그래서 **OPS-13a 를 구현 → 미착수로 내렸다.** 상용 82.8 → **82.0** 이 그 대가다.

### 왜 못 고쳤나 — 그리고 왜 판정기를 고치지 않았나

**이번 턴이 만든 결함이 아니다.** HEAD 에서는 같은 검사가 「고유 호출 36건 · 갈림 0건」이었다.
36 → 39 로 는 것은 **차선 C 가 촬영을 다시 돌려 그 화면이 원래 부르던 호출을 처음으로
기록**했기 때문이다. `/device` 화면은 HEAD 에도 있었다.

고치는 손잡이는 하나뿐이다 — `API_CONTRACT_PROMOTE_PATHS` 에 접두를 넣어 200 봉투를
진짜 HTTP 상태로 승격하는 것. 그런데 **승격이 안전한지 잴 수 없다**:
`/device` 는 rj-core 가 그리는 화면이라 그 오류 처리를 이 저장소에서 읽을 수 없고,
`/device` 를 볼 권한이 **없는** 시드 계정이 저장소에 없어 승격 전/후를 나란히 볼 수도 없다
(턴 F·G·I 세 턴 연속 같은 사유). 이 저장소는 같은 자리에서 이미 판정했다 —
**「못 재는 것을 켜는 것은 판정이 아니라 도박이다」**(`settings.py` · roles·user-profiles 주석).
