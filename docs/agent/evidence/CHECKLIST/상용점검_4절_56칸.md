## 4. 왜 34칸이 비었나 — **둘로 갈라 적는다** (D-396)

### ㉠ 안 눌렀다 (22칸) — 도구가 그것을 누르지 않는다

`walk_scenarios` 는 **길이 이어지는가**를 재고, `capture_screens` 는 **화면이 뜨는가**를
잰다. 둘 다 **폼 검증·오류 흐름·빈 상태**를 누르지 않는다 — 그 셋은 이 저장소에 아직
도구가 없다. 없는 도구의 결과를 표에 적을 수는 없다.

⚠ **여기서 새 도구를 짓지 않았다.** 지금 짓는 도구는 **9-04 번들**을 누르게 되고,
그 결과는 재빌드 즉시 버려진다. 순서가 거꾸로다.

### ㉡ 해 봤는데 못 했다 (12칸) — **번들이 낡았다**

`capture_screens` 가 28장 중 **18장을 찍고 10장을 못 찍었다**:

| step | 라우트 | 기다린 글자 |
|---|---|---|
| 17 | `/dsm/events?preset=unhandled` | 미처리 — 아직 아무도 손대지 않은 것 |
| 18 | `/dsm/events?preset=recent` | 지난 12시간 — 이 시간 창 안에 난 것 |
| 20 | `/dsm/events?preset=system` | 시스템 — 설비 자신이 낸 신호 |
| 21 | `/dsm/events/{id}` (판정 칸) | 처리 단계 · 진위 판정 |
| 22 | `/dsm/queue` | 지금 처리할 것 — 가장 급한 하나 |
| 23 | `/dsm/drill` | 훈련 모드 — 켜면 알림이 사람에게 가지 않습니다 |
| 24 | `/dsm/cameras/import` | 카메라 일괄 등록 — 표를 먼저 봅니다 |
| 25 | `/dsm/cameras/address` | 카메라 주소 채우기 — 한 대씩 |

**이 빨강은 화면의 결함이 아니다.** 17번이 실제로 읽은 본문이 그것을 말한다:

```
프리셋 / 미처리 / 지난 12시간 / 내 담당 / 시스템 …
W1 프리셋 · 미처리 — 대응 축이 아직 「발생」인 것
```

「W1 프리셋」은 **UX-20 에서 화면 밖으로 뺀 절 ID**다(GX-COPY §4). 그것이 아직 떠
있다는 것은 이 번들이 그 커밋보다 **앞선다**는 뜻이다.
→ P-59 게이트가 같은 결론을 독립적으로 낸다: `docs/agent/evidence/P-59/규약_QA.md` §6.

⚠ step 28(모바일 현장 회신)만은 **사유가 확정되지 않았다** — 「현장 회신」이라는
글자 자체는 번들에 있다. 낡은 머리글일 수도, 그 이벤트에 회신 칸이 안 뜬 것일 수도
있다. **모르는 것을 안다고 적지 않는다.**

## 5. 눌러서 나온 것 — 이번 턴의 새것

1. **`capture_screens` 가 첫 불일치에서 죽어 뒤 12장을 삼키고 있었다.**
   17번에서 `raise` 하는 바람에 18~28번은 「해 봤더니 안 된다」가 아니라
   **「해 보지도 못했다」**였다 — 이 파일 자신이 D-396 에 적어 둔 구별을 스스로
   어기고 있었다. 못 찍은 것을 모아 두고 **계속 가도록** 고쳤다(색은 그대로 빨강).
   결과: 찍은 장 수가 **16 → 18**, 그리고 **못 찍은 10장이 이름으로 남았다**.
2. **죽으면 인덱스가 없는 파일을 가리킨다.** `capture()` 는 시작하자마자 PNG 폴더를
   지우고(`rmtree`) 끝에서 `INDEX.yaml` 을 다시 쓴다. 중간에 죽으면 **PNG 는 지워진 채
   인덱스만 옛 28줄을 들고 남는다** — `verify_screens` 가 그때 내는 빨강은 화면이
   아니라 촬영이 죽었다는 뜻이다. 이번 수정으로 인덱스가 **18장으로** 다시 쓰였다.
3. **프리셋 이름이 아직 「프리셋」이다** (세종 P-51 「보기」). 다만 이것은 9-04 번들의
   사실이므로 **미이행으로 등재하지 않는다** — 재빌드 뒤에 다시 본다.
4. **422 `gen-schema` 가 세 시나리오 전부에서 다시 났다** (`GET /api/user-groups/gen-schema?raw=false`).
   상용 점검 §3.1-5 와 같은 자리다 — **아직 있다**.
5. **콘솔 잡음 30건**(§0.4 partner/orders 웹소켓 404 재접속 루프) · **분류되지 않은 오류 3건**
   (위 422 가 남기는 줄). walk 의 빨강은 이 3건이다.
6. **세션을 닫았다** — `walk_scenarios` 가 자기 것을 닫았고(logout 200),
   `capture_screens` 는 **로그아웃을 부르지 않아** 차선이 손으로 닫았다
   (`POST /api/v1/auth/logout` → **200 `Logout successful!`**).
   → 조율자 배선: `capture_screens` 에도 닫는 자리가 필요하다(다음 턴 · Q 소유).

7. **죽는 도구는 자기 뒤에 있는 결함을 함께 숨긴다.** 27번(`/m/inbox`)이 처음으로
   찍히자마자 `verify_screens` 가 빨강을 냈다 — 파일 이름 `m1_mobile_inbox.png` 의
   뿌리가 라우트 뿌리(`m_inbox`)와 달랐기 때문이다(규약 ⑤ `<scenario>/<role>/<route
   뿌리>[_꼬리표].png`). 이 어긋남은 **두 턴 동안 아무도 못 봤다** — 촬영이 17번에서
   죽어 27·28번까지 **가 본 적이 없었기 때문**이다. 슬러그를 `m_inbox_m1` ·
   `m_events_id_m3_field_reply` 로 고쳤다(뒤엣것은 씨앗 id 를 눕힌 형태 · step 21 과 같다).

8. ★ **세션을 빼앗기면 화면 결함이 아니다 — 그런데 이 도구는 그렇게 적고 있었다.**
   슬러그를 고치고 다시 찍는 벌에서 12번째 화면부터 **본문이 전부
   `AI-based Drone-Robot Integrated …`**(로그인 화면)로 바뀌었다. 다른 차선이 같은
   계정으로 들어와(`end_previous_session`) 이 브라우저가 튕긴 것이다 — 이 환경은
   **동시 접속 1개**다. 그 벌은 **16장을 「문구가 없다」로 적었다.** 없던 것은 문구가
   아니라 **세션**이었다.
   `walk_scenarios` 는 이미 이 갈래를 갖고 있다(`session_lost` · 「화면의 결함이
   아니므로 빨강으로 적지 않는다」). `capture_screens` 에만 없어서 **같은 사고가
   여기서만 화면 결함으로 읽혔다.** 갈래를 더했다:
   튕기면 **그 자리에서 멈추고 exit 2(판정 불가)** 를 내며, 「이 실행이 앞선 온전한
   벌을 덮었으니 다시 찍으라」고 적는다.
   ⚠ 남은 함정 하나 — `capture()` 는 **시작하면서 PNG 폴더를 비운다.** 그래서 튕긴
   실행은 앞선 온전한 벌을 지운다. 지금은 「다시 찍어라」로 말할 뿐 막지는 못한다.
   막으려면 임시 자리에 찍고 끝에서 갈아 끼워야 한다 — **다음 턴 · Q 소유.**

## 7-2. 세는 법 — **판정기가 없다. 그래서 세는 법을 적는다**

이 표를 판정하는 게이트는 저장소에 **없다**(찾아봤다: `verify_screens` 는 캡처의
진위를, `walk_scenarios` 는 걸음을 판정한다 — **56칸을 세는 것은 아무도 안 한다**).
그래서 **파일에서 센다**. 옮겨 적지 않는다:

```bash
python - <<'PY'   # ● + ◐ 만 센다. 「—」(해당 없음)는 따로 센다
import io
p='docs/agent/evidence/CHECKLIST/상용점검_4절_56칸.md'
lines=io.open(p,encoding='utf-8').read().splitlines()
i=[k for k,l in enumerate(lines) if l.startswith('| 화면 | 주요 버튼')][-1]   # ★ 마지막 표
rows=[[c.strip() for c in l.strip().strip('|').split('|')] for l in lines[i+2:i+10]]
def mark(c):
    for ch in c:
        if ch in '●◐': return ch
    return '—' if c.startswith('—') else ' '
tot={'●':0,'◐':0,'—':0,' ':0}
for r in rows:
    for m in [mark(c) for c in r]: tot[m]+=1
print(tot, 'N/56 =', tot['●']+tot['◐'])
PY
```

⚠ `[-1]` 이 중요하다 — 이 파일에는 표가 둘이고(§3 은 9-04 번들의 기록), **늦은 것이 정본**이다.

## 7-4. 왜 33칸이 비었나 — **직전 턴과 같은 답, 다만 이제 사유가 하나뿐이다**

직전 턴의 사유는 둘이었다: ㉠ 도구가 없다(22) · ㉡ 번들이 낡았다(12).
**㉡ 은 이번 턴에 사라졌다.** 남은 33칸은 전부 ㉠ 이다:

- **폼(검증·오류) 8칸 · 오류 흐름 8칸 · 빈 상태 8칸** — 이 저장소에 **누르는 도구가 없다.**
  `capture_screens` 는 주소로 열고 글자를 단언한다. `walk_scenarios` 는 정해진 걸음을 걷는다.
  **틀린 값을 넣는 도구도, 500 을 만들어 보는 도구도, 목록을 비워 보는 도구도 없다.**
- 세종 판정이 필요하다(직전 턴 §6-4 와 같은 요청): **「빈 상태와 오류 흐름을 무엇으로 재는가」.**
  지금은 사람 눈뿐이고, 사람 눈은 다음 턴에 같은 수를 내지 않는다.
- ★ 이번 턴에 **오류 흐름을 잴 재료가 하나 생겼다**: 걷기가 `/api/dsm/events/{id}/snapshot`
  **503** 을 실제로 만났다(게이트 runserver 의 MinIO 미연결). 화면이 그 503 을 어떻게
  그리는지는 **아직 안 봤다** — 「오류 흐름」 열의 첫 칸이 될 자리다.
