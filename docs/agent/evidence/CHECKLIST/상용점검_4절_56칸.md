## 4. 왜 34칸이 비었나 — **둘로 갈라 적는다** (D-396)

### ㉠ 안 눌렀다 (22칸) — 도구가 그것을 누르지 않는다

`walk_scenarios` 는 **길이 이어지는가**를 재고, `capture_screens` 는 **화면이 뜨는가**를
잰다. 둘 다 **폼 검증·오류 흐름·빈 상태**를 누르지 않는다 — 그 셋은 이 저장소에 아직
도구가 없다. 없는 도구의 결과를 표에 적을 수는 없다.

⚠ **여기서 새 도구를 짓지 않았다.** 지금 짓는 도구는 **9-04 번들**을 누르게 되고,
그 결과는 재빌드 즉시 버려진다. 순서가 거꾸로다.

### ㉡ 해 봤는데 못 했다 (12칸) — **번들이 낡았다**

`capture_screens` 가 28장 중 **18장을 찍고 10장을 못 찍었다**:

| step | 라우트 | 기다린 글자 |
|---|---|---|
| 17 | `/dsm/events?preset=unhandled` | 미처리 — 아직 아무도 손대지 않은 것 |
| 18 | `/dsm/events?preset=recent` | 지난 12시간 — 이 시간 창 안에 난 것 |
| 20 | `/dsm/events?preset=system` | 시스템 — 설비 자신이 낸 신호 |

| 22 | `/dsm/queue` | 지금 처리할 것 — 가장 급한 하나 |
| 23 | `/dsm/drill` | 훈련 모드 — 켜면 알림이 사람에게 가지 않습니다 |

```
프리셋 / 미처리 / 지난 12시간 / 내 담당 / 시스템 …
```

「W1 프리셋」은 **UX-20 에서 화면 밖으로 뺀 절 ID**다(GX-COPY §4). 그것이 아직 떠
있다는 것은 이 번들이 그 커밋보다 **앞선다**는 뜻이다.
→ P-59 게이트가 같은 결론을 독립적으로 낸다: `docs/agent/evidence/P-59/규약_QA.md` §6.

⚠ step 28(모바일 현장 회신)만은 **사유가 확정되지 않았다** — 「현장 회신」이라는
글자 자체는 번들에 있다. 낡은 머리글일 수도, 그 이벤트에 회신 칸이 안 뜬 것일 수도
있다. **모르는 것을 안다고 적지 않는다.**

## 5. 눌러서 나온 것 — 이번 턴의 새것

1. **`capture_screens` 가 첫 불일치에서 죽어 뒤 12장을 삼키고 있었다.**
   17번에서 `raise` 하는 바람에 18~28번은 「해 봤더니 안 된다」가 아니라
   **「해 보지도 못했다」**였다 — 이 파일 자신이 D-396 에 적어 둔 구별을 스스로
   어기고 있었다. 못 찍은 것을 모아 두고 **계속 가도록** 고쳤다(색은 그대로 빨강).
   결과: 찍은 장 수가 **16 → 18**, 그리고 **못 찍은 10장이 이름으로 남았다**.
2. **죽으면 인덱스가 없는 파일을 가리킨다.** `capture()` 는 시작하자마자 PNG 폴더를
   지우고(`rmtree`) 끝에서 `INDEX.yaml` 을 다시 쓴다. 중간에 죽으면 **PNG 는 지워진 채
   인덱스만 옛 28줄을 들고 남는다** — `verify_screens` 가 그때 내는 빨강은 화면이
   아니라 촬영이 죽었다는 뜻이다. 이번 수정으로 인덱스가 **18장으로** 다시 쓰였다.
3. **프리셋 이름이 아직 「프리셋」이다** (세종 P-51 「보기」). 다만 이것은 9-04 번들의
   사실이므로 **미이행으로 등재하지 않는다** — 재빌드 뒤에 다시 본다.
4. **422 `gen-schema` 가 세 시나리오 전부에서 다시 났다** (`GET /api/user-groups/gen-schema?raw=false`).
   상용 점검 §3.1-5 와 같은 자리다 — **아직 있다**.
5. **콘솔 잡음 30건**(§0.4 partner/orders 웹소켓 404 재접속 루프) · **분류되지 않은 오류 3건**
   (위 422 가 남기는 줄). walk 의 빨강은 이 3건이다.
6. **세션을 닫았다** — `walk_scenarios` 가 자기 것을 닫았고(logout 200),
   `capture_screens` 는 **로그아웃을 부르지 않아** 차선이 손으로 닫았다
   (`POST /api/v1/auth/logout` → **200 `Logout successful!`**).
   → 조율자 배선: `capture_screens` 에도 닫는 자리가 필요하다(다음 턴 · Q 소유).

7. **죽는 도구는 자기 뒤에 있는 결함을 함께 숨긴다.** 27번(`/m/inbox`)이 처음으로
   찍히자마자 `verify_screens` 가 빨강을 냈다 — 파일 이름 `m1_mobile_inbox.png` 의
   뿌리가 라우트 뿌리(`m_inbox`)와 달랐기 때문이다(규약 ⑤ `<scenario>/<role>/<route
   뿌리>[_꼬리표].png`). 이 어긋남은 **두 턴 동안 아무도 못 봤다** — 촬영이 17번에서
   죽어 27·28번까지 **가 본 적이 없었기 때문**이다. 슬러그를 `m_inbox_m1` ·
   `m_events_id_m3_field_reply` 로 고쳤다(뒤엣것은 씨앗 id 를 눕힌 형태 · step 21 과 같다).

8. ★ **세션을 빼앗기면 화면 결함이 아니다 — 그런데 이 도구는 그렇게 적고 있었다.**
   슬러그를 고치고 다시 찍는 벌에서 12번째 화면부터 **본문이 전부
   `AI-based Drone-Robot Integrated …`**(로그인 화면)로 바뀌었다. 다른 차선이 같은
   계정으로 들어와(`end_previous_session`) 이 브라우저가 튕긴 것이다 — 이 환경은
   **동시 접속 1개**다. 그 벌은 **16장을 「문구가 없다」로 적었다.** 없던 것은 문구가
   아니라 **세션**이었다.
   `walk_scenarios` 는 이미 이 갈래를 갖고 있다(`session_lost` · 「화면의 결함이
   아니므로 빨강으로 적지 않는다」). `capture_screens` 에만 없어서 **같은 사고가
   여기서만 화면 결함으로 읽혔다.** 갈래를 더했다:
   튕기면 **그 자리에서 멈추고 exit 2(판정 불가)** 를 내며, 「이 실행이 앞선 온전한
   벌을 덮었으니 다시 찍으라」고 적는다.
   ⚠ 남은 함정 하나 — `capture()` 는 **시작하면서 PNG 폴더를 비운다.** 그래서 튕긴
   실행은 앞선 온전한 벌을 지운다. 지금은 「다시 찍어라」로 말할 뿐 막지는 못한다.
   막으려면 임시 자리에 찍고 끝에서 갈아 끼워야 한다 — **다음 턴 · Q 소유.**

## 7-2. 세는 법 — **판정기가 없다. 그래서 세는 법을 적는다**

이 표를 판정하는 게이트는 저장소에 **없다**(찾아봤다: `verify_screens` 는 캡처의
진위를, `walk_scenarios` 는 걸음을 판정한다 — **56칸을 세는 것은 아무도 안 한다**).
그래서 **파일에서 센다**. 옮겨 적지 않는다:

```bash
python - <<'PY'   # ● + ◐ 만 센다. 「—」(해당 없음)는 따로 센다
import io
p='docs/agent/evidence/CHECKLIST/상용점검_4절_56칸.md'
lines=io.open(p,encoding='utf-8').read().splitlines()
i=[k for k,l in enumerate(lines) if l.startswith('| 화면 | 주요 버튼')][-1]   # ★ 마지막 표
rows=[[c.strip() for c in l.strip().strip('|').split('|')] for l in lines[i+2:i+10]]
def mark(c):
    for ch in c:
        if ch in '●◐': return ch
    return '—' if c.startswith('—') else ' '
tot={'●':0,'◐':0,'—':0,' ':0}
for r in rows:
    for m in [mark(c) for c in r]: tot[m]+=1
print(tot, 'N/56 =', tot['●']+tot['◐'])
PY
```

⚠ `[-1]` 이 중요하다 — 이 파일에는 표가 둘이고(§3 은 9-04 번들의 기록), **늦은 것이 정본**이다.

## 8-4. 빨강 — **무엇이 어떻게 틀렸나**

### (1) ** `StateBoundary` 가 **오류 원문을 사용자 자리에 그대로 그린다** (6화면 · 확정)

```
불러오지 못했습니다.
Request failed with status code 500      <- axios 의 말이다
다시 시도
```

`components/StateBoundary.tsx:47,58` 의 **`description={reason}`** 이다. `reason` 은
`api.ts` 의 `body?.message ?? err?.message` 이고, 오류 본문에 `message` 가 없으면
**axios 원문**이 그 자리에 온다. 서버가 죽은 경우(`netfail`)에는 문자 그대로
**`Network Error`** 가 뜬다 — **GX-COPY 출생 표본 그 자체**이고, 사전
`docs/design/GX-COPY_v1.md` §4 가 이름으로 금지한 줄이다.

대상: 지금 처리할 것 · 이벤트 목록 · 이벤트 상세 · 관리·설정 · 카메라 일괄 등록 · 모바일.
500·503·403 은 원문, **타임아웃만 한국어**(「응답이 10초 안에 오지 않았습니다.」),
서버다운은 **`Network Error`**.

* **타임아웃만 한국어인 이유는 그 문장을 우리가 만들었기 때문**이고, 나머지는 만들지 않아서
  axios 의 말이 나온다. 고칠 자리는 **화면 여섯이 아니라 `StateBoundary` 한 곳**이다.

주의: 왜 게이트가 못 잡았나 — `verify_ui_copy` 는 **소스의 문자열**을 본다. 이 원문은
소스에 없다: **런타임에 axios 가 넣는다.** 소스 게이트로는 영영 안 잡힌다.

### (2) ** 로그인 화면이 **실패를 한 마디도 말하지 않는다** (5/5 갈래)

500·503·403·타임아웃·서버다운을 넣어도 본문이 **203자 그대로**다. 비밀번호를 틀렸을
때(401)도 문구가 **없다**. 관제요원은 「눌렀는데 아무 일도 안 난다」만 본다.
(토스트가 잠깐 떴다 사라지는 경우를 놓치지 않으려고 **1.5초·6초 두 번** 읽었다 — 둘 다 없다.)
· 빈 값은 말한다 — 다만 **영문**이다: `This field is required.`
· **이중 제출**: 빠르게 두 번 누르면 요청이 **2번** 나간다(단추가 안 잠긴다).

### (3) ** **`data_source = live` 가 훈련 모드 화면에 떠 있다** — 그리고 게이트가 **볼 수 없다**

`pages/DrillMode.tsx:118` 의 `<Tag>data_source = {current.data_source}</Tag>` —
화면 본문에서 실측했다. GX-COPY §4 가 **이름으로** 금지한 줄이고(「`data_source = live` 칩」),
D-433 은 이 절(UX-20)을 **「잔여 18 -> 0 · 닫힘」**으로 적었다.

**게이트는 지금도 「잔여 0건 · 통과」를 낸다.** 이유는 판정기의 추출 규칙이다:

```python
JSX_TEXT = re.compile(r">([^<>{}]*[가-힣][^<>{}]*)<")   # verify_ui_copy.py
```

`{`·`}` 를 배제하므로 **보간과 붙은 JSX 본문은 통째로 안 보인다.** 실측:
`user_texts('<Tag>data_source = {x}</Tag>')` -> **`[]`**. 한글을 섞어도 `[]` 다.
대상 43개 파일에서 **판정기가 보는 JSX 조각 80개 · 보간에 붙어 안 보이는 조각 55개** —
**사용자 본문의 41%가 사각지대**다. 같은 사각지대에 두 번째 실물이 있다:
`pages/FocusQueue.tsx:322` 의 **「... F-14 통계는 왼쪽 수를 봅니다.」**(절 ID).

> **「잔여 0」은 「화면에 대장 언어가 없다」가 아니라 「판정기가 읽을 수 있는 자리에 없다」였다.**
> UX-20 을 닫은 근거가 그 수였다.

### (4) 빈 상태 — 셋은 통과, 셋은 **이 도구로 못 쟀다**

| 화면 | 빈 문구 | 판정 |
|---|---|---|
| 지금 처리할 것 | 「지금 열려 있는 이벤트가 없습니다 — 평온합니다.」 | 통과 · 오류 문구와 다르다 |
| 이벤트 목록 | 「조건에 맞는 이벤트가 없습니다. (요청은 성공했고 0건입니다)」 | 통과 |
| 모바일 M1~M3 | 「이 테넌트에 남은 발송 기록이 0건입니다. ...」 | 통과 |
| 관리·설정 · 카메라 일괄 등록 · 보고서 | — | **못 쟀다(도구가 다른 것을 잰다)** |

주의: 아래 셋의 「빨강」은 **화면의 결함으로 읽지 말 것.** 원표가 그 칸에 적은 빈 상태는
「규칙 0건」·「CSV 비었음」·「이벤트 0건 월」이고, 그것들은 **API 응답을 비워서 만들어지지
않는다**(폼 입력·월 선택의 자리다). 도구가 그 칸을 아직 못 누른다 — **빈칸이 옳다.**

## 8-5. 이 도구가 **스스로 만든 거짓**을 어떻게 잡았나 (다음 사람에게)

이 절을 쓰는 동안 **내가 만든 빨강 셋을 취소**했다. 셋 다 「지어낸 입력이 지어낸 결함을
만든다」의 사례이고, 그래서 도구에 **잡는 장치**를 남겼다:

1. **빈 응답의 모양을 손으로 적었다.** `{"items":[],"top":null,"total":0}` 라고 적었는데
   `/api/dsm/events/queue` 의 계약은 `{now, focus, queue, tier_thresholds_sec, ...}` 였다.
   화면이 없는 칸을 읽고 **터졌고**(`Cannot read properties of undefined`), 도구는 그것을
   「빈 상태 빨강」으로 적었다. -> **모양을 화면이 방금 받은 진짜 응답에서 만든다**(`empty_like`).
2. **글로브에 꼬리 `**` 가 없어 주입이 안 먹었다.** `**/api/dsm/events` 는
   `/api/dsm/events?limit=50` 을 **안 잡는다.** 화면은 22건을 그대로 그렸는데 도구는
   「빈 문구가 없다」고 빨강을 적었다. -> **주입 뒤 본문이 기준선과 한 글자도 안 다르면
   판정 불가**로 떨어뜨린다(보고서 화면의 다섯 갈래가 실제로 여기 걸렸다).
3. **세는 것을 누르는 것으로 셌다.** 「보이는 단추 12개」에 `◐` 를 줬다 — 한 번도 안 눌렀는데.
   -> 「주요 버튼」은 **빈칸**으로 두고 목록은 사유로만 남긴다. 자기시험이 이 규칙을 지킨다.

## 8-6. 함정 — 다음 사람이 밟을 자리

- **호스트에서 `docker exec` 가 시간초과로 죽어도 컨테이너 안 프로세스는 계속 산다.**
  10분에 끊긴 실행이 **6분 뒤 자기 증거 파일을 덮어썼고**, 그 사이 내내 **세션을 물고 있어**
  뒤따르는 로그인이 「다른 기기 접속」 창을 만났다. 끊긴 뒤에는 `ps -eo etime,args` 로
  **살아 있는지 확인**하고, 증거 파일의 mtime 을 의심할 것.
- **`_release_session` 을 `sync_playwright` 블록 안에서 부르면 조용히 실패한다** —
  Django 가 `SynchronousOnlyOperation` 을 낸다. 도구는 「세션이 열린 채다」 한 줄만 적고 끝나며
  **세션은 진짜로 물린다.** 반드시 블록 **밖**에서 부른다.
- **브라우저의 `localStorage` 에 토큰이 없다.** 이 앱은 쿠키(`token`)로 들고 있어
  `walk_scenarios._logout` 방식(`userInfo.access_token`)은 **401 로 조용히 실패**한다.
  세션은 `capture_screens._release_session`(ORM)로 푼다.
- **동기 라우트 처리기에서 `time.sleep` 은 디스패처를 막는다.** 타임아웃 주입을 걸리는
  요청마다 재우면 화면의 자동 갱신과 겹쳐 **끝나지 않는다**(한 화면에 10분을 태웠다).
  **첫 요청만** 끌고 나머지는 즉시 504 로 끊는다.
- 비밀번호를 `--password` 로 넘기면 **`ps` 에 그대로 보인다.** `--password-env` 를 쓴다.

## 10-5. 빨강 — 무엇이 아직 틀렸나

### (1) ★ **오류 원문은 0이다** — §8-4 (1) 이 닫혔다 [실측]

```
주입 40건(여덟 화면 x 500·503·403·timeout·netfail) — 원문 0 · 스피너 고착 0
못 쟀다 5 (보고서 한 화면 · 주입이 그 화면에 안 닿았다)
```

턴 G 가 여섯 화면에서 보던 `Request failed with status code 500` · `Network Error` 는
**한 건도 안 나왔다.** 로그인 화면도 다섯 갈래 전부에 **말을 한다**(◐→●).

### (2) 빈 상태를 **침묵으로** 그리는 화면 셋 — 관리·설정 · 카메라 일괄 등록 · 보고서

```
빈 200 응답을 주입 → 「없습니다」·「없음」·「0건」 중 어느 것도 화면에 없다
```

★ 다만 §8-4 (4) 의 단서가 그대로 살아 있다: 정본이 그 칸에 적은 빈 상태는
「규칙 0건」·「CSV 비었음」·「이벤트 0건 월」이고, 그것들은 **API 응답을 비워서
만들어지지 않는다**. 이 빨강은 「목록 API 가 0건일 때 침묵한다」는 뜻이다.

### (3) **이 앱에는 `<a>` 링크가 0개다** [실측 · 새 사실]

여덟 화면 전부에서 `role=link` · `role=menuitem` · `role=tab` 이 **0개**였다.
이동은 전부 단추가 한다. 그래서 이 판정기는 **「눌렀더니 주소가 바뀐 단추」**를
그 칸의 답으로 센다 — 사용자에게 링크는 그것이다. 그렇게 세도 세 화면
(관리·설정 · 모바일 · 보고서)은 **주소를 바꾸는 단추가 0개**여서 빈칸이다.
