# U5#2 `/roles` 「화면은 뜨는데 표 0행」 — **로그인 없이 지운 갈래 다섯** (P-317 · U56 에 넘김)

[조율자(영실) · 2026-09-24 · 턴 AH · 세종 P-317 「0 이면 시드·권한·프록시 중 어디인지 한 갈래씩」]

## 증상 (온보딩 4차 · 8500 · 성한 서버)

```
U5#2  green -> red | /roles
  url=http://gx-nginx-e:8500/roles · 역할 관리=True · 머리줄=True · 표 행 0 · Add New Role=False
```

09-23(3002)에는 초록이었다. 8500 경로를 이은 뒤(P-291) **화면과 머리줄은 선다** — 표만 빈다.

## 지운 갈래 — 전부 **로그인 없이** (대표가 제품을 쓰고 있을 수 있어 계정 세션을 안 건드렸다)

| # | 갈래 | 어떻게 쟀나 | 결과 |
|---|---|---|---|
| 1 | 프록시 | nginx 기록 | ✗ — `/api/roles/` **200** · 본문이 온다 |
| 2 | 두 서버 설정 차이 | gunicorn · gx-shell 환경 대조 | ✗ — `TENANT_SCOPE_ENFORCE='false'` 둘 다 · 깃발 여섯 같음 |
| 3 | 예외를 삼키고 200 | gunicorn 로그 `Error listing roles` | ✗ — 없다 |
| 4 | 데이터가 없다 | ORM `Role._base_manager` | ✗ — **16개** · 전부 `deleted IS NULL` · `Role.objects` 도 16 |
| 5 | 권한 | ORM — u5 역할 × `/roles` 메뉴 `RoleMenu` | ✗ — `admin` · `permit_read: True` |

⚠ 2번은 **가설이 틀려서** 지웠다 — `-old` 컨테이너 환경 이름에 `TENANT_SCOPE_ENFORCE` 가 있던
것이 떠올라 세웠는데, 재 보니 두 서버가 같았다.

## 남은 갈래 — 여기서부터 U56

`/api/roles/` 는 **330~373바이트**였다. 역할 16개(이름·설명·`related_users`)는 그 크기에
안 들어간다 — 거의 빈 답이다. 그런데 dj-core `list_roles` 는
`Role.objects.filter(deleted__isnull=True)` 로 **좁히지 않고** 부른다.

★ 더 유력한 것: `/roles` 는 **인수 자산(rj-core) 화면**이고, 같은 시각 기록에
**`/api/advanced-table/select-data → 200 · 270바이트`** 가 있다. 그 화면의 표는
`/api/roles/` 가 아니라 **이 범용 표 문**으로 채워질 가능성이 크다 — 270바이트면 빈 표다.

다음 한 갈래씩:
1. 8500 에서 `/roles` 를 열 때 **표를 채우는 요청이 어느 문인가** (브라우저 네트워크 1회 · 로그인 필요 → 조용한 창)
2. 그 문의 응답 본문을 `/api/roles/` 와 나란히 (둘 다 0 인가, 하나만 0 인가)
3. 3002 빌드(`dist_u1ab`)와 8500 빌드(`gx-spa`)가 **같은 문을 같은 인자로** 부르는가 —
   두 번들은 다른 빌드다(VITE_API_URL 이 다르다 · P-286)

⚠ rj-core · dj-core 는 §0.4 — 읽기·호출만. 뿌리가 그 안이면 P-274 처럼 **길목에서**.
