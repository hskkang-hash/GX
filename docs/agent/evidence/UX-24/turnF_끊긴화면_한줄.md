# P-62 꼬리 — **끊긴 화면이 왜 끊겼는지 말한다** (한 줄이지 절이 아니다)

- 집행: 차선 S · **2026-09-05 턴 F**
- 파일: `frontend/src/features/session/sessionEnded.ts`(새) ·
  `frontend/src/features/session/SessionEndedNotice.tsx`(새) ·
  `frontend/src/services/API.ts` · `frontend/src/App.tsx`

---

## 1. 먼저 찾아본 것 — **없었다** (턴 E 는 서버 쪽만 세웠다)

```
grep -rn "다른 기기에서 로그인|session_evicted|origin_detail|session_notice" frontend/src
  → 0건
```

턴 E 의 §5 가 그것을 미리 적어 두었다: 「**앞단이 401 본문의 `detail` 을 그려야** 사람이
읽는다. 서버는 이미 말하고 있다. `frontend/` 는 차선 S 의 것이 아니다」. 이번 턴 지시서가
그 자리를 열었다.

그리고 종전 앞단이 401 에 하는 일은 **한 줄**이었다:

```ts
redirectOn401: () => { window.location.href = '/login'; }   // services/API.ts
```

말없이 튕긴다. 사람이 보는 것은 「하던 일이 사라지고 로그인 화면이 떠 있다」뿐이고,
그 모양은 **「토큰이 깨졌다」·「서버가 죽었다」와 글자 하나까지 같다.**

## 2. 서버는 정말 말하고 있는가 — **잰다** [실측 2026-09-05]

로그인을 두 번 해서(둘째가 첫 화면을 밀어낸다) 첫 토큰으로 문을 때렸다:

```
[EVICT] status 401
[EVICT] body   {"detail": "다른 기기에서 로그인되었습니다",
                "origin_detail": "Unauthorized",
                "reason_code": "session_evicted"}
```

말하고 있다. **닿지 않았을 뿐이다.**

## 3. 붙인 것 — 한 줄과 단추 하나

```
 ┌─────────────────────────────────────────┐
 │  다른 기기에서 로그인되었습니다          │  ← 서버가 보낸 `detail` 그대로
 │  이 화면은 닫혔습니다.                    │
 │                      [ 다시 로그인 ]     │  ← 1클릭 → /login
 └─────────────────────────────────────────┘
```

- **낱말을 만들지 않았다** (GX-COPY 규칙 1). 화면에 뜨는 문장은 서버의 `detail` 이고,
  서버가 말이 없을 때만 사전(`GX-COPY_v1.md` §5 「2026-09-05 턴 E 추가」)의 그 줄로 떨어진다.
- **좁게 잡는다.** `reason_code === "session_evicted"` 인 401 에서만 뜬다. 넓게 잡으면
  비밀번호를 틀린 사람이 있지도 않은 다른 기기를 찾는다 — 서버가 같은 이유로 표식을 붙였다.
- **한 번만.** 월 모드는 20초마다 문을 셋 부른다. 401 이 셋 오면 안내도 셋이 된다.
- 그 밖의 401 은 **종전 그대로 튕긴다.**

## 4. ★ 순서가 곧 판정이다 — rj-core 를 읽고 자리를 골랐다 [실측]

처음엔 `API.interceptors.response.use(...)` 로 뒤에 붙였다. **그러면 아무것도 못 본다.**
`node_modules/rj-core/dist/rj-core.es.js` 를 읽어 보니 rj-core 의 응답 인터셉터가 먼저
서 있고, 401 을 보면 이렇게 한다:

```
401 → 토큰 재발급 시도 → **실패** → Promise.reject(재발급 오류) → redirectOn401()
```

즉 뒤에 붙은 인터셉터가 받는 것은 **재발급 오류**이지 원래의 401 이 아니다 —
본문(`reason_code`)이 거기 없다. 그래서 axios 의 처리기 배열 **맨 앞**에 넣었다
(axios **1.13.5** · `interceptors.response.handlers`). **보기만 하고 오류를 그대로 다시
던진다** — rj-core 의 재발급 갈래는 한 자도 안 바뀐다.

⚠ 배열 모양은 axios 의 내부다. 그래서 **확인하고** 넣고(`Array.isArray`), 안 되면 `use()`
로 떨어지며, 그마저 안 되면 아무 일도 하지 않는다 — 그때 동작은 **종전과 똑같다**.
없는 배선을 있는 척하지 않는다.

## 6. 남은 위험

- 이 한 줄은 **밀려남을 막지 않는다.** 동시 세션 자체는 dj-core 의 `user.token` 한 칸이고
  §0.4 다(UX-24b · 손 밖). 월 대형 화면만은 세션 없이 여는 길을 이번 턴에 냈다
  (UX-24a · `X-GX-Wall-Token`).
- axios 처리기 배열에 **맨 앞으로 끼워 넣는 것**은 라이브러리 내부에 기댄다. 버전이 오르며
  모양이 바뀌면 조용히 `use()` 로 떨어지고, 그때 이 안내는 **안 뜬다**(제품은 종전대로
  돈다). 조용히 사라지는 것을 아는 눈은 아직 없다 — **게이트가 없다.**
