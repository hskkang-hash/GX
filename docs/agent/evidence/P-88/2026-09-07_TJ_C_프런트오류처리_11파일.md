# SEC-11a ② — **`try` 가 하나도 없던 11파일**에 `try/catch/finally` 를 넣었다 (+ 훅 1파일)

- 잰·고친 때: **2026-09-07** · 턴 J · 차선 C
- 출처 목록: `docs/agent/evidence/SEC-11a/턴G_잔여193_그대로_다음58의_문턱을_수로_적었다.md` §3
  (차선 S 가 2026-09-06 에 이름으로 센 그 11파일 — **한 파일도 늘리거나 줄이지 않았다**)

---

## 0. 왜 이것이 승격의 문턱인가 (차선 S 가 적어 둔 그대로)

승격하면 거절이 **axios 예외**가 된다. `try` 가 없는 자리에서는 그 예외가 잡히지 않고,
전역 `unhandledrejection`·`window.onerror` 처리기는 이 저장소에 **0건**이다.
그러면 화면은 두 가지로 망가진다:

1. `setLoading(true)` 를 켜 놓고 **끄지 못한다** → **스피너 고착**(W0-18 §2-1)
2. 아무 말도 안 한다 → 사람은 자기가 안 눌렀다고 생각하고 **또 누른다**(P-78 ③ 이중 제출)

고침이 아니라 장식이고, 다음 사람이 그 빈 `finally` 를 「여기는 이미 봤다」로 읽는다.

## 2. ★ 이 턴이 잰 사실 — **스피너가 새던 자리는 셋이었다**

11파일을 다 읽고 나서야 갈렸다. `Handover` 여덟은 훅(`useHandover`)이 이미
`try/catch/finally { hideLoading() }` 를 갖고 있어 **전역 스피너는 안 샜다.**
(`otherEquipments` 의 훅은 **안 갖고 있었다** — §4-2 가 그 자리다.)
화면 쪽에서 스피너가 실제로 새는 것은 **화면이 제 상태로 스피너를 켜는** 세 자리다:

| 자리 | 무엇이 샜나 |
|---|---|
| `otherEquipments/OtherEquipments.tsx::fetchOtherEquipments` | `setLoading(true)` … 마지막 줄에 `setLoading(false)` **하나**. `await` 가 거절되면 그 줄에 **닿지 못한다** |
| `otherEquipments/DetailEquipment.tsx::onSubmit` | `setLoading(false)` 가 **성공·실패 두 갈래에만** 있고 거절 갈래에는 없다 |
| `Handover` 의 확인 상자 넷 | `setShowDeleteNotice(false)` 류가 성공 갈래에만 있어 거절이면 **상자가 열린 채로 남는다** — 열린 상자는 고장으로 읽히고 사람이 또 누른다 |

나머지 여덟에서 새던 것은 스피너가 아니라 **말**이다:

- `HandoverPage.tsx` 의 내려받기 둘은 `{success, message}` 를 **돌려받고도 읽지 않았다.**
  실패해도 화면이 한 자도 말하지 않았고, 사람은 파일이 오는 줄 알고 기다렸다.
- `EditNotice.tsx::onReplyComment` 의 `await actionCommentAPI(params)` 도 같은 모양이다.
- `ItemCard.tsx::handleSave` 는 `boolean` 을 돌려주고 그 값으로 **화면을 떠날지**가 갈린다.
  거절이 예외가 되면 `false` 조차 못 돌려주고 부르는 쪽의 `await` 가 같이 터진다.
  이번에 **거짓 `true` 를 절대 돌려주지 않게** 했다 — 저장 못 한 것을 저장했다고 답하면
  서식이 깨끗한 것으로 표시되고 **사람이 쓴 글이 사라진다.**

## 3. 문장을 새로 짓지 않았다 — `features/session/apiFailure.ts` (신설 1파일)

11파일이 부르는 것은 이 한 함수다:

```ts
failureLine(where, error) -> string
```

- 서버가 보낸 사유(`message`/`detail`, 문자열이든 다국어 객체든)를 꺼내고,
- 그 판정과 문장은 **이미 있는 `features/dsm/copy.ts` 에 그대로 맡긴다**
  (`userFacingError` · `failureHint` · `FAILURE_TITLE` · `FORBIDDEN_TITLE`).
  그 파일의 줄은 전부 사전 `docs/design/GX-COPY_v1.md` §「불러오지 못한 자리」에서 왔다.
- 403·401 은 제목이 **「이 항목에 대한 권한이 없습니다.」**로 갈린다 — 권한은 오류가 아니다(DA-03 §2-5).
- axios 원문(`Network Error` · `Request failed with status code …`)은 `looksRaw` 가 거른다.
  **원문은 콘솔로만 간다**(`reportFailure`).

즉 이 턴에 **새로 지은 문장은 0개**다. GX-COPY 규칙 1 그대로다.

## 4-2. ★ **12번째 파일 — 차선 S 가 이름으로 적어 둔 그 자리**

`backend/config/settings.py` 의 `API_CONTRACT_PROMOTE_PATHS` 주석에 차선 S 가
**안 켠 사유를 이름으로** 적어 두었다:

> `/api/devices/cameras/` 9건 — `features/otherEquipments/hooks/useEquipment.ts` 의
> 다섯 함수(`getEquipmentList` · `getDetailEquipment` · `createEquipment` ·
> `updateEquipment` · `changeStatusEquipment`)가 `showLoading()` 뒤 `await API.*` 를
> **try 없이** 부른다. 승격하면 거절이 예외가 되고 `hideLoading()` 이 영원히 안 돈다
> = **스피너 고착**. 그 파일은 `frontend/` 라 차선 S 의 손 밖이다.
> **고칠 수 없는 자리를 고치지 않은 채로 켜지도 않는다.**

**그 손이 이 차선이다.** 이 파일은 SEC-11a 의 11파일 목록에는 **없었다**(그 목록은
`await` 가 있는 **화면** 파일을 셌고, 이것은 훅이다). 그러나 승격을 막고 있는 실제
자리이므로 같은 잣대로 고쳤다 — **12번째 파일**이다.

다섯 함수 전부 이 모양이었다:

```ts
showLoading();
const { success, message } = await API.post('api/devices/cameras', data);
if (success) { hideLoading(); } else { hideLoading(); }   // ← 갈래가 둘인 척하지만
                                                          //   **한 갈래도 예외를 안 덮는다**
```

고친 뒤: `try { … } catch { return {success:false, message: failureLine(...)} } finally { hideLoading(); }`

| 파일 | 전 `try` | 후 `try` | `finally` |
|---|---|---|---|
| `otherEquipments/hooks/useEquipment.ts` | 2 (뒤쪽 두 함수만) | **7** | **7** |

⚠ `getDetailEquipment` 의 거절 갈래는 **`data` 를 지어내지 않는다** (`data: null`).
그 함수의 성공 갈래는 `data.resolution.width` 처럼 깊이 파고들어 서식 값을 만든다 —
거절 갈래에서 빈 껍데기를 만들어 돌려주면 그 껍데기가 서식에 그려지고
「값이 없다」가 **「빈 값으로 저장됨」**이 된다.

**차선 S 에게**: 이 한 파일로 `/api/devices/cameras/`(반경 9) 를 막던 사유가 사라졌다.
⚠ 다만 **켜 보고 다시 재는 것은 차선 S 의 일**이다 — 이 문서는 「고쳤다」까지다.

---

## 5. 차선 S 에게 — 이제 무엇이 열렸나

턴 G 가 적은 닫는 조건은 「위 **11파일**에 `try/catch/finally` 를 넣고 그 다음에
접두를 켠다 → 193 → **135** 예상」이었다. 그 조건의 **프런트 몫은 이 문서로 닫힌다.**

⚠ 그래도 **한 접두씩 · 반경 세고 · 전/후** 규칙은 그대로다(턴 K §2 P-88′).
그리고 이 문서는 「고쳤다」까지이지 **「켜 보니 좋더라」가 아니다** — `handover`·`devices`
접두를 실제로 켜서 화면을 다시 누른 것은 이 턴에 하지 않았다. 안 한 것을 한 것으로 적지 않는다.
