## 0. 먼저 — **로그인 자동화가 왜 막혔었나** (조율자가 부딪힌 벽)

조율자는 「SPA 로그인 자동화가 안 됐다 · 폼 선택자 추정 실패로 `/login` 에 머물렀다」고 적었다.
**폼 선택자는 맞았다.** 막은 것은 다른 것이다:

```
input 두 칸(nth 0 = ID · nth 1 = Password)  →  role=button name="Log In"  →  ★ 여기서 대화상자
    <div role="dialog" aria-modal="true" class="... custom-modal modal show">
      <div class="modal-title h4">End Session</div>
      This account is active on another device. Would you like to terminate the previous session and log in?
      <button class="btn btn-outline-primary btn-lg"> Confirm</button>   ← 단추 이름은 「Confirm」
      <button class="btn btn-outline-secondary btn-lg"> Cancel</button>
```

- **동시 접속 1개**라서, 앞선 실행/다른 차선의 세션이 남아 있으면 로그인이 **한 걸음 더** 필요하다.
- 그 걸음의 단추 이름은 머리줄과 **다르다**: 머리줄이 `End Session`, 단추는 **`Confirm`**.
  `get_by_role("button", name="End Session")` 은 30초 기다리다 죽는다 [실측 · 이 턴에 그렇게 죽였다].
- 이것을 안 밟으면 브라우저는 `/login` 에 남고, 그 화면을 보고 「폼 선택자가 틀렸다」고 읽게 된다.
  **틀린 것은 선택자가 아니라 로그인 절차의 걸음 수였다.**

`scripts/capture_screens.py` 는 이 걸음이 필요 없다 — 찍기 전에 `_release_session()` 으로
세션을 먼저 닫기 때문이다. 손으로 짠 탐침은 그 함수를 안 부르므로 대화상자를 만난다.

| `frontend/src/features/session/PermissionDeniedNotice.tsx` | **이 턴 차선 C 가 세운 것** — 그 신호를 받아 화면 맨 위에 띠 한 줄을 그린다 |

★ **덮개가 아니라 띠다.** `SessionEndedNotice` 는 화면 전체를 막는다 — 그 뒤 화면이 이미 죽었기

전체를 막으면 「권한이 하나 없다」가 「제품이 죽었다」로 읽힌다.

★ **문장을 여기서 짓지 않았다**(GX-COPY 규칙 1). 아래 실측이 그것을 보여 준다 —
화면에 뜬 큰 글자는 사전의 「볼 권한이 없습니다」가 아니라 **서버가 보낸 `message.ko`**
「권한이 거부되었습니다.」다. 서버가 말이 없을 때만 사전으로 떨어진다.

## 2. 서버 쪽 승격은 살아 있다 [실측 · API 직접]

`gx-shell` 안에서 두 계정으로 같은 문을 두드렸다:

```
gxprobe_e2e  GET /api/devices/devices-management                      -> 403
gxprobe_e2e  GET /api/devices/devices-management?page_number=1&...    -> 403

                                                   "ko":"권한이 거부되었습니다.", ...}}
```

**승격은 반쪽이 아니라 살아 있다.** 남은 반쪽이 앞단이었고, 이 문서가 그것을 잰다.

## 3. ★ 첫 번째 실측 — **`/device`(목록)에서는 그 403 을 볼 수 없다**

지시서는 「`/device` 화면의 라우트에서 403 을 받는다」고 적었다. **재 보니 아니었다.**
`gxprobe_e2e` 로 `/device` 를 열면 브라우저는 그 문을 **한 번도 부르지 않는다.**

번들 둘(승격 전 번들 `abbdf36` @3002 · 이번 턴 번들 @3012)에서 **같은 결과**:

| | `/device` @3002 (안내 없는 번들) | `/device` @3012 (안내 붙인 번들) |
|---|---|---|
| 브라우저가 부른 `devices-management` | **0건** | **0건** |
| 403 응답 | **0건** | **0건** |
| 안내 한 줄 | 안 뜸 (뜰 신호가 없다) | 안 뜸 (뜰 신호가 없다) |
| 스피너 남음 | **없음** | **없음** |
| 본문 | 163~164자 — 표 머리글만, **빈 표** | 같음 |
| 콘솔 오류 | 11건 (전부 `ws://…/ws/orders/notifications/` · `ws://…/ws/partner-callbacks/` 404 — 이 턴과 무관한 기존 빨강) | 11건 (같음) |

브라우저가 그 화면에서 실제로 부른 우리 API 는 이 여섯뿐이다:

```
GET /api/advanced-table/select-data?model_name=theme&distinct=true                  200
GET /api/config-management/list-optimized                                           200
GET /api/user-groups/gen-schema?group_id=4&raw=true                                 200
GET /api/user-groups/gen-schema?group_id=4&raw=false                                200
GET /api/menu/menus?page_size=10000                                                 200
GET /api/advanced-table/select-data?model_name=devicestatus&...&search_field=name   200
```

**왜 안 부르나 — 이름으로** [`frontend/src/features/device/listDevice/ListDevice.tsx:133`]:

```tsx
const [pageSize, setPageSize] = useState<number>();   // 처음엔 undefined
useEffect(() => {
  if (pageSize) {                                     // ★ 여기서 멈춘다
    fetchData({ objSearch, pageSize, currentPage });
  }
}, [pageSize, currentPage, objSearch]);
```

`setPageSize` 는 표 컴포넌트(rj-core)가 **자기 설정을 받은 뒤** 부른다. 이 계정에서는 그 값이
서지 않아 `fetchData` 가 **한 번도 안 돈다.** 그래서 이 화면의 「빈 표」는 승격 이전에도
**403 때문이 아니었다** — 문을 두드리기 전에 앞단이 스스로 멈춘 것이다.

⚠ 이것은 **이 턴의 안내가 못 그린 것이 아니다.** 그릴 신호 자체가 태어나지 않는다.
   그리고 이 자리는 `/users`·`/handover` 의 「본문 0자」와 같은 가족이다
   (`DA-05/blockers.yaml :: RJCORE_BLANK_ON_NO_PERMISSION`) — **표가 권한을 만나면
   말없이 멈춘다.** 안내 한 줄로는 못 닫는다. 닫으려면 표가 「못 불렀다」를 말해야 하고,
   그 표는 rj-core 안이다(§0.4 · 손 밖).

## 7. ★ 번들 신원 — **「이 화면은 어느 번들에서 이랬나」를 한 줄로 세운다**

조율자가 턴 중간에 잡아 준 함정: **3002 가 내는 번들은 HEAD 가 아니다.**
그 번들에는 `permissionDenied.ts` 도 `API.ts` 의 403 갈래도 **없다** — 그 위에서
「안내가 안 뜬다」를 재면 그것은 컴포넌트의 빨강이 아니라 **번들의 부재**다(P-59 착시).

### 7-1. 손으로 이은 대조 [실측 2026-09-07]

`verify_bundle_hash` 는 **구조적으로 회색**이다: 호스트는 `.git` 을 보지만 3002 를 못 보고,
`gx-shell` 안은 3002 를 보지만 `/repo` 에 `.git` 이 없다. 그래서 양쪽을 손으로 이었다.

```
호스트          git rev-parse HEAD           = 778dad36db15001e49b62a1fa6b8b753e9cd9458   (commit_sha)
gx-shell 안     /app/_fe_dist  (= 3002)      GX_COMMIT:abbdf36899054ace64c97904abe045daeeab5c5b   (commit_sha)
                /app/_fe_dist_cJ  (= 3012)   (토큰 없음 — GX_COMMIT 없이 빌드했다)
                /app/_fe_dist_cJ2 (= 3013)   (토큰 없음 — 짧은 형 7자로 빌드했다 · 토큰은 40자리만 박힌다)
```

→ **3002 ≠ HEAD.** 조율자·차선 Q 의 지적이 옳다.

### 7-2. 그래서 이 문서의 실측은 어디서 났나 — **3002 위에서 재지 않았다**

| 포트 | 자리 | 무엇으로 빌드했나 | 이 문서에서 무슨 칸인가 |
|---|---|---|---|
| 3002 | `/app/_fe_dist` | 커밋 `abbdf36` — **안내 컴포넌트가 없다** | §4 의 **「전」** 칸 = 「승격은 됐는데 앞단이 조용한 상태」 — 그것을 재는 것이 이 칸의 목적이므로 **옛 번들이 맞는 도구다** |
| 3012 | `/app/_fe_dist_cJ` | 이번 턴 작업본 — 안내 컴포넌트 **있다** | §4 의 **「후」** 칸 |
| 3013 | `/app/_fe_dist_cJ2` | 같은 작업본 + `GX_COMMIT=778dad3`(짧은 형) | ③④ 촬영 33장 · ⑤ `walk_states` |

즉 「후」 칸은 **처음부터 3002 에서 재지 않았고**, 안내가 실제로 들어 있는 번들에서 쟀다.
그래서 §4 의 「1개 · 뜬다」는 번들 부재로 인한 착시가 아니다.

### 7-2-1. 커밋이 박힌 번들에서 **다시 쟀다** (3014 · `GX_COMMIT:778dad36…` (commit_sha))

§4 의 「후」 칸을 번들 신원이 못 박힌 자리에서 한 번 더 쟀다 — 수가 갈리지 않는다:

```
/device/detail-device/33 @3014   →  GET …/devices-management/33?edit=false&depth=2  403
  안내 요소 1개 · 본문 213자 · 스피너 0 · 콘솔 오류 12건(전부 기존 WS 404)
  화면 아래 버전 한 줄: 「버전 778dad3 · 장애 신고 창구 미등록」
```

즉 **「이 화면은 이 번들에서 이랬다」가 한 줄로 선다.**
증거: `2026-09-07_TJ_C_after_detail_stamped.{json,png}`

### 7-3. ⚠ 그래도 남는 두 가지 — 숨기지 않는다

1. **3002 를 HEAD 번들로 배치하지 못했다.** 조율자가 지시한
   `scripts/deploy.sh --allow-dirty --no-walk` 는 **auto mode 분류기가 막았다**
   (서브에이전트가 `docker exec` 로 프로세스를 다루는 명령을 부를 때 막히는 그 자리 —
   `pkill`·`kill` 과 같은 가족이다). 우회하지 않았다. **조율자가 대신 배치해야 한다.**
   배치 전까지 3002 를 근거로 잰 다른 차선의 화면 수는 **전부 `abbdf36` 의 수**다.
2. **작업본이 더럽다.** 이 문서의 「후」 번들은 커밋 `778dad3` **+ 미커밋 작업본**으로 빌드했다.
   그래서 `GX_COMMIT` 을 박아도 그 값은 「이 내용이 그 커밋이다」를 뜻하지 않는다 —
   `deploy.sh` 가 `--allow-dirty` 를 따로 요구하는 이유가 바로 이것이고,
   그 사실을 여기 적어 두는 것이 그 깃발의 값이다.

## 8. ★ 덤으로 닫힌 자리 — **`/handover` 의 「빈 화면」은 권한 거절이었다**

번들 신원을 못 박은 뒤(§7) `GX_COMMIT:778dad3…` 이 박힌 3014 에서 두 화면을 더 눌렀다.
둘 다 `DA-05/blockers.yaml :: RJCORE_BLANK_ON_NO_PERMISSION` 에 「본문 0자」로 등재된 자리다.

| 화면 | 본문 | 브라우저가 받은 403 | 안내 요소 | 스피너 |
|---|---|---|---|---|
| `/users` | **25자** (버전 한 줄뿐) | **0건** | 0개 | 없음 |

`/handover` 본문 그대로:

```
권한이 거부되었습니다.
이 자료는 지금 계정의 권한으로 열 수 없습니다.
/api/handover/handover/notice
닫기
버전 778dad3 · 장애 신고 창구 미등록
```

**「본문 0자」가 「권한이 거부되었습니다」로 바뀌었다.** 이 자리는 두 가지가 겹쳐 열렸다:

1. **차선 S 가 이 턴에 `/api/handover/handover/` 접두(반경 25)를 승격했다**
   (`settings.py` 의 주석 그대로) — 그래서 200 봉투가 **진짜 403** 이 됐다.
2. **이 턴의 안내 컴포넌트가 그 403 을 그린다** — 승격만 있고 안내가 없었다면
   `/handover` 는 여전히 **본문 0자**였다.

즉 「승격은 반쪽이면 더 나쁘다」의 **반대 증거**다: 두 반쪽이 같은 턴에 서니
빈 화면 하나가 사람이 읽을 수 있는 문장이 됐다. 그리고 그것을 잰 것은
**같은 계정·같은 서버·다른 접두**다 — 이 안내가 `devices` 한 자리에만 붙은 것이
아니라 **전역**임을 보이는 실측이다.

⚠ `/users` 는 **그대로 빈 화면이다.** 그 화면은 막힌 문을 두드리지도 않는다(403 0건) —
`/device` 목록과 같은 모양이고(§3), 안내로는 못 닫는다.
`DA-05/blockers.yaml` 의 그 항목은 **지우지 않는다**: 표본 둘 중 하나가 설명됐고
하나는 그대로다. 항목을 지우지 않고 **사유를 바꾸는 것**이 이 저장소의 규약이다.
