## OPS-13b — **닫히지 않는다** (턴 O · 정전 세 번 뒤 재측정)

### ① 앞단 설정은 세 번의 재기동을 **살아남았다** — 도는 프로세스에서 읽었다

`gx-nginx-e` 의 마스터는 `nginx -c /etc/nginx/gx/gx-front.conf` 로 돈다(`/proc/1/cmdline`).
**그 경로로** `nginx -T` 를 걸어 읽은 결과 `upstream gx_app` 의 peer 는 **한 줄**이다.

⚠ **`-c` 없이 `nginx -T` 를 걸면 재고 설정이 나오고 `upstream gx_app` 이 0줄로 보인다.**
⚠ **[턴 O 새 함정] Git Bash 에서는 `-c /etc/nginx/...` 가 MSYS 경로 변환에 먹힌다** —
  `/etc/nginx/C:/Program Files/Git/etc/nginx/...` 로 바뀌어 `[emerg]` 가 난다.
  그 실패를 「peer 0줄」로 읽으면 **고친 것을 안 고쳤다고 판정한다.**
  `export MSYS_NO_PATHCONV=1` 이 필요하다.

### ② 정전 뒤 수 — 3,598 요청

|---|---|---|---|
| 종전 | 2줄 | 11 / 7,444 | 0.148% |

`gx_app 0.000s` 결함(세 번째 시도가 upstream **이름**으로 새는 것): **0 / 3,598**.

### ③ 그런데 **재시도는 잘 돈다** — 이번 판이 새로 보탠 사실

`$upstream_addr` 의 주소 개수를 3,603줄 전부에서 세었다:

| 주소 수 | 줄 수 | 뜻 |
|---|---|---|
| 1 | 3,547 | 재시도 없음 |
| **2** | **54** | 한 번 재시도 → **되살림** |
| **3** | **2** | 두 번 재시도 → **되살림** |

56건이 재시도됐고 **56건 전부 200 으로 되살아났다.** 세 번 시도한 2건도 **진짜 peer**로 갔다
(`gx_app` 유출 0). 도는 설정에 `proxy_next_upstream error timeout http_502` 와
`proxy_next_upstream_tries 3` 이 **둘 다 선언돼 있다.**

### ④ 남은 502 는 **재시도를 아예 안 탔다** — 그래서 안 닫힌다

    ... "GET /api/dsm/events?limit=50..." 502 150 0.001 "172.18.0.9:8000" 0.002
                                                          └ 주소가 **하나뿐이다**

★ 결함의 이름이 **더 좁아졌다.** 종전 가설은 「재시도가 두 번에서 멈춘다」였다.
  오늘 자료는 그것을 **기각한다** — 세 번까지 가는 줄이 실제로 있다.
  남은 사실은 이것이다: **어떤 502 는 재시도 경로에 들어가지도 못한다**(주소 1개).
  「재시도가 설정이 안 됐다」가 아니라 「이 실패는 재시도 조건에 안 걸린다」다.

**회색 — 표본이 1건이다.** 원인 단계는 아직 못 가렸다. `non_idempotent` 는 **안 건드린다**
(OPS-13a §3 ④ 금지). OPS-13b **열린 채로 둔다.**
