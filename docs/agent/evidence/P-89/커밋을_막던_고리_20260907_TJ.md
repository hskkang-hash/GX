## 1. ①을 어떻게 풀었나 — **판정기가 아니라 원인**

세 턴 동안 잠금 대장에 이렇게 적혀 있었다:

> `/device` 를 볼 권한이 **없는** 시드 계정이 저장소에 없다(턴 F·G·I 세 턴 연속 같은 사유).

**있었다.** `.env.gates` 의 `gxprobe_e2e` — `route-alive` 게이트가 쓰는 바로 그 탐침이
그 라우트에서 그대로 거절당한다. 찾는 데 걸린 시간은 **2분**이었다.

```
GET /api/devices/devices-management     as gxprobe_e2e
  전  HTTP 200  {"success": false, "status_code": 403, "message": "Permission denied."}
  후  HTTP 403
```

★ **없다고 적힌 것을 한 번도 찾아보지 않은 것이 세 턴의 값이다.**
  「없다」는 **측정이 아니라 진술**이었고, 이 저장소는 진술을 실측처럼 옮겨 적었다.
  다음에 「…이 없어서 못 잰다」를 쓸 때는 **없다는 것부터 재라.**

승격 접두는 **반경 1**(`/api/devices/devices-management`) — 세종이 이의를 수용했다.
`/api/devices/` 를 켰다면 인벤토리 **66건**이 같이 뒤집힌다(전/후를 재지 않은 55건 포함).
`authz_envelope` 193 → **185** · 화면이 부르는 면의 갈림 **1 → 0**.

그리고 **앞단도 같은 턴에 세웠다** — `frontend/src/features/session/permissionDenied.ts`.
**승격은 반쪽이면 더 나쁘다**: 서버만 고치고 앞단이 조용하면 빈 표가 「빈 표 + 멈춘
스피너」가 된다. 그 신호를 **그리는 쪽**은 차선 C 가 잇는다.

## 2. ③이 말하는 것 — **훅도 판정기다**

`ga_readiness` 는 손으로 부르면 초록, 훅이 부르면 빨강이었다. 갈린 것은 제품이 아니라
**누가 먼저 세션을 잡았는가**다. 같은 뿌리가 이번 턴에 **두 층에서** 나왔다:

- 판정기 안 — `verify_ga_readiness` 가 게이트 16벌을 나란히 불렀다 → 로그인하는 여섯만 줄 세움
- 훅 사이 — pre-commit 이 훅을 나란히 돌렸다 → `require_serial: true`

★ **동시 접속 1개는 제품의 제약인데 도구가 그것을 몰랐다.** 도구가 제품의 제약을
  모르면, 도구가 내는 색은 제품의 색이 아니다.
