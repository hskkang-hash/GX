# P-286 — **다리를 걷어냈다.** 한 주소(`:8500`)로 화면과 API 가 함께 온다

[실측 2026-09-24 · 턴 AH · 조율자(영실) · **대표가 직접 걸어서 찾은 결함**]

## ① 무엇이 틀렸나 — 게이트는 내내 초록이었다

대표가 `localhost:3002` 로 제품을 보려다 **연결 거부**를 봤다. 조율자가 처음 낸 답은
「그 주소는 컨테이너 안의 것이라 밖으로 안 나와 있다」였고 그것까지는 맞았다.
**그런데 거기서 멈추고 「길이 없다」로 결론지은 것이 틀렸다** — 없었던 게 아니라
**안 낸 것**이었다. 급히 중계 컨테이너(`gx-portfwd`)를 세워 화면은 떴다.

⇒ **그것은 다리이지 길이 아니다. 고객은 다리를 놓을 수 없다.**

### 뿌리 — 빌드 디렉터리의 `.env` 두 줄
```
VITE_API_URL=http://localhost:8000
VITE_API_URL_FE=http://localhost:3002
```
이 두 줄이 있으면 번들이 **어디서 열리든** 그 주소를 부른다. 그래서 화면과 API 가
**늘 다른 출처**였다. `rj-core::initialServices` 는 그 값을 axios `baseURL` 에 그대로
넣고(`L4 = ({baseURL: a, …}) => Tf.create({baseURL: a, withCredentials: !0})`),
**빈 baseURL 은 현재 출처로 붙는다** — 그것이 이 고침의 전제다.

## ② 잰 것 — A/B

| 번들 안의 절대 주소 | 지금 판 | 새 판 |
|---|---|---|
| `http://localhost:8000` (HTTP) | **16** | **0** |
| `http://localhost:3002` | 2 | **0** |
| `http://localhost:8009` | 2 | 2 |

`:8009` 둘은 **양쪽에 똑같이** 있다(GCS · 이번 문과 무관). 남은 `ws://localhost:8000`
여섯은 전부 **웹소켓 기본값**이고 배송·드론 쪽(§0.4)이라 이 문이 아니다 —
**남았다고 다 문제는 아니라서 갈라 적는다.**

### 8500 실측
```
8500/                -> 200
8500/login           -> 200   <title>GuardianX</title>
8500/dsm/events      -> 200
8500/api/dsm/health  -> 200
8500 이 주는 번들 안의 http://localhost:8000  ->  **0건**
POST 8500/api/v1/auth/login  ->  400 "Username is incorrect."  (CORS 헤더 불필요 — 같은 출처)
```
**대표가 `localhost:8500/dsm/queue` 로 로그인해 카드 13장을 봤다 — 다리 0.**

## ③ 어떻게 했나 — 다음 사람이 재현할 수 있게

1. `frontend/.env.example` 의 두 줄을 **비웠다**(이 저장소의 정본 기본값).
2. 빌드 컨테이너에서 같은 두 줄을 비우고 **새 자리에** 지었다 —
   `docker exec gx-fe-build sh -c 'cd /app/_bld_u1ab && npx vite build --outDir dist_sameorigin'`
   (지금 쓰는 `dist_u1ab` 는 **한 글자도 안 건드렸다** — 대표가 그 화면을 쓰고 있었다)
3. 산출물을 호스트로 꺼냈다: `C:/GuardianX/gx-spa` (**저장소 밖** — 30MB 빌드 산출물)
4. `nginx/gx-front.conf` 8500 서버에 SPA 자리를 더하고, 그 경로를 읽기전용으로 물려
   `gx-nginx-e` 를 다시 만들었다(`--log-opt max-size=10m max-file=5` 포함).

### ★ 생성물을 한 줄도 안 고쳤다
관문 블록(`generated/gx-gate.conf`)은 「손으로 고치지 마라」다. 그 안의 `location /` 는
**접두 일치 중 가장 약하고**, `^~` 는 그보다 먼저 잡힌다 — 그 성질 하나로 생성물을
건드리지 않고 화면을 줄 수 있었다.

## ④ 두 번 걸렸다 — **둘 다 「고친 것과 도는 것은 다르다」**

**㉠ `try_files $uri /index.html` 의 마지막 자리는 파일이 아니라 URI 다.**
nginx 가 `/index.html` 로 **내부 재요청**을 돌리고, 그 재요청은 `location` 고르기를
다시 거친다. 그 자리를 안 만들어 두면 생성물의 `location /` 가 잡아 **뒷단으로 가고
장고가 404 를 낸다.** 첫 판이 정확히 그랬다 — `/login` 404 · `/` 본문이
「Page not found at /index.html」. **마운트는 보이는데 답이 뒷단에서 왔다.**
⇒ `location = /index.html { try_files $uri =404; }` 한 줄로 풀렸다.

**㉡ `nginx -s reload` 가 안 먹었다.**
`open() "/run/nginx.pid" failed` — 이 형상은 pid 를 `/var/run/nginx-front.pid` 에 둔다.
**설정만 바뀌고 도는 것은 그대로**였는데, 그 사이 잰 수는 옛 형상의 수다.
⇒ `docker restart` 로 확인했다. **reload 가 실패해도 게이트는 아무 말도 안 한다.**

## ⑤ 남은 것 — 정직하게

- **모든 화면 경로를 안 덮었다.** 지금 이은 것은 `/login` · `/dsm/*` · 자원뿐이다.
  그 밖의 앞단 경로는 여전히 뒷단으로 가 404 가 난다 — 그 404 는 **「아직 안 이은 것」**
  이지 「없는 화면」이 아니다.
  ⚠ `location /` 에 `try_files … /index.html` 을 거는 길은 **일부러 안 골랐다**:
    그러면 **API 404 까지 화면으로 바뀌어 고장이 화면으로 위장된다.**
- **`gx-portfwd`(다리)는 아직 돈다.** 지우는 것은 **대표 결정**(삭제)이라 안 지웠다.
  3002 와 8500 을 나란히 두고 대조할 수 있게 남겨 둔 것이기도 하다.
- 빌드 산출물(`C:/GuardianX/gx-spa`)은 **저장소 밖**이다. 이 자리는 스테이징으로
  갈 때 `compose` 가 가져갈 자리이고, 그때 이 문서의 ③이 절차가 된다.

## ⑥ 이 문서가 남기는 한 줄

> **대표가 본 화면이 게이트보다 먼저다.**
> 온보딩 48행도, 「누른 뒤」도, RC-1 도 이 자리를 초록으로 읽고 지나갔다.
> 게이트는 **컨테이너 안에서** 재고 있었고, 고객은 **밖에서** 연다.
> 같은 제품인데 **재는 자리가 달랐다.**
