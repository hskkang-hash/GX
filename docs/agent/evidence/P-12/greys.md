## 2. 다섯은 한 종류가 아니었다

```
  ① 진짜 빚 2      볼 것이 있는데 못 봤다        route-alive · secrets      → 갚았다
  ② 잘못 칠한 색 1  쟀고 알고 있었는데 SKIP 을 냈다  bypass                    → 래칫으로
  ③ 빚이 아닌 것 2  볼 대상이 설계상 0건이었다      model-inheritance · ui-library → 대기
```

「회색 5」라는 수는 읽는 사람에게 **다섯 자리가 안 지켜진다**로 들린다.
실제로 안 지켜지던 것은 **셋**이었고, 그중 **둘은 이번에 갚았다.**

그래서 집계에 네 번째 칸을 만들었다 — **대기**. 종료 코드는 여전히 2다
(재지 않은 것은 초록이 아니다). 갈리는 자리는 집계 줄이다.
없애지는 않았다 — **대상이 0인 것과 게이트가 없는 것은 다르다**(P-12 ④ · D-301).

## 3. ★ 이번 턴 가장 큰 발견 — 자격증명을 넣었더니 exit 0 이 나왔다

지시대로 자격증명을 로컬 `.env.gates` 에서 읽게 하고 게이트를 돌렸다. **초록이었다.**
출력을 읽어 보니:

```
[ALIVE] 로그인 성공: /api/token/pair
[ALIVE]   401 GET  /api/dsm/events?limit=10           문지기가 섰다(살아 있다)
[ALIVE]   401 GET  /api/media-data/?page_size=25…     문지기가 섰다(살아 있다)
  …  26건 중 24건이 401  …
[ALIVE] 통과 — 26건 전부 살아 있다 (실제 HTTP 로 때렸다)      ← exit 0
```

**로그인은 성공했고 토큰도 받았는데, 그 토큰은 아무 문도 열지 못했다.**

원인 [실측] — dj-core `core/auth.py:38`:

```python
user = User.objects.filter(id=user_id).first()
if not user.token:                       # ← 저장된 세션 토큰이 없으면
    raise HttpError(401, "Token expired")
```

`/api/token/pair` 는 JWT 를 내주지만 **세션을 세우지 않는다.** 제품의 진짜 문은
`/api/v1/auth/login` 이고, 동시 접속이 1개라 **`end_previous_session` 칸이 필요하다** —
없으면 **HTTP 200 에 `success:false`** 가 온다(조용한 성공).

### 그런데 진짜 문제는 원인이 아니었다

401 을 「문지기가 섰다(살아 있다)」로 읽는 규칙은 **옳다.** F-09 는 정확히 그것을 원한다.
틀린 것은 **들어가지 못한 채로 그 규칙을 쓴 것**이다.

`verify_route_alive.py` 의 첫머리에는 이미 이렇게 적혀 있었다:

> 익명으로 때려 401 만 잔뜩 보고 「전부 살아 있다」로 적는 것이 이 판정기의 가장 나쁜 실패다.

**적어 두는 것으로는 안 막혔다.** 그 문장 바로 아래에서 그 일이 일어났다.

### 고침은 규칙이 아니라 증거다

로그인 뒤 **같은 목록을 익명으로 한 번 더 때려** 무엇이 달라졌는지 센다:

```
[ALIVE] 토큰 대조 — 익명과 다른 응답 24/26건 · 토큰을 들고도 401/403 인 자리 0건
```

**토큰을 넣은 것과 안 넣은 것의 결과가 같으면, 그 토큰은 없는 것과 같다.** 0건이면 판정 불가.

양성 대조를 손으로 정하지 않는 것이 요점이다. 「이 라우트는 인증되면 200 이어야 한다」를
적어 두면 그 목록이 곧 옛말이 된다. 목록은 화면이 정하고, 대조는 익명이 정한다.

### 그 401 밑에 있던 것

```
[ALIVE] **죽은 라우트 2건** — 화면이 부르는데 응답이 없다:
          500 GET /api/media-data/?page_size=25&current_page=1
          500 GET /api/media-data?page_size=25&current_page=1
```

**두 자리가 401 에 덮여 있었다.** 회색이 빨강을 가리고 있었던 것이 아니라,
**잘못 얻은 초록이 빨강을 가리고 있었다.**

### 강제 도구 대조 [실측]

| | 종료 코드 |
|---|---|
| 자격증명 있이 | **1** (죽은 라우트 2건) |
| 자격증명 없이 | **2** (판정 불가) |

두 결과가 갈린다 = 자격증명이 실제로 읽히고 있다.

## 4. 시크릿 스캔 — 어디를 보는가가 판정의 절반이었다

gitleaks **8.21.2** 를 판·해시 고정으로 세웠다. 받은 파일이 lock 의 sha256 이 아니면
설치를 **거절한다**. 판은 `.pre-commit-config.yaml` 과 같은 것으로 맞췄다(D-369).

깔고 처음 돌린 날 [실측]:

```
파일 면 (--no-git)    19건
이력 면 (--source .)   1건
```

**같은 저장소, 같은 규칙, 열아홉 배.** 어느 쪽도 거짓말이 아니었다 —
**서로 다른 질문에 답하고 있었다.**

```
파일 면 : 이 디스크에 무엇이 있는가   ← 빌드 산출물 · 로컬 .env.stg 까지 센다
이력 면 : 무엇이 저장소에 들어갔는가  ← 커밋된 것만 센다
```

우리가 물어야 하는 것은 **「저장소가 무엇을 나르는가」**다. 그래서 파일 면을 훑고
**git 이 그 파일을 나르는지**로 가른다. 지금 [실측]: **저장소가 나르는 것 0 · 저장소 밖 4.**

### 실제 발견 1건 — 그리고 그것이 기능 결함이기도 했다

`backend/stream_monitors/example_frontend.html:813`

```javascript
let csrfToken = "…32자…";            // ← 실제 토큰이 박혀 있었다

if (!csrfToken) { /* 쿠키에서 */ }    // ← 위가 차 있어서
if (!csrfToken) { /* 엔드포인트에서 */ } //   이 세 갈래가 한 번도 안 돌았다
```

유출이면서 동시에 **기능 결함**이었다. 값을 비우니 둘이 함께 고쳐졌다 —
**지우는 것이 곧 고치는 것**이었다.

회전 불필요 [판정]: Django CSRF 토큰은 세션 범위이고 그 세션은 오래 전에 끝났다.
장수 자격증명(API 키·비밀번호)이었다면 여기 적지 않고 **폐기·재발급이 먼저**였다.

### 측정기 결함 둘 (D-350 — 측정기를 먼저 의심한다)

**① 줄 단위 허용목록이 큰 파일에서 조용히 꺼진다.**

같은 `"integrity": "sha512-…=="` 한 줄이:

| 파일 크기 | 판정 |
|---|---|
| 118 바이트 | 허용됨 (0건) |
| 202 KB | **오탐** |

gitleaks 가 파일을 청크로 나눠 읽으면 `regexTarget="line"` 이 볼 줄을 잃는다.
**규칙은 그대로인데 눈만 감긴다.** 자리(`paths`)로 한 번 더 잠갔고,
그 잠금이 살아 있는지를 **4000줄 표본**으로 매번 확인한다 — 작은 표본은 이 결함을 못 본다.

**② `git check-ignore` 가 한 건도 못 맞히고 있었다.**

파이썬 `text=True` 가 개행을 CRLF 로 바꿔 경로 이름에 CR 이 섞였고,
git 은 그런 경로를 **C-따옴표로 감싸** 돌려주었다: `"frontend/.env.stg\r"`.
그 문자열은 우리가 물어본 경로와 안 맞는다.

결과는 **무시되는 파일을 「저장소가 나른다」로 읽는 것** — 있지도 않은 유출로 빨개졌다.
NUL 구분(`-z`)으로 고쳤다. **잘못된 빨강은 잘못된 초록만큼 빨리 게이트를 죽인다**(D-353).

### 자기시험 — 무엇을 심는지가 절반이다

첫 심기는 `AKIAIOSFODNN7EXAMPLE` 이었다. **안 잡혔다** — AWS 문서 예제값이라
기본 룰셋의 허용목록에 있다. **나쁜 표본이었다.** 지금은 매번 새로 만든 32자를 심는다
(고정 값을 쓰면 그 값이 곧 허용목록에 오른다).

분류기 양성 대조 [실측]: 저장소가 나르는 자리에 심으면 **exit 1**, 치우면 **exit 0**.

## 5. bypass — 회색이 아니라 아는 빚이었다

이 자리는 **못 잰 자리가 아니었다.** 게이트는 목록을 읽었고 프레임워크 모델이
몇 개 남았는지 **알고 있었다.** 그런데 SKIP 을 냈고, SKIP 은 판정 불가로 집계된다.
**아는 것을 모른다고 적은 것**이다.

아는 빚에는 회색이 아니라 **래칫**이 맞다(D-311):

```
프레임워크 모델 잔존 7건 — 기준선 7건 안 (새로 는 것 0건 · 래칫 D-311)
  빚: coreuser · group · multilanguagecontent · role · usergroup · userprofile · userprofilelink
```

「언젠가 없앤다」가 **「오늘 안 늘었다」**로 바뀐다 — 뒤엣것만 매일 확인할 수 있다.

래칫 대조 [실측]: 양성 1(하나 늘면 잡는다) · 음성 3(그대로 · 줄어듦 · 대소문자만 다름).
