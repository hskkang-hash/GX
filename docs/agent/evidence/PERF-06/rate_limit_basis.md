## 0. 한 문장 — 급한 것부터

**`skipping` 은 이벤트를 버리는 것이 아니다.** 상한을 넘긴 것은 **미뤄지고**,
버려지는 것은 이벤트 행이 아니라 **캐시 무효화 신호**였다. 지금은 그 무효화조차
버리지 않는다(D-367). **호출로 확인했다: 투입 300건 · DB 행 300건 · 소실 0건.**

## 1. 그 값이 어디서 왔는가

| 무엇 | 어디 |
|---|---|
| 상수 | `backend/common/universal_optimization.py:2385` `CACHE_INVALIDATION_RATE_LIMIT = 200` |
| 유일한 사용처 | 같은 파일 `:2389` `@rate_limited(max_per_minute=…)` 가 걸린 `universal_cache_invalidation` — `post_save`·`post_delete` **전역** 수신기 |
| 상한 구현 | `backend/common/cache_signal_protection.py::SignalProtection.check_rate_limit` (모델 이름별 1분 창) |
| 등재 | 표 ① `backend/kernels/k5_trust/thresholds.py` `event.invalidation_rate_limit` (`contract_fixed=False`) |
| 로그 문구의 출처 | 그 파일 머리말 주석 `:21` — **옛 판의 코드가 주석으로 보존돼 있다** |

**[실측] 값의 유래는 「물려받은 값」이다.** D-367 이 이미 판 자리다: 2026년 이전
커밋의 주석은 `FIX: Rate limiting to prevent abuse` 한 줄뿐이었고 DoS 방지인지 DB
보호인지 적혀 있지 않았다. 코드를 읽어 답을 냈다 — 이 수신기는 한 번 돌 때 Redis
키 탐색·버전 증가·패턴 삭제를 한다. **이 상한이 지키던 것은 DB 가 아니라 Redis 와
응답 지연**이다. (「abuse」는 외부 공격이 아니라 **신호 폭풍**을 가리킨 말이었다.)

★ **이름이 사람을 속인다.** 로그는 `Rate limit exceeded for detectionevent
(200/min)` 라고 찍는다. `detectionevent` 는 **무엇을 제한하는가**가 아니라
**어느 모델의 저장 신호가 상한을 건드렸는가**다. 이벤트 기록 경로
(`kernels/k1_event/services.py::record_detection`)에는 **상한도 큐도 없다.**

## 2. ★ `skipping` 은 버리는 것인가 미루는 것인가 — **호출로 확인했다**

정본이 「호출로 확인한다」고 못 박은 자리다. 읽기로 판정하지 않았다.

**[실측 2026-09-05 · `scripts/probe_event_rate_limit.py` · gx-shell · 되돌리는 트랜잭션]**

| 잰 것 | 수 |
|---|---|
| 상한 | 200/분 |
| 투입한 호출 (`record_detection`) | **300건** (상한의 1.5배) |
| 만들어진 DB 행 (`DetectionEvent`) | **300건** |
| **소실 (`dropped`)** | **0건** |
| 미룸 (`deferred`) | 817 |
| 접음 (`coalesced`) | 3,383 |
| 큐가 차서 그 자리 처리 (`ran_inline`) | 0 |
| 흘려 처리 (`drained`) | 50 |
| 실패 (`failed`) | 0 |
| 걸린 시간 | 5.345초 → **56.1건/초 (= 3,366건/분)** |
| 되돌린 뒤 남은 행 | 0건 |

**투입 n = 행 n · dropped 0.** 상한은 실제로 넘겼다(deferred 817 · coalesced 3,383)
— 안 넘긴 시험은 초록이 아니라 아무것도 안 잰 것이므로, 넘겼음을 함께 세었다.

### ⚠ 쓰기 전에 분류 등록부에 물었다 (D-270 ③)

이 도구는 **스트림 300대를 진짜로 심는다.** 그 표가 공용 마스터였다면 측정하는 몇 초
동안 **모든 테넌트의 관제 화면에 유령 카메라 300대**가 떴을 것이다 — 되돌리기 전까지
남의 관제에 얼룩이 남는다. 그래서 첫 `create()` **앞에서** 등록부에 묻고, 공용
마스터면 심지 않고 멈춘다.

| 무엇 | 값 |
|---|---|
| 심는 표 | `stream_monitors.StreamMonitor` (직접 생성 + `_own()` 의 `row.save()`) · `stream_monitors.DetectionEvent` (`record_detection` 이 만든다 — **부작용도 센다**) |
| 등록부 | `backend/tests/tenant_classification.py` — 분류의 **유일한 출처** |
| 문지기 | `scripts/verify_alarm_budget.py::_refuse_if_shared_master` 를 **빌려 쓴다.** 판정식을 복사하지 않는다(D-212) — 두 벌은 반드시 어긋난다(D-369) |

**[실측 2026-09-05] 음성 대조로 문지기가 진짜 무는지 확인했다**: 같은 문지기에
`user.Timezone`(등록부의 공용 마스터)을 넘기니 멈췄다 —
*「user.Timezone 이 분류 등록부에서 **공용 마스터**다. 측정용 행을 공용 표에 심으면
되돌리기 전까지 전 테넌트가 그것을 본다」*. 물지 않는 문지기는 세워 둔 것과 같다.

### ⚠ 이 수를 낼 때 피한 함정 — 표본은 **서로 다른 스트림**이다

`record_detection` 을 **같은 스트림·같은 종류로** 연달아 부르면 K1 의 기록 창
(`DEDUP_WINDOW` 10초)이 두 표본을 **한 행으로 접는다**. 그 상태로 행을 세면
「투입 300 · 행 1」이 나오고, 그것을 「속도제한이 299건을 버렸다」로 읽게 된다 —
**중복 억제를 재고 속도제한이라 적는 일**이다. 그래서 스트림 300대를 따로 세웠고,
**접힘 0건**을 증거에 함께 박았다(위 표에 `folded=0`).

### 무엇이 미루는가 (D-367 의 규칙, 코드로 확인)

`backend/common/cache_signal_protection.py`:

1. 상한 아래면 지금 한다
2. 넘으면 **미룬다** (`SignalProtection.defer`)
3. 같은 `(함수, 모델, pk)` 는 **접는다** — 같은 행의 무효화 두 번은 한 번이다
4. 큐(`DEFER_QUEUE_MAX = 5000`)가 차면 **가장 낮은 등급부터** 버린다
5. ★ **심각 등급은 어떤 경우에도 버리지 않는다** — 큐가 심각 등급으로 차면 그
   자리에서 처리한다(`ran_inline`). `CRITICAL_MODELS` 에 `detectionevent` ·
   `eventclip` · `notificationrule` · `deliveryrecord` 가 들어 있다

강제: `scripts/verify_event_drop.py` · `backend/tests/test_event_no_drop.py`

## 3. 재난 상황의 실제 이벤트율은 얼마인가

★ **[실측]이 아니다. [추정]이다** — 실제 재난 현장의 프레임도 AI 서버도 이 환경에
없다(`ai.invalid`). 그래서 **잰 수(분모)** 와 **셈한 수**를 나눠 적는다.

**[실측] 셈의 분모**

| 무엇 | 수 | 출처 |
|---|---|---|
| 이 DB 의 카메라(스트림) 수 | **40대** | `calls.json` `cameras_in_db` |
| 이벤트 종류 | **7종** | `stream_monitors/models.py` `EventType` (person·vehicle·fire·smoke·intrusion·sos·flood) |
| 기록 단계 중복 억제창 | **10초** | 표 ① `event.dedup_window` |
| 이 환경에서 낸 실제 기록 속도 | **56.1건/초** | 위 §2 |

**[추정] 재난 시 이벤트율의 상한**

기록 창이 `(스트림, 종류)` 마다 10초이므로 **카메라 1대·종류 1개는 분당 최대 6건**
이다. 종류 7이면 **카메라 1대당 분당 최대 42건**.

    40대 × 42건/분 = 최대 1,680건/분   ← 이 테넌트 규모의 이론 상한 [추정]

거꾸로, **200/분을 넘기는 데 필요한 최소 규모**:

    카메라 5대가 전 종류를 쉼 없이 탐지        (5 × 42 = 210/분)
    또는 카메라 34대가 각 1종류를 쉼 없이 탐지  (34 × 6 = 204/분)

**[판정] 재난 상황에서 200/분은 쉽게 넘는다.** 40대 규모에서 다섯 대만 화재·연기를
동시에 잡아도 넘고, 100대 규모 제안서를 쓰는 자리에서는 평상시에도 넘길 수 있다.
**넘는다는 사실 자체는 결함이 아니다** — 넘었을 때 무엇이 일어나는가가 결함 여부를
가르고, 그 답이 §2 다(소실 0).

## 4. [판정] 운영 적정성 — **이 값은 재난 현장에 맞는가**

### ① 값 200 을 **바꾸지 않는다**

근거 셋:

1. **이 상한은 이벤트를 막지 않는다.** 이벤트 기록 경로에 상한이 없다(§1). 실측
   56.1건/초가 그 증거다 — 상한이 이벤트 처리량의 천장이었다면 이 수가 나올 수 없다.
2. **넘어도 잃지 않는다.** 투입 300 · 행 300 · dropped 0 (§2). 상한이 하던 일
   (Redis 순간 부하 억제)은 그대로 서고, 상한이 하던 **다른 일(무효화 소실)** 만
   D-367 이 없앴다.
3. **미룬 무효화가 관제 화면에 닿지 않는다.** P-19 · D-413 이 `dsm/` 를 통째로
   `BYPASS_PATTERNS` 에 올렸다 — DSM 도메인은 **애초에 캐시되지 않는다.** 그러므로
   무효화를 미뤄도 관제 대시보드·이벤트 목록의 신선도는 영향을 받지 않는다.
   「재난이 몰릴 때 낡은 화면이 남는다」는 D-367 시점의 위험이었고, P-19 가 그
   위험의 사정권에서 재난 도메인을 빼냈다.

### ② 버리는 갈래로 되돌리지 않는다 — 그리고 **큐잉은 이미 그 답이다**

정본이 물은 「버려지는 갈래면 미루는 갈래(큐잉)로 바꾸는 것이 옳은가」는
**이미 바뀌어 있다**(D-367 · 2026-09-11). 이 절이 더할 것은 큐잉의 **값**에 대한 판정이다:

| 값 | 지금 | [판정] |
|---|---|---|
| `DEFER_QUEUE_MAX` | 5,000 | 접기(③) 덕에 이 수는 「서로 다른 **행**의 수」다. 40대·100대 규모에서 1분 안에 바뀌는 서로 다른 행이 5,000을 넘기 어렵다 — **그대로 둔다** |
| `DRAIN_BATCH` / `DRAIN_INTERVAL` | 50건 / 5초 | 흘리개 처리량 **600건/분**. 실측 끝의 큐 잔량 767건 → **약 77초**에 다 흘러간다 |
| 심각 등급 불가침 | 상수 | **그대로 둔다.** 이 한 줄이 「재난 때 사라진다」를 막는 자리다 |

**[판정] 77초는 계약을 건드리지 않는다.** F-10 「30초」는 **알림 발송**의 시각이고
(`notify.max_latency`), 이 77초는 **캐시 무효화**의 지연이다. 두 수를 한 칸에 두면
계약이 아닌 것을 계약으로 만드는 일이다(표 ① 이 `contract_fixed=False` 로 적은 이유).

### ③ 다만 — **정본의 한 문장을 고쳐야 한다** (넘김)

PERF-05 는 이렇게 적혀 있다:

> 부하를 올리자 `detectionevent` 에 분당 200건 속도제한이 걸렸다. 이 환경에서
> **먼저 무너진 것은 DB 도 CPU 도 아니라 우리 쪽 속도제한**이다.

**[판정] 이 문장은 「이벤트 처리량이 200/분에서 막혔다」로 읽힌다. 그렇지 않다.**
실측은 **56.1건/초 = 3,366건/분**이 들어갔고 행은 하나도 안 사라졌다. 무너진 것은
처리량이 아니라 **캐시 무효화의 즉시성**이다. 이 문장을 그대로 두면 다음 사람이
「우리 제품은 분당 200 이벤트가 상한」이라고 제안서에 적는다 — 그것이 착시 ①이다.

★ 정본 수정은 조율자의 몫이다(이 차선은 `ga_readiness.yaml` 을 고치지 않는다).
제안 문안: *「먼저 상한에 닿은 것은 DB 도 CPU 도 아니라 **캐시 무효화 신호의
분당 상한**이다. 이벤트 기록 자체는 막히지 않았다(PERF-06 실측 56.1건/초·소실 0).」*
