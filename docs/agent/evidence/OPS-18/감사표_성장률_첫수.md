# OPS-18 — 감사 표 하루 증분: **첫 수**, 그리고 **세는 자리**

차선 F(성능·자료 증가) · 턴 Z · 2026-09-21 · 잰 시각 **12:25~12:26 KST**
표 `logger_auditlogs`(dj-core · §0.4 — **읽기만 했다**) · DB `database_guardianx`

## 0. 왜 이 턴에 수가 아니라 **자리**가 먼저인가

대장이 스스로 닫는 조건을 적어 두었다:

> 「위 수는 내가 psql 로 **손으로 한 번** 낸 것이다. 서 있는 측정 자리도, 이 절을 지키는
> 판정기도 **0곳**이다. 한 번 잰 수를 「센다」로 적으면 **다음 달에 아무도 세지 않아도
> 대장은 초록이다.** 닫는 모양: 증분을 **주기로 적는 자리** + **그 수를 읽는 판정기.**」

그래서 이 턴의 산출은 수 하나가 아니라 **`scripts/measure_audit_growth.py`** 다 —
재는 갈래와 **판정하는 갈래**를 한 파일에 담았다.

### ★ 어떻게 이레치를 쟀나 — 이 일의 핵심

- 시각 칸은 **`create_datetime`** 이다(`created_at` 은 없다). 그 칸을
  `(create_datetime at time zone 'Asia/Seoul')::date` 로 **KST 날짜로 묶어** 집계했다.
  「하루」가 무엇인지 안 적으면 날 경계가 사람마다 달라진다.
- **행이 0인 날을 빠뜨리지 않는다.** `GROUP BY` 는 없는 날을 안 낸다 — 그러면
  「이레치」라고 적어 놓고 실제로는 닷새만 낸 표가 된다. 09-14 는 **0으로 적고
  `empty` 로 표시**한 뒤 통계에서 뺐다. (0을 평균에 넣으면 「하루 증분」이
  「기계가 꺼진 날까지 섞인 값」이 된다.)
- **오늘을 섞지 않는다.** 09-21 은 아직 안 끝난 날이라 따로 적었다.
- **하나만 내지 않는다.** 이 기계의 하루 폭은 **3배**다. 중앙값만 적으면
  「어느 날을 골랐나」가 답을 정한다 — 그래서 중앙값·평균·최소·최대를 **전부** 적는다.
- **논리 바이트와 디스크 바이트를 가른다.** 논리는 `sum(pg_column_size(t.*))` **[실측]**,
  디스크는 `행 수 × (총 바이트 ÷ 총 행)` **[산출]**. TOAST 압축이 줄이고 인덱스·페이지
  여백이 늘린다 — 둘은 같은 수가 아니고, **용량 계획은 디스크 값으로 한다.**

⚠ **이 수는 「이 개발 기계의 하루」다.** 차선 여덟이 두드리는 날이고 상용 부하가 아니다.
`CoreLoggingMiddleware` 가 **요청 한 벌마다 감사 한 행**을 쓰므로, 이 수는 사실상
**「우리가 하루에 몇 번 두드렸나」**다. 「상용에서 하루 몇 MB」로 읽으면 틀린다 —
모수가 다르다. 상용 수는 상용 트래픽에서 다시 재야 한다.

## 2. 무엇이 **먼저** 아픈가 — 고르지 않고 각각 눌렀다

`EXPLAIN (ANALYZE, BUFFERS)` · 질의마다 3벌 · 가운데값:

| 질의 | 모양 | 시간 | 실제 행 | 버퍼 |
|---|---|---|---|---|
| `indexed` — `logger_name` + 시각 (`response_clock.stamps_for`) | Limit / Index | **0.095 ms** | 68 | hit 77 · read 0 |
| `chain_all` — LAW-08 체인 검증 전건(`evidence_chain.chain_entries`) | Sort ← **Seq Scan** | **61.85 ms** | 3,344 | hit 9,256 · **read 12,662** |
| `page` — 화면 목록 한 쪽 (pkey 역순 50행) | Limit | **0.043 ms** | 50 | hit 26 · read 0 |

| # | 후보 | 언제 | 문턱 |
|---|---|---|---|
| **1** | **조회 지연** | **약 197일 뒤 (0.5년)** | LAW-08 전건 검증 한 벌이 1,000 ms |
| 2 | 디스크 | 약 36,544일 뒤 (100년) | 데이터 파일 시스템 여유 0 (**932 GiB** 남음) |
| 3 | 인덱스 | **못 냈다** | 쓰기 지연 — 행 하나마다 인덱스 **35개**가 갱신된다 |

> **먼저 아픈 것은 조회 지연이고, 그중에서도 `chain_all` 이다.**
> 이유가 표에 그대로 있다: `logger_name LIKE 'guardianx.%'` 는 인덱스를 못 타서
> **표 전체(약 22,000 블록 = 171 MB)를 훑는다.** 3,344행을 얻으려고 155,243행을 읽는다.
> 그러므로 이 자리의 시간은 **총 행 수에 비례**하고, 하루 11,930행이 그대로 시간이 된다
> (0.000398 ms/행 × 11,930 = **약 +4.7 ms/일**).
> 턴 Y 가 넣은 `gx_audit_logger_dt_idx` 는 **`indexed` 자리를 표 크기에서 떼어 냈지만**
> (0.095 ms · 버퍼 read 0), **이 자리는 안 덮는다** — 접두사 검색이라 그 인덱스를 못 탄다.

⚠ **디스크는 이 기계에서 문제가 아니다.** 932 GiB 여유에 하루 26 MiB 면 100년이다.
  「자람이 곧 디스크 문제」라는 흔한 직관은 **이 표에서는 틀리다.**
⚠ **인덱스 35개는 셌지만 그 값이 얼마인지는 못 쟀다.** 행 하나가 들어올 때마다 35개가
  갱신되고 인덱스가 힙의 66%(113 MiB / 171 MiB)인데, **쓰기 시간을 안 쟀다** —
  이 도구는 읽기만 한다. 재려면 INSERT 를 트랜잭션 안에서 걸고 되돌려야 한다.
  **안 잰 것을 「안 아프다」로 적지 않는다.** 순위 3위가 아니라 **순위 밖**이다.
⚠ 「197일」은 **가정 위의 수다**: 지금 속도가 유지되고, 체인 행 비율(2.2%)이 유지되고,
  버퍼 적중률이 유지된다고 본다. 셋 중 하나만 틀려도 날짜가 바뀐다 — **날짜가 아니라
  「무엇이 먼저인가」가 이 절의 답이다.**

## 3. 세는 자리 · 판정기 — `scripts/measure_audit_growth.py`

```
# 잰다 (읽기만 · SELECT 와 EXPLAIN 뿐 · 아무것도 안 쓴다)
docker exec -e DJANGO_SETTINGS_MODULE=config.settings gx-shell \
    python /repo/scripts/measure_audit_growth.py --days 7 \
        --disk-free-bytes <밖에서 잰 값> --out /docs/agent/evidence/OPS-18/audit_growth.json

# 판정한다 — **아무도 안 센 것**을 잡는다
docker exec gx-shell python /repo/scripts/measure_audit_growth.py \
    --check /docs/agent/evidence/OPS-18/audit_growth.json [--max-mib-per-day N]
```

판정 갈래 셋 — **① 신선도 ② 분모 ③ 상한**. 눌러서 본 것:

| 대조 | 누른 것 | 결과 |
|---|---|---|
| 양성 | 방금 잰 판 | ① 초록(0.0일 전) · ② 초록(분모 6/창 7) · ③ **회색(선언 없음)** · exit **0** |
| 양성 | `--max-mib-per-day 100` | ③ 초록 (26.1 ≤ 100) · exit 0 |
| **음성** | 파일이 **없다** | **빨강** — 「센다인데 아무도 센 적이 없다」 · exit **1** |
| **음성** | `--max-age-days 0` (수가 늙었다) | **빨강 ①** · exit 1 |
| **음성** | `--max-mib-per-day 1` (상한 초과) | **빨강 ③** · exit 1 |
| 자기시험 | `--self-test` (DB 없이) | **10/10 통과** — 빈 날은 0이 아니라 `None` 포함 |

★ **증가율 상한을 이 판정기가 정하지 않는다.** 그 수는 **선언**이고 주인이 따로 있다
  (LAW-05 보존 정책 · 세종 몫). 안 주면 그 갈래는 **회색**으로 적히고, 회색은 초록이 아니다.
  이 판정기가 겨누는 것은 「수가 크다」가 아니라 **「그 수가 늙었다」**이다.

★ 머리글(P-107) 넷을 찍고, **분모는 「행이 있는 날의 수」**로 적는다 — 창의 길이가 아니다.
  창 7일에 기계가 하루 꺼져 있었으면 분모는 **6이지 7이 아니다.**

## 4. 안 한 것

- **보존·삭제는 안 건드렸다.** 이 절은 **재기만** 한다(LAW-05 v0.4 · 세종 몫).
- **쓰기 시간(인덱스 35개의 값)을 안 쟀다.** §2 ⚠ 참조.
- **상용 성장률을 안 쟀다.** 요청 수 대비 행 수를 재야 하고, 상용 트래픽이 있어야 한다.
- **주기로 도는 자리는 아직 없다.** 판정기는 「늙었으면 빨강」을 내지만,
  **스스로 재러 가지는 않는다** — 그 자리에 거는 것(게이트 묶음·`.pre-commit-config.yaml`)은
  차선 Q 의 파일이다. 내가 안 걸었다.
- dj-core · `backend/delivery`·`orders`·`terminals` · 프런트 **0줄**.
