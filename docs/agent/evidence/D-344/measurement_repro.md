# D-344 — 610/127 과 614/131 은 왜 달랐나 [실측 2026-09-08]

> 지시: ① 두 측정을 **같은 커밋에서 재현**하라. 같은 수가 나오면 원인은 그 사이의 코드
> 변경이다 — 무엇이 늘었는지 **4건을 이름으로 대라.** ② 다른 수가 나오면 술어의 비결정성이다.

---

## 1. 결론 먼저

**술어는 결정적이었다. 달라진 것은 트리다 — 그리고 늘린 것은 우리 자신이었다.**

이전 보고의 「자기 변경분 기여 0건」은 **틀렸다.** 4건 전부 그 턴이 더한 것이다.

| | 610/127 | 614/131 |
|---|---|---|
| 트리 | `030178c` 및 그 이전 | `25daaf5` 이후 |
| 무엇을 잰 것인가 | 그 턴이 **자기 코드를 쓰기 전** | 쓴 **뒤** |

수가 아니라 **측정 시점**이 달랐다. 두 수에 커밋이 붙어 있었다면 이 조사는 필요 없었다.

---

## 2. 방법 — 술어를 고정하고 트리를 옮겼다

`probe_threshold_census.py` 는 `25daaf5` 에서 태어나 **그 뒤 한 줄도 바뀌지 않았다**
(`git log -- scripts/probe_threshold_census.py` → 커밋 1건).

그래서 그보다 앞선 커밋에는 이 도구가 **없다.** 없는 도구로 옛 트리를 잴 수 없으므로,
워크트리를 옛 커밋으로 옮긴 뒤 **HEAD 의 도구를 복사해** 돌렸다 —
**모수와 술어를 두 벌 두지 않는다**(`verify_threshold_table.py` 머리말과 같은 규칙).

```
git worktree add <임시> <커밋>
cp scripts/probe_threshold_census.py <임시>/scripts/
(cd <임시> && python scripts/probe_threshold_census.py)
```

## 4. 늘어난 4건 — 이름으로

전수 목록을 파일·자리로 대조했다. `+4 / +4` 이고, **넷 다 계약 기능 면**이다.

| 파일 | 자리 | 값 |
|---|---|---|
| `backend/common/audit_writer.py` | 기본값 | `limit: int = 100` |
| `backend/kernels/k5_trust/audit.py` | 기본값 | `limit: int = 100` |
| `backend/kernels/k5_trust/credentials.py` | 비교 | `if len(value) <= 8` |
| `backend/kernels/k5_trust/services.py` | 기본값 | `limit: int = 50` |

넷 다 `25daaf5`(표 ①② 커널 · 감사 기록)가 **새로 만든 파일에서 태어났다.**
→ 「자기 변경분 기여 0건」이 아니라 **자기 변경분 기여 4건**이다.

## 5. 무엇을 고쳤나

| 지시 | 한 것 |
|---|---|
| ① 같은 커밋에서 재현 | 위 표. 원인은 코드 변경으로 확정 |
| ② 비결정성이면 술어 고정 | **해당 없음** — 같은 트리에서 두 번 같은 수 |
| ③ 측정 스크립트 커밋 + 2회 동일성 게이트 | `scripts/verify_measure_repro.py` — 등재 도구를 두 번 돌려 대조 |

★ ③에 하나를 더했다: **수에 커밋을 붙인다.** `verify_measure_repro.py` 는 판정할 때
`git rev-parse --short HEAD`(+작업본 여부)를 함께 출력한다. 이번 조사가 필요했던 이유는
술어가 흔들려서가 아니라 **두 수가 어느 트리의 것인지 적혀 있지 않아서**였다.

## 6. 남은 것

`credentials.py` 의 `len(value) <= 8` 은 **자격증명 마스킹 길이**다. 표 ①(임계값 커널)로
옮길지 여부는 판정 대상이다 — 지금은 전수에 세어져 있고 표에는 없다. 이 한 줄이
`verify_threshold_table.py` 의 래칫 기준선 안에 있어 게이트는 초록이다(D-311).
