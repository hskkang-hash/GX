## ② 이 문장을 이제 적을 수 있다

> **배치된 번들이 3002 에서 서비스되고, 그 번들이 8000 을 보고 완주 3/3 했다.**

세 조각이 한 줄로 이어진 근거는 이렇다 — 하나라도 끊기면 이 문장은 거짓이다:

1. **빌드한 것 = 서비스되는 것.** 빌드 산출물의 다이제스트(`c0a8f38d8ea82290`)와
   `_fe_dist` 를 같은 방식으로 다시 센 값이 **같다**(위 표 셋째 줄 · sha256).
   턴 H 는 여기까지도 초록이었다.
2. **서비스되는 것 = 배치 커밋.** 3002 가 내는 두 자산이 스스로 `GX_COMMIT:abbdf36…`
   을 말하고, 그것이 배치 증거의 커밋과 같다 (`verify_bundle_hash.py` 3행 전부 pass).
3. **★ 그 번들이 걸었다.** `walk_scenarios.py` 가 **그 3002 주소**를 열어 S1·S2·S3 을
   지나갔고, 화면이 부른 API 는 **8000** 이다. 턴 H 에서 끊긴 자리가 여기다 —
   그때는 다른 주소(3010→8010)에 다른 번들을 세워 걸었고, 그래서 「배치가 걸렸다」로
   적지 않았다. 이번에는 **주소를 바꾸지 않았다.**

## ③ 무엇이 달라져서 이번엔 됐나 — **우리 코드가 아니다**

턴 H 의 원인은 이름으로 확정돼 있었다: 8000 의 프리플라이트가 `idempotency-key` 를
허락하지 않아 **브라우저가 로그인 요청을 아예 안 보냈다.** 이번 턴 착수 시점 실측:

    OPTIONS /api/v1/auth/login   Access-Control-Request-Headers: content-type,idempotency-key
      8000 → allow-headers: … x-no-cache, x-gx-wall-token, idempotency-key   ← **있다**

즉 고친 것은 코드가 아니라 **서버를 다시 세운 것**이다. 턴 H 가 「기술이 아니라
손의 문제」라고 적은 그대로였고, 손이 움직이자 같은 코드가 걸었다.

## ④ 이 초록의 한계 — **적어 두지 않으면 다음 사람이 넘겨 읽는다**

- ⚠ **`--allow-dirty` 로 배치했다.** 작업본이 더러운 채로 갔고, 그래서 번들에 박힌
  `abbdf36…` 은 **그 커밋의 내용이 아니다.** 이번 턴 차선 C·Q 가 고친 프런트 파일이
  섞여 있다(`dsm/api.ts` · `dsm/pages/EventDetail.tsx` · `dsm/pages/FocusQueue.tsx`).
  배치 로그가 그 세 이름을 찍어 두었다 — 게이트는 이 둘을 구별할 수 없으므로
  **사람이 여기서 구별한다.** 병합 뒤 같은 명령을 한 번 더 돌리면 이 단서가 사라진다.
- ⚠ **빌드가 끝난 뒤 프런트 파일 하나가 더 바뀌었다** — `features/login/loginRequest.ts`.
  **주석 한 문단뿐이고**(「서버가 아직 이 이름을 읽지 않는다」가 거짓이 되어 고쳤다)
  번들 산출물에는 안 실린다. 그래도 적어 둔다: 「배치 뒤에 아무것도 안 건드렸다」와
  「건드린 것이 주석뿐이다」는 다른 문장이고, 앞엣것을 적으면 그것이 거짓이다.
- ⚠ 걷기는 **세 시나리오**다(S1 목록 · S2 대시보드 · S3 단일 초점). 「배치된 번들이
  걷는다」는 그 셋에 대한 문장이지 48행이나 56칸에 대한 문장이 아니다.
- ⚠ 화면이 부른 API 중 **422 가 셋** 있다(`GET /api/user-groups/gen-schema` · §0.4 자산).
  걷기는 이것을 판정하지 않고 「다음 사람이 볼 자리」로 적는다 — 분류는 면제가 아니다.
- 8010 도 이 순간 서 있다(같은 코드). 이 문서의 수는 **전부 8000/3002 것**이다.
