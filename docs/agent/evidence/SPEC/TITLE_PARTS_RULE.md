# TITLE_PARTS 눈금 — 하나다 (P-419 · 차선 N1 · 턴 AP)

소유: 차선 N1. 이 문서는 `scripts/verify_spec_title_parts.py` 가 **존재 여부**와
**아래 「닫힘 status 앞머리」 목록**을 그대로 읽는다 — 이 문서가 없으면 게이트는
회색을 낸다, 이 문서의 목록과 코드 상수(`CLOSED_PREFIXES`)가 갈리면 게이트는
빨강을 낸다. **사람마다 다른 눈금을 쓰는 것을 0 으로 만드는 것이 이 문서의
유일한 일이다.** 표를 만들기 전에 먼저 이 문서를 읽는다(WO-19 §4 N1 줄).

내력: 턴 AO `docs/agent/evidence/SPEC/N1_promotions_ao.md` §2(방법)·§2-2(35 반쪽
사례)에서 이미 쓰인 눈금을 그대로 옮겨 적은 것이다 — 이 문서가 새 규칙을 정하는
것이 아니라, 이미 실제로 쓰인 눈금을 **글로 고정**하는 것이다(P-419 「눈금은
하나다」).

## 1. 「제목이 부르는 것」의 종류

명세 제목 하나를 표(`title_parts`)로 쪼갤 때, 아래 일곱 종류를 빠짐없이
살핀다. 제목·완결조건 문장에 나온 낱말이 아래 종류 중 하나에 해당하는데 표에
그 행이 아예 없으면 — 「빈 칸」이 아니라 **「빠진 행」**이고, 이것도 반쪽이다
(표에 있는 칸만 세는 것이 아니라 표에 없는 것도 센다).

1. **명사 부분** — 제목을 이루는 명사(구)마다 한 행. 예: 「헬기 요청 승인·투하
   구역 지정」 → 「헬기 요청 승인」 행 하나 · 「투하 구역 지정」 행 하나.
2. **완결조건 문장** — 제목 뒤 괄호나 명세 원문의 완결조건으로 적힌 문장.
   서버 응답이 아니라 그 **문장이 실제로 참인지**를 실측해야 닫힘이다(예:
   「한 화면으로 뜬다」 완결조건은 단일 API 응답이 아니라 실제로 한 화면에
   렌더되는지를 잰다 — 대신한 것이 있으면 `excluded_by` 없이는 열린 행).
3. **화면** — 제목이 화면·보드·판을 부르면(「지휘 화면」·「건강 보드」 등)
   실제 프런트엔드 컴포넌트가 그 값을 그리는지까지 잰다. 서버 API 왕복만
   실측하고 화면을 안 대면 그 행은 반쪽이다(옛 턴의 F1-01 「화면이 좌표를
   하드코딩」이 이 함정의 전형).
4. **홈카드** — 제목·완결조건이 홈 화면 카드를 부르면 그 카드가 실제로
   붙어 있는지(라우트·컴포넌트) 잰다. UI 미배선은 열린 행.
5. **외부 기관 실연동** — 산림청·소방·경찰·인증기관 등 제3자 시스템과의
   **진짜** 연동. 내부 이벤트·훈련 채널·수동 입력은 이것이 아니다 — 그런
   대체 채널로 닫으려면 그 사실을 status 에 정직하게 적고, 실연동 부분
   자체는 `excluded_by: "P-428"`(이 턴 결정 — 운영 집행·외부 실연동 부분만)
   + `excluded_why` 로 따로 뺀다.
6. **저장한 값을 실제로 읽는가** — 값을 저장(POST/설정)만 하고 그 값을 실제로
   되읽어 동작(차단·표시·계산)에 쓰는 코드가 없으면 열린 행이다(예: F1-12·
   F2-15 — 저장은 되지만 억제 로직이 그 값을 안 읽는다).
7. **선언값 == 설정값** — 문서·명세·화면 문구가 선언한 수(보관기간·문턱값
   등)와 코드에 실제로 심긴 설정값이 같은지 대조한다. 다르면(예: 선언
   730 일 ≠ 심긴 365 일) 열린 행 — 게이트는 「선언 == 설정」 1행으로 잰다.

## 2. status 앞머리 — 닫힘/열림

게이트(`scripts/verify_spec_title_parts.py`)가 기계로 읽는 값. 아래 목록은
코드 상수 `CLOSED_PREFIXES` 와 **정확히 같아야 한다**(순서·철자까지) — 갈리면
게이트가 빨강을 낸다.

```
CLOSED_PREFIXES = measured, present,있음, 구현
```

- **닫힘 앞머리**(위 넷 중 하나로 시작 — 대소문자 무시·앞뒤 공백 무시):
  `measured` · `present` · `있음…` · `구현 — …`
- **열린 앞머리**(닫힘이 아니다 — 전형적인 실측 표현): `없음(...)` · `부분(...)`
  · `missing …` · `[미확인]` · `… 대안 그대로` · `근사 실측` · `정직하게 비움`
  · `대체(사유 없이)` · `잠정` · `추정`
- **대리 지표 낱말**(`PROXY_PREFIXES`) — status 가 이 앞머리로 시작하면
  다른 닫힘 앞머리와 동시에 시작해도 **열린 행**이다(대리가 우선):
  `근사` · `대리` · `proxy`. 제목이 부르는 수를 다른 수로 근사했다는 뜻이기
  때문이다(예: 「골든타임 준수율」을 「확인 회신 30분 비율」로 근사).

## 3. `excluded_by` 규칙 — 결정으로 뺀 행 (P-406 · 이 턴은 P-428 로 범위를 좁힌다)

- 행에 `excluded_by`(결정 번호 모양 `P-###`/`D-###`) + `excluded_why`(사유
  1줄)가 **둘 다** 있어야 status 앞머리와 무관하게 닫힘이다.
- 번호 없이 그냥 「없음」·「범위 밖」이라고만 적은 행은 여전히 **열린 행**이다
  (번호 없는 「없음」은 빈 칸과 같은 대접 — P-406).
- **이 턴(P-428)은 그 번호를 쓸 수 있는 자리를 좁힌다**: `excluded_by` 는
  오직 (a) **운영 집행**(예: 실제 키 회전 집행, 실제 배포 되돌리기 실행)이나
  (b) **외부 기관 실연동**(예: 산림청 앱 실제 푸시, 실제 인증기관 발급, 실제
  타 시스템 이관)에 해당하는 부분에만 붙인다. 그 밖의 사유(화면 미배선·값
  안 읽힘·홈카드 없음·선언≠설정 등)는 `excluded_by` 로 빼지 않는다 — 코드
  결손이므로 정직하게 열린 행으로 남긴다.

## 4. 대조 방법 (턴 AO N1 §2 그대로)

절마다 ① `docs/agent/roadmap/기능명세_미포함표_20260925.md` + 명세 원문
(`docs/design/DSM_재난안전관리App_명세서_v1.1_*.md` ·
`FWS_산불감시App_명세서_v1.0_*.md` · `GuardianX_플랫폼구조설계서_v1.0_*.md`)
에서 제목·완결조건을 위 §1 일곱 종류로 쪼개고 ② 기존 evidence json
(`request`/`response`/`what`) ③ 구현 서비스 파일(대개 머리말에 ★ 로 미비를
스스로 적어 둔다) ④ 시험 코드를 대조한다. 각 절의 `retro` 칸에 사람 확인
1줄을 남긴다(누가 · 언제 · 무엇을 대조했나). **채워 넣지 않는다** — 닫힌
부분은 닫힘으로, 못 채운 부분은 정직하게 열어 둔다. 하나라도 열려 있으면
그 절은 반쪽이다.

## 5. 자기시험 짝 (O 게이트가 이 문서를 읽는 것 자체를 시험한다)

`scripts/verify_spec_title_parts.py --self-test` 안에 이 문서에 대한 짝이
있다: ① 문서의 목록 == 코드 상수 → ok ② 목록이 코드 상수와 다르면(글자 하나
빠져도) → red ③ 문서를 아예 못 읽으면(파일 없음·목록 줄 모양이 바뀜) → grey.
사람마다 다른 눈금을 쓰는 것이 0 이 되도록, 이 문서를 고치면 반드시
`CLOSED_PREFIXES` 도 같이 고치고(또는 그 반대), 자기시험을 다시 돌린다.
