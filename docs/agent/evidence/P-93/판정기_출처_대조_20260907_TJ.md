## 0. 뿌리 교훈 (출생 표본)

`OPS-13a` 는 턴 D 에 「구현」으로 닫혔고 **그 뒤 두 턴 동안 판정기가 회색**이었다.

판정기는 여전히 `/var/log/nginx/gx-front.access.log` **파일**을 열고 있었다.
읽을 자리를 고치자 곧바로 빨강(502 13건 · 미설명 7)이 났다.

> **판정기가 읽는 출처 ≠ 앱이 쓰는 출처.** 한쪽을 고치면 다른 쪽이 눈이 먼다.
> 그리고 **닫힌 절 위에서 판정기가 눈이 멀면 아무도 그것을 모른다.**

## 2. 어떻게 쟀나 (재현 가능한 방법)

1. **정적 해석** — 각 스크립트를 `ast` 로 파싱하고 **모듈 상수 심볼표**를 세워
   `ROOT / "docs" / …` 같은 `Path` 연산을 실제 경로로 접었다(3회 고정점 반복).
   문자열 정규식만으로는 `EVIDENCE / "route_baseline.txt"` 를 못 편다 — 그래서 심볼표를 세웠다.
2. **출처 갈래 다섯**으로 나눴다: 저장소파일 · 스냅샷(증거 JSON/YAML/TXT) · 컨테이너파일 · HTTP · DB/Django.
3. **실재 대조** — 저장소 경로는 `Path.exists()`, 컨테이너 경로는 `docker exec <c> ls`,
   HTTP 는 **호스트와 컨테이너 양쪽에서** 한 번씩 두드렸다(★ 이 「양쪽」이 §3-2 를 잡았다),
   스냅샷은 `mtime` 과 **살아있는 실측본**을 나란히 놓았다.
4. **실행** — 어긋남이 의심되는 판정기는 실제로 돌려 색을 받았다(읽어서 답하지 않는다 · D-210).

재현하는 명령 (정본):

```
MSYS_NO_PATHCONV=1 docker exec gx-nginx-e ls -la /var/log/nginx/
MSYS_NO_PATHCONV=1 docker exec gx-nginx-e sh -c "grep -rn access_log /etc/nginx/"
MSYS_NO_PATHCONV=1 docker exec gx-shell    sh -c "ls -ld /backup"
MSYS_NO_PATHCONV=1 docker exec gx-celery-e sh -c "ls -ld /backup"
MSYS_NO_PATHCONV=1 docker exec -w /repo -e GX_COMMIT=<HEAD> gx-shell \
    python scripts/verify_bundle_hash.py --web http://localhost:3002
python scripts/verify_tenant_scope.py
netstat -ano | grep -E ":8000|:8010|:3002|:8500"
```

**두 표의 차 = 99경로.** 즉 D-272 칸은 지난 16일에 생긴 99개 라우트를 **한 개도 못 본다.**

→ **회색이어야 한다.** 사유 `SNAPSHOT_STALE`.

### 3-2. ★★ `verify_bundle_hash.py` — `SOURCE_SPLIT` · **양쪽을 합치면 빨강이었다**

이 판정기는 **두 가지**를 나란히 놓아야 판정한다: ① 서버가 내는 번들의 `GX_COMMIT` ② 지금 커밋.
그런데 그 둘이 **서로 다른 기계에 산다**:

| 어디서 도나 | ① 번들(`http://localhost:3002`) | ② 커밋(`.git/HEAD` · `docs/agent/evidence/deploy`) | 색 |
|---|---|---|---|
| 호스트 | **못 읽는다** — 호스트에 3002 포트가 없다(`gx-fe-build` 는 `3002/tcp` 를 게시하지 않는다) | 읽는다 | 회색 |
| `gx-shell` 안 | 읽는다 | **못 읽는다** — `/repo` 에 `.git` 도 `docs/` 도 마운트되지 않는다 | 회색 |

**어느 자리에서도 둘을 함께 볼 수 없다.** 그래서 이 판정기는 **구조적으로 회색**이었다.

양쪽을 손으로 이어 붙였다(컨테이너 안에서 `GX_COMMIT` 을 넣어 준다):

```
[BUNDLE] X 번들 해시 = 현재 커밋   번들 abbdf36 != 현재 778dad3
         — 서버가 내는 것은 지금 코드가 아니다.
[BUNDLE] 실패 — 화면에서 본 것을 「병합된 코드」라고 부를 수 없다 (P-59)
```

> **3002 의 SPA 는 지금 HEAD 가 아니라 직전 커밋 `abbdf36` 을 내고 있다.** [실측]
> 판정기가 양쪽 어디서도 눈을 못 떴기 때문에 **아무도 이것을 몰랐다.**
> 화면 캡처·점검표가 이 번들을 보고 있다면 그것은 「병합된 코드」가 아니다(P-59).

### 3-3. `ops_log_collectors.py` — `SOURCE_MISSING` · ⑤칸이 「없어서 초록」

```
CONTAINER_FILE_LOGS = {"gx-nginx-e": ("/var/log/nginx/gx-front.access.log",)}

$ docker exec gx-nginx-e ls -la /var/log/nginx/
access.log -> /dev/stdout      <- 그 이름의 파일은 없다
error.log  -> /dev/stderr
$ grep -rn access_log /etc/nginx/gx/gx-front.conf
66:  access_log /dev/stdout gx;
```

수집 코드는 그 자리를 **조용히 건너뛴다**:

```
rc, out, _ = docker("exec", cname, "sh", "-c", "test -f %s && ... wc -c < %s" ...)
if rc != 0 or not out.strip().isdigit():
    continue                       # 없으면 **없다고** 세지 않는다
```

그래서 ⑤ 「멈춘 파일 잔재」 칸이 `OK · 멈춘 채 남은 파일이 없다` 를 낸다.

**지금 이 초록은 틀리지 않았다** — 앞단은 정말로 stdout 으로 가고, 그 stdout 수집기는
`--log-opt` 상한이 걸린 채 ③④ 칸에 제대로 세어져 있다. 문제는 **다른 데** 있다:

> `CONTAINER_FILE_LOGS` 는 이제 **죽은 자리를 가리키는 지도**이고,
> 그 자리가 죽었다는 사실이 **출력 어디에도 안 나온다.**
> 앞단이 다시 파일로(이름을 바꿔서든) 돌아가면 이 판정기는 또 눈이 먼다 —
> **OPS-13a 가 두 턴 동안 눈이 멀었던 그 모양 그대로.**

`continue` 는 「없음을 확인했다」와 「못 읽고 넘어갔다」를 같은 침묵으로 만든다.
**못 읽은 자리는 이름을 남겨야 한다**(`verify_front_line_502` 가 §3-9 에서 하는 것처럼).

  둘의 할 일은 같다 — 도장을 읽고 창을 두고, 낡으면 exit 2.

### 3-11. ★★ `verify_delta.py` — `HEAD_NOT_SEEN` · **Q 자신의 판정기가 같은 병이었다 (고쳤다)**

전수 점검이 **점검하는 사람의 손 안**에서도 하나를 잡았다.

`verify_delta.py` 는 기준선의 가장 최근 두 점을 견준다. 그런데 `BASELINE_STALE`
(「뒤 점이 HEAD 가 아니다」)을 **빨강일 때만** 붙이고 있었다:

```
if moved and head and new_c != head:      <- moved = 문턱 밖으로 움직였을 때만
    found.add("BASELINE_STALE")
```

그래서 **낡은 두 점이 서로 조용하면 초록**이 났다:

```
[DELTA] 갈래 backend-unit — e96ab7d(09-06T10:45) → abbdf36(09-06T13:39)
[DELTA] 초록 — 셋 다 ±20% 안이고 오류가 늘지 않았다        <- HEAD 는 778dad3 다
```

**지금 코드를 한 줄도 안 보고 낸 초록이다.** §0 의 그 모양 그대로 —
읽는 자리가 지금이 아닌데 색은 초록.

**고쳤다**(이 파일은 Q 소유다): 가장 최근 점의 커밋이 HEAD 가 아니면 **회색(exit 2)**.
`HEAD` 를 모를 때는 회색을 짓지 않는다(없는 사실을 짓지 않는다). 자기시험 갈래 셋을 넣었다.

같은 파일에서 함께 고친 것 둘:

| 무엇 | 왜 |
|---|---|
| `dirty_files` — 잰 순간 작업본이 몇 파일 더러웠는지를 **점과 함께** 적는다 | 종전 `DIRTY_RUN` 은 「두 점의 커밋이 같은데 수가 달라졌다」로만 잡혔다. **커밋이 움직인 위에 미커밋 작업본이 얹힌 오염**은 `REAL_REGRESSION`(코드가 원인일 자리)으로 잘못 이름 붙었다 — 할 일이 갈린다(「고친다」 ↔ 「다시 돌린다」). 모를 때는 `-1`(0 ≠ 모른다) |
| `--baseline-note` — **점은 안 적고 사유만** 적는다 | 턴 I 는 오염된 벌을 적지 않기로 옳게 정했는데, 사유를 남길 길이 「적으면서 다는 것」뿐이었다. 안 옮기기로 한 것도 판단이고, 판단과 사유는 같은 자리에 있어야 한다 |

### 3-9. ★ 반대 예 — 고쳐진 자리는 이렇게 생겼다

`verify_front_line_502.py` 는 턴 I 에 고쳐졌다:

```
#: 파일이 있으면 파일, 없으면 `docker logs`. 둘 다 없으면 여전히 회색이다.
#: ⚠ 회색을 초록으로 바꾼 것이 아니다 — 읽을 자리를 하나 더 안 것이다.
```

**이것이 P-93 의 출생 표본이다.** 「읽을 자리를 둘 다 본다 · 둘 다 없으면 회색」 — 이 모양을
§3-1~3-3 에 그대로 옮기면 세 자리가 닫힌다.

두 번째 반대 예 — **신선도 창을 가진 판정기**는 이렇게 생겼다:

```
scripts/verify_write_auth.py
  ⑤ **증거 신선도**  낡은 증거로 내는 초록은 아무것도 재지 않은 것이다 (D-301)
  stamp = payload.get("measured_at")        <- 스냅샷이 자기가 언제 났는지 말한다
  자기시험: measured_at="2020-01-01…" 을 넣으면 잡는가 (음성 대조)
```

`write_surface.json` 은 `measured_at` 을 **스냅샷 자신이** 들고 있고, 판정기는 그것을 읽어
창 밖이면 색을 내리며, **자기시험이 낡은 스냅샷으로 음성 대조까지 한다.**
§3-1 의 `openapi_routes.json` 에는 그 셋이 하나도 없다 — 스탬프도 · 창도 · 음성 대조도.
**스냅샷을 읽는 판정기는 이 셋을 가져야 한다.**

## 6. 이 표가 놓친 것 — 정직하게

1. **정적 해석이 못 펴는 자리가 있다.** 런타임에 만들어지는 경로(`EVIDENCE / stamp / "steps.md"` 등)는
   `<expr>` 로 남아 대조하지 못했다. 그런 자리는 이 표에서 **초록으로 세지 않고** 대표 출처만 적었다.
2. **96종 전부를 돌려 보지는 않았다.** 어긋남이 의심되는 것만 돌렸다(§2 ④). 돌리지 않은 판정기의
   「초록」은 **「읽는 자리가 실재한다」**는 뜻이지 **「그 판정이 통과했다」**는 뜻이 아니다. 두 낱말을 섞지 않는다.
3. **DB 를 읽는 43종의 「지금 것인가」는 재지 않았다.** 스레드에 남은 요청·응답 캐시가 만드는 거짓 초록은
   이 표의 축이 아니다 — 별도 절이다.
4. **`scan_*.py` · `check_*.py` · `walk_*.py` 는 대상 밖이다** (턴 J 지시서가 셋으로 좁혔다).
   그쪽에도 같은 병이 있는지는 **재지 않았다** — 다음 턴의 자리다.

## 7. 관측 — **판정 도중에 색이 움직였다** (P-85 축 · Q 는 고치지 않는다)

같은 판정기를 이 턴에 두 번 불렀고 **색이 달랐다.** 코드가 아니라 **대장이 움직였다**:

| 부른 때 | `verify_ga_readiness.py` | 내용 |
|---|---|---|
| 16:0x | **회색 exit 2** | 색이 같다 24 · **못 쟀다 2** (`PERF-04` · `LAW-02a`) |
| 16:2x | **빨강 exit 1** | 색이 같다 24 · 못 쟀다 **1** (`PERF-04`) · **FAIL `OPS-13a`** |

빨강의 문장:

```
FAIL OPS-13a: 게이트 «scripts/verify_front_line_502.py» 가 **초록**인데
              대장은 '미착수' 다 — 다 해 놓고 안 적었다 (P-85 방향 ①)
              <- 게이트 마지막 줄: 판정 **통과** (exit 0)
```

두 가지를 그대로 적는다(고치지 않는다 — `ga_readiness.yaml` 은 Q 의 손 밖이다):

1. **`OPS-13a` 절이 이 턴 도중 대장에서 「미착수」로 되어 있다.** 게이트는 초록이다.
   턴 J 브리핑은 이 절을 「턴 D 에 구현으로 닫혔다」고 적었다 — **대장과 브리핑과 게이트가 셋 다 다르다.**
2. **`verify_front_line_502.py` 는 지금 `exit 0` (통과)** 다. 브리핑이 적은
   「읽을 자리를 고치자 곧바로 빨강(502 13건 · 미설명 7)」과 **색이 다르다.**
   그 빨강은 그때의 창에서 난 것이고 지금 창은 다른 수를 낸다 — **다시 재야 한다.**

> ★ 이것이 §0 의 교훈과 같은 가족이다. 그때는 **판정기가 낡은 자리를 읽었고**,
> 여기서는 **대장이 게이트보다 낡았다.** 어느 쪽이든 「닫혔다」는 말과 실제가 갈린다.
> 다만 이번에는 `verify_ga_readiness` 가 **그 갈림을 스스로 빨강으로 냈다** — P-85 가 일했다.
