# P-59 규약 — **서버가 내는 번들 = 현재 커밋** (QA/E2E 차선이 읽을 규약)

- 발행: 2026-09-05 · 턴 E · 차선 Q(QA/E2E) · 판정기 `scripts/verify_bundle_hash.py`
- ⚠ **이 파일은 Q 의 절이다.** Frontend 차선은 같은 폴더에 **자기 파일**로 적는다.
  두 절이 어긋나면 **구현이 정본**이고, 그때는 이 파일과 게이트를 함께 고친다.
- 착수 시각에 이 폴더는 **비어 있었다** [실측 2026-09-05 10:4x · `ls` 결과 없음].
  그래서 Q 가 **먼저 규약을 정하고** 판정기를 그 규약에 맞춰 세웠다.
  → **조율자 배선 필요: Frontend Agent 와 아래 ①의 토큰 문자열을 맞출 것.**

---

## 0. 무엇을 막는가

턴 D 에 프런트 빌드 컨테이너가 **낡은 사본**을 묶었고 `exit 0` 이 났다.
사람은 그 0을 「병합된 코드가 선다」로 읽었다.

> **빌더의 종료 코드는 산출물의 신원이 아니다.**
> `vite build` 의 0 은 「이 소스로 묶는 데 실패하지 않았다」이지
> 「그 소스가 지금 커밋이다」가 아니다. 두 문장 사이의 틈이 이 사고의 크기다.

틈은 **산출물을 물어야만** 메워진다. 그래서 번들이 스스로 자기 커밋을 말하게 한다.

## 1. 규약 셋

### ① 엔트리 JS **안에** 리터럴 토큰 — 이것이 정본이다

```
GX_COMMIT:<40자리 소문자 16진>
```

- 예: `GX_COMMIT:3d40cf66411a22ec7d93501f4665781435ace788`
- 자리: `index.html` 이 부르는 JS **어느 덩이든** 좋다.
  판정기는 `<script src>` 와 `<link rel=modulepreload href=*.js>` 를 **둘 다** 훑는다
  (코드 쪼개기로 `router-*.js` 쪽에 들어가도 찾는다).
- 만드는 법(제안 · Frontend 소유): `vite.config.ts` 의 `define` 으로
  `__GX_COMMIT__` 를 넣고, 소스에서 그 값을 **문자열에 이어 붙인다.**
  이어 붙인 결과가 번들에 리터럴로 남아야 한다 — 계산으로 만들면 안 된다
  (트리셰이킹·상수 접기가 지우거나 쪼갤 수 있다).
- 값의 출처는 **빌드 시각의 커밋**이다. 빌드 컨테이너가 낡은 사본을 들고 있으면
  그 사본의 커밋이 박히고, **그래서 게이트가 빨개진다.** 그것이 이 규약의 전부다.

### ② 화면 하단에 짧은 7자리 — 사람이 읽는 자리

- 문구: 「버전 `3d40cf6`」 (세종 P-59 · 고객 지원이 전화로 묻는 자리다)
- 이 갈래는 **브라우저가** 확인한다(`capture_screens` 의 화면 캡처).
  `verify_bundle_hash.py` 는 ①만 판정한다 — 화면을 안 열기 때문이다.
- ⚠ 사람에게 7자리를 보이되 **판정은 40자리로** 한다. 7자리는 다른 커밋과
  부딪힐 수 있고, 부딪히는 신원은 신원이 아니다.

### ③ `version.json` 같은 곁파일은 **정본이 아니다**

- 두어도 좋다. 두면 판정기가 **①과 같은 말을 하는지**만 본다.
- 곁파일만 새로 쓰이고 JS 는 낡은 채로 남는 것이 **정확히 P-59 사고의 모양**이다.
  그래서 곁파일이 새 커밋을 말하고 번들이 낡았으면 **빨강**이다.
- 모양(있을 때): `{"commit": "<40hex>", "built_at": "<ISO8601>"}`

## 2. 왜 접두 토큰인가 — **맨 40자리 16진을 찾으면 안 된다**

[실측 2026-09-05 · `/app/_fe_dist/assets/index-BaRLuf6q.js`] 지금 번들에서
`[0-9a-f]{40}` 은 이미 **두 군데** 걸린다:

```
3025850929940456840179914546843642076011
0148862877297603332790096757260967735248
```

둘 다 **숫자 상수**다. 접두어가 없으면 이 게이트는 남의 숫자를 커밋으로 읽고,
그 초록은 아무것도 맞추지 않는다. 자기시험에 이 문자열이 fixture 로 박혀 있다.

## 3. 왜 `git rev-parse` 를 부르지 않는가

- `gx-shell` 은 `backend`·`docs`·`scripts` 만 마운트한다 — **`.git` 이 없고 git 도 없다**
  [실측 2026-09-05 · `docker inspect gx-shell`].
- 하위 프로세스로 git 을 부르면 **어디서 돌리느냐로 답이 달라진다.**
  `.git/HEAD` 는 파일이고 어디서 읽어도 같은 답이다.
- 차례: `GX_COMMIT` 환경변수 → `.git/HEAD` → `refs/…` → `packed-refs`.
  **못 고르면 회색(exit 2)** 이지 초록이 아니다.

## 5. 조율자에게 — 배선 넷

1. **Frontend Agent 와 토큰 문자열 맞추기** — `GX_COMMIT:<40hex>`.
   다른 이름을 이미 정했다면 `scripts/verify_bundle_hash.py` 의
   `TOKEN_PREFIX` 한 줄만 고치면 된다(자기시험이 그 값을 따라간다).
2. **빌드가 커밋을 어떻게 아는가** — 빌드 컨테이너에는 `.git` 이 없다.
   빌드 명령에 `GX_COMMIT=$(...)` 를 넘기는 자리가 `RUNBOOK_로컬기동.md` 의
   「빌드 컨테이너 재생성 한 줄」 옆이다(세종 P-59 가 요구한 그 줄).
3. **게이트를 어느 대상에 걸 것인가** — 본줄기는 `--web`(서버가 내는 것)이다.
   `--dist` 는 곁길이다. SPA 3002 가 서는 절차가 정해지면 `--web` 으로 옮긴다.
4. **화면 하단 7자리**는 Frontend 소유 · 확인은 `capture_screens` 캡처.

## 6. ★ 이 턴에 실제로 잡힌 것 — **3002 가 내는 번들은 2026-09-04 사본이다**

게이트를 세우자마자 **본줄기**(`--web`)로 물었다. `gx-shell` 안의 SPA 서버
(`/tmp/spa_server.py` · `ROOT = /app/_fe_dist`)가 내는 번들은:

```
/app/_fe_dist/assets/*.js   mtime 2026-09-04 07:17:25 +0000   [실측]
```

현재 커밋 `3d40cf6`(턴 D)보다 **하루 이상 앞선 사본**이다. 번들 안을 글자로 확인했다:

| 문구 | 소스(현재) | **번들(3002 가 내는 것)** |
|---|---|---|
| `W1 프리셋` (절 ID · UX-20 에서 뺐다) | 없다 | **있다** ← 낡음 |
| `미처리 — 아직 아무도 손대지 않은 것` (현재 안내 줄) | 있다 | **없다** |
| `지금 처리할 것 — 가장 급한 하나` (FocusQueue 머리) | 있다 | **없다** |
| `카메라 주소 채우기` (UX-02 · 턴 C 화면) | 있다 | **없다** |

**그래서 이번 턴의 화면 증거는 전부 「9-04 번들」의 증거다.** 이 사실을 안 적으면
다음 사람이 그 캡처를 「병합된 코드가 이렇게 생겼다」로 읽는다 — 턴 D 와 **같은 오독**이다.

### 이것이 곧바로 세 가지를 뒤집는다

1. **`capture_screens` 의 빨강은 화면 결함이 아니었다.** 17번
   (`/dsm/events?preset=unhandled`)이 기다린 문구가 번들에 없어 멈췄다.
   문구가 없는 이유는 화면이 잘못돼서가 아니라 **번들이 낡아서**다.
   → 이 게이트가 없었으면 이 빨강은 「UX 문구 회귀」로 등재됐을 것이다.
2. **온보딩 48행(P-60)은 「소스에 있다」까지다.** U5 #5 `/dsm/cameras/address` 는

   않는다.** 「구현됐다」와 「지금 사용자가 쓸 수 있다」는 다른 문장이다.
3. **점검표 56칸의 상한이 여기서 정해진다.** 낡은 번들을 눌러 칸을 채우면
   **없어진 제품을 점검한 표**가 된다. 그래서 이번 턴 점검표는
   「9-04 번들에서 눌렀다」로 못박고, 재빌드 뒤 다시 채우는 것이 옳다.

### 조율자에게 (다섯째 배선)

5. **`/app/_fe_dist` 재빌드 + SPA 서버 재기동**이 P-59·점검표·온보딩 세 가지의

## 7. Frontend 차선과 맞춰졌다 — **배선 1·2·4 닫힘** [실측 2026-09-05 · 턴 E 후반]

같은 폴더에 `구현_프런트.md` 가 들어왔다. 착수 시각에 폴더가 비어 두 차선이 각자
규약을 정했고, 맞춰 보니 **Frontend 가 C 안(머리표 · 7자리 · 접두어 없음)을 접고
이 문서의 규약 ①을 그대로 채택**했다. `TOKEN_PREFIX` 는 **고치지 않았다.**

| 배선 | 상태 |
|---|---|
| 1. 토큰 문자열 맞추기 | **닫힘** — `GX_COMMIT:<40hex>` 양쪽 같다 |
| 2. 빌드가 커밋을 아는 법 | **닫힘(문서)** — `-e GX_COMMIT=$(git rev-parse HEAD)` 세 줄이 `구현_프런트.md` §2 에 있다. RUNBOOK 등재는 조율자 |
| 3. 어느 대상에 걸 것인가 | **열림** — 본줄기 `--web` 은 재빌드·재배치 뒤 |
| 4. 화면 하단 7자리 | **닫힘(규약)** — 확인은 재촬영. ⚠ 「버전 3d40cf6」을 **통짜로 grep 하면 언제나 못 찾는다**(템플릿으로 이어 붙인다) — 그 빨강은 확인하는 쪽의 오답이다 |
| 5. `/app/_fe_dist` 재빌드·재기동 | **열림 · 이번 턴 최대 잠금** |

### Q 가 독립으로 다시 잰 것 — **양쪽 방향이 다 선다**

Frontend 는 `--web` 을 못 쟀다(라이브 세션 한 자리가 Q 것이었다). Q 가 그들의
산출물을 꺼내 **호스트에서 직접** 돌렸다 — 남의 보고를 옮겨 적지 않는다:

```
docker cp gx-fe-build:/app/dist_te <scratch>/dist_te
python scripts/verify_bundle_hash.py --dist <scratch>/dist_te
  현재 커밋 3d40cf66411a22ec7d93501f4665781435ace788 ← .git/refs/heads/master
    번들이 자기 커밋을 말한다   `GX_COMMIT:3d40cf6…` ← /assets/index-HJjiVC5m.js
    번들 해시 = 현재 커밋      3d40cf6 = 3d40cf6
  통과 — exit 0
```

| 대상 | 결과 |
|---|---|
| Frontend 의 새 번들 `dist_te` | **exit 0 · 초록** |
| 지금 3002 가 내는 `/app/_fe_dist` (9-04 사본) | **exit 1 · 빨강** |

**같은 게이트가 하나에 초록, 다른 하나에 빨강을 낸다.** 아무것에나 초록을 내는
물건이 아니라는 것이 뒤엣줄이고, 규약이 실제로 만족될 수 있다는 것이 앞엣줄이다.
