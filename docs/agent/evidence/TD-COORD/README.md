# 턴 D 조율자 선등록 — 쓰기 면과 낱말을 **턴 머리에서 한 번** 고친다

- 기계 시각 2026-09-05 · 턴 부호 `20260905_TD` · 작성 Code(조율자)

## 왜 선등록인가

이 턴에도 차선 넷이 동시에 돈다. 새 화면 셋(월 모드 · 카메라 격자 · 열람·삭제 청구)은
저마다 `routes.ts` 와 `App.tsx` 를 고쳐야 하는데, 그 둘은 **넷이 같이 쓰는 자리**다.
넷이 각자 고치면 충돌하고, 충돌한 쪽은 대개 **경로 문자열**이며 그 충돌은
**라우팅 침묵**으로 나타난다 — 화면이 안 뜨는데 오류도 안 난다
(`frontend/src/features/dsm/routes.ts` 머리말이 이미 적어 둔 함정이다).

그래서 조율자가 **먼저 한 번** 고치고, 차선은 자기 파일 안에서만 산다.

| 선등록한 것 | 자리 |
|---|---|
| 경로 셋 (`/wall` · `/dsm/cameras/grid` · `/dsm/privacy-requests`) | `frontend/src/features/dsm/routes.ts` |
| 지연 임포트 셋 + 라우트 등재 셋 | `frontend/src/App.tsx` |
| 화면 자리표 셋 (`Wall.tsx` · `CameraGrid.tsx` · `PrivacyRequests.tsx`) | `frontend/src/features/dsm/pages/` |
| 낱말 19 (턴 D 추가) | `docs/design/GX-COPY_v1.md` §5 |

## ★ 자리표에 대한 규약 — 초록으로 세지 않는다

세 자리표는 「준비 중입니다」 한 줄만 그린다. **병합 뒤에도 그 글자가 남아 있으면
그 절은 닫히지 않은 것이다.** 병합 검사에 그 글자를 찾는 한 줄을 넣는다:

    grep -l "준비 중입니다" frontend/src/features/dsm/pages/{Wall,CameraGrid,PrivacyRequests}.tsx

빈 화면이 경로에 붙어 있는 것은 **게이트가 잡지 못한다** — `verify_screens.py` 는
캡처 목록의 메타와 시각을 대조할 뿐 화면 안이 비었는지 보지 않는다. 그래서
사람이 잊지 않게 **여기 한 줄로 적어 둔다.**

## ★ 걸으면서 잡은 것 — `/wall` 은 사이드바 밖에 설 수 있는가

월 모드는 사이드바 없이 서야 한다(대형 화면에는 마우스가 없다). 그래서 `/wall` 을
`PrivateLayout` 의 **직계 자식**으로 두었다 — `Sidebar` 의 형제다.

그런데 `PrivateLayout` 은 `Outlet` 을 직접 그리지 않는다:

    const PrivateLayout = () => (<><PrivateRouter redirectPath="/login" /> … </>);

**만약 실제 `Outlet` 이 `CustomSidebar` 안에만 있었다면**, 사이드바 밖에 둔 이 경로는
아무것도 안 그리고 **오류도 안 낸다** — 이 저장소가 이름 붙여 둔 라우팅 침묵 그 자체다.
가정하지 않고 **번들을 열어 읽었다** [실측 2026-09-05]:

    frontend/node_modules/rj-core/dist/rj-core.es.js:9
      import { …, Outlet as ye, … } from "react-router-dom";
    같은 파일 68081 행 (PrivateRouter 의 반환문 끝)
      /* @__PURE__ */ s.jsx(ye, {})

`PrivateRouter` 가 `Outlet` 을 그린다. 따라서 `/wall` 은 **관문을 지나고 사이드바 없이**
그려진다. `rj-core` 는 §0.4 금지구역이라 고칠 수 없고, **읽는 것은 금지가 아니다.**

> 재지 않고 「형제로 두면 되겠지」로 넘어갔으면, 이 절은 화면이 흰 채로 초록이 났을 것이다.

## 시험 실행 규약 — 차선 넷에 정정 전달

내가 처음 차선들에 준 명령에 `--nomigrations -p no:randomly` 가 빠져 있었다. 대조 [실측]:

| 명령 | 결과 |
|---|---|
| `pytest tests/test_dsm_app.py -q --nomigrations -p no:randomly` | **34 passed · 10.52초** |
| 같은 명령에서 두 조각을 뺀 것 | **34 errors · 122.74초** (`KeyError: 'multilanguage'`) |

같은 코드다. 뒤엣것은 **실패가 아니라 환경 미비**이고(dj-core `logger/0009` 가 의존을
선언하지 않는다 · §0.4 · OPS-03 이 우회층으로 남긴 자리), 34 errors 처럼 보인다.
`backend/pytest.ini` 가 이미 그 착각을 경고해 두었는데도 조율자가 그 자리에서 두 번 헛돌았다 —
**경고를 적어 두는 것과 읽는 것은 다른 일이다.**

한 가지 더: 이 저장소는 배경 스레드가 시험이 끝난 뒤에도 stderr 로 로그를 토한다.
`| tail` 로 읽으면 **pytest 요약 줄이 그 잡음에 밀려 안 보인다** — `2>/dev/null` 을 붙인다.

# 병합 (조율자 · 2026-09-05 턴 D)

## ★ 게이트가 빨개졌고, 빨갛게 만든 것은 차선이 아니라 **나**였다

병합 첫 판정에서 `contract-route-reach` 가 **9건 404** 로 빨갰다. 새 라우트 아홉이
「선언은 됐는데 배선에 없다」로 읽혔다 — 차선 둘의 일이 통째로 안 붙은 것처럼 보였다.

그것이 아니었다. **서버가 옛 코드를 물고 있었다.** 재기동하니 아홉 전부 401(문지기가
섰다 · 도달)로 바뀌었다. 여기까지는 흔한 일이다. 값이 나간 것은 그 다음이다:

재기동한 뒤 **다른 자리 둘이 새로 빨개졌다** — 스냅샷 문과 미디어 목록이 503.
원인은 내가 서버를 **MinIO 자격증명 없이** 띄운 것이었다. 원래 떠 있던 프로세스는
누군가 자격증명을 손으로 얹어 띄운 것이었고, **그 기동 절차는 어디에도 적혀 있지 않았다.**

> **게이트가 두 턴 동안 초록이었던 것은 그 프로세스가 죽지 않았기 때문이다.**
> 죽는 날 아무도 다시 못 세운다 — 그리고 그날은 「어제까지 초록이던 게이트가
> 갑자기 빨갛다」로 보인다.

되띄운 명령(값은 적지 않는다 · 근거는 `scripts/ops_patrol.py:124`):

    docker exec -d -e MINIO_ENDPOINT=minio:9000 \
        -e MINIO_ACCESS_KEY=<뿌리 .env 의 MINIO_ROOT_USER> \
        -e MINIO_SECRET_KEY=<뿌리 .env 의 MINIO_ROOT_PASSWORD> \
        -e DJANGO_SETTINGS_MODULE=config.settings gx-shell \
        sh -c 'cd /app && python manage.py runserver 0.0.0.0:8000 --noreload > /tmp/gate8000.log 2>&1'

신선도 창(24시간) 안이면 초록이 나므로, 이 게이트는 **한 턴 동안 구조적으로 눈이 먼다.**

**신고하고 넘은 것과 몰래 넘은 것은 다르다** — 받는다.

## ★★★ 그리고 내가 낸 초록 하나가 거짓이었다 — **빌드가 낡은 사본을 빌드했다**

병합 중에 `vite build` 를 돌려 **exit 0 · 57.42초**를 얻고, 그것을 「병합된 코드가 선다」로
적었다. **틀렸다.**

빌드 산출물이 저장소에 안 들어온 것을 확인하다가 이상해서 마운트를 봤다:

    docker inspect -f '{{range .Mounts}}…{{end}}' gx-fe-build   →  **마운트 0건**
    docker exec gx-fe-build ls /app/src/features/dsm/pages/     →  Wall·CameraGrid·PrivacyRequests **없음**
    docker exec gx-fe-build grep -c wall /app/src/.../routes.ts →  **0**

`gx-fe-build` 의 `/app` 은 저장소를 물고 있지 않다. **자기 사본**이다.
그 사본에는 이 턴에 만든 화면 셋이 **한 장도 없었다.** 즉 그 초록은
「턴 D 코드가 빌드된다」가 아니라 **「턴 C 코드가 여전히 빌드된다」**였다.

    docker cp frontend/src/. gx-fe-build:/app/src/     ← 넣고 다시 빌드했다

> **exit 0 은 무엇이 성공했는지 말해 주지 않는다.** 무엇을 먹였는지 따로 봐야 한다.
> 이 저장소가 이미 아는 문장의 새 얼굴이다 — 「낡은 인벤토리가 게이트를 초록으로
> 만든다」(D-427). 이번엔 낡은 **소스**였고, 같은 병이다.

★ 왜 안 보였나: 빌드는 진짜로 돌았고 시간도 걸렸고(57초) 종료 코드도 0 이었다.
  **실패한 흔적이 어디에도 없다.** 사본이 낡았다는 사실은 산출물 밖에서만 보인다.
  다음 사람을 위해 절차에 한 줄을 못박는다:

> **프런트 빌드 전에 `docker cp frontend/src/. gx-fe-build:/app/src/` 를 먼저 한다.**
> 안 하면 그 빌드는 **직전 턴의 코드를 빌드한 것**이고, 그 exit 0 은 이번 턴에 대해
> 아무 말도 하지 않는다.
