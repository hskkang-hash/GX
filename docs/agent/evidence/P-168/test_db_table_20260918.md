## ⚠ 「CONNECT 회수」는 이 기계에서 **못 한다** — 그리고 그게 더 큰 사실이다

| 사실 | 실측 |
|---|---|
| 이 서버의 로그인 역할 | **둘뿐** — `pgroot`(superuser) · `postgres`(superuser) |
| 앱이 쓰는 역할 | **`postgres`**(`gx-gunicorn-e` 의 `DB_USER=postgres`) — 즉 **superuser** |
| 시험 DB 넷의 소유자 | 전부 `postgres` |
| `REVOKE CONNECT … FROM postgres` 의 효과 | **없다.** superuser 는 `GRANT/REVOKE` 를 통째로 우회한다(문서·구현 모두). 회수해도 붙는다 |

그래서 P-168 의 「접근 차단은 세종」은 **이 상태로는 집행할 수 없다.** 두 가지를 갈라 적는다:

1. **못 한 것** — CONNECT 회수 **0/4**. 회수한 척하고 「차단했다」로 적으면 그것이 거짓 초록이다.
2. **드러난 것(더 무거움)** — **앱이 데이터베이스 superuser 로 붙는다.** 이것은 시험 DB 문제가 아니라
   최소권한 문제다: 앱을 잡은 사람이 곧 DB 전체를 잡는다. 대장 OPS 절에 **새 줄 하나**로 올린다
   (아래 「대장에 올릴 두 줄」 ①).

## 대장에 올릴 두 줄 (세종 판정 요청 — 조율자는 적기만 한다)

① **OPS-14(가칭) 앱 DB 역할이 superuser** — 지금 `DB_USER=postgres`. 닫는 모양: 앱 전용 역할
   `gx_app`(NOSUPERUSER · 앱 DB 에만 CONNECT · 스키마 소유 아님) 을 만들고 앱 env 의 `DB_USER` 를 바꾼다.
   ⚠ env 변경 = 재생성 = **창**(P-167 과 같은 창 2 에 묶을 수 있다) · 실값(비밀번호)은 대표.
② **OPS-15(가칭) 시험 DB 이름 규칙이 절반만 지켜진다** — 넷 중 **둘이 규칙 밖**(`test_database_guardianx` ·
   `…_e2e`). P-168 이 말한 「격리 이름의 기본값은 없다」가 바로 이 자리다: `DB_TEST_NAME` 을 안 주면
   Django 가 **앱 DB 이름 앞에 `test_` 를 붙인 기본값**을 쓴다 — 그 기본값이 규칙 밖 이름을 만든다.
   닫는 모양: `config/settings.py` 의 `TEST NAME` 이 `DB_TEST_NAME` 없을 때 **멈추게** 한다(기본값 금지)
   — 판정기 한 줄 + 시험 1. ⚠ 이 자리는 `backend/config/**` 라 차선 F 소유 → 다음 턴 등록 요청.
