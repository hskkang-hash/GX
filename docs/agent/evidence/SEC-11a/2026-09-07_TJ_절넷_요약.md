## 이 턴에 뒤집힌 「사실」 넷

1. **「권한 거절 계정이 없다」** (세 턴 연속 기록) → `.env.gates` 의 `gxprobe_e2e` 가
   역할 0개 계정이라 `@path_permission` 이 붙은 **모든** 라우트에서 거절된다.
2. **「finally 가 하나씩 모자란다」** (턴 I) → 수는 맞고 **뜻이 틀렸다.** 모자란 자리는
   셋 다 `showLoading()` 을 안 부르는 함수였고 둘은 우리 접두도 아니었다.
3. **「`read_only_in_practice` 5자리는 익명이 핸들러까지 닿는다」** → 넷은 이미
   `@path_permission` 이 막고 있었다. 「닿았다」로 읽힌 이유가 **200 봉투**다 —
   판정기의 병과 제품의 병이 같은 병이었다.
4. **「구역을 만드는 공개 면은 아직 없다」** (census · Zone) → `POST /api/dsm/settings/zones`
   가 실재한다. 그 줄을 쓴 뒤에 생겼고, 판정기가 **2026-08-22 사진**(531라우트)을 들고
   있어 두 달 동안 못 봤다.

```
POST /api/delivery/etri-integration/receive-from-etri     auth= 없음 · @path_permission 없음
  익명 → 400 "Delivery operation with ID 999999999 not found"   ← 핸들러가 실제로 돌았다
  호출 그래프: … → EtriService._update_delivery_status
      delivery_operation.order.status = OrderStatus.objects.get(code='cancelled')
      delivery_operation.order.save()   ·   OrderService.create_order_history(...)
```

익명이 `RECEIPT_ID` 하나로 **남의 배송을 취소**할 수 있었다. 같은 컨트롤러의 **모의**
둘(`etri-mock/*`)은 이미 막혀 있었고 진짜 입구만 열려 있었다.
`backend/delivery/` 는 §0.4 라 라우트를 못 고치므로 `common/access_gate.py` 의
`AUTHN_REQUIRED_PATHS` 로 막았다 — 전 400 → 후 **401** [실측].
