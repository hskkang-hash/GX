## 3. 그 58 을 이번에 안 켠 이유 — **문턱을 수로 쟀다**

턴 F 가 정한 규칙은 「**승격을 정하기 전에 그 화면의 오류 처리를 전부 읽는다**」이다.
읽었다. 그리고 그 규칙이 정한 되돌릴 조건에 지금 걸린다:

```
features/Handover · features/otherEquipments 에서 await 가 있는 파일 19개 중
  **try 가 하나도 없는 파일 11개** [실측 2026-09-06]

  Handover/components/NoticeSlider.tsx                     async 2 · try 0
  Handover/pages/HandoverPage.tsx                          async 2 · try 0
  Handover/pages/tabs/CompletedNotice/CompletedNotice.tsx  async 1 · try 0
  Handover/pages/tabs/HandoverManagement/HandoverManagement.tsx      async 3 · try 0
  Handover/pages/tabs/HandoverManagement/components/ItemCard.tsx     async 4 · try 0
  Handover/pages/tabs/NoticeManagement/AddNoticeManagement.tsx       async 1 · try 0
  Handover/pages/tabs/NoticeManagement/EditNotice.tsx                async 10 · try 0
  Handover/pages/tabs/NoticeManagement/NoticeManagement.tsx          async 1 · try 0
  otherEquipments/AddNewEquipment.tsx                      async 4 · try 0
  otherEquipments/DetailEquipment.tsx                      async 4 · try 0
  otherEquipments/OtherEquipments.tsx                      async 2 · try 0
```

승격하면 거절이 **axios 예외**가 된다. `try` 가 없는 자리에서는 그 예외가 잡히지 않고,
전역 `unhandledrejection`·`window.onerror` 처리기는 저장소에 **0건**이다(턴 F 실측 · 이번에
다시 확인). 그러면 화면은 **스피너가 고착된 채** 멈춘다 — W0-18 §2-1 이 이름 붙인 그 모양이고,
턴 F 가 settings 주석에 적어 둔 **되돌릴 조건 그 자체**다.

즉 이 58의 문턱은 백엔드가 아니라 **프런트의 오류 처리 11자리**다. 턴 F 가 켠 12건은
넷 다 `finally` 로 스피너를 껐기 때문에 켤 수 있었다 — 같은 잣대를 여기에도 댄다.

★ **켜고 나서 화면이 멈추면 그것은 우리가 만든 결함이다.** SEC-11a 의 수를 내리려고
  제품을 나쁘게 만드는 것은 갚는 것이 아니라 옮기는 것이다.
