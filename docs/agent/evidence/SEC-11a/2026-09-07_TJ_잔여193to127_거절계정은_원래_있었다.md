## 0. 왜 세 턴 동안 못 쟀나 — **계정이 없어서가 아니었다**

턴 F·G·I 의 이 문서 계열은 매번 이렇게 끝났다:

> 승격 뒤 화면을 확인하는 갈래: 못 했다 — **권한 거절 계정이 없다.**

없지 않았다. `.env.gates` 의 `gxprobe_e2e`(route-alive 탐침용)가 **역할이 하나도 없는
계정**이다. 그 사실 하나가 모든 것을 잰다:

```
core/role/permission.py :: _check_path_permission
    user_roles = user.roles.all()
    if not user_roles.exists():
        logger.warning(f"User {user.username} has no roles")
        return False        ← 경로·방법과 **무관하게** 거절
```

[실측 2026-09-07] `gxprobe_e2e` id=105 · `is_superuser=False` · `roles=[]`.
그러므로 `@path_permission` 이 붙은 **모든** 라우트에서 이 계정은 거절당한다.
「거절 계정이 없다」는 세 턴의 문장은 **찾아보지 않은 것**이었다.

## 3. 켜기 전에 화면을 줄 단위로 읽었다 — **훅이 경계다**

### `/api/report-template/` 5건 — 막는 것은 제품이 아니라 **계약 시험의 표본 소유**
`backend/tests/test_api_contract.py` 의 `ROUTE_LIST_SCHEMA`(`/api/report-template/`)와

화면 쪽은 안전하다 — `useReportTemplate.ts` 6함수 전부 try/catch/finally.

## 6. 못 쟀다 (회색 — 0 으로 적지 않는다)

- **쓰기 메서드(POST/PUT/DELETE)의 전/후는 안 쟀다.** 같은 데코레이터·같은 무역할 계정이라
  판정이 같다는 것은 **추론**이지 실측이 아니다. 그렇게 구분해서 적는다.
- `…/by-id-management` 두 자리는 승격 전후 모두 **422**다 — ninja 스키마 검증이
  `@path_permission` 보다 먼저 선다. 필수 질의 인자를 채운 자리(`?id=…`)는 뒤집혔다.
- 브라우저로 승격 뒤 화면을 본 갈래는 여전히 못 했다. 화면 쪽 근거는 **원본 줄 읽기**이지
  렌더링 실측이 아니다.
