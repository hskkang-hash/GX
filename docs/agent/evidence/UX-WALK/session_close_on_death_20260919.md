# 걷기가 **도중에 죽어도 세션이 닫히는가** — 실측 (2026-09-19 · 턴 W · 차선 Q · ㉢)

## 왜 쟀나

이 환경은 **계정당 동시 접속 1개**다. 걷기가 세션을 물고 끝나면 다음 사람이 로그인을
못 하거나(또는 앞 사람을 튕기고), 그 튕김이 「화면이 안 뜬다」로 오인된다.

종전 `walk_scenarios.py` 에도 걸음 묶음마다 `finally: _logout(...)` 이 있었다.
그런데 그 `finally` 는 **그 `try` 에 들어간 뒤에만** 돈다 — 로그인은 섰는데 그 다음에
프로세스가 통째로 죽으면(주간 한도 · KeyboardInterrupt · SystemExit · 판정기 밖 예외)
그 자리는 **실행되지 않는다.** 「끝까지 간 판」만 닫히고 「죽은 판」은 안 닫힌다.

## 고친 것

`walk_scenarios.py` 에 **열린 세션 등록부**(`_OPEN_SESSIONS` · `_SESSION_TALLY`)와
`atexit.register(close_open_sessions)` 를 두었다. 로그인 **직전에** 닫는 법을 등록하고,
닫으면 지운다. 프로세스가 어떻게 끝나든 마지막 그물이 남은 것을 닫는다.
그리고 「연 수 · 닫은 수 · **열린 채 N**」 을 세어 판정에 올렸다 — 분모 없는 0 을
초록으로 주지 않는다(한 번도 로그인 안 한 판도 「열린 채 0」이다).

## 눌러서 본 것 — **세 가지 죽음, 열린 채 끝난 것 0/3**

세션 하나를 열어 둔 채 프로세스를 세 가지로 죽였다(닫히면 파일에 `CLOSED` 를 남긴다):

```
exception  → exit=1    · 세션 닫힘 = CLOSED
sysexit    → exit=3    · 세션 닫힘 = CLOSED
interrupt  → exit=130  · 세션 닫힘 = CLOSED
```

**음성 대조**(등록부를 안 지나고 같은 자리에서 죽인 판):

```
등록 없음  → 세션 열린 채   ← 이것이 종전 모양이다
```

그리고 `--self-test` 안에서 등록부를 **직접 눌렀다**: ① 남은 세션을 마지막 그물이
닫는가 ② 닫기가 **예외를 던지는** 세션을 「열린 채」로 세는가 — 둘 다 선다.

## 아직 못 한 것 (정직하게)

**살아 있는 걷기를 다시 돌리지 않았다.** 걷기의 임자는 `gxseed_u4_official` 이고,
같은 계정을 턴 W 의 U3 창(17:47~18:10)과 U24 창(18:15~19:00)이 쓴다 — 동시 접속 1개라
겹치면 둘 다 튕긴다. 그러므로 위 0/3 은 **기계 수준의 실측**이고, 「살아 있는 걷기가
0건으로 끝났다」는 아직 아무도 못 봤다. 다음 걷기 회차의 `sessions.left_open` 이
그 수다. 판정 줄 이름: 「세션이 열린 채 끝난 것 0」.

# 2차 — **사람 셋으로 걸었더니 1차 고침이 모자랐다** (2026-09-19 18:4x~19:0x · 조율자 실측 → Q 고침)

## 무엇이 났나

조율자가 `deploy.sh` 의 `GX_SEED_ROLE_PASSWORD` 누락을 고치면서, 턴 V 가 P-181 로 등재한
**W5(u2)·W6(u5)** 이 **처음으로 실제로 걸렸다**. 그러자:

```
[WALK]   걷기 5 시나리오를 다 걸었다   완주 5/5
[WALK] X 세션을 닫았다              **세션이 열린 채다.**
[WALK] X 세션이 열린 채 끝난 것 0     연 3 · 닫은 1 · **열린 채 2**
[DEPLOY] **실패(walk exit 1)** — 되돌렸다
```

★ 이 수가 보인 것은 판정 줄이 **분모(연 N)와 함께** 적게 돼 있었기 때문이다.
「닫았다/못 닫았다」 한 칸만 있었으면 **「1 닫았다」로 지나갔다.**

## 왜 1차 고침으로는 모자랐나 — **시험이 하나만 열었다**

1차의 죽는 길 시험은 세션을 **하나만** 열었다. 걷기는 사람 **셋**으로 로그인한다
(W1~W3 `route` · W5 `u2` · W6 `u5`). 하나만 여는 시험으로는 이 결함이 **절대 안 잡힌다.**

## 진짜 원인 둘 — 고치고 나서야 **글자로** 보였다

사유를 적게 해 둔 덕에 한 번 돌려서 둘 다 나왔다:

```
route/gxseed_u4_official: 브라우저 로그아웃 — POST /api/v1/auth/logout → 200
u2/gxseed_u2_manager: **못 닫았다** — 정본 닫기 실패: SynchronousOnlyOperation:
    You cannot call this from an async context - use a thread or sync_to_async.
    (브라우저 길: localStorage.userInfo 에 토큰이 없다 (이 앱은 쿠키에 든다))
```

- **㉠ 브라우저 길이 미덥지 않다.** `localStorage.userInfo` 에 토큰이 없다 — 이 앱은
  토큰을 **쿠키**로 든다. `walk_states.py:774` 가 **턴 G(2026-09-06)에 이미 적어 두고**
  정본(`capture_screens._release_session`)으로 옮겼는데, **이 파일만 옛 길에 남아 있었다.**
  「두 벌을 두면 한쪽이 조용히 아무것도 안 닫는다」(D-369)의 실물이다.
  u4 하나만 200 이 난 것은 그 계정만 우연히 들어맞은 것이다 — **셋 다 미덥지 않았다.**
- **㉡ 정본을 부르는 자리가 틀렸다.** `sync_playwright()` 안은 **비동기 문맥**이라
  Django ORM 의 동기 질의가 거절된다(`SynchronousOnlyOperation`). Django 가 말한 그대로
  **딴 실(thread)** 에서 부르니 선다.

## 고친 것

- 등록부가 **사람 이름을 같이 든다** — 페이지가 죽으면 브라우저 길은 못 쓰고 정본만
  남는데, 정본은 **이름으로** 닫는다.
- 닫기는 **제품 길 먼저, 그 다음 정본**. 둘 다 져야 「열린 채」다.
- 정본은 **딴 실**에서 부른다.
- **어떻게 닫혔는지**를 증거(`session_log`)와 화면에 남긴다 — 조용한 실패가 이 결함을
  한 턴 넘게 숨겼다.

## 변이 시험 — 이 시험이 그 결함을 **실제로** 잡는가

고친 코드에 「브라우저 길이 지면 정본으로 안 넘어간다」(= 종전 모양)를 심고 자기시험을 돌렸다:

```
[WALK] 자기시험 실패 — 판정기를 먼저 의심한다 (D-350):
    ★ 브라우저 로그아웃이 **401 로 지면 정본으로 못 넘어간다** — 이것이 턴 W 에
      「연 3 · 닫은 1 · 열린 채 2」를 만든 그 자리다
    브라우저 길이 진 사유(401)가 **기록에 안 남는다**
    ★ 브라우저 길이 셋 다 져도 정본으로 셋을 닫아야 한다 — 닫은 0 · 열린 채 3
```

그날의 모양(`닫은 0~1 · 열린 채 2~3`)이 그대로 재현된다. 자기시험에 박은 자리 여덟 —
사람 **셋**을 동시에 열고, 브라우저 길을 일부러 지게 만들고, **정본까지 지면 빨강**인지도 본다.
