# P-137 · OPS-13a/b 격리 재측 — 전/후 502 (2026-09-15 · 턴 Q · 차선 E)

판정(RESUME_NEXT §2 P-137): 「nginx `proxy_next_upstream` + 재시도 3 + gunicorn `graceful_timeout` 한 벌로,
격리에서 전/후 502 3,600 중 N → 0 을 잰다 · 본 서버 적용은 다음 턴」.

**결론: N 은 29·33 → 10·11 이다. 0 이 아니다 → OPS-13a 는 잠김 유지.** 다만 OPS-13b 의 모양
(재시도 없이 나가는 502)은 B 에서 **0** 이 됐다 — 남은 502 는 전부 「세 번 다 죽어 가는 워커를 만났다」다.

정본: `iso_20260915T1053Z.json` · 판정기 원문 `judge_20260915T1053Z_{A,B,A2,B2}.md` · 재현 `iso_run.py`
(배관 확인 `iso_20260915T1052Z_smoke.json` · 300 요청).

## 1. 무엇을 쟀나

| | A (전 · 지금 모양) | B (후) |
|---|---|---|
| 앞단 | `nginx/gx-front.conf` 그대로(주석만 걷음) · peer **한 줄** | A 와 한 자리만 다름 · 같은 peer **세 줄** |
| 공통 | `gx-proxy.inc`·`generated/gx-gate.conf` 원본을 읽기전용으로 물림 · `proxy_next_upstream error timeout http_502` · `tries 3` · `timeout 15s` · `non_idempotent` 지시어 0 (`nginx -T`) | 같음 |
| 뒷단 | gx-gunicorn-e 와 같은 이미지·망·환경(이름 50개 · 값 출력 0)·명령 + `--max-requests 50 ±10`(재활용을 자주 일으키려고) · `--graceful-timeout 30`(= `backend/gunicorn.conf.py` 값을 명시) | 같음 · **한 컨테이너를 네 판 내내** |
| 부하 | 익명 GET `/admin/login/` 3,600 · 동시 10 · 격리 부하 컨테이너에서 | 같음 |

순서 A → B → A2 → B2 (nginx 설정 주석이 요구하는 A/B/A 이상).

## 2. 수 [실측]

| 판 | 502 / 3,600 | 500 | 재시도 | 되살림(2xx) | 502 의 모양(`$upstream_addr`) | 재활용(`Autorestarting`/`Worker exiting`) | 속도 |
|---|---|---|---|---|---|---|---|
| A  | **29** | 12 | 171 | 166 | 한 칸 `peer` **25** · `peer, peer` 3 · `peer×3` 1 | 67 / 64 | 26.6 rps |
| B  | **10** | 10 | 195 | 183 | `peer, peer, peer, gx_app` **10** | 67 / 63 | 34.1 rps |
| A2 | **33** | 0 | 192 | 185 | 한 칸 `peer` **26** · `peer, peer` 7 | 70 / 64 | 47.7 rps |
| B2 | **11** | 0 | 215 | 204 | `peer, peer, peer, gx_app` **11** | 68 / 64 | 46.8 rps |

peer 한 줄 **62 / 7,200 = 0.86%** · peer 세 줄 **21 / 7,200 = 0.29%** (−66%). 두 벌씩 같은 쪽으로 갈렸다.

## 3. 읽기

* **가설 확인 — 한 줄이면 새 연결의 실패는 재시도되지 않는다.** A·A2 의 502 62건 중 51건이 `$upstream_addr` 가
  **한 칸**이고 `rt` 0.000~0.02초다(OPS-13b 가 턴 K 에 「왜 어떤 것만 재시도를 안 타는지 못 쟀다」고 남긴 그 모양).
  B·B2 에서 그 모양은 **0/21** 이다. nginx 는 peer 가 하나면 실패한 연결을 놓을 때 남은 시도를 0 으로 만들고,
  예외는 keepalive 로 재사용하던 연결의 오류뿐이다 [가설 · nginx 소스 기억 — 이 표가 그 예측과 맞는다].
* **그러나 3 이 모자란다.** B 의 502 21건은 **전부** 세 peer 를 다 쓰고 `gx_app`(= `no live upstreams` · 앞단 오류로그 10·11건과
  같은 수)으로 끝났다. 셋 다 같은 순간의 죽어 가는 워커 연결을 만났다는 뜻이다. 이 판의 재활용은 **3,600 요청에 67회**
  (54 요청마다 1회 · 워커 넷 × `max_requests 50`)다 — 운영 모양(`200 ±50`)보다 약 네 배 잦다. **운영 모양에서의 수는 재지 않았다.**
* **`graceful_timeout` 은 이 모양의 손잡이가 아니다 [추론].** 502 는 요청이 0.000~0.4초에 끊긴 것이고, `graceful_timeout 30` 은
  「처리 중인 요청을 30초까지 기다린다」다. 두 판 모두 30 으로 같게 두었고, 바꿔서 재지 않았다.
* **500 이 22건 있다(A 12 · B 10 · A2·B2 0)** — 앞단이 아니라 뒷단이 낸 응답이다. 원인을 못 쟀다(격리 컨테이너를 지운 뒤에 봤다).
  502 수에 섞지 않았고 지우지도 않는다 — **회색**.
* 판정기 `verify_front_line_502.py --front gx-nginx-iso --back gx-gunicorn-iso`: A **exit 1**(② 요청 구간 안의 `Worker exiting` 으로
  설명 안 되는 502 1건) · B·A2·B2 **exit 2**(③ 대조 분리 차 24·18·28%p < 30%p — 재활용이 54 요청마다 나면 정상 200 도 72~82% 가 그 옆이다.
  **이 판의 재활용 밀도에서는 음성 대조가 못 가른다** — 판정기의 결함이 아니라 부하 설계의 한계).

## 4. 격리였다는 증거

* 만든 컨테이너 넷(`gx-redis-iso`·`gx-gunicorn-iso`·`gx-nginx-iso`·`gx-load-iso`)을 끝에 지웠다 → 남은 것 **0**.
* 도는 컨테이너 10개의 `StartedAt`·상태·재시작 수가 전/후 **같다**(`untouched_unchanged: true`).
* **DB 쓰기 0**: 요청마다 `CoreLoggingMiddleware` 가 `task_add_log.delay()` 로 감사 쓰기를 싣는다(dj-core `core/logger/middleware.py`).
  iso 뒷단만 `REDIS_HOST` 를 임시 redis 로 돌렸고, 그 브로커에 **14,455건**이 쌓였다가 컨테이너와 함께 사라졌다 —
  공용 브로커(→ `gx-celery-e` → `AuditLogs.objects.create`)로는 한 건도 안 갔다.
* 격리 설정 파일은 `nginx/` 아래가 아니라 `evidence/P-137/iso/` 에 두었다 — `verify_live_freshness` 가 `gx-nginx-e` 를
  `nginx/**.conf` 의 시각으로 재므로(`scripts/verify_live_freshness.py:57·226`), 거기 새 `.conf` 가 생기면 도는 앞단이 「낡았다」로 읽힌다.

## 5. 다음 턴 계획 — 막힌 자리

1. **운영 모양에서 한 번 더**: 같은 `iso_run.py` 를 `MAX_REQ=200 · JITTER=50` 로(한 줄) A/B/A/B. 이 판 밀도의 1/4 이면
   B 는 3,600 당 ~3 이 예상이다 — 0 이라고 적으려면 **그 판에서** 재야 한다.
2. 0 이 안 서면 두 갈래를 A/B 로: ㉠ peer 다섯 줄 + `proxy_next_upstream_tries 5`(GET 만 · `non_idempotent` 은 금지 유지)
   ㉡ 뒷단 쪽 — gthread 워커가 재활용 직전에 받아 둔 연결을 버리는 창(가설). 설정 손잡이가 없으면 코드가 아니라 **판정**으로 올린다.
3. 500 22건의 정체 — 다음 판은 뒷단 로그를 지우기 전에 증거 파일로 떠 둔다(`iso_run.py` 한 줄).
4. 본 서버(`gx-nginx-e`) 적용은 판정대로 다음 턴 — B 모양은 `nginx/gx-front.conf` upstream 에 같은 줄 둘을 더하고 **reload**(재기동 아님).
