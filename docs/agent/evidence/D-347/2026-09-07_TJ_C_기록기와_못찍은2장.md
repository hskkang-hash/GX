## ③ 기록기 — 「`/login` 을 찍었는데 그 화면이 부른 API 가 기록되지 않았다」

### 무엇이 틀렸었나 — **시험이 옳았다**

`tests/test_screens_browser.py::test_captured_screens_and_recorded_routes_agree` 가 빨갰다.
인덱스에는 `/login` 이 **다섯 줄**(턴 I 가 늘린 로그인 실패 다섯 갈래) 있는데
`screen_routes.json` 의 `screens` 에는 `/login` 자리가 **아예 없었다.**

원인은 한 자리다: 로그인 갈래 반복문이 `entries` 에는 다섯 줄을 넣으면서
`api_calls` 는 **한 번도 안 건드렸다**. 화면 스물여덟을 도는 아래 반복문에만
기록 코드가 있었다.

그 빈자리가 왜 위험한가는 시험이 제 이름으로 적어 두었다 —
**기록에 없는 화면 몫만큼 `verify_route_alive` 는 때릴 것을 잃고, 때릴 것이 없는
판정기는 조용히 초록이 된다**(D-301).

### 무엇을 고쳤나 (`scripts/capture_screens.py` — **시험은 한 자도 안 고쳤다**)

1. **로그인 갈래마다 `seen_calls` 를 비우고, 찍은 뒤 그 화면이 부른 것을 `/login` 자리에 합친다.**
2. ⚠ **주입한 응답은 세지 않는다.** L2~L5 의 로그인 응답은 playwright 가 만든 것이고
   **서버에 닿은 적이 없다.** 그것을 「브라우저가 실제로 부른 것」 파일에 적으면
   그 파일이 거짓말을 하고, `verify_route_alive` 가 있지도 않은 상태값을 기준으로 삼는다.
   진짜로 나간 것(L1 의 로그인 거절, 화면이 곁들여 부른 설정 문)만 남긴다.
3. **찍은 화면마다 자리를 만든다 — 비어도.** `main()` 에 그물을 하나 놓았다:
   `entries` 에 있는데 `api_calls` 에 없는 라우트는 **빈 목록 + 사유**로 자리를 만든다.
   앞으로 누가 화면을 늘리며 기록을 잊어도 그 자리가 **눈에 보인다.**
   ⚠ 그 자리는 시험을 **빨갛게** 만든다. 그것이 옳다 — 빈 기록은 통과가 아니다.
4. **자리마다 한 줄 사유**를 `api_notes` 로 남긴다. 목록이 비었을 때 그것이
   「이 화면은 우리 API 를 안 부른다」인지 「기록기가 못 적었다」인지를 가른다.
   가르지 않으면 다음 사람이 그 둘을 같은 것으로 읽는다.

## ④ 못 찍은 2장 — 원인은 **권한(역할)** 이다. 라우트 변경도 시드도 아니다.

직전 턴 기록(`docs/agent/onboarding_48.md` §④): `/roles`·`/survey-profile` 이
기다린 글자(`Add New Role`·`Add New Profile`)를 못 냈고 **우리 한국어 머리줄과 빈 표**만 떴다.

### 갈라 보는 법 — 번들과 계정을 따로 흔들었다

| 무엇을 흔들었나 | 번들 | 계정 | `Add New Role` 이 화면에 | 뜬 것 |
|---|---|---|---|---|
| A. 옛 번들 · 이번 계정 | `abbdf36` @3002 | `gxprobe_e2e` | **있다** | 정상 |
| B. 옛 번들 · 다른 계정 | `abbdf36` @3002 | `gxprobe_v` | **없다** | 「역할 관리 · 관리자 전용 화면입니다」 + 빈 표 |
| C. 이번 번들 · 이번 계정 | 778dad3 @3013 | `gxprobe_e2e` | **있다** (촬영 성공) | 정상 |

`/survey-profile` 도 같다 — B 에서 `Add New Profile` **없음**, 뜬 것은
「조사 프로파일 · 관리자 전용 화면입니다」 한 줄뿐(본문 164자).

**A 가 있으므로 번들(라우트 변경)이 아니다.** 같은 옛 번들에서 계정만 바꾸니 갈렸다.

### 두 계정의 차이 — 한 줄이다 [실측 · 개발 DB]

```
gxprobe_e2e    roles=[]                                    ← 역할이 하나도 없다
gxprobe_v      roles=[(3, code='user', 'Basic system access', is_default=True)]
gxprobe_c      roles=[(3, code='user', 'Basic system access', is_default=True)]
```

즉 **직전 턴이 찍은 계정은 기본 역할 `user`(id 3)를 갖고 있었고, 그 역할에는
`/roles`·`/survey-profile` 의 만들기 권한이 없다.** rj-core 가 그 단추를
`ROLE_PERMISSION` 으로 가리므로 `must_see` 가 화면에 없었다.
역할이 **아예 없는** `gxprobe_e2e` 는 그 가림에 걸리지 않아 단추가 그려진다.
