## 1. 만든 것

| 파일 | 역할 | 상태 |
|---|---|---|
| `scripts/backfill_owner_apply.py` | 적용본 (a)(b) | `py_compile` 통과 · **실행 대기** |
| `scripts/backfill_owner_rollback.py` | 되돌리기 — D-261 의 필수 짝 | `py_compile` 통과 · **실행 대기** |
| `backend/tests/tenant_classification.py` | (b)(c) 선언부 | `py_compile` 통과 · 일관성 대조 통과 |

### 1-1. ★ 적용본은 dry-run 의 분류 로직을 **import 해서 쓴다**

귀속 규칙(R1/R2/R3)·제외 앱(`operation_settings`)·소프트삭제 판정을 **복제하지 않았다.**
복제하면 언젠가 dry-run 과 적용본이 다른 수를 말하고, 그때 **어느 쪽이 진실인지 알 수 없다** —
`tickets.sha256`(D-227) 이 만든 것과 같은 상태다. 그래서 `importlib` 로 같은 모듈을 읽는다.

### 1-2. ★ 적용 거부 가드는 체크박스가 아니라 **파일의 실재**다

D-261 의 조건 3건을 인자로 받고, 하나라도 못 채우면 `exit 2`:

| 조건 | 어떻게 확인하나 |
|---|---|
| (1) dry-run 리포트 (D-209) | `--dryrun-report` 경로가 **실재하는 파일**인지 |
| (2) 사전 백업 (D-002) | `--backup` 이 실재하고 **1MB 이상**인지 — 빈 덤프·실패한 덤프를 백업으로 세지 않는다 |
| (3) 롤백 저널 (D-261) | `--journal` 필수. **이미 있으면 덮지 않고 거부** — 지우면 그 적용분은 되돌릴 수 없다 |

"백업했다"는 말은 검증할 수 없지만 **덤프 파일의 크기는 검증할 수 있다.**

### 1-3. 저널과 롤백의 안전 규칙 2개

- **쓰기 전에** 옛 값을 저널에 남기고 `fsync` 한다. 저널이 디스크에 닿기 전에 죽으면 롤백이 불가능하다.
- 롤백은 **현재 값이 우리가 쓴 값일 때만** 복원한다. 다르면 건너뛰고 보고한다 —
  **남이 그 뒤에 바꾼 값을 덮는 것이 백필이 만들 수 있는 두 번째 사고다.**

또: 적용은 `.update()` 로 한다. `save()` 는 `auto_now`·시그널을 건드려 **백필이 다른 열까지 바꾼다.**

### 1-4. (b)(c)를 왜 컬럼이 아니라 선언으로 했나

`is_system` 컬럼이 D-209 ② 가 말한 정공법이다. 그러나 **스키마 변경 + 데이터 마이그레이션**이라
파괴적이고 WP-2 EXIT 를 늦춘다 — EXIT 는 WP-DA2 착수 조건이므로 전체 일정이 밀린다
(P-DA-3 을 C안으로 판정한 것과 같은 논리).

문제는 백필 후에도 (b)(c) 둘 다 `group IS NULL` 로 남아 **"공용이라서 비었다"와 "아직 안 정했다"가
DB 에서 구별되지 않는다**는 것이다. 그래서 `tenant_classification.py` 에 **선언**하고,
격리 시험이 그 선언을 **단언으로 지킨다**:

- `SHARED_MASTERS` **12건** → 기대값 **전 테넌트 조회 가능**
- `TENANT_UNASSIGNED` **1건** → 기대값 **전역 관리자 외 비노출**
- `DEFERRED` **5건** → "별도 판단 필요"를 **명시**한다. 조용히 빠뜨리면 "안 봤다"와 "봐서 괜찮았다"가 구별되지 않는다

전건에 근거 한 줄이 붙어 있고, **18건 전부 W0-13 인구조사에 실재함**을 대조했다(0건 불일치).

> **PUBLIC 은 검사 면제가 아니라 "공용임을 시험으로 증명한 것"이어야 한다** (D-261 c).

## 3. 기동본에서 할 일 — 순서와 명령

`RUNBOOK_로컬기동.md` 로 기동한 뒤:

```bash
# ── 0) 백업 먼저. 이것이 없으면 적용본이 스스로 거부한다 (D-002)
docker exec gx-db pg_dump -U <user> -Fc <db> > /backup/gx_before_backfill.dump
ls -l /backup/gx_before_backfill.dump          # 1MB 이상인지 눈으로 확인

# ── 1) 계획만 (한 행도 쓰지 않는다). dry-run 과 같은 수가 나와야 한다
docker exec gx-shell sh -c "cd /app && python scripts/backfill_owner_apply.py"
#    기대: (a) R3+R2 합계 ≈ 23,616 · (b) 단일소유 ≈ 1,809 · 참조0 ≈ 1,590 · 다중소유 0

# ── 2) 적용 — 조건 3건을 전부 파일로 준다
docker exec gx-shell sh -c "cd /app && python scripts/backfill_owner_apply.py --apply \
    --dryrun-report docs/agent/evidence/W0-13/backfill_dryrun.md \
    --backup /backup/gx_before_backfill.dump \
    --journal docs/agent/evidence/W0-13/backfill_journal.jsonl"

# ── 3) 되돌려야 하면
docker exec gx-shell sh -c "cd /app && python scripts/backfill_owner_rollback.py \
    --journal docs/agent/evidence/W0-13/backfill_journal.jsonl --apply"
```

### 3-1. 계획 단계의 수가 dry-run 과 다르면 — **적용하지 말 것**

dry-run 은 2026-08-24 실측이다. 그 사이 데이터가 변했으면 수가 달라진다.
**차이 자체가 조사 대상**이고, 맞을 때까지 인자를 고치는 것이 아니라 왜 달라졌는지를 먼저 밝힌다.

특히 **다중 소유가 0 이 아니면 전제가 달라진 것이다.** dry-run 은 0건이었고, 그 0 이
"1,809 + 1,590 으로 깨끗하게 갈린다"의 근거다. 0 이 아니면 그 행들은 채우지 않고 보고된다.

### 3-2. 적용 뒤에 이어지는 것

1. `UNASSIGNED_BASELINE` 을 **실측으로 확정** — 지금 값(1,590)은 dry-run 예측치다.
   실측이 다르면 **그 차이가 조사 대상**이다. 조용히 맞추지 말 것.
2. `tenant_classification.py` 를 격리 시험이 소비하도록 단언 배선 (D-261 b·c 의 기대값).
3. W0-14c — P0 **15종**을 `Target` 에 올린다.
   > **정정(2026-08-27)**: 이 문서가 처음 쓴 **19종**은 D-263 재측정의 *2차* 값이다.
   > 같은 날 3차로 단건 경로의 정의를 시정해(pk 없는 쓰기를 단건에서 분리) **15종**이
   > 정본이 됐다 — `evidence/W0-14/leak_targets_coverage.md` §7-2 · `p0_target_draft.md`.
   > 내려간 4종은 사라진 것이 아니라 P1 에서 사유와 함께 센다. D-266 의 2종은 15종의 1·2번이다.
    `flight_log.FlightLog` ·
   `surveillance.VideoAnalysis` **먼저** (D-266 · WP-DA2 착수를 막는 2종).

## 4. ★ R1 45행을 적용하지 않는 이유

D-261 (a) 는 "부모 상속 가능 23,616행"이라 썼고, 그 내역으로 R3 항목들과 "created_by 소속 343"을
열거했다. 산술이 맞는다 — **23,273 + 343 = 23,616**. 즉 R1(group 은 있는데 `created_by` 가 없는
45행)은 **판정에 포함되지 않았다.**

45행은 작고, 규칙도 단순하다. 그래도 적용하지 않는다 —
**승인받지 않은 행을 쓰는 것이 이 스크립트가 가장 하면 안 되는 일이다.**
`--include-r1` 플래그를 두었으나 별도 판정이 있을 때만 쓴다.

(참고: R1 은 `created_by` 를 채우는 갈래라 **노출 방향**의 구멍이고,
R2·R3 는 `group` 을 채우는 **손실 방향**의 구멍이다. 성격이 다르므로 같이 묶어 판단할 것도 아니다.)
