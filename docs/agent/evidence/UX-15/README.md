### 1/2/3 을 **무엇에** 붙였나 — 그리고 왜

이 저장소의 축은 둘이다: **판정**(실제/오탐 · `review`)과 **처리 단계**(미처리 →
접수 → 조치 중 → 종결 · `response`). 사전 규칙 4 는 「한 화면에 축은 하나」다.

**이 화면이 실제로 가진 단추는 처리 단계뿐이다** — 초점 카드의 단추가 서버가 준
`allowed_next` 로만 그려지고, 판정 단추는 이 화면에 **없다**(판정은 상세 화면의 자리).
그래서 1/2/3 을 **처리 단계**에 붙였다. 판정 단축키를 여기 붙였다면 이 화면의 축이
둘이 되고, 축이 둘이면 사람이 어느 축을 눌렀는지 모른다.

    1 = 접수하기 (acknowledged)
    2 = 조치 시작 (in_progress)
    3 = 종결하기 (closed)

**고정 자리**다. `allowed_next` 의 **순서**에 붙이지 않았다 — 순서에 붙이면 카드마다
1 의 뜻이 달라진다(미처리 카드에서 1 은 접수, 접수된 카드에서 1 은 조치 시작).
관제실에서 뜻이 흔들리는 키는 오조작을 만든다. 자리는 고정이고, **서버가 허락한
칸만 살아난다** — 화면은 여전히 자기 전이표를 갖지 않는다(D-399 그대로).

단추 라벨에 숫자를 함께 적었다(`접수하기 (1)`). 안 보이는 단축키는 없는 단축키다.

**숫자 키는 초점 카드(가장 급한 하나)에만 든다.** 대기 카드에는 서버가
`allowed_next` 를 주지 않는다(그 필드는 `focus` 에만 온다) — 화면이 지어낼 수 없다.
J·K·Enter 는 대기 카드에도 든다: 그것은 **읽는 일**이지 쓰는 일이 아니다.

### 소리 3종 — **등급이 아니라 사건 종류**로 갈랐다

「심각만 소리가 난다」가 제약이다. 등급으로 셋을 가르면 **경계·주의의 두 소리는
영원히 울리지 않는다** — 없는 소리를 셋이라고 세는 셈이다. 그래서:

| 소리 | 언제 | 모양 |
|---|---|---|
| `newCritical` | **심각**이 새로 큐에 들어옴 | 두 음 올라감 (880 → 1320) |
| `overdueCritical` | **심각**이 문턱 표의 마지막 칸을 넘음 | 세 음 내려감 (1200 → 900 → 660) |
| `actionEcho` | **사람이 단계를 넘겼을 때** | 짧고 낮은 한 음 (620) |

①②는 사건 소리이고 **심각에서만** 난다. ③은 사건 소리가 아니라 **자기 손가락의
되울림**이다 — 키보드로만 일하는 사람은 「눌렸나」를 화면 갱신 전까지 알 수 없고,
그 반 초가 같은 키를 두 번 누르게 만든다. 그래서 ③만 등급을 묻지 않는다.

소리 파일을 넣지 않았다(WebAudio). 번들·저작권·사설망 셋 다 피한다.

### 묶음(×N)은 1회

`useCriticalAlarm` 이 카드가 데리고 있는 **원본 id 전부**(`member_event_ids`)를
기억한다. 묶음이 7 → 8 로 자라 카드가 다시 그려져도, 아는 id 가 하나라도 있으면
다시 울지 않는다. 첫 응답은 **기억만 하고 울지 않는다**(쌓여 있던 것이 한꺼번에
울면 알림이 아니라 소음이다). 기억은 매번 **지금 응답에 있는 id 로 줄인다** —
8시간 근무에도 자라지 않는다.

### 음소거 · 안 들리는 이유를 먼저 말한다

`M` 이 켜고 끈다(`localStorage` 에 남아 새로고침을 건너 산다).
**브라우저는 사람이 한 번 만지기 전까지 소리를 잠근다** — 음소거가 아닌데도 안
들리는 상태가 실재한다. 그래서 화면은 `audible`(= 음소거 아님 **그리고** 잠금 풀림)
하나로 판단해 「소리가 꺼져 있습니다」를 **먼저** 띄운다. 오른쪽 위 단추는 상태가
아니라 **누르면 일어나는 일**을 적는다(「소리 켜기」/「소리 끄기」).

### 입력창에서는 안 먹는다

`isTypingTarget()` 이 입력칸·여러 줄 칸·고르는 칸·편집 가능한 자리를 가린다.
조합키(Ctrl·Alt·Meta)와 입력기 조합 중(`isComposing`)도 지나 보낸다.

**★ 일하다 찾은 것:** `event.key` 가 아니라 **`event.code`** 를 본다. 이 화면을
쓰는 사람은 한국어를 치고, **한글 입력기가 켜져 있으면 `j` 를 눌러도 `event.key`
는 `ㅓ` 로 온다** — 즉 `key` 로 짰으면 입력기가 켜진 순간 단축키가 전부 죽고,
그 고장은 「가끔 안 먹는다」로 보고되어 아무도 재현하지 못했을 것이다.
`code` 는 자판의 **자리**라 입력기와 무관하다. `Numpad1~3` 도 함께 받는다.

## 3. 못 쟀고 왜 못 쟀나

| 못 잰 것 | 왜 |
|---|---|
| 소리가 **실제로 울리는가** | WebAudio 는 브라우저 안에서만 존재한다. 이 환경은 화면 동시 접속이 1개라 브라우저를 열지 않았다. 판정기가 잰 것은 **갈래의 실재**이지 소리 자체가 아니다 |
| 키가 **실제로 먹는가** | 위와 같다. 입력창 갈래도 소스에서 잰 것이다 |
| 한글 입력기에서 `code` 가 정말 사는가 | 실제 입력기로 눌러 봐야 안다. 판단의 근거는 브라우저 명세이고, **실측이 아니다** |
| 앱 전체 타입 검사 | `node_modules` 설치 불가(위 참조) |

## 4. 다음 사람이 브라우저에서 확인할 것 세 줄

1. `/dsm/queue` 에서 **검색·입력 칸에 커서를 두고 `j`** 를 쳐라 — 글자가 들어가고
   목록이 **안 움직여야** 한다. 커서를 빼고 `j`·`k` 를 치면 파란 테두리가 움직인다.
2. **한글 입력기를 켠 채로** `j`·`1`·`m` 을 눌러라 — 그대로 들어야 한다(`code` 로 읽는다).
   `m` 한 번에 오른쪽 위가 「소리 켜기」로 바뀌고 위쪽에 「소리가 꺼져 있습니다」가 뜬다.
3. 심각 이벤트를 하나 넣고(훈련 모드 권장) **같은 카메라·같은 유형으로 3분 안에
   여러 번** 울려라 — 카드는 「×N」 한 장이고 **소리는 한 번**이어야 한다.
   경계·주의 이벤트에서는 **아무 소리도 나면 안 된다.**
