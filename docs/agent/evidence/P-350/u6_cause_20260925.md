# P-350 증거 — U6 로그인 400 의 원인 · U2/U5 회색 사유표 · gen-schema 호출자 (2026-09-25 · 차선 U)

## 0. 한 줄

**도구는 옳다 — 예비 계정 `gxseed_u5_newop` 의 DB 비밀번호가 게이트 공용
`GX_SEED_ROLE_PASSWORD` 와 다르다.** dj-core `login_user()`(`core/api/v1/auth.py:347`)
는 계정없음·비활성·삭제·잠김·**비밀번호 불일치**를 전부 같은 **HTTP 400**으로
접어 낸다 — 그래서 걷기 로그(`walk_8500_20260924.txt`)의 `HTTP 400` 한 줄만으로는
다섯 원인 중 무엇인지 가를 수 없었다. 읽기 전용 Django 셸로 갈랐다.

## 1. 어떻게 갈랐는가 — 읽기만 했다(로그인 0회)

`MSYS_NO_PATHCONV=1 docker exec -e DJANGO_SETTINGS_MODULE=config.settings
-e GX_SEED_ROLE_PASSWORD -w /app gx-shell python manage.py shell -c "..."`
(비밀번호는 값 없이 **이름만** 넘겼다 — 호스트 셸이 이미 쥔 값을 docker 가
가져간다 · 명령줄에 값을 싣지 않는다. `rotate_shared_passwords.py` 와 같은 규약.)

```
[실측 · 2026-09-25 · gxseed_u5_newop]
pk = 117 · is_active = True · deleted = None(=False)
has_usable_password = True · password_hash_algo = pbkdf2_sha256
is_account_lock = False · account_locked_until = None · is_account_locked() = False
login_fail_count = 0 · failed_login_attempts = 4  ← 잠금 상한(5)에 하나 남았다
check_password(GX_SEED_ROLE_PASSWORD) = False  ← ★ 여기다
GX_SEED_ROLE_PASSWORD sha256[:12] = de08e1f17eb3 · 길이 24 (.env.gates 와 동일 지문)
```

같은 실행에서 U1·U2·U4·U5(`gxseed_u5_sysop`)는 **같은** `GX_SEED_ROLE_PASSWORD`
로 로그인에 성공했다(걷기 증거 자체가 그 증인이다) — 그러므로:

- ❌ **`.env.gates` 의 `${VAR}` 미펼침 함정(D-457)이 아니다** — 그 함정이면
  U1·U2·U4·U5 도 같이 400 이 났어야 한다(같은 값을 같은 로더로 읽는다). 실측으로
  `GX_SEED_ROLE_PASSWORD` 라인 자체는 `${` 참조도, `#`도 없이 깨끗하다(길이 24).
- ❌ **필드 이름(username vs email) 문제가 아니다** — dj-core `LoginInput`
  스키마(`core/api/v1/schemas.py:15`)는 `username: str` 이고, 걷기 도구
  (`verify_route_alive.login()` 163행)가 보내는 페이로드도 `{"username": ...}`
  다. 같은 페이로드 모양으로 다른 네 계정은 통과했다.
- ❌ **잠금(V_LOCK)·다른 세션·율제한이 아니다** — 그랬다면 같은 IP·같은 실행의
  다른 네 로그인도 같이 막혔을 것이다. 그리고 방금 읽기로도 `is_account_lock`
  `is_account_locked()` 모두 `False` 다.
- ✅ **비밀번호 불일치 하나로 닫힌다** — `check_password()` 가 `False` 를 낸
  순간 dj-core 는 `authenticate()` 실패 갈래(`auth.py:404` 부근, "Password is
  incorrect")로 빠지고 그 갈래도 `status=400` 이다. U6 만 400 이고 나머지
  넷은 200 인 이유가 이것으로 전부 설명된다.

## 2. 왜 이 계정만 다른가 — 정황(확정 아님)

- `gxseed_u5_newop` 은 `seed_role_users.py` 가 아니라 **다른 경로**로 태어난
  「온보딩 첫 근무일 계측용 예비 계정」이다(`0003_p224_seed_account_marks.py:64`
  주석 그대로) — U1/U2/U4/U5 넷과 만들어진 자리가 다르다.
- `scripts/rotate_shared_passwords.py` 의 `NEVER_TOUCH`(64~68행)에는
  `gxseed_u1_operator`·`u2_manager`·`u3_field`·`u4_official`·`u5_sysop`·
  `gxprobe_*` 아홉 이름이 있고 **`gxseed_u5_newop` 는 없다**. P-112 회전이
  실제로 이 계정까지 돌았다면(공유 낱말을 쓰고 있었다면) 새 값은 저장소 밖
  원장에만 적히고 `.env.gates` 는 갱신되지 않는다 — 그 경우 이 계정만
  `GX_SEED_ROLE_PASSWORD` 와 갈라지는 모양이 지금 실측과 정확히 들어맞는다.
  ⚠ 이 문단은 **정황**이다 — P-112 원장은 저장소 밖에 있어 이 차선이 확인할
  수 없다. 「비밀번호 불일치」라는 1절의 사실과 섞지 않는다.

## 3. 고칠 자리 — 도구가 아니라 자격증명

도구(`scripts/verify_onboarding_walk.py` · `verify_route_alive.py`)는 **고치지
않았다** — 로더·필드 이름·`login()` 갈래 전부 실측으로 옳다고 확인됐고
(1절), 여기서 코드를 건드리면 옳은 것을 고치는 것이다. `backend/tests/
test_p311_onboarding_walk.py` 11건 재실행 — **전부 통과**(아래 §5).

**대표 결정 필요** — 둘 중 하나, 대표가 고른다(이 차선은 실행하지 않는다):

1. `gxseed_u5_newop` 의 비밀번호를 `GX_SEED_ROLE_PASSWORD` 값으로 재설정한다
   (다른 네 시드 계정과 같은 값으로 맞춘다). 실행 예:
   `docker exec -e DJANGO_SETTINGS_MODULE=config.settings -e GX_SEED_ROLE_PASSWORD
   gx-shell python manage.py shell -c "필요한 값으로 set_password 후 save"`
   — **주의**: `failed_login_attempts=4` 로 잠금 상한(5)에 하나 남아 있다.
   비밀번호를 맞추기 전에 틀린 값으로 한 번 더 때리면(수동이든 재실행이든)
   이 계정이 잠긴다.
2. 이 계정의 **실제 비밀번호**를 알아내(P-112 원장 등) `.env.gates` 에
   별도 이름(예 `GX_SEED_RESERVE_PASSWORD`)으로 적고, 그 이름을 읽도록
   도구를 바꾼다 — 이 갈래를 고르면 `scripts/verify_route_alive.py`
   `LOCAL_ENV_KEYS` 와 `verify_onboarding_walk.py` 의 비밀번호 조회 자리를
   함께 바꿔야 한다(두 벌이 어긋나지 않게).

어느 쪽이든 **로그인 재시도는 이 차선이 하지 않는다** — 첫 실측은 V 의 몫이다
(P-311 규약 그대로).

## 4. U2 1/3 · U5 3/6 — 회색(미완료) 사유표

`걷기` 는 손대지 않고 **같은 판정 함수**(`apps.dsm.onboarding.progress`)를
Django 셸에서 그 역할 계정의 `TenantScope` 로 직접 불러 얻었다(HTTP 0회 ·
로그인 0회) — 걷기 증거의 1/3·3/6 과 정확히 일치한다.

### U2(`gxseed_u2_manager`) — 분모 3(닫는 술어 있는 카드) 중 1

| 카드 | 닫는 서버 레코드 | 지금 안 닫힌 이유 |
|---|---|---|
| `u2.report`(사건 보고서 한 쪽) | `DsmReportRun` 행 | **닫혔다** — `report_run#1`(2026-09-18) |
| `u2.threshold`(임계값 시험) | 내가 바꾼 `ThresholdChange` 행 | 이 계정(`changed_by`)이 바꾼 이력이 없다 — 남이 바꾼 임계값은 이 카드를 못 닫는다(행위자로 좁힌다, 본문 193행) |
| `u2.drill`(훈련 모드 위치 확인) | `drill_state().last_action` | 이 테넌트의 훈련 모드를 켜거나 끈 기록이 없다 |

분모 밖(`blocked` · 4장, 서버 기록 자체가 없어 진행률에 안 들어간다):
`u2.summary`·`u2.unhandled`·`u2.by_reviewer`(조회 자체가 서버에 안 남는다) ·
`u2.regrade`(재판정을 사건별로 되짚는 자리가 아직 없다).

### U5(`gxseed_u5_sysop`) — 분모 6(닫는 술어 있는 카드) 중 3

| 카드 | 닫는 서버 레코드 | 지금 안 닫힌 이유 |
|---|---|---|
| `u5.people`(사람 6명 이상) | `UserProfileLink` 그룹 인원수 | **닫혔다** — `people:35` |
| `u5.recipients`(심각 등급 수신자) | `resolve_recipients(severity="critical")` 규칙 | **닫혔다** — `notify_rule#9` |
| `u5.retention`(보관 기간 선언) | `retention.declared_retention_days` | **닫혔다** — `retention:30d` |
| `u5.cameras`(카메라 주소 채우기) | `camera_address_gap` 의 `without_address == 0` | 주소 없는 카메라가 아직 남아 있다(0 이 아니다) |
| `u5.drill`(훈련 모드 켜 보기) | `drill_state().last_action` | U2 와 같은 사유 — 이 테넌트에 훈련 on/off 기록이 없다 |
| `u5.channel`(알림 채널 시험 발송) | 감사표(`AuditLogs`)의 `test_send` 행(이메일 또는 웹푸시) | 이 계정(`user_id`)이 누른 시험 발송 기록이 없다 |

분모 밖(`blocked` · 1장): `u5.backup`(백업 회수증) — 그 화면·기록이 이번
턴(U56)에 서는 중이라 아직 술어가 없다.
