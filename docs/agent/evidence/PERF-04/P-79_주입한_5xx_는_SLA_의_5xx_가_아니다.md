# P-79 ③ — **뺄 것이 없었다.** 0.139% 는 주입이 아니라 앞단 502였다

[실측 2026-09-06 · 턴 H · 차선 Q] `scripts/verify_perf_budget.py` · `scripts/verify_route_alive.py`

## 물음

> 직전 실측 5xx **0.139%**(예산 0.1% 초과). 그런데 같은 시각 다른 차선이 **오류 주입
> 시험**(500·503 을 일부러 주입)을 돌리고 있었다. 주입한 5xx 는 SLA 의 5xx 가 아니다.

## 답 — **뺀 건수 0건.** 그리고 그 0 은 손잡이가 아니라 사실이다

### ① 주입은 서버에 닿은 적이 없다

`scripts/walk_states.py` 의 주입은 **Playwright 요청 가로채기**다:

```
★ 주입은 브라우저 안에서 끝난다. Playwright 의 요청 가로채기는 요청이 네트워크로
  나가기 전에 가짜 응답을 돌려준다 — 서버는 그 요청을 본 적이 없다.
      (walk_states.py 머리말 · `"how": "…주입한 요청은 네트워크로 나가지 않는다"`)
```

게다가 `_install_write_guard()` 가 로그인·로그아웃을 뺀 모든 비-GET `/api/` 요청을
네트워크 앞에서 막는다. **주입 시험이 계량기의 분모에 들어갈 경로가 구조적으로 없다.**

### ② 계량기는 **자기 요청만** 센다

`verify_perf_budget.measure()` 는 자기가 보낸 GET 의 상태 코드만 센다. 다른 차선의
요청은 이 게이트의 분자에도 분모에도 들어오지 않는다.

### ③ 그 5건은 전부 **502** 였다 — 주입한 500·503 이 아니다

`docs/agent/evidence/PERF-04/budget_turnG_secV.json` (2026-09-06T07:30:53Z · 합격선 모드):

| 면 | n | 5xx | `error_detail` |
|---|---:|---:|---|
| F05 | 900 | **4** | `/api/dsm/events?limit=50 -> 502` |
| SCREEN | 900 | **1** | `/api/dsm/dashboard/frame -> 502` |
| MEDIA | 900 | 0 | — |
| STATUS | 900 | 0 | — |

**5/3,600 = 0.139% · 전부 502.** 502 는 앞단(nginx)이 상류에 못 닿았다는 뜻이다.
같은 실행의 `co_resident` 가 원인을 이름으로 적고 있다 — **runserver 프로세스 6개**
(8000 · 8400 · 8401 과 각각의 sh 래퍼), loadavg **3.57 / 8 CPU**.
차선들이 같은 8 코어 위에서 각자 개발서버를 띄우고 있었다.

## 뺀 뒤의 수 — **0.139%. 바뀌지 않았다. 그리고 여전히 빨강이다**

새 원장을 통과시킨 재판정 [실측 2026-09-06 · 기계]:

```
$ python scripts/verify_perf_budget.py --evidence docs/agent/evidence/PERF-04/budget_turnG_secV.json
X [전체] 가용성 · 5xx ≤ 0.1%
  5xx 5/3,600 = **0.139%** > 0.1% … · 면별 F05 4/900=0.44% · MEDIA 0/900 ·
  SCREEN 1/900=0.11% · STATUS 0/900 ·
  주입 제외 **0건**(뺀 것이 없다 — 이 계량은 주입하지 않는다)
  — **응답시간이 아니라 가용성이 빨갛다.** 고칠 자리는 예산 표가 아니라 앞단·워커다
exit 1
```

## 어디가 옳은 자리였나 — **표는 보내는 쪽이, 원장은 세는 쪽이**

읽고 정한 것이다(`perf_measure.py` · `verify_perf_budget.py` · `walk_states.py`):

| 자리 | 무엇을 하나 | 왜 여기인가 |
|---|---|---|
| `verify_route_alive.hit(headers=…)` | 부르는 쪽이 **자기 요청에 표를 달 수 있게** | 이름 없는 트래픽에는 나중에 아무 사유나 붙는다 — 그것이 P-71 의 「환경」이었다 |
| `verify_perf_budget.PROBE_HEADER` | 계량 요청마다 `X-GX-Probe: perf-budget` | 앞단 로그에서 계량 트래픽을 **이름으로** 가려낸다. 로그로 SLA 를 재는 날 필요하다 |
| `verify_perf_budget.INJECT_HEADER` + `INJECTED_CALLS` | 일부러 고장 내는 호출에 `X-GX-Fault-Inject`. **지금은 비어 있다** | 비어 있다는 사실이 「뺄 것이 없다」의 근거다 |
| `judge_availability` | 표가 붙은 5xx 만 **분자·분모 양쪽에서** 빼고, **뺀 건수와 사유를 언제나 적는다**(0건이어도) | 안 적힌 0 은 「안 쟀다」와 구분되지 않는다 |

`perf_measure.py` 는 자리가 아니다 — 그것은 커널 지연(K1·K2)을 재고 HTTP 5xx 를 세지 않는다.

## ⚠ 빼기가 「빨강을 없애는 손잡이」가 되지 않도록 — 자기시험 갈래 셋

`verify_perf_budget.py --self-test` 에 박았다:

1. 주입 표가 붙은 5xx 8/4,000 → **초록**이고 사유에 「주입 제외 **8건**」이 적힌다.
2. ★ **출생 표본** — 표 없는 **502 5/3,600 = 0.139%** → **빨강.**
   주입이 아닌 502 를 빼면 그 빼기는 빨강을 없애는 손잡이다.
3. 뺄 것이 없어도 **「주입 제외 0건」이라고 적는다.**

## 남는 일 (이 절이 아니다)

0.139% 의 뿌리는 **8 코어를 여섯 개의 runserver 가 나눠 쓴 것**이고, 고칠 자리는
예산 표가 아니라 앞단·워커다(OPS-13). 합격선은 gunicorn+nginx 뒤에서 다시 잰다 —
그때까지 이 수는 **기준선**이지 합격 판정이 아니다(`budget.json::caveat`).
