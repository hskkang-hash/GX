── 2. 비밀 — **값은 저장소 밖에 있다** ────────────────────────────────────────────

    사람이 하나씩 넣는다(P-41).

── 3. 스테이징 compose 가 **안 세우는 것** — 밖에서 받아야 한다 ────────────────────────────────────────────
  [실측] docker-compose.stg.yml 의 서비스: nginx-stg frontend-stg backend-stg celery-stg beat-stg redis-stg
  [빈칸] postgres 가 compose 에 **없다** — 관리형 DB 든 별도 컨테이너든 **밖에서** 준다
  [빈칸] minio(객체저장)가 compose 에 **없다** — 영상·이미지가 갈 곳이 없으면 저장이 조용히 실패한다
  [계획] 둘의 주소·자격증명을 backend/.env.stg 에 넣고, 아래 4에서 **닿는지 먼저 잰다**

── 4. 의존이 살아 있는가 — 세우기 전에 잰다 ────────────────────────────────────────────
  [계획] docker compose -f docker-compose.stg.yml config -q      # 파일이 말이 되는가
  [계획] psql "$DATABASE_URL" -c 'select 1'                      # DB 에 닿는가
  [계획] redis-cli -u "$REDIS_URL" ping                          # 브로커에 닿는가
  [계획] mc alias set stg "$MINIO_ENDPOINT" … && mc ls stg      # 객체저장에 닿는가
  ★ 넷 중 하나라도 안 되면 **여기서 멈춘다.** 반쯤 선 스테이징은 안 선 것보다
    나쁘다 — 「띄웠는데 왜 안 되지」를 사람이 며칠 쫓게 만든다.

── 5. 세운다 (되돌릴 수 없는 자리) ────────────────────────────────────────────

  [안함] docker compose -f docker-compose.stg.yml up -d celery-stg beat-stg frontend-stg nginx-stg

── 6. 파기 주기 — **끈 채로 세운다** (P-57 · OPS-07) ────────────────────────────────────────────
  ★ beat 는 뜨는 순간 `beat_schedule` 을 DB 표로 옮겨 심고, `last_run_at` 이 빈
    crontab 항목을 「밀렸다」로 읽어 **즉시 발화한다** [실측 2026-09-05 17:41:59:
    beat 가 뜬 지 0.5초 만에 14개가 한꺼번에 나갔다]. 그중에 파기가 있다.
  ★ 그리고 감사 보존 일수는 **아무도 선언하지 않았다** — 90은 코드 기본값이다
    [실측 2026-09-05 · OPS-07]. 미선언 상태의 파기는 아무도 정하지 않은 수로
    감사 기록을 **하드 삭제**하는 일이다.
  [안함] docker compose -f docker-compose.stg.yml exec -T backend-stg python -c "import django;django.setup();from django_celery_beat.models import PeriodicTask;print(PeriodicTask.objects.filter(task__in=['common.ops_audit_purge_beat','common.video_retention_sweep_beat','core.logger.tasks.purge_old_audit_logs']).update(enabled=False))"
  [계획] 켜는 조건: 보존 일수를 **선언**하고 `scripts/verify_purge.py` 가 초록일 때

── 7. 섰는가 — 판정기가 답한다 ────────────────────────────────────────────
