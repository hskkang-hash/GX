## dry-run 이 **실제로 찾아낸 것** — 이것이 준비의 값이다

계획을 적기만 했으면 안 나왔을 수들이다. **돌려 봤기 때문에** 나왔다.

### ① compose 에 없는 것 둘 (bootstrap 3)

    [빈칸] postgres 가 docker-compose.stg.yml 에 **없다** — 밖에서 받아야 한다
    [빈칸] minio 가 **없다** — 영상·이미지가 갈 곳이 없으면 저장이 조용히 실패한다

승인 당일에 이것을 알면 그날이 통째로 날아간다. 지금 알면 준비할 수 있다.

### ② `.env.stg` 에 빠진 열쇠 55개 — 그중 **셋이 위험한 기본값으로 떨어진다** (mirror 3b)

    TENANT_SCOPE_ENFORCE          없음 → **False**          (테넌트 격리 강제 **꺼짐**)
    TENANT_TRUST_LEGACY_SUPERUSER 없음 → **True**           (옛 superuser 신뢰 **켜짐**)
    GUARDIANX_ENVIRONMENT         없음 → **"development"**  (스테이징이 자기를 개발이라 부른다)

    K2_SEND_ALLOWED_DOMAINS       없음 → **[]**   ← 안전한 쪽(실발송 0 · P-41)
    K2_OPS_ALERT_ROLE_CODES       없음 → **[]**   ← 안전한 쪽
    DJANGO_CSRF_TRUSTED_ORIGINS   없음 → https 로 세우면 **POST 가 전부 막힌다**

★ **「열쇠 55개 빠짐」이라는 한 줄로 적으면 아무도 안 읽는다.** 그래서 판정기가
  「없으면 무엇이 되는가」까지 잰다 — 안전한 기본값과 위험한 기본값은 다른 사실이다.

### ③ 작업 트리가 깨끗하지 않다 (mirror 2)

커밋 안 된 것은 스테이징에 안 간다. 배포는 **태그**로만 한다.

## 두 스크립트의 규약

    · **기본값은 dry-run 이다**(D-209). 실제로 하려면 `--apply` 를 명시한다.
    · dry-run 은 **원격에 아무것도 보내지 않는다.** `[계획]`/`[안함]` 으로 시작하는
      줄은 **하지 않은 일**이다.
    · 미러는 **데이터를 옮기지 않는다** — 테넌트 데이터·감사 로그·비밀 값·객체.
      개발 DB 를 덤프해서 부으면 그 순간 스테이징이 개인정보 처리 시스템이 되고,
      그 시스템에는 접근 통제도 파기 주기도 서 있지 않다.
    · 파기 주기는 **끈 채로 세운다**(bootstrap 6 · P-57). beat 는 뜨는 순간
      밀린 crontab 항목을 **즉시 발화한다** [실측 2026-09-05 17:41:59].
