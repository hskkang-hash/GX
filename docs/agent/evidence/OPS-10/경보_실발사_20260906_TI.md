# OPS-10 · **경보를 하나 실제로 발사했다** — 발송 경로 O · 운영 수신처 대기

- 날짜: **2026-09-06** (턴 **TI** · 차선 E) · 기계 시각 UTC
- 판정 근거: 지시서 §3 E행 ② · 세종 P-41(허용 목록) · P-68(mailpit)
- 앞선 실측: `docs/agent/evidence/OPS-10/mailpit_수신함_실측.md`(턴 G·H) — 그 문서가
  잰 것은 `send_mail` 과 `EmailChannel.send()` **두 조각**까지다.

---

## 0. 이 문서가 **이전 문서보다 더 잰 것 한 줄**

턴 G·H 는 어댑터 조각(`EmailChannel.send()`)을 태웠다. 그 문서는 스스로 이렇게 적었다:

> ⚠ 여기까지가 태운 구간이다. `k2_notify/services.py::send()`(이벤트 → 수신자 해석 →
> 발송 이력 행 기록)는 **태우지 않았다.**

**이번 턴에 그 줄을 태웠다.** 즉 잰 것은 **제품이 경보를 내보내는 전 구간**이다:

```
DetectionEvent  ->  k2_notify.send()  ->  DeliveryRecord 행 생성
                ->  훈련모드 판정      ->  P-41 허용목록 관문
                ->  EmailChannel      ->  SMTP 소켓  ->  수신함
```

그래서 이 문서가 낼 수 있는 새 사실은 하나다: **`ops_alert_routing` 의 ④ 「사람에게
도달」이 0건이던 자리에, 실제로 나가서 도착한 발송 1건이 생겼다.**

---

## 1. ⛔ 먼저 — **이것으로 OPS-10 이 닫히지 않는다**

받은 통은 **우리가 세운 계측기**(mailpit)다. 사람의 수신함이 아니다.
이 초록으로 「경보가 당직자에게 도달한다」를 적으면 그것이 D-284 의 「조용한 성공」이다.

| 잰 것 | 못 잰 것 |
|---|---|
| Django 설정 → SMTP 소켓 → 메시지 파싱 → HTTP API 되읽기 | **TLS 협상** (`EMAIL_USE_TLS=False` 로 돌았다) |
| `k2_notify.send()` 전 구간 · `DeliveryRecord` 행에 무엇이 남는가 | **SMTP AUTH · 발송 업체 릴레이** (업체 미정 · DA-04 D4-1) |
| P-41 허용 목록이 **막을 것을 막는가** (§4 음성 대조군) | **SPF / DKIM / DMARC · 스팸함 · 수신 거부** |
| | **사람이 읽었는가** — 어떤 기계도 여기서 답하지 못한다 |
| | **운영 수신처** — 대표 결정 대기 |

→ 대장에는 **둘로 갈라** 적는다: **「발송 경로 O」 · 「운영 수신처 대기」.**
   하나로 뭉개면 「경보가 나간다」가 되고, 그것은 아직 사실이 아니다.

## 2. 배선 — **설정으로만 했다. 코드에 주소를 박지 않았다**

`backend/config/settings.py` 의 `EMAIL_*` 는 이미 전부 `env(...)` 다. 그러므로 고친 코드는
**0줄**이고, 준 것은 환경변수뿐이다.

### 개발·스테이징 발송처 = mailpit (넣을 값 그대로)

```
EMAIL_HOST=mailpit
EMAIL_PORT=1025
EMAIL_USE_TLS=False
EMAIL_HOST_USER=gx-alerts@gx-dev-inbox.local
EMAIL_HOST_PASSWORD=mailpit-accepts-any
DEFAULT_FROM_EMAIL=gx-alerts@gx-dev-inbox.local
K2_SEND_ALLOWED_DOMAINS=gx-dev-inbox.local
K2_ALERT_CHANNEL=email
```

★ **왜 `EMAIL_HOST_USER`·`EMAIL_HOST_PASSWORD`·`DEFAULT_FROM_EMAIL` 을 함께 주는가.**
  `EmailChannel.configured()` 는 이 넷이 **자리 표시자**(`your-email@gmail.com` ·
  `your-app-password` · `CHANGE_ME` · 빈 문자열)면 `ok=False`(회색)를 낸다. 지금 평시
  형상은 `DEFAULT_FROM_EMAIL=''` 이라 **회색**이다 — 그 회색은 옳다. 위 넷을 채워야
  「보낼 수 있는 모양」이 된다.

★★ **허용 도메인을 딱 하나로 좁혔다 — 이것이 이 배선의 가장 중요한 줄이다.**
  `K2_SEND_ALLOWED_DOMAINS=gx-dev-inbox.local` 이므로 **개발 계정 30명**
  (`yopmail.com` 24 · `seed.invalid` 6 · [인용 · 턴 B])에게는 **한 통도 나가지 않는다.**
  P-41 이 허용 목록으로 만든 이유가 이것이다 — 차단 목록이면 내일 생길 계정이 통과한다.

### ⚠ `.env` · `docker-compose*.yml` 은 차선 E 가 고치지 않았다

위 블록은 **다른 차선 소유 파일**(`.env` · `docker-compose*.yml`)에 들어가야 최종적으로
「평시 형상의 사실」이 된다. 차선 E 는 그 파일들을 건드리지 않고 **보고 본문으로 넘긴다.**
그 전까지 이 문서의 초록은 **환경변수로 덮어쓴 형상의 사실**이지 평시 형상의 사실이 아니다.

## 3. 실측 — **경보 1건, 실제로 나가서 실제로 도착했다**

일회용 컨테이너(`docker run --rm`)에서 태웠다. 살아 있는 컨테이너의 환경을 영구히
바꾸지 않기 위해서다. 모듈은 **제품의 것을 그대로** 불렀다 — 흉내 낸 코드 0줄.

```
MSYS_NO_PATHCONV=1 docker run --rm --network gx-main-network \
  --env-file <살아있는 gx-celery-e 의 환경> -e PYTHONPATH=/app \
  -e EMAIL_HOST=mailpit -e EMAIL_PORT=1025 -e EMAIL_USE_TLS=False \
  -e EMAIL_HOST_USER=gx-alerts@gx-dev-inbox.local \
  -e EMAIL_HOST_PASSWORD=mailpit-accepts-any \
  -e DEFAULT_FROM_EMAIL=gx-alerts@gx-dev-inbox.local \
  -e K2_SEND_ALLOWED_DOMAINS=gx-dev-inbox.local -e K2_ALERT_CHANNEL=email \
  -v <저장소>/backend:/app:ro -v <저장소>/scripts:/repo/scripts:ro \
  -w /app --entrypoint python guardianx-backend:ops19-pg18-ti /tmp/fire_alert.py
```

## 4. 음성 대조군 — **이 측정은 무엇이든 초록으로 만들지 않는다**

수신함을 보는 측정은 무엇을 넣어도 초록이면 값이 없다. 그래서 **허용 목록에서 그
도메인을 빼고** 같은 코드를 한 번 더 태웠다 — **도착하면 안 되는 메일**이다.

```
... -e K2_SEND_ALLOWED_DOMAINS=example.com ...        # 나머지는 전부 같다
```

| 항목 | 값 |
|---|---|
| `send_allowed()` | **`ok=False`** — 「`gx-dev-inbox.local` 는 실발송 허용 도메인 목록 밖이다(P-41). 허용된 것: example.com」 |
| `DeliveryRecord` | 121행 → 122행 · 새 행 `id=362` |
| 새 행의 내용 | `channel=email` · **`succeeded=False`** · `sent_at=None` · `failure_reason` 에 **막힌 사유가 그대로** |
| 수신함 총량 | **4 → 4** (변화 없음) |
| 그 표식의 메일 | **없다** |

→ 이 측정은 **막힌 것을 막혔다고 말한다.** 그리고 P-41 의 설계가 실물로 확인됐다:
  차단해도 **행은 남고 사유가 적힌다** — 「보낸 적 없음」과 「막혔음」이 구별된다(D-290).
