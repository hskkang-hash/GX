# OPS-10 — 허용 도메인 게이트 **초록** · SMTP **대기** (2026-09-05 · 턴 C · 차선 E)

## 판정: **회색이다. 닫지 않는다.**

**회색은 초록이 아니다.** 이 절은 이번 턴에 닫히지 않는다 — 그 이유가 아래에 있다.

## 1. 순서를 지켰다 — 게이트가 먼저다 (세종 §3 함정 ③)

지시는 분명했다: **허용 도메인 게이트가 먼저 초록이어야 채널을 켠다.** 지금 켜면
대표 주소가 아니라 개발 계정에게 진짜로 메일이 나간다.

차선 Q 의 게이트를 **이 자리에서 돌렸다**:

```
docker exec -w /app gx-shell python /repo/scripts/verify_send_allowlist.py
exit=0        ← **초록**
```

| 갈래 | 결과 |
|---|---|
| 강제가 코드에 있다 (AST) | `send_allowed @225` · `send_mail @233` |
| 빈 목록이면 전부 로그 | 실발송 0 |
| 음성 대조 — 목록 밖은 안 나간다 | `dev-account-12@yopmail.com` → 발송함 **0통** · 로그로 떨어짐 |
| 양성 대조 — 목록 안은 나간다 | `duty@allowed.example` → 발송함 **1통** |
| 꼬리 일치로 새지 않는다 | `notyopmail.com` 은 `yopmail.com` 을 타지 못한다 |

★ **[실측] 개발 계정 실발송 0.** 규칙이 고르는 수신자 항목 **42** · 고유 주소 **15명** ·
도메인 `yopmail.com` 8 · `org.kr` 4 · `seed.invalid` 3. **채널을 `email` 로 켜도**
허용 목록이 비어 있어 실발송 0명 / 로그 강제 15명이다.

> 지난 턴의 가장 큰 발견(「켜는 순간 개발 계정 12명에게 진짜로 나간다」)이
> **구조로 막혔다.** 이제 사고는 「켜는 것」이 아니라 「목록에 도메인을 적는 것」이고,
> 그것은 손이 한 번 더 가는 일이다.

## 2. 그런데 채널을 못 켠다 — **보낼 계정이 없다**

대표가 주신 것은 **받을 주소**이고(로컬 `backend/.env` 의 `K2_ALERT_EMAIL_TO` ·
저장소에는 값이 없다 · D-204), **보낼 계정**은 아직 오지 않았다.
`EMAIL_HOST`·`EMAIL_HOST_USER`·`EMAIL_HOST_PASSWORD` 가 비어 있다.

    「값이 있다」와 「보낼 수 있다」는 다르다.
    받을 주소만으로는 한 통도 못 보낸다.

그래서 `K2_ALERT_CHANNEL` 은 **`log` 그대로 둔다.** 켜 놓고 안 나가는 것보다
안 켜고 안 나가는 것이 낫다 — 앞엣것은 「보냈는데 안 왔다」로 읽히고, 뒤엣것은
「아직 안 켰다」로 읽힌다. 두 상태를 같은 모양으로 만들면 안 된다.

## 3. 닫는 데 남은 것 — **셋. 순서까지 적는다**

  ① **SMTP 자격증명**(보낼 계정) — 대표/에스비가 준다. 이것이 없으면 나머지가 무의미하다
  ② **허용 도메인 목록**에 대표 주소의 도메인 하나를 적는다
     (`K2_SEND_ALLOWED_DOMAINS` · 로컬 `backend/.env` · 저장소에는 이름만)
  ③ **대표 주소를 U5 시스템관리자 역할 계정 1명으로 등록**한다 (세종 P-41).
     지금 `K2_OPS_ALERT_ROLE_CODES` 는 **비어 있고**(=아무도 안 받는다 · 안전한 쪽),
     U5(`K3_ROLE_SYSOPS`)는 `['admin']` 이다. 이 계정을 만드는 것은 **공유 개발 DB 에
     대표의 실제 이메일 주소를 심는 일**이라 이번 턴에 하지 않았다 — ①이 오는 날
     같은 손으로 한 번에 한다.

닫는 증거는 **수신함 캡처 한 장**이다. 그 한 장이 없으면 이 절은 여전히 회색이다.
