## 한 상수에서 온다 — 그리고 그것을 **쟀다**

글자는 `frontend/src/features/dsm/constants/kick.ts` 의 `KICK_SENTENCE` 하나다.
자리 1과 2가 둘 다 그것을 읽는다.

★ 「한 상수에서 온다」는 주장은 **번들이 증명한다**. 빌드된 산출물에서 이 문장의
리터럴이 몇 번 나오는지 셌다 [실측]:

```
grep -o "GuardianX는 대응 시간을 잽니다." dist_te/assets/index-BK_Tg6NJ.js  | wc -l  →  1
grep -o "GuardianX는 대응 시간을 잽니다." dist_te/assets/FocusQueue-*.js     | wc -l  →  0
```

**번들 전체에 리터럴이 하나다.** 두 화면이 그 하나를 나눠 쓴다 —
자리마다 손으로 적었으면 둘이 나왔을 것이고, 둘은 언젠가 갈린다.

## 셋째 자리 — **조율자 배선 필요**

월간 1쪽 「이번 달 우리 센터」는 **프런트가 그리지 않는다.** 실측한 것:

- 서식은 `docs/design/GX-REPORT_월간1쪽_이번달우리센터_서식_v0.1.md` 에 있고,
  첫 줄은 `{테넌트명} 재난안전 관제 — {YYYY년 MM월} 운영 결과` 다.
- 치환 변수는 `backend/kernels/k4_report/schemas.py` 의 `MONTHLY_VARIABLES` 에
  **이름으로 잠겨 있다**(서른여섯 개). 머리글 변수는 `tenant_name` · `period_label`
  둘뿐이고, **머리 문장을 받는 변수가 없다.**
- 프런트에 월간 1쪽을 그리는 화면도 없다(`features/dsm/pages` 전수 확인).

즉 셋째 자리는 「우리 층에서 상수를 꽂으면 되는 자리」가 **아니다**. 그 커널 파일이
스스로 적어 둔 규약대로, **서식 문서와 변수 튜플을 같은 커밋에서** 고쳐야 한다.
이번 턴 프런트 차선은 문서도 커널도 만지지 않는다(개발 차선은 문서를 쓰지 않는다 ·
`backend/` 전부는 손대지 않는다).

**넘기는 것은 글자 하나다.** 서식 첫 줄에 `KICK_SENTENCE` 와 **토씨까지 같은**
문장을 두면 된다. 이 문장은 테넌트마다 다르지 않으므로 변수로 만들 필요도 없다 —
고정 문장 한 줄이면 족하다. 변수로 등재하려면 이름은 `kick_sentence` 를 권한다.

⚠ 넘긴 채로 두면 셋 중 둘만 같은 글자다. **절반은 초록이 아니다.**
