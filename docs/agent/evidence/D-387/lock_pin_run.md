# lock 고정 — 재현 불가능한 빌드를 닫았다 (D-387)

**실행 2026-09-13** · 도구 `npm`/`vite` (컨테이너 `gx-fe-build`) · 판정 `scripts/verify_deploy_ready.py`

## 0. 왜 이것이 상용을 막는 일이었나

`frontend/package.json` 의 두 의존이 **커밋이 아니라 브랜치**를 가리키고 있었다.
브랜치는 움직인다 — **같은 명령이 시점마다 다른 코드를 가져온다.** 오늘 되던 빌드가
내일 깨지고, 원인은 우리 커밋이 아니라 남의 브랜치가 움직인 것이다. 그 상태로는
**배포할 때마다 다른 것이 나갈 수 있다.**

## 1. 지금 우리가 서 있는 땅 [실측 2026-09-13]

설치본의 진실은 컨테이너 `gx-fe-build:/app/package-lock.json` 에 있었다 —

2. `package.json` 의 두 git 의존을 **커밋 핀**으로 바꿨다 (위 해시). lock 안의 명세도 함께.
3. 브랜치 참조 **전수** — 저장소의 `package.json` 은 하나뿐이고, git 의존은 둘이며,
   **둘 다 고정됐다. 잔여 0건** [실측 · `verify_deploy_ready.py` 가 매번 다시 센다]

⚠ 첫 시도는 **JS 힙 부족으로 죽었다**(기본 2GB). `NODE_OPTIONS=--max-old-space-size=6144`
로 넘겼다. 이것은 판 어긋남이 아니라 **번들 크기**의 문제다 — 둘을 섞어 읽지 말 것.

⚠ **비교 방법을 한 번 고쳤다** (D-350). 1차 대조는 `find | xargs md5sum` 이었고,
`Full Version-Black-….png` 처럼 **이름에 공백이 있는 4개를 조용히 건너뛰고도**
「전부 일치」라고 말했다. `-print0 | xargs -0` 로 고쳐 197/197 을 실제로 셌다.
**빠뜨리고도 초록인 대조가 이 국면이 잡으려는 바로 그 모양이다.**

## 4. 확인하지 못한 것 — **부재도 근거를 적는다** (D-389)

**핀이 실제로 그 커밋을 가져오는지는 이 환경에서 못 봤다.**

```
$ git ls-remote git+ssh://git@192.168.0.22/HuyPhat/rj-core.git
ssh: connect to host 192.168.0.22 port 22: Connection refused          [실측 2026-09-13]
```

사내망 저장소에 닿지 못하므로 `npm ci` 로 **처음부터 설치해 보는 갈래를 돌리지 못했다.**
그래서 이 문서가 말하는 재현성은 **번들의 재현성**이고 **설치의 재현성이 아니다.**
「검사하지 못했다」와 「0건이었다」는 다르다 (D-301). 해소는 사내망에서 `npm ci` 1회.
