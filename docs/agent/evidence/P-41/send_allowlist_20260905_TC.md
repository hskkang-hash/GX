# P-41 — 실발송 허용 도메인 게이트 (첫 측정)

[실측 2026-09-05 · 턴 TC · 차선 Q] 판정기 `scripts/verify_send_allowlist.py` ·
강제 `backend/kernels/k2_notify/channels.py::EmailChannel.send_allowed` ·
이름 `backend/config/settings.py :: K2_SEND_ALLOWED_DOMAINS · K2_OPS_ALERT_ROLE_CODES`

> 채널을 켜기 전에 「실발송 허용 도메인 목록」 게이트를 먼저 건다. 목록 밖 도메인은
> 채널이 `email` 이어도 **로그 어댑터로 강제**한다. — 세종 판정 P-41

## 1. 왜 게이트가 채널 스위치보다 앞에 서는가

[실측 2026-09-05 · 턴 B → 이 턴 재확인] 규칙이 고르는 **수신자 항목 42** ·
**고유 주소 15명** · 도메인 `yopmail.com 8 · org.kr 4 · seed.invalid 3`.
(턴 B 의 「42명」은 규칙×사람 항목 수이고, 그중 **서로 다른 주소는 15개**다. 두 수는
같은 것을 다르게 센 것이므로 **둘 다 적는다** — 한쪽만 적으면 다음 사람이 못 맞춘다.)

즉 지금 `K2_ALERT_CHANNEL=email` 로 바꾸면 **개발 계정(yopmail·seed.invalid) 11명**
에게 진짜 경보가 나간다. 「보내기로 정했다」와 「이 사람에게 보내도 된다」는 다른
판단이고, 뒤엣것을 앞엣것이 대신하게 두면 **첫 발송이 곧 사고**다.

## 2. 강제는 게이트가 아니라 **런타임**에 있다

`EmailChannel.send()` 는 `send_mail` **앞에서** `send_allowed(address)` 를 부르고,
목록 밖이면 **로그 어댑터로 떨어뜨린 뒤 되돌아간다.** 보내고 나서 세는 것은 늦다 —
나간 메일은 취소되지 않는다.

떨어뜨린 발송은 `ok=False` 로 답한다. **로그에 닿은 것을 사람에게 닿았다고 말하지
않기 위해서다**(D-284). 사유는 발송 이력의 `failure_reason` 에 그대로 남는다:
「실발송 차단 — 로그 어댑터로 떨어뜨렸다. … 허용 도메인 목록 밖이다(P-41)」.

**비어 있으면 전부 로그다.** 「목록을 잊었다」가 「전부 허용」이 되지 않게 —
바닥값이 빈 튜플인 이유이고, 타임아웃의 바닥값과 방향이 반대인 이유다.
대조는 **정확히 같은 도메인**이다. 꼬리 일치를 쓰면 `notyopmail.com` 이
`yopmail.com` 을 타고 나간다.

## 3. 판정 — 일곱 수 (`[SEND-ALLOWLIST]` · exit 0)

    강제가 코드에 있다 (AST)      send_allowed @225 · send_mail @233   ← 순서를 구문으로 본다
    빈 목록이면 전부 로그          목록이 비면 실발송 0
    음성 대조 — 목록 밖은 안 나간다  'dev-account-12@yopmail.com' → 발송함 **0통** ·
                                 outcome.ok=False · **로그 어댑터로 떨어짐=True**
    양성 대조 — 목록 안은 나간다     'duty@allowed.example' → 발송함 1통 · ok=True
    꼬리 일치로 새지 않는다         notyopmail.com 은 yopmail.com 을 타지 못한다
    개발 계정에 실발송 0 (실측)     항목 42 · 고유 15명 · 켜면 실발송 0명 / 로그 강제 15명
    운영 경보는 U5 시스템관리자만    K2_OPS_ALERT_ROLE_CODES=[] ⊆ K3_ROLE_SYSOPS=['admin']

### ★ 음성 대조가 이 판정기의 심장이다

「막는 코드가 있다」는 AST 가 본다. 그러나 코드가 있어도 순서가 어긋나면, 설정이
다른 이름으로 읽히면, 어댑터가 바뀌면 그것은 **안 문다**. 그래서 목록 밖 주소로
**실제로 `EmailChannel().send()` 를 부르고** 발송함이 0통인 것과 그 통지가 로그
어댑터로 떨어진 것을 **둘 다** 잰다. 물지 않는 문지기는 세워 둔 것과 같다.

⚠ 판정기는 **진짜 SMTP 로 보내지 않는다.** 컨테이너의 `EMAIL_BACKEND` 는 smtp 지만
음성·양성 대조는 그 자리에서 locmem 으로 바꿔 놓고 잰다. 「보냈다」의 증거는
발송함이지 남의 수신함이 아니다 — 판정기가 사람에게 메일을 보내면 그 판정기가 사고다.

### ★ 문다는 증거 — 허용 목록에 `yopmail.com` 을 넣어 보았다

    K2_SEND_ALLOWED_DOMAINS=yopmail.com → **exit 1**
    X 개발 계정에 실발송 0 (실측) … 켜면 실발송 8명 / 로그 강제 7명
      — **개발 계정 8명이 허용 목록을 타고 나간다(yopmail.com).** 이 수만큼 사고가 난다

허용 목록은 사람이 손으로 적는다. 급할 때 개발 도메인을 적는 순간 게이트가 「목록
안이니 통과」라고 말하면 그 게이트는 **사고를 승인한 게이트**다. 그래서 알려진 개발
도메인이 허용 목록에 섞여 들어간 것만 따로 잡는 **덫**을 둔다 — 정책은 여전히
허용 목록 하나뿐이고, 덫은 그 정책을 대신하지 않는다.

## 4. 시험 쪽에 남긴 것 — **초록의 뜻이 바뀌었다**

「메일이 실제로 나갔다」를 재는 시험 6개(K2 커널·OPS-10·안부 요약·FX-5 주소·E2E 1·2)에
`@override_settings(K2_SEND_ALLOWED_DOMAINS=[...])` 를 **명시**했다. 밝히지 않고 서는
초록은 운영에서 재현되지 않는다 — **운영의 목록은 비어 있기 때문이다.**
그리고 `tests/test_e_ops10_alert_routing.py::SendAllowlistTest` 넷을 새로 세웠다
(목록 밖 0통 · 목록 안 1통 · 빈 목록 0통 · 꼬리 일치 거절).

## 5. 아직 사람이 정해야 하는 것

- `K2_SEND_ALLOWED_DOMAINS` 의 **실값**(대표가 준다 · 로컬 `.env` · D-204).
  저장소에는 이름만 있다. 비어 있는 동안 실발송은 **0건**이다.
- `K2_OPS_ALERT_ROLE_CODES` 의 실값. 비어 있으면 **아무도 안 받는다**(안전한 쪽).
  넣을 수 있는 값은 `config/k3_roles.K3_ROLE_SYSOPS` = `('admin',)` 뿐이다 —
  게이트가 그 밖의 코드를 빨강으로 잡는다.
- 운영 경보(`ops_monitor --check` exit 1)를 **보내는 자리**는 아직 없다. 지금은 종료
  코드만 낸다 — 그 배선이 생기는 날 이 역할 목록이 처음으로 쓰인다.
