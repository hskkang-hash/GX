## §1 창 전에 잰 것 (2026-09-22 · 창 안에서 다시 재지 않는다)

### 컨테이너 둘은 **손으로 `docker run`** 했다 — compose 로는 못 고친다
```
gx-celery-e    image=guardianx-backend:latest   compose_project=(빈 값)   restart=unless-stopped
  entrypoint=[python]
  cmd=[-m celery -A config worker -l INFO --concurrency=2 --time-limit=600
       --soft-time-limit=300 -n gx-worker-e@%h]
gx-gunicorn-e  image=guardianx-backend:latest   compose_project=(빈 값)   restart=unless-stopped
  entrypoint=[python]
  cmd=[-m gunicorn config.wsgi:application --bind 0.0.0.0:8000 --workers 4 --threads 4
       --worker-class gthread --timeout 120 --access-logfile - --error-logfile -]
```
⚠ `com.docker.compose.project` 가 **빈 값**이다 — `docker-compose.yml` 을 고쳐도 **지금 도는 것에는 안 닿는다.**
(`docker-compose.yml` 자신이 이 사실을 주석으로 적어 두었다.)

### 마운트 — **celery 가 다섯, gunicorn 이 하나.** 다르다. 섞지 마라
```
gx-celery-e
  bind   <repo>/backend                          -> /app                        rw
  volume gx_backup_vault_e                       -> /backup                     rw   ★ 금고
  bind   <repo>/docs/agent/evidence/D-373        -> /docs/agent/evidence/D-373   rw   ★ 판정문 쓰는 자리
  bind   <repo>/backend                          -> /repo/backend               ro
  bind   <repo>/scripts                          -> /repo/scripts               ro
gx-gunicorn-e
  bind   <repo>/backend                          -> /app                        rw
```
망 둘 다 `gx-main-network` · 포트 바인딩 **없음**(nginx 가 앞에 선다).

### 환경 — **VAPID 가 둘 다에 없다** [실측 · 이름 기준]
`docker inspect` 의 env **이름**을 세었다: `VAPID` 를 포함하는 이름 **0개** —
`gx-celery-e` 0 · `gx-gunicorn-e` 0 · `gx-shell` 0.
**이것이 고객의 「내 기기로 한 통」이 503 인 이유다.**
그 밖 48개 이름(`DB_*` · `SMTP_*` · `MINIO_*` · `OPENSEARCH_*` · `DJANGO_*` …)은 그대로 옮겨야 한다.
⚠ **값은 이 문서에 한 자도 적지 않는다.** 옮길 때도 이름으로만 옮긴다(§3-2).

### 이미지 — 왜 다시 지어야 하나
```
guardianx-backend:latest   created 2026-02-10
컨테이너 안: Debian 13 (trixie) · postgresql-client-17 17.7-0+deb13u1 · libpq5 17.7
```
trixie 기본 저장소가 17 까지만 준다. **PGDG 저장소를 붙여 `postgresql-client-18`** 을 더한다
— `backend/Dockerfile` 에 **이미 적어 두었다**(턴 AD 전날 · 커밋됨).
⚠ 17 을 **지우지 않는다.** 18 을 더하고 `pg_wrapper` 가 높은 판을 고르게 둔다 —
**그 선택이 실제로 18 인지는 지은 뒤 눌러서 확인한다.** 가정하지 않는다.

## §2 순서 — 되돌릴 수 있는 차례대로

### ㉡ ~~12:00~12:15 이미지 짓기~~ → **이미 끝났다** (09-22 저녁 · 조율자)

**이 단계는 창 전날 밤에 했다. 내일은 0분이다.**

```
docker build -t guardianx-backend:pg18 -f backend/Dockerfile.pg18 backend     # rc 0
docker run --rm --entrypoint pg_dump guardianx-backend:pg18 --version
  → pg_dump (PostgreSQL) 18.6 (Debian 18.6-1.pgdg13+2)      ★ 서버 18.1 이상 — 됐다
docker run --rm --entrypoint ls guardianx-backend:pg18 /usr/lib/postgresql/
  → 17 18                                                    ★ 17 을 안 지웠다
docker run --rm --entrypoint pg_dump guardianx-backend:latest --version
  → 17.7                                                     ★ :latest 는 안 건드렸다
```

#### ★ 전날 밤에 해 보고 알아낸 것 둘 — **창 안에서 알았으면 창을 잃었다**

**① `backend/Dockerfile` 로는 이 PC 에서 못 짓는다.**
```
#11 22.47  fatal: Could not read from remote repository.
ERROR: ... "pip install --no-cache-dir -r requirements.txt" exit code: 1
```
`requirements.txt` 가 **비공개 저장소**(rj-core · dj-core)를 `--mount=type=ssh` 로 받는데
이 PC 엔 **ssh-agent 가 없다**(`ssh-add -l` → 연결 불가).
→ 그래서 **다시 짓지 않고 얹는다**: `backend/Dockerfile.pg18` 은 `FROM guardianx-backend:latest`
로 시작해 **apt 한 겹**만 더한다. pip 도 SSH 도 안 탄다. **1초에 지어졌다.**
⚠ `backend/Dockerfile` 의 PGDG 블록은 **정본 조리법으로 남겨 둔다**(열쇠가 생기는 날을 위해).
  그리고 그 블록은 `pip` **뒤로** 옮겼다 — 앞에 두면 비싼 층이 전부 무효화된다.
  **붙이는 자리가 곧 창의 길이다.**

**② 확인 명령에 `--entrypoint` 가 없으면 앱이 뜬다.**
이 이미지는 `ENTRYPOINT ["/entrypoint.sh"]` 라 `docker run --rm <태그> pg_dump --version` 은
**celery 와 beat 를 띄우고** minio·opensearch 를 찾다가 화면을 수천 줄로 덮는다.
반드시 `--entrypoint pg_dump ... --version` 으로 부른다.

### ㉢ 12:15~12:20 — **VAPID 값을 금고에서 꺼낸다** (새로 만들지 않는다)
- U3 이 되살려 둔 값. `.env*` 와 저장소에는 **쓰지 않는다.**
- 확인은 **이름 · 길이 · sha256 앞 12자**까지만 기록한다. **값은 어디에도 안 적는다.**
- 없으면 **VAPID 는 이 창에서 뺀다**(백업만 하고 넘어간다). 없는 값을 지어내지 않는다.

### ㉣ 12:20~12:30 — **한 통씩** 재생성 (★ 동시 0)
**`gx-celery-e` 먼저.** 백업이 도는 곳이고, 죽어도 API 는 살아 있다.

```
# 1) 지금 인자를 파일로 떠 둔다 (되돌리기용 · 값은 안 찍는다)
docker inspect gx-celery-e > <scratch>/gx-celery-e.before.json

# 2) 멈추고 이름을 비킨다 — ★ 지우지 않는다

docker stop gx-celery-e-old

# 3) 새 이미지로 띄운다 (마운트 다섯 · 망 · env 전부 그대로 + VAPID 셋)
docker run -d --name gx-celery-e --restart unless-stopped --network gx-main-network \
  --env-file <금고 env 파일> \
  -v <repo>/backend:/app \
  -v gx_backup_vault_e:/backup \
  -v <repo>/docs/agent/evidence/D-373:/docs/agent/evidence/D-373 \
  -v <repo>/backend:/repo/backend:ro \
  -v <repo>/scripts:/repo/scripts:ro \

    --time-limit=600 --soft-time-limit=300 -n gx-worker-e@%h

# 4) 눌러 확인
docker exec gx-celery-e pg_dump --version        # → 18.x

```
⚠ **`--env-file` 을 쓴다.** 명령줄(argv)에 비밀 0 — `-e KEY=VALUE` 로 값을 쓰지 않는다.
⚠ **MSYS 경로 함정**: Git Bash 에서는 `MSYS_NO_PATHCONV=1` 을 앞에 붙인다.
  안 붙이면 `/app` 이 `C:/Program Files/Git/app` 으로 바뀐다(이 저장소가 이미 만난 함정).
⚠ **`gx-celery-e-old` 를 지우지 않는다.** 되돌릴 것이 남아야 창이다. 정리는 대표 한 줄로.

**살아난 것을 확인한 뒤에만** `gx-gunicorn-e` 를 같은 방법으로(마운트는 **하나**).
5분 안에 안 올라오면 **거기서 멈추고 되돌린다**(§4).

## §4 되돌리기 — 한 줄씩

| 어디서 틀어졌나 | 되돌리는 법 |
|---|---|
| ~~이미지가 안 지어진다~~ | **전날 밤에 이미 지었고 눌러 확인했다**(pg_dump 18.6) — 이 칸은 비었다 |
| ~~지었는데 `pg_dump` 가 17 이다~~ | **18.6 임을 전날 밤에 눌러 확인했다** — 이 칸도 비었다 |
| celery 가 안 올라온다 | `docker rm gx-celery-e && docker rename gx-celery-e-old gx-celery-e && docker start gx-celery-e` |
| gunicorn 이 안 올라온다 | 같은 방법. **celery 는 이미 새것이어도 둔다**(백업은 celery 몫) |
| 덤프가 떠도 바이트가 0 | 판정기가 빨강을 낸다. **절을 올리지 않는다.** 그대로 보고 |
| VAPID 를 못 찾았다 | 그 부분만 뺀다. 백업은 그대로 간다 — **둘은 서로 묶이지 않는다** |

★ **되돌린 것도 보고에 적는다.** 「했다가 되돌렸다」와 「안 했다」는 다른 사실이다.
