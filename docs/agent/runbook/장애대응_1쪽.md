## 0. 첫 3분 — 무엇이 죽었는지부터

```bash
docker exec -e DJANGO_SETTINGS_MODULE=config.settings gx-shell \
    python /repo/scripts/ops_monitor.py --check
# exit 0 정상 · 1 경보 · 2 판정 불가(못 쟀다 — 초록이 아니다)
```

| 신호 | 빨간불의 뜻 | 첫 손 |
|---|---|---|
| `db_ping_ms` | DB 가 느리거나 죽었다 | §1 |
| `cache_alive` | Redis 가 죽었다 | §2 |
| `object_store_alive` | 영상 저장소가 죽었다 | §3 |
| `latest_event_age_min` | 파이프라인이 멈췄다 (탐지가 안 들어온다) | §4 |
| `unsent_deliveries` | 알림이 안 나간다 (F-10 30초 약속이 깨진다) | §5 |
| `db_size_gb` | 디스크가 찬다 | §6 |

★ **`UNKNOWN` 을 정상으로 읽지 마라.** 못 잰 것이지 괜찮은 것이 아니다(D-301).

## 1. DB 가 느리다·죽었다

```bash
docker ps --filter name=postgres              # 떠 있나
docker logs --tail 50 postgres                # 마지막 말
docker exec postgres psql -U postgres -c "SELECT count(*) FROM pg_stat_activity"
```
- 커넥션이 상한에 붙었으면 → 앱을 먼저 재기동한다(`docker restart gx-backend`). DB 를 먼저 죽이지 않는다.
- 디스크가 찼으면 → §6.
- **되돌릴 수 없는 명령을 여기서 치지 않는다.** `DROP`·`TRUNCATE`·`VACUUM FULL` 금지.

## 2. 캐시(Redis)가 죽었다

- 시스템은 **선다.** 캐시는 없어도 되는 부품이다 — 느려질 뿐이다.
- `docker restart redis` 후 `ops_monitor.py` 재실행.
- ★ 재기동 뒤 **캐시가 비었다**는 것을 기억할 것: 응답이 한동안 느리다. 그건 장애가 아니다.

## 3. 영상 저장소(객체저장)가 죽었다

- 이벤트 기록·알림은 **계속 나간다**(저하 운전). 막히는 것은 **영상 재생·클립 추출**뿐이다.
- 저장소를 살린 뒤, 죽어 있던 동안의 이벤트는 **영상 없는 이벤트**로 남는다 — 그건 손실이고 기록한다.

## 4. 탐지가 안 들어온다 (`latest_event_age_min` 이 계속 커진다)

```bash
docker logs --tail 100 gx-backend | grep -i "grpc\|rtsp\|detect"
```
- AI 서버가 죽었나 · 카메라 RTSP 가 끊겼나 · 우리 파이프라인이 멈췄나 — **셋을 가른다.**
- 카메라 한 대만 조용한 것과 전부 조용한 것은 다른 사고다. `cameras` 신호와 함께 본다.
- ★ **밤에는 조용한 것이 정상일 수 있다.** 이 임계값(60분)은 운영 데이터로 조여야 하는 첫 후보다.

## 5. 알림이 안 나간다 (`unsent_deliveries` 가 쌓인다)

- 발송 실패는 **행으로 남는다**(`succeeded=False` + `failure_reason`). 먼저 그 사유를 읽는다.
- 「보낸 적 없음」(행 없음)과 「보내다 실패」(행 있음)는 다른 사고다 — 앞은 파이프라인, 뒤는 발송처.
- SMTP·외부 발송처가 죽은 것이면 시스템은 계속 돈다. **이벤트는 쌓이고 알림만 밀린다.**

## 6. 디스크가 찬다

- 먼저 **무엇이** 찼는지: DB(`db_size_gb`) 인가 객체저장인가.
- 지우기 전에 **백업**한다(§7). 지운 뒤에 백업할 수는 없다.

## 7. 백업 · 복구 — 이 순서로만

```bash
# 백업 (클라이언트 판이 서버 판과 맞는 자리에서 뜬다)
python scripts/ops_backup.py --db --objects --via docker:postgres \
    --out docs/agent/evidence/D-354/backup

# 복구 시험 — **임시 DB 로만.** 원본 이름을 주면 스크립트가 거부한다
python scripts/ops_restore.py --via docker:postgres \
    --manifest docs/agent/evidence/D-354/backup/manifest.json
```

- ★ **복구를 해 보지 않은 백업은 백업이 아니다.** 최근 복구 성공 기록: `evidence/D-354/restore_run.md`
- ★ 실운영 복구는 **이 문서가 아니라 대표·기획의 판정**으로 시작한다. 혼자 하지 않는다.

## 8. 여기서 멈추고 사람을 부르는 선

| 상황 | 하지 말 것 | 부를 사람 |
|---|---|---|
| 데이터가 사라진 것 같다 | 아무것도 쓰지 마라. 재기동도 하지 마라 | 대표 · 가이온 2차 |
| 익명이 데이터를 받고 있다 | 로그만 남기고 경로를 막아라 | 대표(보안 사고) |
| 원인을 모르겠다 | 추측으로 설정을 바꾸지 마라 | 가이온 2차(1영업일) |

**에스컬레이션**: 1차 에스비 4영업시간 → 2차 가이온 1영업일.

## 9. 이 문서가 아직 못 적는 것 — 정직하게

- **실운영 복구 절차** — 임시 DB 복구만 해 봤다. 실운영 자리에 되돌린 기록은 없다.
- **되돌리기(배포 롤백)** — 절차 문장은 매뉴얼 §5 에 있으나 **되돌려 본 기록이 없다.**
  해 본 적 없는 절차는 절차가 아니다 — 상용 표 ④의 `OPS-08` 이 그래서 아직 '미측정'이다.
- **경보 발송처** — `--check` 의 exit 1 을 사람에게 보내는 자리(메일·문자·챗)는
  고객 환경마다 다르므로 여기서 정하지 않았다. 설치 시 정한다.
