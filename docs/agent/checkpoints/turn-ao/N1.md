## ⑤ 스스로 의심하는 점

- **소급 방법의 한계** — 5개 읽기전용 조사를 병렬로 돌려 39건을 교차 대조했다.
  각 id 의 `retro` 칸에 "무엇을 대조했는지"를 적었지만, 이 차선(N1) 스스로
  코드를 한 줄씩 전부 다시 실행해 본 것은 아니다(대부분은 이미 있는 pytest
  결과·서비스 파일 docstring·spec 원문 대조). 조율자가 특히 의심할 만한 곳:
  FWS-F6-06(「DSM」이 저장소 내부 DSM App 인지 국가망인지 제목 해석이 갈릴 수
  있다) · FWS-F6-08/F6-10(같은 코드 경로를 공유하는 두 kind 값 중 하나만 HTTP
  로 직접 두드렸다 — 코드 분기가 없어 닫힘으로 셌지만 전용 시험은 아니다).
- **WO 문서의 "40"과 실측 "39"가 다르다** — 판정기 출력을 정본으로 삼았다
  (`_규약.md`·WO-18 §3 모두 "판정기 출력 정본"을 명시). 조율자가 혹시 다른
  절 하나를 더 기대했다면(예: 이미 초록이라 게이트가 「옛 승격」으로 안 세는
  절), 그건 이 차선이 놓친 것이 아니라 애초에 게이트가 재는 대상(영역 7)
  밖일 수 있다 — 확인 부탁.
- **DSM-U5-05 body 5줄 변경** — `test_u1_handover_and_note.py`(다른 차선 소유)가
  `assertGreaterEqual(len(body.splitlines()), 4)` 로만 재서 깨지지 않는 것을
  확인했지만, 그 파일을 이번 턴에 직접 돌려 보지는 못했다(파일 소유가 아니라
  gx-shell 시간을 더 안 썼다) — 조율자 전량 실행에서 재확인 부탁.
- **동시 docker exec** — 이 턴 초반에 실수로 두 개(`handover_roster`/`annual_stats`
  묶음과 `u4_rest`/`f6_07` 묶음)를 겹쳐 띄웠다(규약 위반 — 「한 번에 하나」).
  다른 차선(O·Q·L)도 같은 시각 gx-shell 을 썼던 것으로 보여 두 실행 모두
  6~8분씩 걸렸다 — 결과 자체는 정확했지만(44 passed·8 passed), 앞으로는
  순차로만 부르겠다.
