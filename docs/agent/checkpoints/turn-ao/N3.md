## ⑤ 스스로 의심하는 점

0. **[조율자 지적 · 해결됨]** `python scripts/verify_layers.py` 가 `ops_an_service.py`
   의 `from kernels.k5_trust import inbound_keys`(비공개 하위 모듈 직접 import)를
   금지①로 잡았다. `rotate_key` 는 `kernels/k5_trust/__init__.py::__all__` 에
   이미 오른 공개 면 이름이라 `from kernels.k5_trust import rotate_key` 로
   고쳤다 — `verify_layers.py` 재실행 **위반 0건**(분모 129) 확인.
1. **O-01 의 "역할 홈"** — 완결조건 뒤 절반을 "role=admin 이 K3 MANAGER
   프리셋에 이미 배선돼 있다"는 **정적 근거**(config/k3_roles.py)로 대신
   했다. 실제로 새 관리자 계정이 로그인 뒤 **화면**(프리셋 판정 API)까지
   찍어 확인하지는 않았다 — 로그인(JWT 발급)까지만 실측이고, 그 뒤 "역할
   홈이 실제로 그려지는가"는 다음 사람이 한 번 더 밟아 보면 좋겠다.
2. **O-01 의 초기 관리자 생성 경로** — 처음에는 `POST /api/v1/user/create-user`
   를 익명으로(인프로세스 `django.test.Client`) 불렀는데, 이 저장소의
   `common/access_gate.py::AccessGateMiddleware`(`AUTHN_REQUIRED_PATHS`)가
   바로 그 경로를 "dj-core 원본에 권한 검사가 없는 알려진 구멍"이라 자격증명
   없는 요청만 막아 두고 있었다 — 401 을 실측하고서야 알았다. 고친 방법:
   **바깥 요청(U0)의 Authorization 헤더를 그대로 안쪽 호출에 물려준다**
   (새 세션 안 만든다). 이 판단이 "이미 인증된 U0 의 대행"인지 "새 구멍"인지
   조율자가 한 번 더 봐 주면 좋겠다 — 내 생각엔 전자다(익명은 여전히 막힘,
   U0 문지기(`_require_operator`)를 반드시 먼저 지나야 이 경로에 온다).
3. **감사 스냅샷 = "새 모델 0"의 해석** — O-02·O-06·O-09·O-12 의 "저장"은
   전부 `logger.AuditLogs` 에 `data_after` 로 전체 스냅샷을 싣고 "같은 키의
   최신 행"으로 현재 상태를 접어 읽는다. 이것이 §7 완결조건이 말하는 "행"
   (`k_app_installation` 등 전용 표)과 같은 무게인지는 논쟁 여지가 있다 —
   `O-02.json` 의 title_parts 에 "전용 모델이 없어 감사 스냅샷 행으로
   대신함"이라 정직하게 적어 뒀다. 세종/조율자가 이 대체를 인정하는지 확인
   부탁드린다.
4. **O-05 자동 인시던트의 dedup 키** — `summary.startswith("[건강 보드 자동]")`
   로 "이미 열린 자동 인시던트"를 찾는다. 요약 문자열에 의존하는 것이 약한
   키다 — 다음 사람이 더 단단한 태그(예: `source="health_board"` 칸)로
   바꾸면 좋겠다. 지금은 새 칸을 안 늘리려고 문자열로 했다.
5. **O-08 의 "테넌트별"** — 실제로는 현재 이 환경에 진짜 테넌트가 거의
   없어(시험 데이터 기준) "테넌트별 D-day 진행"이 사실상 한두 행이다. 로직은
   맞지만 다중 테넌트 환경에서 재확인이 필요하다.
6. **동시성** — `_audit_rows` 가 계열 전체를 매번 읽어 파이썬에서 접는다
   (예: 인시던트 목록이 커지면 O(N)). 지금 규모에선 문제없지만 "전건" 이
   수만 건이 되는 날엔 DB 쪽 집계로 옮겨야 한다.
