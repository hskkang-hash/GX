## ⑤ 스스로 의심하는 점

- **U6-01 인증이 세종 판정의 문자를 반쪽만 따랐을 수 있다.** 지시서는 "인증은
  JwtOrInboundKey(들어오는 키 inbound_api_key)"라고 적었다. `common/
  inbound_api_key.py` 클래스 이름은 그대로 썼지만 `inbound_key=True`(라우트가
  실제 API 키를 받는 갈래)는 **주지 않았다** — `tests/test_f05_inbound_api_key.py::
  ReadOnlyTest::test_no_write_route_accepts_an_inbound_key` 가 "쓰기 라우트에
  들어오는 키를 연 것 0건"을 강제하고, 그 허용 목록이 `common/access_gate.py::
  INBOUND_KEY_ALLOWED` · `docs/agent/evidence/D-343/route_classes.yaml` 과
  삼각형으로 맞물려 있어 한 차선이 셋을 동시에 안전하게 못 고칠 것으로 판단했다.
  대신 **JWT + HMAC 서명 검증**(위조 방지의 실제 문지기)으로 절충했다. 만약
  세종 판정이 정말 "발급된 API 키로 외부 시스템이 직접 부른다"는 뜻이었다면
  이 절은 인증 모양이 반쪽이다 — 그 경우 별도 창(세 파일을 한 커밋에서 함께
  고치는 창)이 필요하다.
- **U6-03 "LAW-05 범위"의 해석이 임의적이다.** 저장소 안 "LAW-05" 는 SLA(가용성·
  응답·복구)를 가리키는 id 라 재식별 검색과 직접 연결되지 않았다(grep 실측).
  "감사 줄 1"을 문자 그대로 따르고 재식별 AI 를 짓지 않는 쪽으로 좁혀 읽었다 —
  다른 뜻이었다면(예: 별도 법적 문서 표) 이 절은 반쪽일 수 있다.
- **U3-01 의 역할×유형 문안 표는 이 차선이 새로 지은 값**(명세가 준 예시 한
  줄 "시설 담당 「도로 통제 후 회신」" 외 나머지 15줄)이다. 실제 재난안전과
  운영 매뉴얼과 문구가 다를 수 있다 — 문구 자체의 정확성은 대표·현업 검수가
  필요하다.
- 인접 시험 회귀(EVENT_ENTRY_SURFACE 핀 시험)가 "실패"로 뜨지만 이것은 **여러
  차선이 동시에 새 라우트를 여는 이 턴의 구조적 상태**이지 내가 깬 것이 아니다
  — 그래도 조율자가 그 판단에 동의하지 않을 가능성을 열어 둔다.
