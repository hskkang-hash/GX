## 3. 본 일 ③ — U6 5행의 원인을 **이름으로** [실측]

### 원인 (짐작 아님 · 바이트로 댐)

> **`measure_onboarding_t.py:446 api_token()` 이 `web`(= `--web`, 기본 `http://localhost:3002`)으로
> `/api/v1/auth/login` 을 POST 했다. 3002 은 API 가 아니라 `SimpleHTTP/0.6 Python/3.11.14`
> **정적 SPA 서버**(`gate_spa_server.py`)다 — POST 를 모르고 **501 `Unsupported method ('POST')`
> 를 `text/html;charset=utf-8` 로** 낸다. `r.json()` 이 `JSONDecodeError` 로 터지고
> `api_token` 이 `None` 을 돌려주어 U6 다섯 행이 「기계 자격이 없다」 회색이 됐다.**

```
# gx-shell 안에서, 같은 자격으로 두 원점에 같은 본문을 보냈다
8000 → 200 · application/json · success:true · user.access_token  (len 1109)
3002 → 501 · text/html;charset=utf-8 · b'<!DOCTYPE HTML>…Unsupported method (\'POST\')' (len 357)
3002 GET /  → 200 Server=SimpleHTTP/0.6 Python/3.11.14
3002 GET /api/dsm/events → 404 "this is the SPA static server, not the API"
```

### 네 가설을 **하나씩 기각** [전부 실측]

| 가설 | 판정 | 근거 |
|---|---|---|
| 계정 자체 문제 | **아니다** | `gxprobe_q` = user_id **112** · `gxprobe_v` = **116** · 둘 다 8000 에서 200 · 토큰 받음 |
| 라우트가 HTML 오류 쪽을 탄다 | **맞다 — 단 3002 쪽만** | 8000 의 `/api/v1/auth/login` 은 정상. HTML 을 낸 것은 **우리가 문을 잘못 골랐기 때문** |
| 속도 제한 | **아니다** | 제한은 실재하나 그때도 **JSON** (`429 · code:"rate_limited" · retry_after_seconds:34`) |
| UX-24 한 세션 제한 | **아니다** | 2회차부터 `session_notice` 키가 붙을 뿐 **계속 200 JSON** |

★ **속도 제한의 실측값이 문서와 다르다** — 지시서는 「5회/분/IP」인데 **4번째 부름부터 429** 가 났다
(연속 8회 중 1·2·3 만 200). 이 한 줄은 N 에게 따로 보냈다.

### 고침 — **U6 전체가 정적 서버를 재고 있었다** (로그인만이 아니다)

`rows_u6` 의 `call()` 도 `web + path` 였다. 그래서 **U6#12·#14·#15 의 빨강은 거짓 빨강**이었다:

| 행 | 어제(3002) | 오늘(8000) |
|---|---|---|
| U6#12 익명 읽기 5건 | 전부 **404** → 빨강 | 전부 **401** → **초록** |
| U6#14 `X-GX-Schema` | 404 · 헤더 없다 → 빨강 | 200 · **`1.1`** → **초록** |
| U6#15 `health` | 404 → 빨강 | 200 · `['db','cache','queue']` → **초록** |

`--api`(`GX_API`, 기본 8000)를 새로 두고 `api_token`·`rows_u6` 를 거기로 돌렸다.
**`--web` 은 사람이 보는 화면, `--api` 는 기계가 두드리는 문** — 한 글자로 둘을 가리키면 이 사고가 다시 난다.

### 그다음 — U3 쪽지 넷을 전부 넣었다

U3 가 이 파일 위쪽에 남긴 명세를 **그대로** 집행했다(U3 는 코드를 한 줄도 안 고쳤다):

- **쪽지 ①** `422` 는 「본문 대신 쿼리」 — django-ninja 는 **맨 스칼라 인자를 `Query` 로 잡는다**(POST 라도).
  `issue_api_key(…, name: str, …)` · `create_webhook_subscription(…, endpoint_url, signing_key_ref, …)` ·
  `advance_response(…, event_id, to_state, …)` 셋 다 그 모양이라 **질의로** 싣게 고쳤다.
  ⚠ 「비밀은 쿼리에 0」과 안 부딪힌다 — 실리는 것은 **이름·주소·참조 이름**뿐이고 `secret` 은 **응답 본문**으로만 온다.
- **쪽지 ①의 덧** 「손으로 지운다」는 **지울 것이 없다** — 422 는 핸들러 앞에서 떨어진다.
  `[되돌릴 것 없음] 422 는 핸들러 앞에서 떨어졌다 — 키 0개 생성` 으로 고쳤다.
- **쪽지 ②** `api_token` 에 **429 를 가르는 길**을 넣었다 — 한 번만 `GAP_SECONDS` 기다렸다 재시도, 두 번째도 429 면 포기하고 **받은 것을 그대로 적는다**.
- **쪽지 ③** `no_cred()` 가 **사유를 짐작하지 않는다.** 이제 `LOGIN_WHY` 에 담긴 **실제 상태·본문 앞부분·때린 주소**를 적는다.
  (어제 「GX_PROBE_PASSWORD 를 주면 잰다」는 **거짓말이었다** — 그 값은 있었고, 틀린 것은 문이었다.)
- **쪽지 ④** `"gxprobe_q"` 하드코딩을 **`GX_PROBE_USER`** 로 바꾸고 `logins` 에 **실제로 쓴 계정**을 적는다.

### 못 한 것 — **정직하게 적는다**

### 「0건 뺐다」와 「못 뺐다」를 **갈랐다**

조용히 안 거르는 것이 가장 나쁜 모양이라는 지적 그대로다. 돌려주는 값의 뜻을 셋으로 나눴다:

| 돌려주는 값 | 뜻 |
|---|---|
| `[]` | 잴 수 있었고 **뺄 것이 0건**이었다 |
| `[id…]` | 잴 수 있었고 **이만큼 뺐다** |
| **`None`** | **못 쟀다 — 거르지 못했다** (분모가 틀릴 수 있다 · D-301) |

**표식 칸이 아예 없는 응답**은 이제 `None` 을 돌려준다 — `is_probe_track` 이 언제나 거짓인 것을
「탐침이 없다」로 읽으면 **분모 0인 초록**이 되기 때문이다. `track_id` 가 실리는 날 갈래는 저절로 산다.
`ImportError` 갈래도 **조용히 안 지나가고** 한 줄 찍는다.

부르는 쪽 증거줄도 사유를 **이름으로** 적게 고쳤다(종전엔 원인을 「정본을 못 불렀다」 하나로 단정했다):

> ⚠ **probe 를 못 걸렀다**(이 수에는 게이트 사건이 섞일 수 있다) — 응답 행에 `track_id` 가 없고
> (`data_source` 는 drill/live 둘만 낸다) 카메라 이름으로 거르는 갈래는 **훈련을 탐침으로 읽어서
> 폐지**했다 (P-201 · P-184). **못 쟀다는 뜻이지 0건이라는 뜻이 아니다**

반드시 넣어라. 표식 없이 쌓이면 다음 사람이 「제품이 만든 것」과 「게이트가 만든 것」을 못 가른다.

### 1-②  임계 저장

| 칸 | 명세 |

턴 U 의 U5#9 가 정확히 그 사고였다. **올리는 쪽**으로 재고 되돌려라.

### 1-④ 분모에 관한 부탁 (A 가 정하지 않는다)

`FLOWS` 는 **48행 고정**이고 자기시험이 그 수를 지킨다(`len(FLOWS) != 48 → 자기시험 깨짐`).

## U3 쪽지 ① — U6#1 · U6#4 의 **422 는 「본문 대신 쿼리」다** [U3 실측 · 격리 재현]

판정기가 보내는 것과 **똑같은 모양**을 관리자 토큰으로 한 번 보냈다:

```
POST /api/dsm/settings/api-keys
Authorization: Bearer <sysop>
Content-Type: application/json
{"name": "u3-probe-noop"}

→ 422 {"detail": [{"type": "missing", "loc": ["query", "name"], "msg": "Field required"}]}
```

`loc` 이 **`["query", "name"]`** 이다. 제품의 시그니처가 이렇게 생겼기 때문이다:

- `backend/apps/dsm/api.py:1058` — `def issue_api_key(self, request, name: str, expires_days: int | None = None, scopes: str = "")`

django-ninja 는 **스키마가 아닌 맨 스칼라 인자를 `Query` 로 잡는다** — POST 라도 그렇다.
그래서 JSON 본문에 실은 `name` 은 **아무 데도 안 닿고** 422 가 난다.
U6#4 의 「구독 422」도 **같은 뿌리**로 보인다(같은 모양의 시그니처 · U3 는 U6#4 는 안 두드렸다).

★ 위 「차선 A 쪽지」의 §0 이 같은 사실을 **설정 세 문에서** 따로 재서 적었다
(「임계·등급규칙은 전부 질의다」). **두 차선이 다른 문에서 같은 모양을 봤다.**

### 고침 명세

```
POST /api/dsm/settings/api-keys?name=<이름>[&expires_days=..][&scopes=..]      (본문 없음)
POST /api/dsm/webhook-subscriptions?endpoint_url=..&signing_key_ref=..        (본문 없음)
```

⚠ **비밀은 쿼리에 0** 이라는 규약과 충돌하지 않는다 — 여기 실리는 것은 **키 이름·주소·참조 이름**뿐이고

적었는데, **422 는 핸들러가 돌기 전에 떨어진 것**이라 **아무것도 안 만들어졌다.**

**읽었고도** 쓰기라 했습니다 — `verify_classification.py:220` 의 `any(v in sql.upper() …)` 가
**부분 문자열**을 봤습니다.

**저장소 전수를 게이트 자신의 `_const_str` 로 다시 셌습니다**(그래야 게이트와 같은 의미가 됩니다):

```
해석된 execute — 부분일치 쓰기 **14건** · 단어경계 쓰기 **5건** · 달라지는 것 **9건**
```

★ **조율자께 정정 둘** — 제 수가 F 의 보고와 다릅니다. 제 것을 적습니다:

| | 조율자가 전한 F 의 수 | **Q 가 다시 잰 수** |
|---|---|---|
| 부분일치 | 11건 | **14건** |
| 단어경계 | 5건 | 5건 (같다) |
| 달라지는 것 | 6건 | **9건** |
| 그 성격 | 「**전부 SELECT**」 | **SELECT 6 · EXPLAIN SELECT 3 · 그중 하나는 `WITH …`** |

차이는 `_const_str` 이 변수에 담긴 SQL·f-string·`+` 이어붙임까지 푼다는 점에서 온 것 같습니다
(저는 게이트의 것을 그대로 썼습니다). **어느 쪽이든 결론은 같습니다** — 아래 9건을 다 읽었습니다.

### 달라지는 9건 — **하나씩 눈으로 읽었다. 전부 읽기다.**

| 자리 | 옛 판정이 집은 동사 | 실제 | 어디서 왔나 |
|---|---|---|---|
| `backfill_owner_apply.py:274` | DELETE | **읽기** | `WITH orphan AS (SELECT …), usage AS () **SELECT** …` — CTE 가 **SELECT 로 끝난다**. 집힌 DELETE 는 `deleted` 칸 |
| `backfill_owner_dryrun.py:75` | DELETE | 읽기 | `l.deleted IS NULL` |

★ 첫 줄이 **이 고침의 유일한 위험한 모양**이었습니다 — `WITH …` 로 시작하는 문은
`WITH x AS (…) DELETE` 처럼 **진짜 쓰기일 수 있습니다.** 그래서 본문을 끝까지 읽었고,
이 자리는 `SELECT` 로 끝납니다. **모양만 보고 넘기지 않았습니다.**

⇒ **세어지던 SQL 쓰기 14건 중 9건(64%)이 거짓 양성이었습니다.**

## 2. 넣은 고침 — 한 자리 + **판정을 한 함수로 모았다**

```python
SQL_WRITE_RE = {_v: re.compile(r"(?<![A-Za-z0-9_])" + _v + r"(?![A-Za-z0-9_])")
                for _v in SQL_WRITE}

def sql_write_verbs(sql: str) -> list[str]:
    """이 SQL 이 쓰는가 — **낱말로** 본다. 빈 목록이면 읽기다."""
    upper = (sql or "").upper()
    return [v for v in SQL_WRITE if SQL_WRITE_RE[v].search(upper)]
```

★ 판정을 **함수 하나**로 모았습니다 — 자기시험도 판정도 이것을 부릅니다.
두 벌로 두면 **자기시험은 통과하는데 판정은 다른 답을 내는** 자리가 생깁니다(D-369).

주석에 **왜 넓어 보이지만 안 느슨한지**와 **「모르면 세는 쪽에 둔다」와 다른 이유**를 박았습니다:
그 규칙은 **SQL 을 못 읽었을 때**(→ `unknown`) 쓰는 것이고, 여기는 **읽었고도 오독한** 자리입니다.

## 7. **안 한 것** — `verify_gates.sh` 이름 등재

조율자 말씀대로 `verify_gates.sh --gate classification` 은 **없는 이름**이라 rc 2(회색)입니다.
이 검사는 `.pre-commit-config.yaml` 의 `gx-classification` 훅으로만 섭니다.

**이번 턴에 등재하지 않았습니다.** 사유:

- `verify_gates.sh` 의 게이트는 이름 한 줄이 아니라 **`gate_<이름>()` 함수**여야 하고,
  `run_gate` 가 `[입력] N건` 표식(`GATE_INPUTS_MARK`)을 **안 찍으면 빨강**을 냅니다
  (「건수 없는 게이트는 게이트가 아니다」· D-301). 그러니 함수를 제대로 써야 합니다.
- 그리고 등재하면 **`verify_gate_counts` 의 「게이트 21종 · 등재 21종」이 22 로 바뀝니다** —
  그 대장과 함께 맞춰야 하고, **지금은 조율자가 커밋 직전**입니다. 병합 창에서 건드릴 자리가 아닙니다.

⇒ 다음 턴 후보로 남깁니다. **못 했다고 적습니다.**

★ 조율자께 한 줄: **rc 2 를 「통과 아님」으로 읽지 않으신 것이 옳습니다.** 그 회색은
「이 게이트가 나쁘다」가 아니라 **「그 이름으로는 아무것도 안 쟀다」**입니다.
