# U24 → U1 (턴 AB · 2026-09-21)

두 가지입니다. **①은 제가 잰 사실이고 ②는 제가 못 지은 자리입니다.** 둘 다 U1 소유 파일입니다.

## ① ★★ U2#4 — **「데스크톱 상세는 사진을 `<img>` 로 안 그린다」가 틀렸습니다**

정본 표(`onboarding_48.md` ◐ 4 줄)가 이렇게 적어 두었습니다:

> U2#4(snapshot 200 jpeg + 주소는 섰으나 `img[src*=snapshot]` naturalWidth>0 이 0 —
> **데스크톱 상세는 사진을 `<img>` 로 안 그린다** · U3#3 모바일은 그린다)

**두 화면은 같은 부품 하나를 씁니다.** 재서 확인했습니다:

```
[실측 2026-09-21 · 턴 AB · 코드 세 갈래]
  frontend/src/features/dsm/pages/EventDetail.tsx:545        <EventSnapshot …/>
  frontend/src/features/mobile/pages/MobileEventDetail.tsx:689 <EventSnapshot … dataGx="snapshot"/>
  frontend/src/features/dsm/components/EventSnapshot.tsx:161  <img src={url} data-gx={dataGx} …/>
  frontend/src/features/dsm/api.ts:338   const url = URL.createObjectURL(blob);
```

곧 **둘 다 `<img>` 를 그립니다.** 갈리는 것은 화면이 아니라 **판정식 두 개**입니다:

| 행 | 판정식 (`scripts/measure_onboarding_t.py`) | 결과 |
|---|---|---|
| U3#3 모바일 | `img` 중 `naturalWidth > 0` 인 것 ≥ 1 | ● |
| **U2#4 데스크톱** | `img` 중 `naturalWidth > 0` **그리고 `src.includes('snapshot')`** | **0** |

★ **`src` 는 `blob:` 입니다.** P-25 가 서명 URL 없이 인증 헤더로 받기로 했기 때문에
(`EventSnapshot.tsx` 머리말) 바이트를 `createObjectURL` 로 싸서 넣습니다. 그 주소에는
`snapshot` 이라는 글자가 **어떤 사건·어떤 씨앗으로도 들어갈 수 없습니다.**

**그러므로 U2#4 의 0 은 제품의 결함도, 씨앗의 결함도 아닙니다 — 판정식의 결함입니다.**
그림 실린 씨앗을 넣어도 그 술어는 **영원히 0** 입니다.

### 제가 못 고치는 까닭 · 고칠 자리 둘

`EventDetail.tsx` 는 **U1 소유**이고 `scripts/measure_onboarding_t.py` 는 **V 소유**입니다.
한 줄씩입니다:

```tsx
// ① frontend/src/features/dsm/pages/EventDetail.tsx:545  (U1)
   <EventSnapshot
     eventId={e.event_id}
     snapshotPath={e.snapshot_path}

+    dataGx="snapshot"        // [P-148] 판정기가 찾는 표식 — 모바일 상세와 같은 자리
   />
```

```python
# ② scripts/measure_onboarding_t.py:1067  (V · 조율자 경유)
-  ".filter(i => i.naturalWidth > 0 && (i.src||'').includes('snapshot')).length"
+  ".filter(i => i.naturalWidth > 0 && i.dataset.gx === 'snapshot').length"
```

⚠ **①만 해서는 U2#4 가 안 섭니다** — 술어가 여전히 `src` 를 봅니다.
⚠ **②만 해도 안 섭니다** — 데스크톱에 표식이 없습니다.
**둘 다 있어야 ● 입니다.** 하나만 넣고 초록으로 적으면 아무도 안 잰 초록이 됩니다.

★ 제가 ①을 대신 넣지 않은 이유: 한 파일은 한 차선이고, 같은 턴에 두 차선이 같은
줄에 손대면 병합에서 한쪽이 조용히 사라집니다. **제 보고에는 이 행을 회색으로 적습니다.**

## ② U2#3 등급 재판정 — **자리도 문도 없습니다. 제 파일 안에 지을 수 없습니다**

WO-04 §3 이 제게 「사건 상세 「등급 다시 매기기」 · 감사 행 1」을 주었는데,
그 자리가 **전부 U1 소유**입니다. 재서 적습니다:

```
[실측 2026-09-21 · 턴 AB]
 ① 화면  EventDetail.tsx:432  등급은 <Tag> 하나 — **읽기 전용**. 고르는 자리 0개
 ② 문    api.py / api_u24.py 에 severity 를 쓰는 라우트 **0건**
         (`POST …/review` 는 **진위 축**입니다 — confirmed/rejected. 다른 축입니다)
 ③ 커널  kernels/k1_event/services.py 에 severity 는 `record_detection` 의 **입력**과
         `_validate` 의 검사뿐 — **바꾸는 함수가 없습니다**
```

곧 ①②③ 어디에도 없고, ③은 U1 의 파일, ①도 U1 의 파일입니다.
**제가 제 파일(`api_u24.py`)에 라우트만 세우면 커널을 건너뛰고 모델을 직접 쓰게 되고,
그것은 D-281(커널 밖에서 모델을 만지지 않는다)을 깨는 일입니다.** 그래서 **안 지었습니다.**

### 설계는 여기 적어 둡니다 — U1 이 서면 저는 한 줄도 안 바꿉니다

| 층 | 자리 | 무엇 |
|---|---|---|
| 커널 | `kernels/k1_event/services.py::regrade_event(*, scope, event_id, severity, reason)` | `_validate` 의 등급 목록을 **그대로** 쓰고(두 벌 금지) 바뀐 `EventView` 를 낸다. **같은 등급으로 다시 매기면 409** — 「눌렀다」와 「바뀌었다」를 200 으로 뭉치지 않는다 |
| 문 | `api_u24.py::POST /events/{int:event_id}/severity` | 제가 셉니다. **U1 이 커널 함수를 세우면 그날 제가 잇습니다** — 한 줄입니다 |
| 감사 | `audit.record_event_action(action="regrade:{전}->{후}")` | **행이 1 늘어야** 이 행이 초록입니다. 감사에 못 남기면 재판정도 일어나지 않습니다(`audit.py` 머리말 규약) |
| 화면 | `EventDetail.tsx` 등급 `<Tag>` 옆 「등급 다시 매기기」 | 누르면 고르는 자리 + 사유 한 칸. **누르기 전/후 말이 달라야** 합니다 |

★ ⚠ **사유를 필수로 두십시오.** 등급은 사람이 나중에 「왜 내렸나」를 반드시 묻는 칸입니다.
  사유 없는 재판정 행은 감사에서 「누가 등급을 낮췄다」만 남고 답을 못 냅니다.

★ ⚠ **오탐 판정(`review`)과 섞지 마십시오.** 「오탐이었다」와 「심각이 아니라 경계였다」는
  다른 사실입니다. 한 문으로 묶으면 오탐률 분모가 등급 조정에 흔들립니다.

**제 보고에는 U2#3 을 회색(넘김)으로 적습니다 — 재서 없음을 확인했고, 제 파일 안에 지을 수 없습니다.**
