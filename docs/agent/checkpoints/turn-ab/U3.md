# ② U3#7 — **POST 의 답을 버리던 자리를 고쳤다**(소스) · **누른 뒤는 회색**

## 무엇이 틀려 있었나 — **화면이 제 말을 믿고 있었다**

서버는 빈 200 을 주지 않는다(`kernels/k1_event/response_flow.py` 마지막 `return`):

```
{ event_id, from, to, allowed_next[], audit_id }
```

그런데 화면은 그 답을 **한 글자도 안 읽고** 버린 뒤 **제가 보낸 값**으로
「〈접수〉 단계로 옮겼습니다」를 적고 있었다. 그것은 **누른 뒤를 본 것이 아니라 누른
것을 본 것**이다 — 서버가 다른 칸으로 옮겨도, 감사 행이 안 남아도 **똑같이 초록**이다.

★ 그 자리가 온보딩 48행에 자국을 남겼다: U3#7 의 술어는 「재조회 전이 + **감사 행 1**」
인데 턴 AA 실행 기록의 그 칸은 **`감사 행=-1`**(못 셌다)이다.
**셀 수 있는 수가 응답 안에 이미 있었는데 화면도 판정기도 안 읽고 있었다.**

## 고친 뒤

```
전:  「〈접수〉 단계로 옮겼습니다.」                     ← 우리가 보낸 toState
후:  「〈접수〉 단계로 옮겼습니다 (미처리 → 접수) · 서버 기록 #<audit_id>.」
                                                       ← 전부 서버가 답한 값
```

- **`audit_id` 가 없으면 그 조각을 안 적는다** — 「실제 값이 없는 문구는 비표시」(턴 AA 불변).
- **시험 장치가 아니다**(P-220): 제품에 같은 모양이 이미 있다 — M4 시험 발송이
  `#{delivery_id}` 를 그대로 적는다(P-160 ③).
- 새 라우트 0 · 새 쓰기 문 0 · 계약 값 0 변경.
- 낱말은 `severity.ts::RESPONSE_STATE_LABEL` 그대로다(`occurred`=「미처리」 · `acknowledged`=「접수」) — **새 낱말 0.**

## ★ 그런데 **누른 뒤를 못 봤다** — 회색

  **실재 id 로는 안 두드렸다**(쓰기 경로를 실재 id 로 두드리면 남의 자료가 바뀐다).

   그리고 `docker cp src <있는 자리>/` 는 **안에 넣으므로** 먼저 `rm -rf <자리>/src` 한다.
4. **「이미 고쳐져 있었나」는 작업본으로 못 가른다.** 동시에 도는 차선이 같은 파일을
   고치고 있으면 그 줄이 **이번 턴 것**일 수 있다. `git status` 로 `M` 을 보고,
   `git show HEAD:<경로>` 로 **지난 커밋의 판**을 봐야 갈린다 — 안 그러면 남의 공을
   내 것으로 적거나, 내 일을 남이 한 것으로 적는다.
