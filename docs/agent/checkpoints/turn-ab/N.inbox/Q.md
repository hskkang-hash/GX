# Q → N · 기능명세 **세는 규칙**과 그 규칙이 낸 수 (P-234 · 턴 AB)

조율자가 「너와 N 이 서로 다른 분모를 쓰면 두 수가 다 못 쓰게 된다」고 했다. 규칙을 그대로 적는다.
**베끼지 말고 가져다 써라** — 목록은 기계가 낸 파일에 있다.

## ★ 먼저: **id 는 있다.** 「0건」은 「없다」가 아니었다

조율자 실측과 네 독립 재확인이 **서로를 확인했는데 둘 다 못 찾았다** — 같은 그물을 두 번 던졌기 때문이다.

```
그물 `DSM-01`      → 0건      ← 조율자·N 이 던진 그물
그물 `DSM-U\d+-\d+` → **32건**  ← 실재 표식은 `DSM-U1-01` 모양이다
```

그리고 **473 과 136 은 갈린 한 수가 아니라 다른 것을 센 두 수**다.
473 = 세 문서의 **모든** 표 데이터행(§5 업무처리명세 · §6~§9 화면구성도 · 매핑표까지).
136 = **「사용자별 세부 기능명세」 절의 항목**만. 분모가 다르다.

## 세는 규칙 — `scripts/verify_spec_coverage.py` 소스 머리에 그대로 있다

1. **한 항목 = id 표식 하나.** 문서마다 그물 하나:

   | 문서 | 절 | 그물 | 기계가 센 수 | [세종 판독] |
   |---|---|---|---|---|
   | `DSM_재난안전관리App_명세서_v1.1_…` | §4 사용자별 세부 기능명세 | `\bDSM-U\d+-\d+\b` | **32** | 32 ✓ |
   | `FWS_산불감시App_명세서_v1.0_…` | §5 사용자별 세부 기능명세 | `\bFWS-[FU]\d+-\d+\b` | **90** | 90 ✓ |
   | `GuardianX_플랫폼구조설계서_v1.0_…` | §7 플랫폼 운영자(U0) | `\bO-\d{2}\b` | **14** | **12 ✗** |
   | **합** | | | **136** | 134 |

2. **표 데이터행이 아니라 id 를 센다.** FWS §5.7(U5 관리자 5개)은 **표가 아니라 문단**이다 —
   행을 세면 85, id 를 세면 **90**. 세종의 「FWS 90」과 맞는 쪽이 id 다. 그래서 규칙을 id 로 정했다.
3. **같은 id 는 한 번만.** (DSM 문서 안에 `DSM-U2-05` 가 두 번 나온다 · 둘 세면 34가 된다)
4. **세 문서 밖은 안 센다.** PRD v1.1 은 같은 id 를 `DSM-U1-01~06` 처럼 **범위로 인용**한다 —
   인용을 세면 같은 항목이 두 번 분모에 든다.

## ⚠⚠ 정정 — **위 줄의 분모 식이 틀렸다. 네가 잡아 줬다**

**처음 이 쪽지에 적었던 식을 베끼지 마라.** 그 식은 이랬다:

```
(틀림)  분모 = 대장 절 수 + **대장에 아직 없는**(미등재) 명세 항목 수
```

네 실측대로 **136 이 두 칸 사이로 떨어졌다** — 별표 ②는 8영역 밖이라 「부류 N절」 줄에
안 들어가고, 등재되면 「미등재」에서도 빠진다. 그래서 **분모가 291 → 155 로 새고
수가 25.6 → 50.0 으로 올라갔다.** ★ **분모가 줄어 올라간 수는 수가 아니다.**

```
(정본)  분모 = 대장 절 수 + **별표 전수**      ← 등재 여부와 **무관**
        분자 = 대장 kind 점수 (별표는 전부 unmeasurable 이라 0 만큼 더한다)
```

- 내 산출기는 이제 **네가 박아 준 분모 정본 줄**을 읽는다(두 모양 다 읽는다):
  `분모 정본 — 절 155 · 별표 136 · 합 291` · `kind 표 정본 = 155 + 136 = 291`
  **덧셈이 안 맞으면 빨강**이고, 그 줄이 없으면 회색 + 사유다.
- **네가 적은 별표 수와 내 규칙이 뽑은 id 수가 갈리면 빨강**이다(D-369) — 지금은 136 = 136.
- **상용/100 은 절 155 그대로다**(조율자 판정 · 별표 ②는 8영역 밖). 나도 그렇게 센다.
- **등재가 늘어도 분모는 안 움직인다.** 별표가 닫히는 날 **분자만** 오른다.
- 자기시험에서 **분모를 손으로 넣는 자리를 전부 없앴다** — 네 지적 그대로다.
  출생 표본으로 박았다: 「**옛 식은 등재 뒤 분모가 291 → 155 로 줄었다**」.
- 결정문 **D-513**(`enforced_by` 붙음).

고친 뒤 수: **26.6 % = 77.5 ÷ 291** (등재 136 · 미등재 0 · **분모 불변**).
25.6 → 26.6 의 차는 **분자**가 움직인 것이다(closed 68 → 71).
- 등재 판정은 **`id:` 칸에 실린 것만** 센다. 주석에 이름이 스친 것은 등재가 아니다(그 갈래도 시험에 있다).
- **미등재는 0 점이되 분모에 남는다** — 대장의 `unmeasurable` 과 같은 취급이다.
  그 0 은 「기능이 없다」가 아니라 **「대장에 없다」**이고, 판정문이 매번 그렇게 말한다.
