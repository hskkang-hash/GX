## ③ ★★ **고장을 하나 만들었다가 재서 고쳤다 — 그리고 규칙을 남겼다**

첫 판은 HTML 이 멀쩡한데 **DOCX 가 아예 안 나왔다**:

```
apps.dsm.docx_export.DocxRenderFailed: IndexError: list index out of range
```

원인을 추측하지 않고 **같은 변환기에 네 모양을 넣어 갈랐다**:

```
[실측 2026-09-21 · htmldocx]
  _row · _row · _pair   →  **FAIL** IndexError        ← 좁은 줄이 먼저
  _pair · _row · _row   →  OK  36,843 B
  _row  · _row · _row   →  OK  36,819 B               ← 폭이 고르면 괜찮다
  _pair · _pair         →  OK  36,830 B
```

**`htmldocx` 는 표의 첫 줄로 열 수를 잡는다.** `_row` 는 `colspan="3"` 이라
**눈에는 네 칸이지만 셀은 둘**이고, 그 차이가 전부였다.

- 고친 자리: ①②③ 절의 줄 차례(넓은 줄 먼저) — 덤으로 **보고 구분과 그 근거가 다른 칸**이 됐다
- **규칙을 `docx_export.py` 머리말에 박았다**(서식을 새로 쓰는 다음 사람이 먼저 읽는 자리)
- **시험으로도 박았다** — `EveryTableHasItsWidestRowFirstTest` 가 **서식 넷 전부**에
  「첫 줄이 가장 넓은가」를 건다. 글자로만 적으면 다음 사람이 안 읽는다.

★ **이 고장은 HTML 을 보면 안 보인다.** 그래서 서식 시험은 **완성된 DOCX 바이트까지** 간다.

## ⑤ U2#2 미처리 0건 — **프리셋마다 0건의 뜻이 다르다**

```
[실측 2026-09-21] 프리셋 다섯 전부가 한 문장이었다:
  「조건에 맞는 이벤트가 없습니다. (요청은 성공했고 0건입니다)」
```

두 군데가 틀렸다. ① 괄호 안은 **바로 아래 줄이 이미 적는 말**이다
(`copy.ts::emptySpeech.why`) — 같은 상자에 같은 문장이 두 번 있었고, 그것은 사람의 말이
아니라 **응답 상태**다(`Reports.tsx` 에서 턴 W 에 같은 이유로 지운 문장이다).
② 관제팀장이 **미처리 보기**에서 보는 0건은 「자료가 없다」가 아니라
**「지금 손댈 것이 없다」**이고, 그것은 팀장이 듣고 싶어 하는 **좋은 소식**이다.

- 프리셋 다섯에 `emptyText`·`emptyNext` 를 각각 두었다
- ⚠ **「전부 종결됐습니다」라고 안 적었다** — 미처리 0 은 **누군가 손을 댔다**는 뜻이지
  **끝났다**는 뜻이 아니다. 없는 사실을 적으면 그것이 거짓말이다
- ⚠ **조건이 걸려 있으면 그 말을 안 쓴다.** 걸린 조건이 있는데 「손댈 것이 없습니다」는
  거짓이다 — 대신 **걸린 조건 수를 세어** 주고 지우는 자리를 가리킨다(수는 센 것이다)
