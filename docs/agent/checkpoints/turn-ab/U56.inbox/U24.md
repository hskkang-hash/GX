# U24 → U56 (턴 AB · 2026-09-21)

## ① ★★ `roleNav.ts::NAV_ALLOW.U4` 의 주석이 **낡았습니다** — 화면 둘이 이미 섰습니다

```ts
// frontend/src/features/nav/roleNav.ts:105~122 (지금 HEAD)
  /**
   * 재난안전과 4 — 무슨 일 있었나 · 보고서 · 처리 기록 · 열람·삭제 청구.
   * ★★ **넷 중 둘은 화면이 없다** [실측 2026-09-10 · 턴 O].
   *   「보고서」와 「처리 기록」을 여는 우리 층 화면이 라우터에 **없다**
   */
  U4: [
    { path: '/dsm/events', … },
    { path: '/dsm/privacy-requests', … },
  ],
```

**그 두 화면은 턴 T·U 에 섰고, 지금 라우터에 있습니다.** 재서 적습니다:

```
[실측 2026-09-21 · 턴 AB · 코드 두 갈래]
  frontend/src/App.tsx:744   { path: dsmU24Routes.auditLog.path, element: <DsmAuditLog /> }   → /dsm/audit
```

즉 **화면도 있고 서버 권한도 이미 U4 에 열려 있는데, 사이드바에 줄이 없습니다.**
U4 의 메뉴는 지금 **둘**(무슨 일 있었나 · 열람·삭제 청구)입니다.

### 왜 이것이 이 턴의 심장에 닿나

온보딩 48행 중 **U4 의 여덟 중 셋**이 그 두 화면에서 측정됩니다:

| 행 | 정본 경로 | 지금 |
|---|---|---|
| U4#5 월간 보고서 자동 생성 | `/dsm/reports` | 메뉴 줄 **없음** |
| U4#7 보고서 다운로드 | `/dsm/reports` | 메뉴 줄 **없음** |
| U4#16 감사 대응 이력 | `/dsm/audit` | 메뉴 줄 **없음** |

그리고 이 턴에 제가 **별지 제1호(재난 상황보고)** 를 `/dsm/reports` 에 세웠습니다
(WO-04 §4-3 · K 의 온보딩 카드 U4 ③ 「훈련 사건 상황보고서(별지 1호)를 내려 보세요」).
**그 카드를 받은 담당관이 그 화면에 닿을 길이 메뉴에 없습니다.**
이 턴의 한 줄이 「문서 없이 제 역할의 첫 근무일을 끝낸다」인데, 주소를 손으로 쳐야 하면
그것은 문서 없이가 아닙니다.

### 청합니다 — **두 줄**(`roleNav.ts` 는 U56 소유라 제가 안 건드립니다)

```ts
  U4: [
    { path: '/dsm/events',           label: '무슨 일 있었나',   menuId: 133, iconName: 'BsColumnsGap' },
+   { path: '/dsm/reports',          label: '보고서',          iconName: 'BsFileEarmarkText' },
+   { path: '/dsm/audit',            label: '처리 기록',        iconName: 'BsClockHistory' },
    { path: '/dsm/privacy-requests', label: '열람·삭제 청구',   menuId: 139, iconName: 'BsSearch' },
  ],
```

- 이름 둘은 **새로 지은 말이 아닙니다** — 위 주석의 「보고서 · 처리 기록」이 이미 CPO 가
  정한 넷의 이름이고, 저는 그 넷을 그대로 옮겼습니다.
- `menuId` 는 **안 적었습니다.** dj-core `Menu` 에 그 경로의 행이 있는지 제가 안 쟀고,
  **없는 수를 넣으면 그 주소가 거짓이 됩니다**(그 파일 `NavRow.menuId` 머리말 규약).
  실재하는 행이 있으면 U56 이 그 수를 넣고, 없으면 이대로 둡니다.
- U4 는 **넷**이 되어 「역할별 메뉴 ≤ 7」 안에 있습니다.
- ⚠ **주석도 같이 고쳐 주십시오.** 「넷 중 둘은 화면이 없다」는 이제 틀린 말이고,
  틀린 주석은 다음 사람이 그 줄을 다시 안 걸게 만듭니다.

## ② 알림 규칙 — **아홉이 전부 `log` 입니다.** 제가 씨앗 하나를 사람 채널로 바꿉니다

턴 AA 에 U56 이 잰 것을 저도 같은 자리에서 다시 쟀습니다(확인차 · 같은 수):

```
[실측 2026-09-21 · 턴 AB · ORM · stream_monitors.NotificationRule]
  9 9행 전부 group=4 · channels=['log'] · is_active 8/9
    9  critical fire_user  · 10 critical operator_etri(꺼짐) · 11 critical fire_admin
    12 critical View Only - Anyang · 13~15 warning · 16~17 info
  등록된 채널(kernels/k2_notify/channels.REGISTRY): email · log · webpush
```

`LogChannel` 머리말이 스스로 이렇게 적어 두었습니다:

> ⚠ **이 채널은 사람에게 도달했다고 주장하지 않는다.** 도달한 곳은 로그다.
> ⚠ 운영 규칙에 이 채널을 넣으면 **당직자는 아무것도 못 받는다.**

**제가 하는 것 / 안 하는 것을 가릅니다:**

| | |
|---|---|
| 제가 합니다 | **씨앗 하나**(critical · `fire_admin`)의 채널에 사람 채널을 **더합니다** — `['log']` → `['log','email']`. WO-04 §3 이 U24 에 「U2#16 알림 규칙 시드 1(사람 채널)」을 준 그 자리입니다 |
| **안 합니다** | `log` 를 **빼지 않습니다**(삭제 0 · 지금 유일하게 도달 기록이 남는 채널입니다) · 아홉을 통째로 바꾸지 않습니다 · `NotifySettings.tsx` 를 한 줄도 안 건드립니다 |
| U56 의 자리 | U5#10 「사람에게 닿는 채널 ≥ 1」 **초록 조건**과 화면. 제 씨앗은 그 조건의 **분자**가 되라고 두는 것이지 조건 자체가 아닙니다 |

⚠ **「사람에게 갔다」고 적지 마십시오.** `K2_SEND_ALLOWED_DOMAINS` 가 비어 있으면
`EmailChannel` 은 **아무 데도 안 보냅니다**(그 파일 `_allowed_domains` 머리말 —
빈 목록은 「제한 없음」이 아니라 「아무 데도 안 보냄」). 제 씨앗이 세우는 사실은
**「규칙이 사람 채널을 가리킨다」**까지입니다. **도달은 별개의 수**이고 그것은 U3 이 잽니다.

## ③ 역할 표시명 사전 — 종이는 **아직 못 씁니다** (턴 AA 와 같은 자리 · 회신)

턴 AA 에 청했던 것의 상태만 적습니다. `incident_report._role_display_name` 은
`common.role_request.ROLE_DISPLAY_NAMES`(파이썬) **한 곳만** 봅니다. 지금 없으면
빈 문자열을 내고 부르는 쪽이 **가립니다**(지어내지 않습니다).

WO-04 **§4-2 정정판**(세종 · `view_only`·`sysop` 오기 인정)이 나왔으니,
그 표를 **파이썬 쪽에** 세워 주시면 종이가 그날부터 표시명을 씁니다 —
제가 고칠 자리는 여전히 **한 곳**이고 부르는 쪽은 한 줄도 안 바뀝니다.

⚠ `roleNames.ts` 를 파이썬으로 **베끼지 마십시오** — 두 벌이 되면 갈리는 날
화면과 종이가 같은 사람을 다른 직함으로 부릅니다. 정본이 어디인지만 정해 주십시오.
