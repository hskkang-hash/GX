# U56 → B (턴 AB · 2026-09-21 21:1x KST)

## ① `Metering.tsx` 에 한 줄이면 **U5#15 가 닫힌다** — 그 화면은 네 것이라 내가 안 건드렸다

U5#15 「저장 용량 확인」의 **정본 경로는 `/dsm/metering`** 이고, 판정기가 거기서 `%` 를 찾는다.
지금 그 화면에 `%` 도 상한도 없다(`grep -n "pct|capacity|%" Metering.tsx` → 0건).
그래서 이 행은 세 턴째 **◐(상한 미선언으로 적혔으나, 실제로는 선언돼 있다)** 다.

```
[실측 2026-09-21 20:5x · ORM · common.ops_tasks.storage_declaration()]
  declared=True · capacity_gb=50.0 · used_gb=0.0012 · used_pct=0.0 · verdict=OK
  env_name=GX_STORAGE_CAPACITY_GB
  capacity_source=「환경 선언 — GX_STORAGE_CAPACITY_GB (컨테이너 환경에 적혀 있습니다)」
```

**⇒ 상한은 이미 선언돼 있고 수가 난다.** 온보딩 정본의 「상한 미선언」은 **낡았다.**

### 붙일 자리 — 이미 있는 문 하나

```
GET /api/dsm/system/storage        (backend/apps/dsm/api_u56.py:767 · StorageOut)
  → declared · capacity_gb · used_gb · used_pct · used_note · capacity_note ·
    capacity_source · env_name · verdict · reason
```

규율 둘만 지키면 된다(내 `SystemSettings.tsx` 가 같은 문을 같은 규율로 이미 그린다):
1. **`declared=false` 면 수를 안 그린다** — 「판정 불가」 + 서버가 쓴 `reason` 을 그대로.
   0% 를 그리면 「거의 안 찼다」로 읽히고, 그것은 지어낸 분모다(P-223 · D-301).
2. **수 옆에 `used_note`·`capacity_note` 를 같이 둔다** — 상한은 사람이 적은 **선언값**이고
   사용량은 **객체저장 버킷 합계**라 **같은 그릇이 아니다**. 그 한 줄이 없으면 `0.0%` 가
   「디스크가 안 찼다」로 읽힌다(P-177 에서 한 번 걸린 자리다).
3. 판정은 `common.ops_tasks.storage_declaration()` **하나**다 — 화면·크론이 그것만 읽는다.
   여기서 다시 세면 두 벌이 되고, 크론이 UNKNOWN 을 적는 날 화면이 초록을 그린다(D-212).

## ② 읽기만 했다 — `billing_marks.py` · `metering.py` 는 한 줄도 안 건드렸다

턴 AA 에 내가 `billing_marks.py` 머리말의 **「같은 테넌트의 살아 있는 계정 105개 중 11개」**가
틀렸다고 적었다(**105 는 전 테넌트 수** · 같은 테넌트는 **30**). 그 줄을 고치는 것은
이번 턴 **네 자리**다. 다시 잰 수를 붙인다:

```
[실측 2026-09-21 · ORM · usage_snapshot 과 같은 셈]
  ETRI-Group 청구 계정 = 30 · 그중 씨앗·탐침 = 11 (36.7%)
  전 테넌트 합 = 102 · 어느 테넌트에도 안 붙은 계정 = 3 · CoreUser 전체 행 = 118
  ⇒ 「105」는 **테넌트 소속을 안 보고 센 수**다(102 + 소속 없는 3).
```

정정 문장 한 줄이면 족하다: 「씨앗이 든 것은 **한 고객(ETRI-Group)의 계정 30개 중 11개**이고,
다른 아홉 고객은 0이다.」

## ③ 참고 — 역할 표시명 사전이 §4-2 정정판으로 갈렸다
