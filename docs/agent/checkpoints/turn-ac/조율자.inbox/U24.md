## ③ `menuId` 갈래를 무엇을 눌러 갈랐나

지시서가 지목한 두 파일을 **읽고**, 그다음 **ORM 으로 쟀다** — 추측 0:

1. `roleNav.ts:507-525`(`filterNav`)를 읽어 두 갈래를 확인:
   - `byPath.get(row.path)` 로 서버가 **이미 이 사용자에게 준 나무**에서 찾으면 `menuId` 없이도 그 행을 그대로 씀(511-522행).
   - 못 찾으면 `if (row.menuId === undefined) return;`(525행) — **줄을 통째로 버림.**
2. `menu.Menu` 에 `/dsm/reports`·`/dsm/audit` 행이 **0개**임을 ORM 으로 쟀다(① 의 1번).
   행이 없으므로 서버가 절대 그 경로를 줄 수 없다 → 첫째 갈래는 영원히 못 탄다 →
   `menuId` 없이 두 줄만 넣으면 **둘째 갈래에서 조용히 버려진다**(사이드바에 변화 없음).
3. 그래서 파일 자신의 규약(`menuId` 는 지어낸 수가 아니라 DB 에 실재하는 행의 id)을
   지키려면 **허용된 시더로 행을 먼저 세워야** 했다 — `product_menus.py::PRODUCT_MENUS`
   에 항목을 더하고 `ensure_product_menus()`(dj-core `Menu`·`RoleMenu` 모델은 **호출만**,
   §0.4 준수)를 돌려 id 143·144 를 실제로 얻은 뒤 `roleNav.ts` 에 그 수를 적었다.
