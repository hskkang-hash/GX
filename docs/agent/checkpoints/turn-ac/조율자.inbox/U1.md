## ⑤ 숨겼나 말하게 했나 — 정확히

**전부 말하게 했다. 숨긴 것 0·안 세는 것으로 바꾼 것 0.**
- probe: 이미 턴 AA 가 「안 센다」(집계 제외) 로 처리해 둔 채였다 — 이번 턴에 **더
  숨기지 않았다.** 내가 추가한 seed 판정은 probe 표식이 있으면 **비껴가도록**
  가드했을 뿐, probe 자체의 노출/차단 로직은 한 글자도 안 건드렸다.
- drill: 이미 「센다 + 배지」였다(P-201, 턴 Y) — 그대로 뒀다. MobileInbox 에 배지
  자리를 새로 달아 **드러냈다**(가리지 않았다).
- seed: 종전엔 서버가 `live` 로 냈다(사실상 "감춰진" 상태와 같다 — 고객이 구별할
  수 없었다). 이번에 서버가 `seed` 로 내도록 고쳤고, 화면(3곳: U1·U2·U3)이 그
  값을 배지로 그린다 — **드러냈다.** 지우거나 분모에서 뺀 것은 없다(청구 칸은
  아예 안 건드렸으므로 청구 숫자도 이 턴에 움직이지 않는다).

## ⑦ 틀린 전제

- 지시서 참고문은 D-514 를 "배선할 자리(턴 AC)"로 적었지만, **내가 배선한 것은
  그 칸(StreamMonitor.data_source)이 아니다** — event 레벨 낱말(k1_event 가 답하는
  질문)을 카메라 **코드**로 식별해 답을 하나 더 늘렸을 뿐, D-514 등재문이 가리키는
  청구 칸은 여전히 미배선이다. 등재는 **그대로 유효하다** — 지운 적 없다(그 파일은
  Q 소유라 손도 안 댔다).
- 지시서는 probe 를 "말하게" 할 대상처럼 §의 흐름상 읽힐 여지가 있었으나, 실측하니
  `GET /api/dsm/events` 는 이미 `include_probe` 기본 거짓이라 고객 화면에 probe 가
  **애초에 안 온다**(턴 AA 가 닫음). 그래서 이번 턴의 진짜 구멍은 probe 가 아니라
  **seed** 였다 — 지시서의 "탐침·씨앗이 섞여 있다"는 진단은 옳았지만, 처방 지점은
  seed 쪽 서버 배선이었다.
