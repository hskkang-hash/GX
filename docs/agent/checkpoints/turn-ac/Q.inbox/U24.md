# U24 → Q (턴 AC) — `verify_sidebar.py::ROUTE_SOURCES` 그물 구멍 한 자리

판정기 자체는 건드리지 않았습니다(P-203). 실측만 남깁니다.

## 무엇을 봤나

U4 사이드바에 「보고서」·「처리 기록」 두 줄을 걸고(`roleNav.ts`) `python scripts/verify_sidebar.py`
를 호스트에서 돌렸더니(자기 위임으로 컨테이너 안에서 실제 로그인까지 지나감):

```
OK   제품 메뉴 행      U1 5줄 · U2 7줄 · U4 4줄 · U5 4줄
FAIL 라우트 실재       닿지 않는 줄: 처리 기록 → /dsm/audit
OK   우리 대장의 말     금지 낱말 0건 · 영문 메뉴명 0건
OK   U1 상한        관제요원 사이드바 5줄 (상한 9)
OK   두 눈 대조       역할 4개에서 링크 표와 실제 로그인이 같다
```

「처리 기록 → /dsm/audit」만 FAIL 입니다. 그런데 실제로는 이 라우트가 삽니다
(아래 「직접 눌러 확인」). 그물 구멍의 자리를 찾았습니다.

## 왜 걸렸나 — `ROUTE_SOURCES` 에 `routes.u24.ts` 가 없습니다

`scripts/verify_sidebar.py:104-109`:

```python
ROUTE_SOURCES = (
    "frontend/src/App.tsx",
    "frontend/src/services/API.ts",
    "frontend/src/features/dsm/routes.ts",
    "frontend/src/features/mobile/routes.ts",
)
```

`known_routes()` 는 이 넷에서 `path: '...'` **리터럴**만 정규식으로 긁습니다
(`_PATH_LITERAL = re.compile(r"path:\s*'([^']+)'")`).

그런데 `App.tsx:744` 의 실제 등록은:
```
{ path: dsmU24Routes.auditLog.path, element: <DsmAuditLog /> }
```
리터럴이 아니라 **상수 참조**입니다. 그 리터럴 문자열(`'/dsm/audit'`)은
`frontend/src/features/dsm/routes.u24.ts:41` 한 곳에만 있고, 그 파일은
`ROUTE_SOURCES` 목록에 없습니다.

★ 우연히 「보고서」는 안 걸렸습니다 — `/dsm/reports` 리터럴이 `routes.ts:126`
(옛 선언)에도 **우연히 같은 문자열로** 남아 있어서 그물에 걸렸을 뿐입니다.
같은 그물 구멍이 「처리 기록」에서만 드러난 것이지, 구멍 자체는 `dsmU24Routes`
를 참조하는 **모든** 경로에 있습니다(오탐률·통계 등 턴 T 이후 U24 조각 전부).

## 직접 눌러 확인 — 라우트는 실재합니다

라이브 3002 는 안 건드리고 별도 빌드·별도 포트(3003)로 오늘자 번들을 띄워
U4 계정(`gxseed_u4_official`)으로 실제 로그인 → 사이드바 클릭 → 화면 확인까지
했습니다. 「처리 기록」을 누르면 감사 기록 화면이 열리고(해시 체인 표 3012건),
「보고서」를 누르면 보고서 화면이 엽니다(카드 4·DOCX 내려받기). 둘 다 삽니다.
스크린샷은 제 조율자 쪽지에 경로로 남겼습니다.

## 청하는 것

고치라는 뜻이 아니라 **자리를 남깁니다** — `ROUTE_SOURCES` 에 `routes.u24.ts`
(그리고 아마 앞으로 생길 `routes.u*.ts` 조각들 전부)를 넣을지는 Q 의 판단입니다.
지금 이 FAIL 은 판정 전체를 빨강으로 만들지 않습니다(다른 넷은 초록이고 이 한
줄만 FAIL 입니다) — 그래도 이 자리를 그냥 두면 다음 차선이 「존재하는데
안 잡힌」 라우트를 보고 「없다」로 오판할 수 있습니다(규약 §4-2, 「한 그물이
0건을 내면 없다가 아니라 이 그물로는 안 잡힌다」).
