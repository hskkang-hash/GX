목표(≥5) 초과 달성.

**못 닫은 셋(L · 하지 않음 후보)** — 「무엇이 없는가」 1줄:

  (모델 학습·추론 파이프라인은 L 규모 · 대표 승인이 필요한 별도 사업). 값을
  받는 빈 칸만 짓는 것은 "저장은 되는데 아무 일도 안 하는 스위치"라 짓지
  않았다.
- **DSM-U5-04** 임계값 소스 등록 — 차선 배정표 밖(WO-17 이 이 차선에 맡긴 것은
  U5-01·U5-03 둘뿐이다). `kernels.k5_trust` 기존 표와 맞물린 별도 차선 몫.
- **O-03** 라이선스·계량·청구 — 사업 결정(가격 정책)이 먼저 서야 하는 L 규모

## ⑤ 스스로 의심하는 점
- **FWS-U5-02·03의 "본인 것만" 한계**가 실사용에서 얼마나 아플지 확신이 없다
  — U5 를 "정보통신과 담당 또는 관제센터 운영 담당" 한 자리로 읽었지만, 실제
  현장에서 여러 사람이 교대로 관리자 계정을 쓴다면(같은 사람으로 로그인하지
  않고) 등록 내용이 조회자마다 갈릴 수 있다. 감사 표에 테넌트 칼럼이 없다는
  구조적 제약을 우회하려면 실제 표(1개 예산)를 여기 썼어야 할 수도 있는데,
  두 절(U5-02·03) 모두에게 필요해 보여 "어느 것에 예산을 쓸까"를 판단하기
  어려웠고, 결국 **0개**로 정직한 한계를 택했다 — 조율자·세종이 이 판단을
  다시 봐 주시면 좋겠다.
- **FWS-U5-04의 "산림청" 수신**이 annex 의 뜻(외부 기관에 실제로 알림이
  가는가)을 완전히 만족하는지 의심스럽다. 이 차선은 "산림청" 을 K2 의
  내부 `role_code` 제안(`fws_kfs_liaison`)으로만 다뤘다 — 실제로 산림청
  담당자 계정에 그 역할을 붙이는 것은 관리자의 몫이고, 웹훅으로 외부
  시스템에 직접 쏘는 경로(F6-02)와는 다른 결이다. 완결조건이 "등급별
  수신"(사람이 받는가)만 요구한다고 읽어 이 정도로 닫았지만, 반쪽일 수
  있다는 의심을 남긴다.
- **DSM-U5-01 문서의 "PDF" 부재**가 annex 완결조건 밖이라고 판단했지만,
  §5.7·§4.5 원문의 "출력" 칸("방침 PDF")을 엄격히 읽으면 이 절도 반쪽일
  수 있다 — 완결조건 문장 하나("보관 기간 = 파기 정책 값")만 보고 닫았다는
  점을 조율자가 다시 검토해 주시면 좋겠다.
- 세 못 닫은 절(U5-05·DSM-U5-04·O-03)은 지시서가 명시한 "하지 않음" 후보와
  정확히 일치하는지 재차 확인했다 — 일치한다.
