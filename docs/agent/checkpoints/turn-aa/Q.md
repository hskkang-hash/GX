### ⚠ 내가 만든 거짓 빨강 하나 — **같은 낱말을 두 뜻으로 썼다**

첫 판은 칸마다 「분모 **0.67**/1.00」처럼 **소수**를 적었다. 그랬더니 내 머리글이
**내 게이트에 걸렸다**:

```
✗ 머리글: MEASURED= 의 **분모가 0**이다 — 0건 검사는 통과가 아니다 (D-301)
```

`_gate_header` 의 `분모\s*([0-9][0-9,]*)` 가 「분모 **0**.67」의 **`0` 만 집었다.**
고쳤다: **맨 앞의 `분모` 는 언제나 「칸 수」(정수)**이고, 가중은 `몫` 이라 부른다.
같은 낱말을 두 뜻으로 쓰면 읽는 쪽(사람이든 정규식이든)이 둘 중 하나를 고르게 된다.

## ② P-216 — 점수를 `kind` 로 센다 · **내려간 수**

### 내려간 수와 사유

```
[SCORES] ★★ **상용 66.5 → 63.3** (-3.2) — P-216 「점수를 `kind` 로 센다」
         사유: 세 턴 동안 「67.x」라 부르던 수는 `status: 구현` 을 센 수였다.
               **「구현」은 닫혔다는 뜻이 아니다** — 대장은 이미 다섯 부류로 갈라
               적고 있었는데 **점수식만 그 갈래를 안 봤다.**
         실은: 닫힌 절 **80/154** = 51.9 · kind 점수 **86.5/154** = 56.2
               (래칫 3 · 규칙만 3 · 게이트만 4 · 못 잼 64)
         ★ **내려간 수가 정본이다.** 후퇴가 아니라 **반납**이다 — 절 수는 154 그대로다.
```

★ **분모는 안 움직였다(154).** 움직인 것은 **세는 눈**이다. 그래서 모든 줄이 `N/D` 를
값과 같은 줄에 싣는다 — 안 그러면 읽는 사람이 「제품이 후퇴했다」로 읽는다.

### ⚠ **경합 중 수는 수가 아니다** — 대장이 이 턴 안에 움직였다

| 잰 때 | closed | unmeasurable | kind 평평 | 영역 가중(kind) |
|---|---|---|---|---|
| 17:4x | 80/154 | 64 | 56.2 | **63.3** |
| 18:0x | **67/154** | **77** | 47.7 | **53.8** |

`ga_readiness.yaml` 이 18:01 에 수정됐다(차선 N 이 쥔 파일). 13절이 `closed → unmeasurable` 로 갔다.
**두 수 다 옳다 — 잰 때가 다를 뿐이다.** 산출기는 대장을 **살아서** 읽으므로 병합 뒤 다시 돌리면
그때의 수가 나온다. 내가 적은 수를 인용하지 말고 **돌려서** 받아라.

### ★★ 확정 — **N 과 맞췄다. 최종 수는 53.8 이다(내 63.3 이 아니다)**

쪽지 두 번 오갔다(`N.inbox/Q.md` ↔ `Q.inbox/N.md`). 결론:

```
상용 오픈 가중 합계   66.5%  →  **53.8%**   (−12.7)
  · P-216(점수를 kind 로)       66.5 → 63.3   (−3.2)   ← 내가 낸 수
  · P-215(확인 못 함 26절 정리)  63.3 → 53.8   (−9.5)   ← N 이 낸 수
절 수 **154 불변** · 닫힌 절 80/154 → **67/154** · 손 안 도달율 66.9%(상태 셈 · 안 움직임)
```

내 영역별 검산표(①~⑧ → 63.34)는 **P-215 전 대장 기준으로 N 의 코드와 소수점까지 같았다**.
그 뒤 N 이 26절을 손으로 보며 **13절을 `closed → unmeasurable`** 로 내렸고 최종이 53.8 이다.
**커밋 첫 줄은 N 의 수(53.8)로 간다.**

### ★★ 내 쪽 오판 하나 — **별명을 못 보고 「없다」는 거짓을 찍었다**

N 은 쪽지를 읽고 `verify_ga_readiness.py` 에 이렇게 세웠다:

```
KIND_POINTS = {"closed":1.0, "ratchet":1.0, "rule_only":0.5, "gate_only":0.5, "unmeasurable":0.0}
KIND_SCORE = KIND_POINTS     ← 「베끼지 말고 가져다 쓰라」는 뜻의 별명
```

**내 쪽이 그것을 못 봤다.** 첫 판의 `aa_kind_score_table()` 은 소스를 정규식으로 읽으며
`KIND_SCORE = {` 형태만 찾았고 **별명은 그 그물에 안 걸렸다.** 그래서 판정문이
「N 쪽에 `KIND_SCORE` 가 **아직 없다**」고 찍었다 — **거짓이었다.**
눈금이 이미 서 있는데 「없다」고 말하는 게이트는 **갈림을 못 본 게이트**이고,
P-216 이 막으려던 바로 그 모양이다.

고쳤다 — **모듈을 import 해서 그 이름을 읽는다**(N 이 주석에 적은 그 뜻대로 · D-210):

```
[SCORES] · N 쪽 `verify_ga_readiness.py::KIND_SCORE` 를 **import 로 가져왔다** —
           눈금이 같다. 두 벌을 두지 않는다 (D-369 · P-216 은 한 커밋이다)
```

자기시험에 그 갈래 셋을 박았다(「별명이어도 찾는다」 · 「다섯 부류를 다 덮는다」 ·
「**어디서 가져왔는지 말한다**」). import 가 막히면 소스로 물러서되 **물러선 사실을 적는다.**

### `53.8 → 53.8 (-0.0)` 을 「안 내려갔다」로 읽지 않게 문장을 갈랐다

N 의 합계가 **이미 kind 셈**이라 내 「내려간 수」 줄의 전·후가 같은 수가 된다.
그 `0` 은 **「두 도구가 같은 수를 낸다」**는 뜻이지 「안 내려갔다」가 아니다. 판정문이 그렇게 말한다.

### ★ N 이 물은 것을 **내가 정했다** — 셈법 ① (영역 ⑧ 비율)

P-215 로 `LAW-04` 가 내려가며 갈렸다: **상태(구현 5/10) 0.500 · 부류(kind 4.00/10) 0.400.**

**판단: 이번 턴에는 옮기지 않는다. 대신 「갈렸다」를 소리 내어 적는다.**

1. CR 셈법 규칙 2 는 **문서**가 정한다. 문서를 안 고치고 코드만 0.400 으로 옮기면
   **문서와 코드가 갈리고, 갈린 것을 아무도 모른다** — 이 산출기가 막으려고 있는 그 병이다.
   문서를 고치는 것은 **세종·조율자의 자리**다(P-203).
2. 그렇다고 조용히 0.500 을 쓰면 P-216 의 한 줄과 어긋난 채로 산다.

그래서 **회색이다 — 빨강이 아니다**(「제품이 무너졌다」가 아니라 「정할 사람이 아직 안 정했다」).

```
[SCORES] ? 셈법 ①: 영역 ⑧ 비율이 **갈렸다** — 상태 0.500 · 부류(kind) 0.400.
           이 산출기는 **상태 0.500 을 쓴다**. 부류로 옮기려면 **문서를 먼저 고친다**
```

### 파서는 안 깨졌다

N 이 영역 줄에 `kind x/n = p%` 를 **덧붙였다**(기존 `절 d/n = p%` 는 그대로).
`parse_ga_areas()` 도 내 `_AREA_TAIL` 도 가운데를 `.*?` 로 지나므로 **그대로 읽는다.**
영역별 `closed` 를 꼬리에서 뺄셈으로 되찾는 것도 그대로 돈다.

### 자기시험 — **각 kind 하나씩 표본 5** (P-216 지시)

```
★ P-216 표본 · closed 한 절 = 1.0
★ P-216 표본 · ratchet 한 절 = 1.0 (늘지 않음이 조건)
★ P-216 표본 · rule_only 한 절 = 0.5 (규칙은 섰으나 현장이 비었다)
★ P-216 표본 · gate_only 한 절 = 0.5 (제목이 게이트보다 넓다)
★ P-216 표본 · unmeasurable 한 절 = **0.0** (잠김도 여기 있고 분모에서 안 뺀다)
★ 음성 · 다섯 밖의 부류가 오면 **잡는다** (조용히 0 으로 세지 않는다)
★ 출생 표본 · 대장 154절의 kind 점수는 86.5 · 닫힌 절은 80/154
★ 음성 · 닫힌 절만 세면 51.9 — **56 과 다른 수**다
```

★ 소리 내어 적어 둔 것 둘:
- `ratchet` 1.0 은 **조건부**다. 「늘지 않았다」는 대장이 스스로 적은 말이고 이 산출기가
  다시 잰 것이 아니다. 세는 자리마다 그 문장을 함께 낸다.
- `unmeasurable` 0.0 은 **회색이 아니다.** 재고 나서 내린 판정이다. 이 산출기의 회색과 다르다.

세종이 이름으로 지목한 바로 그 모양이다(「서버가 404」). **그 두 차선이 이번 턴에 고칠 수 있다.**

### 래칫 — **빈 화면 84건은 잠갔다. 잠근 것은 빚이지 면제가 아니다**

빈 화면 술어 하나가 **170자리**를 낸다. 그 수를 그대로 빨강으로 내면 사람이 게이트를 끈다 —
**꺼진 게이트는 없는 게이트보다 나쁘다**(이 파일의 래칫 규약 · D-311). 그래서 갈랐다:

- **잠근 것**: 「빈 화면 · 다음 손 없음」 **84건** → `docs/agent/evidence/UX-20/copy_baseline.txt`
  (날짜와 사유를 머리글에 적었다. 한 자리를 고칠 때마다 그 줄을 지운다. **새로 생기면 빨강**)
- **안 잠근 것**: 표시명·오류 본문 **2건** → **지금 빨강**
  회색을 잠그는 것과 **고칠 수 있는 빨강을 잠그는 것**은 다르다.

잠근 것의 결은 이렇다(U1·U3·U0 의 일감):

```
「이 기간에 사건이 없습니다. (요청은 성공했고 0건입니다)」   ← 괄호가 우리 안심이다
「표시할 항목이 없습니다.」  「아직 회신이 없습니다.」        ← 다음 손이 없다
```

### 그물을 **두 번 좁혔다** — 그 값도 적는다

첫 판이 **179건**을 냈고 대부분이 빈 화면이 아니었다. 둘을 고쳤고 사유를 코드 주석에 박았다:

1. 「승인 필요 **없음**」 「알 수 **없음**」 — 그냥 **라벨**이다 → `없음` 을 술어에서 뺐다.
   「둘 다 비우면 … 채울 수는 **없습니다** — … 때문입니다」 — **설명 문단**이다 →
   빈 화면 문구는 **짧다**. `EMPTY_MAX_LEN = 40`.
2. ★★ **방어선을 결함으로 읽었다.** 영문 오류 원문만 한글 없이도 보게 예외를 뒀더니
   잡힌 것이 `copy.ts::RAW_MARKERS` 였다 — `'Network Error'` 가 거기 있는 이유는
   화면에 내보내려는 것이 아니라 **그 문장을 버리려고** 적어 둔 것이다.
   예외를 지웠다. 음성 대조 세 줄을 자기시험에 박았다.

★ **놓치는 쪽으로 틀린다**를 두 번 다 택했다. 수백 건을 내는 그물은 아무도 안 고친다.

### ★ 자기시험(출생 표본)은 **반드시** 붙였다
