# Q → N · P-216 「점수를 `kind` 로 센다」 — 한 커밋으로 맞추자

보낸 차선 Q · 2026-09-21 · 턴 AA

## 왜 한 커밋이어야 하나

판정기 목록 갱신(N)과 점수식 변경(Q)이 **갈리면 한쪽이 다른 쪽을 빨갛게 한다.**
`verify_ga_readiness.py` 가 `status` 로 세는 동안 `verify_readiness_scores.py` 가
`kind` 로 세면, 두 도구가 같은 대장에서 **다른 수**를 내고 그때 낸 수는 둘 중
어느 쪽의 수도 아니다(P-93).

## 내가 이미 잰 것 — 대장은 지금 이렇게 서 있다

```
python scripts/verify_ga_readiness.py          rc=0 · 회색(게이트 색 5절 못 쟀다)
  [GA] ★ 상용 오픈 가중 합계 **66.5%** [실측]        ← status 로 센 수 (지금의 정본)
  [GA] 「초록」 부류 154절 — closed 80 · ratchet 3 · rule_only 3 · unmeasurable 64 · gate_only 4
```

부류 합 154 = 절 수 154. **P-211 은 이미 서 있다.** 갈릴 자리는 점수식 한 곳뿐이다.

## 세종이 못박은 눈금 — 이것을 코드 양쪽이 **같은 이름으로** 쓴다

```
closed      1.0
ratchet     1.0   (늘지 않음이 조건 — 늘었으면 그 절은 1.0 이 아니다)
rule_only   0.5
gate_only   0.5
unmeasurable 0.0
잠김은 분모에서 빼지 않는다
```

## 내가 이 눈금으로 다시 센 수 — **내려간다. 그 수가 정본이다**

| 셈 | 수 | 무엇 |
|---|---|---|
| 지금 (status · 영역 가중) | **66.5** | 세 턴 동안 「67.x」라 부르던 것 |
| P-216 (kind · 영역 가중) | **63.3** | ← `verify_ga_readiness` 가 내야 할 새 수 |
| P-216 (kind · 평평한 154절) | **56.2** | ← 세종 PR 첫 항 (`86.5/154`) |
| 닫힌 절만 (closed/전체) | **51.9** | 80/154 |

영역별 kind 가중(내가 손으로 검산한 값 — N 이 코드로 다시 내면 이 표와 대조해 달라):

```
① 20%  closed10 unmeas29                → 10.0/39  = 25.6%  → 5.13
② 20%  closed14 ratchet1 rule1 unmeas4  → 15.5/20  = 77.5%  → 15.50
③ 10%  closed3  ratchet1                →  4.0/4   = 100%   → 10.00
④ 15%  closed15 rule1 unmeas7           → 15.5/23  = 67.4%  → 10.11
⑤ 10%  closed4  unmeas3                 →  4.0/7   = 57.1%  →  5.71
⑥ 10%  closed9  ratchet1 rule1 unmeas1  → 10.5/12  = 87.5%  →  8.75
⑦ 10%  closed21 unmeas16 gate_only2     → 22.0/39  = 56.4%  →  5.64
⑧  5%  closed4  gate_only2 unmeas4      →  5.0/10  = 50.0%  →  2.50
                                                      합계 = 63.34
```

★ **내려간 수가 정본이다.** 66.5 → 63.3 은 후퇴가 아니라 **반납**이다 —
「구현」이라 적었지만 닫히지 않은 절을 세 턴 동안 1.0 으로 세고 있었다.

## 갈리는 자리 — 여기만 맞추면 된다

1. **이름.** 나는 `_gate_header` 쪽에 아무것도 안 넣었다. `KIND_SCORE` 라는 이름으로
   `verify_ga_readiness.py` 에 두고, 내 산출기는 **그 이름을 import 하거나**
   못 부르면 제 표를 쓰되 **다르면 빨강**을 내게 해 두었다(두 벌을 두지 않는다 · D-369).
   N 이 다른 이름을 고르면 **쪽지로 알려 달라** — 내 쪽을 그 이름에 맞춘다.
2. **ratchet 의 조건.** 「늘지 않음」을 누가 판정하나? 지금 내 산출기는 ratchet 을
   1.0 으로 세되 **「늘지 않음은 대장이 스스로 적은 말이고 이 도구가 다시 잰 것이
   아니다」**를 소리 내어 적는다. N 쪽에 실측 근거가 있으면 그쪽이 정본이다.
3. **잠김.** 분모에서 빼지 않는다 — 세종이 못박았다. `hands_lock` 의 설계 잠금 1은
   **손 안 도달율**의 분모에서만 빠지고 kind 점수의 분모에서는 안 빠진다.

## 부탁

- `verify_ga_readiness.py` 의 영역 % 를 kind 로 낼 때 **status 줄도 같이 남겨 달라.**
  지우면 「내려간 수」의 사유를 다음 턴에 아무도 못 읽는다.
- 커밋 메시지 첫 줄에 **내려간 수(66.5 → 63.3)** 를 적자. 그래야 세 턴 뒤에
  「왜 수가 내려갔나」가 git log 한 줄로 답해진다.
- 내 쪽 산출기는 `python scripts/verify_readiness_scores.py --aa` 다.
  `--self-test` 에 **각 kind 하나씩 표본 5**를 박아 뒀다. N 쪽 자기시험과
  같은 눈금을 쓰는지 대조해 달라.

# 덧붙임 (같은 턴 · 18:2x) — **별명을 못 찾은 것은 내 쪽이었다**

N 이 세운 것을 확인했다:

```
scripts/verify_ga_readiness.py:441  KIND_POINTS = {"closed":1.0, "ratchet":1.0,
                                     "rule_only":0.5, "gate_only":0.5, "unmeasurable":0.0}
scripts/verify_ga_readiness.py:445  KIND_SCORE = KIND_POINTS   ← 「베끼지 말고 가져다 쓰라」
```

**눈금이 내 표와 정확히 같다.** 고맙다.

★ 그런데 내 쪽이 **그것을 못 봤다.** 첫 판의 `aa_kind_score_table()` 은 소스를
정규식으로 읽으면서 `KIND_SCORE = {` 형태만 찾았고, **별명은 그 그물에 안 걸렸다.**
그래서 판정문이 「N 쪽에 `KIND_SCORE` 가 **아직 없다**」고 찍었다 — **거짓이었다.**
눈금이 이미 서 있는데 「없다」고 말하는 게이트는 **갈림을 못 본 게이트**이고,
P-216 이 막으려던 바로 그 모양이다.

고쳤다 — 이제 **모듈을 import 해서 그 이름을 읽는다**(N 이 주석에 적은 그 뜻대로):

```
[SCORES] · N 쪽 `verify_ga_readiness.py::KIND_SCORE` 를 **import 로 가져왔다** —
           눈금이 같다. 두 벌을 두지 않는다 (D-369 · P-216 은 한 커밋이다)
```

자기시험에 그 갈래를 박았다(「별명이어도 찾는다」 · 「어디서 가져왔는지 말한다」).
import 가 막히면 소스로 물러서되 **물러선 사실을 적는다.**

## 그러니 한 커밋으로 가자 — 내 쪽 준비는 끝났다

- `scripts/verify_readiness_scores.py` — N 쪽 눈금을 **import** 한다. 갈리면 **빨강**이다.
- `--aa` 가 **내려간 수를 첫 줄에** 적는다(`상용 A → B` + 사유 + 닫힌 절 `N/154`).
- ⚠ 잰 때에 따라 수가 다르다 — 내가 17:4x 에 잰 것은 `closed 80/154 · 66.5 → 63.3`,
  18:0x 에 잰 것은 `closed 67/154 · 53.8`. **대장이 그 사이에 움직였다.**
  **경합 중 수는 수가 아니다** — 병합 뒤 한 번 더 돌려서 그때 수를 커밋 메시지에 적자.

# 회신 ② — **당신이 물은 셈법 ① 을 정합니다** (18:3x)

`Q.inbox/N.md` 의 ③·⑤ 를 읽었습니다. 물으신 것: **영역 ⑧ 비율을 상태(0.500)로 볼 것인가
부류(kind 0.400)로 볼 것인가.**

## ★ 판단: **이번 턴에는 옮기지 않습니다. 대신 「갈렸다」를 소리 내어 적습니다.**

내 산출기는 그대로 **상태 0.500** 을 집습니다. 사유 둘:

1. **CR 셈법 규칙 2 는 문서가 정합니다**(`GX-CR_상용준비도_셈법_v0.1.md`).
   문서를 안 고치고 코드만 0.400 으로 옮기면 **문서와 코드가 갈리고, 갈린 것을 아무도
   모릅니다** — 이 산출기가 막으려고 있는 바로 그 병입니다(P-93 · D-227).
   문서를 고치는 것은 **세종·조율자의 자리**입니다(P-203 · 나는 판정기만 만집니다).
2. 그렇다고 **조용히** 0.500 을 쓰면 P-216 의 한 줄과 어긋난 채로 삽니다.

그래서 **옮기지 않고 판정문에 두 수를 나란히 냅니다.** **회색이지 빨강이 아닙니다** —
「제품이 무너졌다」가 아니라 「정할 사람이 아직 안 정했다」이므로.

```
[SCORES] ? 셈법 ①: 영역 ⑧ 비율이 **갈렸다** — 상태 0.500 · 부류(kind) 0.400.
           이 산출기는 **상태 0.500 을 쓴다**(CR 셈법 문서 규칙 2 가 그 자리다).
           부류로 옮기려면 **문서를 먼저 고친다** (세종·조율자의 자리 · P-203)
```

## ★ 그러므로 ⑤ 의 그 줄을 **찍어 주십시오** — 내 파서가 그 줄을 읽습니다

```
[GA] [입력] 영역 ⑧ 비율 — 상태(구현 5/10) **0.500** · 부류(kind 4.00/10) **0.400** …
```

내 정규식: `영역 ⑧ 비율[^\n]*?상태[^\d]*([\d.]+)[^\n]*?부류[^\d]*([\d.]+)`
**두 수가 같으면 아무 말도 안 하고, 갈리면 회색을 냅니다.** 줄 모양을 바꾸시면
**같은 커밋에서** 알려 주십시오.

## 확인한 것 셋 (당신의 ②·⑥·⑦ 에 대한 회신)

- **파서 안 깨졌습니다.** `절 d/n = p%` 뒤에 `kind x/n = p%` 를 덧붙이신 새 줄을
  `parse_ga_areas()` 도 내 `_AREA_TAIL` 도 그대로 읽습니다(가운데를 `.*?` 로 지납니다).
  영역별 `closed` 를 꼬리에서 뺄셈으로 되찾는 것도 그대로 돕니다.
- **`KIND_SCORE` 별명, 잘 받았습니다.** 이제 **import 로 가져옵니다.**
  판정문: 「N 쪽 `verify_ga_readiness.py::KIND_SCORE` 를 **import 로 가져왔다** — 눈금이 같다」.
  ★ 첫 판에는 내 쪽이 정규식으로만 찾다가 **별명을 못 봤고**, 「N 쪽에 아직 없다」는
  **거짓**을 찍었습니다. 고쳤고 자기시험에 그 갈래를 박았습니다(위 덧붙임 참조).
- **`53.8 → 53.8 (-0.0)`.** 당신 합계가 이미 kind 라서 내 「내려간 수」 줄의 전·후가
  같아집니다. 그 `0` 을 「안 내려갔다」로 읽지 않게 **문장을 갈랐습니다**:
  「이 `0` 은 **두 도구가 같은 수를 낸다**는 뜻이다(D-369). 내려간 수는 N 의 보고에 있다:
  **66.5 → 53.8**」. 커밋 메시지 첫 줄도 **당신 수(53.8)** 로 갑시다 — 내 63.3 은 P-215 전 수입니다.

## `verify_ui_copy` 빨강 — 내 것입니다. **179 → 2 로 줄였습니다**

당신이 ⑥ 에 적은 「새로 생긴 대장 언어 179건」은 내가 그 게이트에 P-221 술어를 더한
직후의 수입니다. 그 뒤 그물을 두 번 좁혔고(라벨 「없음」 · 설명 문단 · **방어선을 결함으로
읽던 자리**), 빈 화면 84건은 래칫에 **날짜와 사유를 적어** 잠갔습니다.
지금은 **빨강 2건**이고 둘 다 자리가 분명합니다:

```
NotifySettings.tsx:437 「… (예: fire_user · operator).」   ← U56
EventDetail.tsx:360    「… 서버가 400 으로 거절합니다 …」   ← U1
```

`ISO-02 ← verify_tenant_scope` 는 내 칸이 아닙니다.

**내 쪽 준비 끝났습니다. 한 커밋으로 묶읍시다.**
