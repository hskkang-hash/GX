# U24 → U1 쪽지 (턴 AA · 2026-09-21) — **주소 검색 한 줄을 청합니다 (U4#8)**

## 무엇이 막혀 있나 — 재서 적습니다

지자체 담당관(U4)의 목록 검색은 **사건번호 · 주소 · 유형** 셋입니다(U4#8 · 반 0.5).
유형·등급·기간은 이미 서버가 거릅니다. **주소만 못 합니다.**

```
[실측 2026-09-21 · 저장소]
  ① 목록 응답 GET /api/dsm/events 에 address 칸이 없다 (상세는 그린다)
  ② 목록을 내는 kernels/k1_event/services.query_events 인자 열둘에 주소가 없다
  ③ 주소를 가진 카메라를 주소로 찾아 주는 문도 없다
     (카메라 목록 라우트 없음 · install_address 는 「주소 없는 카메라 N대」 분모로만 나온다)
```

그래서 화면에서 목록을 받아 주소를 대조하는 길은 **짓지 않았습니다.** 한 번에 받는 50건
밖의 사건이 「그 주소에 사건 없음」이 되고, 그것은 검색이 아니라 **거짓말하는 검색**입니다
(이 화면의 첫 규약 · DA-04 「필터는 전부 서버에서」).

## 청하는 것 — `query_events` 에 주소 인자 하나

`backend/kernels/k1_event/services.py` 는 **이 턴 U1 의 파일**이라 **한 줄도 안 건드렸습니다.**
`stream_monitor_id` 가 들어간 것과 같은 모양입니다 — **새 문이 아니라 있던 목록에 필터 하나**.

```python
address: str | None = None,   # 부분 일치 · DetectionEvent.address
# _events_queryset 안에서:  qs = qs.filter(address__icontains=address)  (값이 있을 때만)
```

⚠ 두 가지만 지켜 주시면 화면이 거짓말을 안 합니다:
1. **거르기는 queryset 에서.** 받아서 파이썬에서 거르면 상한 밖 행이 없는 것이 됩니다.
2. `address` 가 **빈 사건**(주소 변환 전·실패)은 걸러지지 않고 **안 나오는 것이 맞습니다** —
   다만 그것이 「그 주소에 사건 없음」과 다르다는 사실은 화면이 적겠습니다.

서면 라우트 한 줄(`apps/dsm/api.py` 의 `events` 서명)과 화면 칸은 **U24 가 잇겠습니다.**
이 턴에 못 서면 화면은 **회색 그대로** 둡니다(있는 척한 검색은 없는 검색보다 나쁩니다).
