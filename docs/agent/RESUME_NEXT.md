## 0. 절차 위반 — 처분한다 (D-286)

**먼저 말한다: 자진 신고가 옳았다.** 그리고 배운 것을 "조심하겠습니다"가 아니라 `entrypoint: ["sleep"]` 로 못박은 것이 이번 턴의 가장 큰 성과다.

```
D-286  마이그레이션 4건 중 승인 밖 3건 — 【되돌리지 않는다】 (네 권고 수용) + 최상위 원칙 신설

  판정: 되돌리지 않는다. 역방향이 varchar 좁히기라 되돌림이 원상복구가 아니라 **새로운 파괴**다.
        확인된 사실 5건(운영 DB 아님 · DROP/DELETE 0줄 · 4건 전부 역방향 있음 · 행 수 보존 ·
        적용 후 스냅샷 확보)이 위험 미실현을 보인다.
  단, 지우지 않는다:
   ① "승인 범위 밖 3건이 적용됐고 선행 스냅샷이 없다"를 결정문에 그대로 기록한다(은폐 아님).
   ② 적용 후 스냅샷을 **이 시점의 기준선**으로 명시 등재하고, 3건의 DDL 전문을 증거로 남긴다.
   ③ 이후 되돌림이 필요해지면 기준선 복원으로 처리한다 — 역방향 마이그레이션은 쓰지 않는다.

  ★★ 최상위 원칙 신설 — 이 프로젝트를 관통하는 것을 이제 이름 붙인다:
     **「문서는 기억을 요구하고, 도구는 기억을 요구하지 않는다」**
     사람의 기억에 맡긴 절차는 도구가 우회한다. 그러므로 판정·규약·금지는 전부
     **깨지면 멈추는 도구**로 내려앉아야 한다.
     계보: D-264(모르면 멈춘다) · D-270③(등록부 게이트) · D-277(양성 대조) ·
           D-281(시그니처) · D-282(환경 정합) · **D-286(엔트리포인트 고정)**
     앞으로 모든 결정문은 마지막 줄에 **"이 판정을 강제하는 도구"** 를 적는다. 없으면 미완이다.
```

  ▣ 재정의 — 커널 done 요건에서 "호출처 2곳"을 뺀다:
     기존: 이중 AC green + 호출처 2곳
     개정: 이중 AC green + **실제로 산출물을 만드는 경로 1곳** + 계약 AC 충족

           K2·K3·K4 가 K1 을 소비하는 것으로 증명된다 — AI 호출처 개수가 아니다.
           대리 지표를 만족시키려 추정 파서를 쓰는 것은 본말전도이고 D-280 위반이다.

  ▣ ②(detect_and_save) 처분: **정직화 상태(NotImplementedError) 유지.**
     `ai-analysis.invalid` 로 응답 모양을 못 재는 동안 잇지 않는다 — 추정 파서 금지(D-280) 그대로.
     → 신규 티켓 **W2-3 「AI 응답 스키마 실측」** 등재: 실 서버 응답을 캡처해 스키마를 확정한 뒤
       ②를 K1 에 잇는다. 그 전까지 ②는 실패를 정직하게 던진다.

  → K1 done. ⑦ K2 ‖ K6 착수하라.
```

## 2. 인정·승인 3건

```
D-288  D-282 ②눈(마이그레이션 → 실제 DB) 추가 승인
  · 판정문 밖 추가라 확인을 구한 것이 옳다. **승인하고 문언에 반영한다.**
  · 근거: D-282 의 취지는 "재는 자리가 실물인가"이므로 모델↔마이그레이션만으로는 미완이다.

D-289  양성 대조 강화 — 표본은 실물에서 뽑는다 (착시 ④의 2차 형태)
  · 사실: 거짓 성공 조사기가 **합성 대조 7건을 전부 통과하면서 진짜 과녁(return True, results)을 놓쳤다.**
    D-282 눈 대조도 build_graph() 가 가정을 지워 실패했다. 탐지기를 검증했는데 검증 표본이 합성이었다.
  · 원칙: **양성 대조의 표본은 저장소 실물에서 최소 1건 이상 뽑는다.**
    합성 표본만으로 검증한 탐지기는 "내가 만든 것만 잡는" 상태가 된다 — 착시 ④가 한 겹 안으로 들어온 형태다.
  · 네가 이걸 스스로 발견해 코드와 문서에 남긴 것을 높이 산다. 숨기면 아무도 몰랐을 일이다.

D-290  기본값으로 오류를 삼키지 않는다 + 곁가지 3건 인정
  · `.get('results', [])` 가 상류 오류를 빈 목록으로 바꿔 뷰의 400 갈래를 죽은 코드로 만들었다.
    **원칙: "없는 것"과 "실패한 것"을 같은 값으로 표현하지 않는다.**
    기본값은 정상 부재에만 쓰고, 실패는 예외나 명시적 오류 값으로 올린다. (D-284 거짓 성공의 형제)
  · 곁가지 3건 전부 인정 — 특히 **쓰기 쪽 IDOR 차단**: 남의 stream_monitor_id 로 남의 테넌트에
    이벤트를 심을 수 있었다. 우리는 읽기 격리만 보고 있었고, D-281 시그니처가 쓰기 구멍을 잡았다.
    → 격리 시험에 **쓰기 방향 시나리오**를 정식 추가하라(읽기 5 + 쓰기 N).
  · W2-2 배선 시험이 커널 결함(F-04 위반 — 접힌 관측이 매번 알림)을 잡은 것도 인정.
    기존 30초 간격 시험이 그 갈래를 안 지나갔다는 분석이 정확하다.
```

## 3. ★ E2E 체계 — 이제 기능을 끝까지 만들고 끝까지 시험한다 (D-291)

```
D-291  E2E 3시나리오 체계 신설 — 계약 6차(2027.1) 통합시험을 지금부터 자동으로 쌓는다

  계약 [별첨1] 8장의 시나리오 3종이 곧 통합시험 과녁이다. 그때 수동 시연을 하지 않기 위해,
  **커널이 하나 붙을 때마다 E2E 시나리오를 한 단계씩 늘린다. 끝에 몰아넣지 않는다.**

  E2E-1 화재  : 프레임 투입 → AI 탐지 → K1 이벤트 → F-04 판정 → K2 알림(30초) →
                SDN QoS 요청(Mock·10초) → K3 대시보드(클릭→영상 3초) → K4 보고서 PDF
  E2E-2 침수  : 수위선 초과 → F-02 이벤트(30초) → 같은 구역 인명(F-03) 결합 → 등급 상향 →
                등급별 수신자 그룹이 실제로 달라지는지
  E2E-3 통신두절: SDN 링크다운(Mock I-3) → F-08 이벤트(60초) → F-07 대체 경로 요청 →
                F-13 정찰 프로파일 초안 + **비행 명령 미전송 단언**(spec_claim=0 유지)

  ▣ 모든 E2E 의 공통 규약 (하나라도 빠지면 E2E 로 인정하지 않는다)
   ① 실 마이그레이션 DB 에서 돈다 — `--nomigrations` 금지 (착시 ⑤ 대응, D-282 의 실전판)
   ② 격리 단언 포함 — 다른 테넌트 계정으로 전 단계 조회 시 0건. **읽기·쓰기 양방향**(D-290)
   ③ 양성 대조 포함 — 이벤트를 심지 않으면 이 E2E 가 실패하는가. 표본 최소 1건은 실물(D-289)
   ④ 저하 변형 포함 — 외부 의존을 죽인 상태에서 핵심 경로가 200 을 유지하는가
   ⑤ 시간 단언은 **논리 시계**로 — 실시간 sleep 금지. CI 에서 30초를 실제로 기다리지 않는다
   ⑥ 증거를 evidence/e2e/<시나리오>/ 에 남기고, 실패 시 **어느 단계에서 끊겼는지 표로** 낸다
      (D-274 "실패는 뒤를 가리지 않는다"의 E2E 판)

  ▣ 증분 규칙 — 커널 완료 시점마다 시나리오가 길어진다
   K2 done → E2E-1 의 1~5단계 가동 · K6 done → 피드백 단계 추가
