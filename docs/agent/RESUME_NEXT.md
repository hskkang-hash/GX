## §0 발상 — 「알림은 내부에서 돌고, 보고서는 한글로 나간다」

지난 턴까지 우리는 U3(현장 대응자)을 **외부 사람**으로 그렸다. 대표 결정 1로 그 그림이 틀렸음이 확정됐다. 알림을 받는 사람은 재난안전과 담당 공무원(U4)·관제요원(U1)·관제팀장(U2), 즉 **이미 GuardianX 계정이 있는 사람**이다. 따라서:

- 「외부 수신자용 무계정 링크」는 만들지 않는다. 링크를 열면 **로그인 상태의 모바일 화면**이 뜬다. 인증은 기존 authn을 쓴다(K5). 새 인증 경로를 만들지 마라.
- U3은 별도 사용자 종이 아니라, U1(관제요원)·U2(관제팀장)·U4(재난안전과)의 **「이동 중 수신 모드」**다. PRD에는 「U3 = 이동 중인 U1/U2/U4」로 재정의한다. (번호는 09-14 PDF 그대로: U1 관제요원 · U2 관제팀장 · U3 현장→재정의 · U4 재난안전과 · U5 시스템 관리자 · U6 외부 연계 시스템)
- 왕복 고리(접수 확인 → 조치 중 → 완료 회신 → 종결)는 그대로다. 사람이 바뀐 게 아니라 사람의 위치가 바뀐 것뿐이다.
- 보고서(K4)는 PDF에 **HWPX**를 더한다. 바이너리 .hwp가 아니라 개방형 HWPX(KS X 6101, zip+XML)다. 한컴오피스 2014+가 연다 [인용]. 우리 환경에 한컴이 없으므로 **최종 검증은 대표/고객이 파일을 열어서 한다** — Code는 「zip 구조 유효 + XML 스키마 유효 + 필수 파트 존재」까지만 [실측]으로 보고하고, 「한컴에서 열림」은 [미검증]으로 남겨라. 이것을 초록으로 쓰면 착시 ⑥형(스키마)이다.

## D-394 이벤트 상태 4값 [판정]

```
▣ 현재 이벤트는 사실상 2값(발생/처리)이다 [실측: 2026-09-13 보고 인용]. 4값으로 바꾼다.
   발생(occurred) → 확인(acknowledged) → 조치중(in_progress) → 종결(closed)
▣ 전이 규칙: 앞으로만 간다. 되돌림은 「종결 → 조치중」 한 가지만, 관제팀장(U2) 권한으로, 사유 필수.
▣ 각 전이에 who · when · from · to · reason 을 남긴다 (K5 감사). 기존 이벤트 감사 테이블이 있으면 그것을 쓴다 — 새 테이블을 만들기 전에 안을 뒤져라 (D-333).
▣ 「이미 있음/부분/없음」을 먼저 보고하라 (D-379). 상태 필드가 이미 enum이면 값만 늘리고, 문자열이면 enum으로 올리되 마이그레이션은 dry-run 먼저 (D-209).
▣ 기존 2값 데이터 이관: 발생→occurred, 처리→closed. 이관 건수를 [실측]으로 보고.
▣ 강제 도구: 상태 전이 시험 — 허용 전이 4개 통과, 금지 전이(예: occurred→closed 직행, closed→occurred) 거절을 각각 1건씩. 
   「거절」은 HTTP 4xx이어야 하며 200 봉투 안 오류는 실패다 (착시 ⑧형).
```

