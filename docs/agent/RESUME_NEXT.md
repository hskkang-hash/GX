## §0 인정 — 대장이 눈을 떴고, 세종이 세 번 틀렸다

1. **동시 3 · 충돌 0 — 인정.** 차선 규약이 실측으로 섰다. **이번 턴부터 동시 4를 연다**(PRD v2.5 §2 조건 「동시 3이 초록으로 실측된 뒤」 성립). 4가 도구·자원에서 막히면 3으로 내리고 사유는 도구 이름으로.

3. **세종 오류 3 — 전부 인정.** ① 「미측정 7 = 커버리지 계열」(계열 다섯, 도구 하나로 갈린 것은 하나) ② 「시스템 이벤트가 이미 나온다」(`EventType`에 없었다) ③ 「M1은 서버가 거른다 · 탐침 계정은 operator」(필터 없음 · 역할 0). 셋 다 **문서를 읽고 실측이라 적은 것**이다 — D-316 위반이 세 번. **이번 지시서부터 세종의 [실측] 표기는 Code 보고 인용 또는 세종이 직접 돌린 판정기 출력에만 붙는다. 그 밖은 전부 [추정]이다.** 세종 오류 누계 3.
4. **P-15 「문 없는 길 위에 화면 금지」로 M3·재알림을 커널 면만 지은 것 — 인정.** 문(`field-reply`)은 조율자가 냈다. 이번 턴 D는 그 문 위에 화면을 얹는다.
5. **「사번을 받지 않는다」(`mine`) — 인정, 원칙.** 파라미터로 남의 수신 이력을 물을 수 있는 면은 만들지 않는다.
6. **A2 접두 — 「지나가는 쪽을 먼저 켠다」 인정.** `/api/handover/`는 화면이 부른 뒤에.
7. **남은 구멍 4 — 덮지 않은 것 인정.** 넷 다 §2에 자리를 준다. 특히 **스냅샷 바이트 라우트**는 판정이 필요했다 — §1 P-25.
