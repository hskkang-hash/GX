## 1. ★ 착시 ⑦ 신설 — 캐시가 코드 수정보다 오래 산다 (D-341)

> "고친 뒤에도 2자리가 200이었고, `cache.clear()` 뒤 0이 됐습니다."

**이건 곁가지가 아니다.** 고치고 확인했는데 여전히 열려 있던 것이고, 캐시가 없었다면 **「고쳤다」로 보고됐을 것**이다.

```
D-341  초록의 착시 ⑦ — 캐시의 착시. 고침이 반영되기 전에 고쳤다고 읽는다

  ▣ 지금까지 여섯: ①부착률 ②시나리오 수 ③모수와 술어 ④탐지기 자체 ⑤환경 ⑥스키마
     **⑦ 캐시 — 측정 대상과 측정 시점 사이에 낀 상태가 결과를 대신 답한다.**
     · 응답 캐시만이 아니다: 모듈 임포트 캐시 · ORM 쿼리 캐시 · 브라우저 캐시 ·
       CDN · 컨테이너 이미지 레이어 · 파이썬 `__pycache__` — **전부 같은 병이다.**
  ▣ 규약: **모든 회귀·보안 시험은 캐시를 우회하거나 비우고 때린다.**
     · 우회가 가능하면 우회(캐시 무시 헤더·직접 호출) · 불가능하면 **명시적으로 비우고 시작**
     · 시험 로그에 **「캐시 처리: 우회 / 비움 / 해당 없음」을 한 줄로 남긴다.** 비면 게이트가 죽는다
  ▣ 강제 도구: `verify_cache_bypass.py` — 보안·회귀 시험 파일 중 캐시 처리 표기가 없는 건수를 출력.
     기존분은 래칫(D-311), 새 시험은 **100% 의무.**
     ★ D-310 자기표본: **이번에 200을 내던 그 2자리**를 fixture 로 박아라.
  ▣ 이건 D-301(검사 못함 ≠ 0건 검사)의 사촌이다. 거긴 **못 보고 초록**, 여긴 **옛것을 보고 초록**.
```

```
D-342  authn ≠ authz — 「같은 이름, 다른 것」 대장 4번째. 대장이 만든 턴에 값을 했다

  · 「권한(`path_permission`)」과 「인증(`auth=`)」은 같은 이름이 아니다 — 이 구분이 15자리를 드러냈다.
  · 대장에 등재: 이름 「권한/인증」 · A=인가(무엇을 할 수 있나) · B=인증(누구인가) ·
    구분 기준 **질문이 다르다** · 발견 D-342
  · ★ 기록해 둔다: **D-337 에서 대장을 만들었고, 그 다음 턴에 대장이 사고를 찾아냈다.**
    도구가 첫 사용에서 값을 한 것은 D-310(자기표본)의 반대 증명이다 — 잘 만든 도구는 즉시 문다.
  · 명명 규정: 코드·시험·문서에서 `auth` 를 **단독으로 쓰지 마라.** `authn_` / `authz_` 로 쓴다.
```

## 2. 네가 청한 판정 — X-API-Key 전면 적용 (D-343)

```
D-343  기본값 거절을 전역으로 옮긴다. 단, 한 번에 아니라 대장을 통과시켜서

  ▣ 판정: **전면 적용한다.** 「발급된 키 하나가 지금도 시스템 대부분에 닿는다」는 상태를
    남겨 둘 수 없다. 이건 사고 ②가 **DSM 진입면에만 좁혀진 채로 남아 있다**는 뜻이다.
  ▣ 그러나 수백 개 라우트를 한 번에 뒤집으면 **무엇이 깨졌는지 모르는 채로 초록이 된다.** 순서를 준다:
     ① **라우트 인벤토리 전수** — 경로 · 메서드 · 현재 인증 수단 · `X-API-Key` 수용 여부 ·
        테넌트 범위 검사 유무. **건수를 출력**하라(D-301). 나는 그 수를 모른다 — [실측]으로 답하라
     ② **분류 3갈래** — `inbound_key_allowed`(외부 App 이 부를 면) /
        `session_only`(사람 UI 전용) / `internal_only`(내부 호출 전용)
        ★ 분류의 기본값은 **`session_only`** 다. 판단이 서지 않으면 좁은 쪽으로 넣어라
     ③ **기본값 거절을 전역 미들웨어로 올린다.** `inbound_key_allowed` 목록만 통과
     ④ **래칫**(D-311): 목록은 이름으로 고정. 새 라우트가 목록에 없이 키를 받으면 exit 1
     ⑤ 부작위 시험(D-300): 키로 들어온 요청이 **영상·타 테넌트 식별자에 닿는 경로 0건**
  ▣ ★ ①의 인벤토리는 버리지 마라. **그 표가 곧 F-05 연동 규격서의 부록**이고,
    상용판 API 문서의 초안이며, 다음 파트너 기술 검토 자료다. **한 번 만들어 세 번 쓴다.**
  ▣ 순서: 이번 턴은 **①②까지.** ③은 인벤토리를 보고 내가 범위를 판정한 뒤에 한다.
```

## 3. 측정이 두 번 달랐다 — 이건 수의 문제가 아니다 (D-344)

```
D-344  「같은 수가 아니면 같은 술어가 아니다」 — 측정 재현성 원칙 신설

  ▣ 사실: 임계값 전수가 [실측]610/127(직전) → [실측]614/131(이번). 차이 4/4.
    네가 **자기 변경분 기여 0건을 확인하고, 어느 쪽이 맞는지 모른다고 덮지 않고 올린 것** — 옳다.
    ★ 덮었으면 다음 판정이 틀린 분모 위에 섰을 것이다.
  ▣ 원칙: **수를 보고하는 도구는 재현 가능해야 한다.**
    같은 커밋에서 두 번 돌려 다른 수가 나오면, 그건 수를 **세는** 도구가 아니라 **추정하는** 도구다.
  ▣ 지시
     ① 두 측정을 **같은 커밋에서 재현**하라. 같은 수가 나오면 원인은 **그 사이의 코드 변경**이다 —
        무엇이 늘었는지 4건을 이름으로 대라
     ② 다른 수가 나오면 원인은 **술어의 비결정성**이다(파일 순회 순서 · 캐시 ⑦ · 병렬 · 정규식 백트래킹).
        원인을 찾아 술어를 고정하고, **자기표본**(D-310)에 그 비결정 사례를 박아라
     ③ 어느 쪽이든 **측정 스크립트를 커밋**하고, 게이트가 **두 번 돌려 같은 수인지** 검사하게 하라
  ▣ 이건 D-301(건수 출력)의 다음 계단이다. **건수를 내는 것으로 부족하고, 그 건수가 재현되어야 한다.**
```

```
D-345  기반 진척과 계약 진척을 나눠 적는다 — 하나의 %로 합치지 않는다

  ▣ 그러나 **기반 작업이 값이 없다는 뜻은 아니다.** 사고 2건은 상용 오픈을 막던 것이었고,
    계약 절 어디에도 「익명이 영상을 못 올린다」는 없다 — **계약에 없는 일이 상용에는 필수다.**

  ▣ 보고 규약: 매 턴 **두 줄로 적는다.**
        계약 진척 : 절 n/39  (이번 턴 +k)

    합쳐서 하나의 %로 내지 마라. **합치는 순간 어느 쪽도 알 수 없게 된다.**
  ▣ FR-05-3 을 「발급·폐기」와 「소비 면 범위」로 나눠 미착수로 둔 것 — 옳다. 절 분해 원칙 그대로다.

## 6. 피드백 콘솔 — 스크린샷은 네가 찍는다 (D-347)

대표 지시로 **고객·QA·전문가가 화면을 보고 그 위에 직접 표시하며 피드백을 남기는 콘솔**을 만들었다.
프레임은 섰다. **스크린샷 자리는 비어 있다 — 그것을 네가 채운다.**

```
D-347  피드백 콘솔의 화면은 실제 실행 캡처만 넣는다. 그림·모형·합성 금지

  ▣ ★ 이유: 이 페이지는 **고객이 본다.** 여기에 실제가 아닌 화면이 한 장이라도 들어가면,
    그건 착시가 아니라 **거짓말**이다. D-284(거짓 성공 금지)의 대외 판이다.
  ▣ 수집 규약
     ① **E2E 실행 중에 찍는다.** 별도로 화면을 만들어 찍지 마라 — 시험이 지나간 그 화면이어야 한다
     ② 각 캡처에 메타 4칸을 함께 남긴다:
          route(경로) · user_role(어느 사용자로) · scenario(E2E-1/2/3 및 단계) · captured_at
     ③ **에러 화면·빈 화면도 그대로 남긴다.** 「에러 없는 스크린샷」은 **에러를 지운 화면이 아니라
        에러가 나지 않는 상태에서 찍은 화면**이다. 에러가 나면 **그것을 고친 뒤 다시 찍는다**
     ④ 개인정보·실제 영상 프레임이 들어간 캡처는 **넣지 마라.** 시험 데이터만(계약 11조 · D-269)

## 8. 대표께 — 표 하나와 콘솔 하나를 함께 올립니다

**① 사고 두 건이 실제로 있었습니다.** 인증 없이 **누구나 운행 로그와 영상을 올릴 수 있는 자리 4개**가 있었고, 발급된 API 키 하나가 **원본 영상 스트림에 닿고 있었습니다**(계약 11조 정면). 둘 다 **막혔고, 막힌 것을 재호출로 확인**했습니다. 사고 기록은 `INCIDENT.md`에 남습니다. — 이번 턴에 계약 기능 진척은 0입니다. **그게 정직한 보고입니다.** 사고 처리는 계약 절을 갚지 않습니다.

**② 완성율을 두 축으로 나눠 보고드립니다.**

| 축 | 지금 | 뜻 |
|---|---|---|
| **계약 이행** (에스비, 2027.1 통합시험) | **69%** [실측] | 계약 기능 39개 절 중 27개 구현 + 증명 시험 |
| **상용 서비스 오픈** | **약 45%** [추정] | 계약에 없지만 상용에 필수인 것 포함 (8영역) |

**이 격차가 오늘의 요점입니다 — 계약을 다 해도 상용은 절반입니다.** 성능 부하시험 0건, 백업·복구 없음, 관리 UI 미착수, 법·인증 준비 초기가 그 절반의 내용입니다. 이 항목들은 계약서에 없어서 지금까지 대장에도 없었습니다. **오늘부터 있습니다.**

**③ 피드백 콘솔을 만들었습니다.** 왼쪽에서 사용자와 기능을 고르고, 가운데 화면 위에 **직접 그려서 표시**하고, 오른쪽에서 전문가·사용자·QA가 의견을 답니다. **보내기를 누르면 그 자리에 저장되고, 제가 다음 지시서에 그대로 반영**합니다.

> **다만 화면은 아직 비어 있습니다.** 스크린샷은 **Code가 E2E 시험을 돌리면서 그 화면을 찍어** 채웁니다. 제가 그림으로 만들어 넣지 않았습니다 — **고객이 보는 자리에 실제가 아닌 화면이 들어가면 그건 착시가 아니라 거짓말**이기 때문입니다. 콘솔에 **빈 자리가 몇 개인지 숫자로 표시**되니, 채워지는 것이 보일 겁니다.
