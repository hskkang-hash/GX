## 0. 먼저 — 네가 실측으로 뒤집은 것에서 원칙 하나를 세운다

나는 VIDEO 잠김을 **실 스트림 부재**로 추정했다. 너는 실측해서 **배선 부재**라고 답했다. 추정이 틀렸다.
그러나 나는 그 추정으로 처분하지 않고 사유를 물었고(D-302), 그래서 틀린 추정이 계약이 되지 않았다.

```
D-304  「추정이 틀린 것은 잘못이 아니다. 추정으로 처분한 것이 잘못이다」 — 정본화

  · D-296·D-302 의 선례가 옳게 작동했다. 앞으로도 **추정에는 반드시 확인 요청을 붙인다.**
  · 실측이 추정을 뒤집으면 그 자리에서 추정문을 폐기하고, 폐기 사실을 결정문에 남긴다.
    → 이 문서의 D-302 후단("실 스트림 부재로 추정")은 **폐기.** 사유는 배선 부재다.

  ▣ ★ 그리고 이번 실측은 초록의 착시 **여섯째 형**을 드러냈다 — 지금까지 없던 종류다.

     ⑥ 스키마의 착시 — 필드가 있으면 기능이 있다고 읽는다.
        `clip_path` : 정의 1건 · 읽기 2곳 · **쓰기 0곳.**
        읽는 코드가 있으니 살아 있는 것처럼 보이고, 시험은 읽기만 지나가며 초록이 된다.
        **쓰기가 없는 필드는 "구현된 것처럼 보이는 미구현"이다.**

  ▣ 강제 도구 (D-286) : `verify_dead_fields.py`
     · 모델 필드 전수를 AST 로 훑어 **쓰기 지점 0곳인 필드**를 낸다. 검사 건수 출력 필수(D-301).
     · 화이트리스트는 「선언된 미구현 + 사유 + DA 번호」가 있는 것만. 그 외 1건이라도 있으면 **exit 1**.
     · 즉 이제부터 **필드를 먼저 만들고 배선을 나중에 하는 일이 게이트에서 막힌다.**
```

**착시 여섯 형 — 보고 규약은 그대로다.** `green N/M (대상=…, 술어=…)` · 분모 없는 초록은 보고로 인정하지 않는다.

## 1. 커밋 전략 판정 — ㉯ 2커밋 + 릴리스 후보 태그 (D-305)

```
D-305  커밋은 "무엇을 했나"의 단위가 아니라 **"무엇을 되돌릴 수 있나"의 단위**다

  ▣ 판정: ㉯ **두 커밋.** 브랜치는 만들지 않는다.
     · 직전 턴분(SDN 표준 · DSM App · D-293/294 시험)과 이번 턴분(Zone · FX-5 · 게이트 건수 · 계약 산출물)은

       Zone 폴리곤이 열리면 뒤 커밋이 확장된다. 한 덩어리면 둘 중 하나를 건드릴 때 다른 하나가 딸려 온다.
     · **브랜치는 반려한다.** 검토자가 없는 브랜치는 격리가 아니라 지연이다.

     반년 뒤 이 태그를 여는 사람에게 필요한 건 커밋 해시가 아니라 그날의 분모다.

  ▣ 커밋 메시지 규약 — 결정 번호를 본문에 적는다 (제목 아님)
       feat(sdn): 연계 표준 포트·수령요건 34건 + 부작위 시험

  ▣ 강제 도구: `verify_commit_trace.py`
     · 커밋 본문의 D-번호가 **결정 레지스트리에 없으면 exit 1**(오타·유령 번호 차단)
     · 결정문을 고친 커밋에 D-번호가 **하나도 없으면 exit 1**
     → 내력이 사람의 성실성이 아니라 도구에 걸린다.
```

## 2. VIDEO 판정 — 지금 연다. 단, 여는 것은 "참조"까지다 (D-306)

네 진단이 맞다. **개발로 풀 수 있으므로 계약 블로커가 아니고, 그래서 지금 착수한다.**
다만 열되 **Zone 과 똑같은 대칭**으로 연다 — 지금 확실한 것만 채우고, 무거운 것은 선언된 미완성으로 잠근다.

```
D-306  이벤트↔영상 배선 — 「구간 참조」를 지금 만들고, 「구간 추출」은 선언된 미완성으로 잠근다

  ▣ 지금 만드는 것 — 새 인코딩 0건. "어디를 보라"만 적는다.
       EventClip(BaseModel)                 # dj-core BaseModel = group FK 자동 (D-292 실측)
           event        : FK(Event)
           object_key   : Char              # 이미 MinIO 에 있는 녹화 객체 (/start-record 산출물)
           start_offset : Float             # 이벤트 시각 − PRE_ROLL
           duration     : Float             # PRE_ROLL + POST_ROLL
           clip_status  : 'unavailable' | 'referenced' | 'extracted'
     · 쓰기 지점은 **이벤트 생성 경로 안 한 곳**이다(K1). 밖에서 나중에 채우는 배치는 만들지 마라 —
       그게 `clip_path` 가 죽은 필드가 된 경로다.
     · 그 시각에 녹화가 없었으면 `'unavailable'` + 사유. **D-290 준수 — "아직 안 함"과 "없음"을 같은 값에 두지 마라.**

  ▣ 재생 라우트 — 계약 11조(원본 영상 무반출)가 여기서 걸린다. 규약 넷을 **시험으로** 건다.
       ① 테넌트 범위 — 남의 event_id 로 접근 시 404(403 아님. 존재도 알리지 않는다. D-269)
       ② 만료 서명 URL — 무기한 링크 금지. 만료 시각을 시험이 확인한다
       ③ 구간 한정 — 요청 구간 밖 바이트가 나가지 않는다
       ④ **다운로드 아님** — 원본 파일 전체를 주는 경로가 생기지 않았음을 **부작위 시험**으로 확인(D-300)
     ★ 여기가 이번 턴에서 가장 위험한 지점이다. 영상은 우리가 만든 것 중 반출 위험이 가장 큰 산출물이고,
       계약 11조는 그것을 정면으로 금지한다. **넷 중 하나라도 시험이 없으면 라우트를 내지 마라.**

  ▣ 잠그는 것 — 실제 구간 추출·트랜스코딩
       CLIP_EXTRACTION_READY = False
       · clip_status='extracted' 인 행이 하나라도 있는데 상수가 False → **게이트 exit 1**
       · True 로 올리면 추출 결과의 무결성 시험이 즉시 의무가 된다
     → SDN·ZONE 과 같은 패턴이다. 세 번째 재사용이므로 이제 이건 우리 표준이다.

  ▣ E2E-1 VIDEO 칸: `clip_status='referenced'` + 재생 라우트 4규약 통과로 **연다.**
    잠김 3칸 중 하나가 줄어 **SDN 1칸만 남는다.**
```

## 4. 정정 고지 수용 + 릴리스 후보 인정 (D-308)

```
D-308  알림 본문 좌표 노출 — 완화 승인, 경계 명문화 / 릴리스 후보 선언의 의미 한정

  ▣ 정정 고지 수용. 네가 스스로 「방침이 한 겹 바뀌었다」고 고지한 것이 옳다 —
    지시(D-298)가 기존 방침(__subject_and_body 좌표 원문 금지)을 덮었는데 조용히 덮으면 나중에 사고가 된다.
    ▸ 확정 경계 — 세 줄로 못박는다. 시험이 이 경계를 잡는다.
       resolved → **주소만.** 좌표 나가지 않는다
       failed   → 좌표 1줄 허용("주소 확인 불가(좌표: …)")
       pending  → **알림을 지연시키지 않는다.** 좌표로 즉시 발송하고 주소는 나중에 화면에서 채운다
                  ★ 알림 지연이 좌표 노출보다 나쁘다. 새벽 화재에 30초는 사람 목숨의 단위다(F-10 AC)
    ▸ 범위: 이 완화는 **알림 본문 한정**이다. 로그·보고서·외부 연계에는 적용하지 않는다.
      계약 11조 반출 금지는 영상에 대한 것이고 알림 본문은 그 대상이 아니다 — 둘을 섞어 확대 해석하지 마라.

  ▣ 릴리스 후보(SDN 제외판) 도달 — **인정한다.** D-303 다섯 조건 충족, verify_release_candidate.py exit 0.
    ▸ 다만 "선언"의 의미를 좁힌다: 이것은 **내부 판정이며 에스비 제출물이 아니다.**
      제출은 계약 7조 3단계(통합시험, 2027.1)다. 지금 이 선언의 값은 하나 — **되돌아갈 점이 생긴 것.**
    ▸ 「빈 DB에서 세워 보며 설치 매뉴얼을 작성」한 것 — §4 지시를 글자 그대로 지켰다. 인정한다.
      이미 돌던 환경에서 적었으면 빠진 단계가 초록 속에 숨었을 것이다.
```

## 5. ★ 이번 턴의 초효율 — 계약 AC 전수 대장 (D-309)

지금까지 우리는 F-09~F-12 를 이야기했다. **계약 기능은 14건이다.** 나머지의 상태를 우리는 표로 갖고 있지 않다.

```
D-309  계약 AC 전수 대장 F-01~F-14 — 실측으로 만든다. 문서 읽기로 만들지 않는다(D-292 반성)

  ▣ 한 줄에 다음을 적는다:
       기능번호 · 계약 AC 원문 · 현재 상태(구현/부분/미착수/잠김) · **그 상태를 증명하는 시험 파일:라인** ·
       잠김이면 unlock_type(D-307) · 커널 귀속(K1~K7)
  ▣ ★ 규칙: **증명 시험이 없는 칸은 "구현"으로 적을 수 없다.** 그런 칸은 '부분'이 아니라 '미측정'이다.
    "미측정"이 몇 건인지가 이 표의 진짜 값이다 — 우리가 무엇을 모르는지 세는 표이기 때문이다.
  ▣ 초효율: 이 표가 곧 **통합시험 결과서의 목차**이고, 동시에 **검수 대비표**이며,
    동시에 U1~U4 상용판이 어느 커널에 얹히는지 보여 주는 **이중 AC 지도**다. 한 번 만들어 세 번 쓴다.
  ▣ 강제 도구: `verify_contract_ac.py` — 대장 행 수 ≠ 14 이면 exit 1.
    '구현' 칸에 시험 경로가 비면 exit 1. 검사 건수 출력 필수(D-301).
```

2·3번은 **개발이 아니라 사무 1회**입니다. 각 10분이면 끝나고, 그 10분이 없어서 기능 두 개가 잠겨 있습니다.
1번만 상대방 몫이고 나머지 둘은 우리 몫이니, 오늘 셋을 함께 처리하시면 잠김이 **3종 → 1종**이 됩니다.
