## §3 청구 — 「5/5」라고 적지 않는다

| 지시서의 자리 | 실측 결과 |
|---|---|
| ① 게이트 탐침 카메라 | 생성 7곳 중 **DB 에 남는 2곳**만 배선 (다섯은 `atomic()` + 롤백) |
| ② 온보딩 계측기 | **못 했다** — Q 소유 파일이고 ORM 접근이 아예 없는 순수 Playwright. 걸 신호가 없다 |
| ③ 훈련 창 | **태어나는 자리 자체가 없다**(create/save 0건) |
| ④ 씨앗 계정 | 배선함 |
| ⑤ 탐침 계정 | 손으로 한 번 만든 고정 픽스처 — 반복 생성 0 |

**배선 셋 · 대상 아님 둘 · 못 한 것 하나.** 「5/5」는 분모를 손으로 적는 일이다.

### ★ 씨앗 유출 22 → 0 — 앞뒤를 **조율자가 같은 그물로 두 번** 쟀다
Q 가 「예측이지 실측 아님」으로 남긴 자리를 조율자가 먼저 재서 빨강임을 확인하고(16:45) B 에 넘겼고,
고친 뒤 같은 명령으로 다시 쟀다(17:00).
```
전  [P20] ✗ 씨앗 23건 중 청구 셈에 남은 것 22건 — seed 사건이 청구·월간 KPI 로 샌다   rc 1
후  [P20]   씨앗 23건 중 청구 셈에 남은 것 0건                                    rc 0
```
원인은 카메라가 아니라 **사건**이었다 — `DetectionEvent` 는 제 칸도 `track_id` 표식도 없어
`exclude_unbillable` 의 세 갈래 어디에도 안 걸렸다. 넷째 갈래 **㉣(카메라에서 상속)** 을 신설했다.

### ★ 고객이 다치지 않았는가 — **무엇이 남았는지**로 증명한다
```
카메라 52대 — live 40 · probe 8 · seed 1 · drill 3
live 아닌 12대 전수: GX-SEED-DSM · gxprobe-D384-screen-CAM · GX-ONB-V-* 7 · GX-DRILL-ANYANG-01~03
```
**열둘이 전부 우리가 만든 것이고 고객 카메라 40 대는 전부 `live` 로 남았다.**
그리고 `NONBILLABLE_SOURCES` **집합 자체는 한 글자도 안 바꿨다**(diff 확인) —
훈련이 청구에 드는지는 이 턴에 **움직이지 않았다**.

> **청구를 줄이는 변경은 「무엇이 빠졌나」가 아니라 「무엇이 남았나」로 증명한다.**

### 마이그레이션 둘 — 운영 DB 에 먹었다(`[X]`) · 삭제 0
둘 다 **되돌리는 함수**가 있고, 역함수의 `delete()` 는 **자기가 만든 표식만** 지운다.
계정 표식은 `pk + username` 을 **대조한 뒤에만** 얹는다 — id 가 밀려도 엉뚱한 사람을 안 잡는다.
