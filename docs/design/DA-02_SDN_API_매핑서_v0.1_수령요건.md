# DA-02 SDN 연계 API 매핑서 — v0.1 **수령 요건서**

**티켓** DA-02 (WP-DA1) · **상태** `blocked` — 입력 미수령 · **작성** 2026-08-25
**근거** 계약 DEV-SBIT-GX-20260810 3조2항(착수 15일 내 API 명세 제공) · 6조3항(미제공 기간만큼 기한 연장)
· [별첨 1] 기능명세서 §4 연계 인터페이스 I-1~I-5
**승인** ☐ 대표 (human_gate)

---

## 0. 이 문서가 **매핑서가 아닌** 이유

에스비정보기술의 SDN 컨트롤러 API 명세를 아직 받지 못했다(기한 2026-08-25).

명세 없이 매핑서를 쓰면 그 문서는 추측이다. 추측한 필드명 위에 F-06·F-07·F-08 어댑터를
구현하면 **재작업이 확정**된다. 계약 [별첨 1] §4 각주도 같은 말을 한다 —
"각 인터페이스의 엔드포인트·필드 정의는 '갑'이 제공하는 SDN 컨트롤러 API 명세를 기준으로
1단계 「연계 인터페이스 설계서」에서 확정한다."

그래서 지금 내는 것은 **무엇을 받아야 매핑이 가능한지의 목록**이다.
명세가 도착한 날 이 문서의 빈칸을 채우면 그대로 매핑서(v1.0)가 된다.

> **대표 조치(지시서 §5)**: 미수령 시 이메일로 기록하고 6조3항에 따라 기한 연장을 통지한다.
> **일정 영향**: 계약 §9 월별 계획상 F-06~F-08 은 4회차(2026.11)다. 리스크표(§7)의
> 완화책은 **"Mock 서버로 선행 개발"** 이다 — 그러나 Mock 조차 I-1~I-5 의 **필드 이름과 타입**이
> 있어야 만들 수 있다. 즉 명세 지연은 Mock 단계부터 막는다.

## 1. 계약이 이미 확정한 것 (여기는 협의 대상이 아니다)

[별첨 1] §4 — 이 5개 인터페이스와 그 **주요 데이터·방향**은 계약 본문이다.

| No | 인터페이스 | 방향 | 계약이 명시한 주요 데이터 | 대응 기능 · 비고 |
|---|---|---|---|---|
| **I-1** | 영상 QoS 우선 제어 요청 | GX → SDN | 카메라/드론 식별자, 소스·목적지, 우선순위, 대역폭, 유지 시간 | F-06 · REST(JSON) · **결과 코드 수신** |
| **I-2** | 경로 우회 요청 | GX → SDN | 스트림 식별자, 장애 링크, 대체 경로 정책 | F-07 |
| **I-3** | 링크·장비 상태 통보 | SDN → GX | 링크 ID, 상태(UP/DOWN/혼잡), 대역폭, 시각, **위치 매핑** | F-08 · **Webhook 또는 주기 폴링** |
| **I-4** | 제어 결과·감사 이력 | SDN → GX | 요청 ID, 처리 결과, 처리 시각 | F-09 표시 · F-11 보고서 반영 |
| **I-5** | 인증 | 양방향 | API Key 또는 OAuth2 토큰, **TLS 1.2 이상** | 키는 코드 외부(비밀 저장소) 보관 |

## 2. 수령 요건 — 항목별로 "왜 필요한가"까지 적는다

받아야 할 것을 **A(차단) / B(설계 제약) / C(있으면 좋음)** 으로 나눈다.
**A 가 하나라도 비면 그 인터페이스는 Mock 조차 만들 수 없다.**

### 2-1. 공통 (전 인터페이스)

| # | 받아야 할 것 | 등급 | 없으면 무엇이 막히나 |
|---|---|---|---|
| C-1 | **Base URL** (시험환경 / 운영환경 각각) | **A** | 호출 대상이 없다 |
| C-2 | **인증 방식 확정** — API Key 인가 OAuth2 인가 (I-5 는 "또는"으로 열려 있다) | **A** | 어댑터의 인증 계층 설계가 갈린다. 둘은 갱신·만료 처리가 전혀 다르다 |
| C-3 | 토큰/키의 **유효기간·갱신 절차** | **A** | 만료 처리를 못 쓴다. 새벽에 조용히 죽는 연동이 된다 |
| C-4 | **오류 응답 형식** — HTTP 상태 코드 사용 여부 + 오류 바디 스키마 | **A** | ★ 아래 §3 참조. 이 저장소가 실제로 겪은 문제다 |
| C-5 | **타임아웃 권장값** 및 서버측 최대 처리 시간 | **B** | 값을 정할 근거가 없다. 임의값은 나중에 장애로 돌아온다 |
| C-6 | **재시도 허용 여부** — 같은 요청을 두 번 보내도 되는가(멱등성) | **B** | 재시도가 이중 제어를 일으키면 네트워크를 두 번 흔든다 |
| C-7 | **호출 빈도 제한**(rate limit) | **B** | 이벤트 폭주 시 우리가 SDN 을 때린다 |
| C-8 | TLS 인증서 — 사설 CA 인가 공인 CA 인가 | **B** | 사설 CA 면 신뢰 저장소 배포 절차가 추가된다 |
| C-9 | OpenAPI/Swagger 문서 파일 (있다면) | C | 있으면 매핑 작업이 며칠 줄어든다 |

### 2-2. I-1 영상 QoS 우선 제어 (F-06)

| # | 받아야 할 것 | 등급 | 없으면 |
|---|---|---|---|
| 1-1 | 엔드포인트 경로 · HTTP 메서드 | **A** | 호출 불가 |
| 1-2 | **"카메라/드론 식별자"의 실제 형식** — SDN 이 아는 식별자는 무엇인가(IP? 포트? 장비 ID?) | **A** | ★ **최대 위험**. GuardianX 의 `StreamMonitor.id` 와 SDN 의 식별자가 다르면 **둘을 잇는 매핑 테이블이 신규 개발 항목이 된다.** 그 항목은 지금 견적에 없다 |
| 1-3 | 우선순위 값의 **범위와 의미**(1이 높은가 낮은가, 단계는 몇 개인가) | **A** | 반대로 걸면 재난 시 영상을 **낮추는** 요청이 된다 |
| 1-4 | 대역폭 단위(Mbps? Kbps?)와 허용 범위 | **A** | 단위 오해는 3자리 오차다 |
| 1-5 | "유지 시간" 만료 시 **자동 원복되는가**, 아니면 해제 요청이 따로 있는가 | **A** | 원복이 없으면 우선순위가 영구히 남아 평시 트래픽을 왜곡한다. 해제 API 가 별도면 **인터페이스가 6개**다 |
| 1-6 | **결과 코드 목록**과 각 코드의 의미(성공/거부/부분성공/장비미지원) | **A** | F-06 AC 가 "결과 코드 기록"이다. 코드표 없이는 기록이 무의미하다 |
| 1-7 | 동시 다발 요청 처리 — 같은 링크에 여러 QoS 요청이 겹치면 | **B** | 재난은 동시다발이다. 겹침이 기본 상황이다 |

### 2-3. I-2 경로 우회 요청 (F-07)

| # | 받아야 할 것 | 등급 | 없으면 |
|---|---|---|---|
| 2-1 | 엔드포인트 · 메서드 | **A** | 호출 불가 |
| 2-2 | "스트림 식별자"가 I-1 의 식별자와 **같은 체계인가** | **A** | 다르면 매핑 테이블이 하나 더 필요하다 |
| 2-3 | "대체 경로 정책"의 표현식 — 정책 이름인가, 경로 명세인가, 자동 선택인가 | **A** | 우리가 경로를 골라야 하면 GuardianX 가 망 토폴로지를 알아야 한다. **그것은 계약 범위 밖이다** — 반드시 확인 |
| 2-4 | 전환 완료를 **어떻게 아는가** — 동기 응답인가 I-4 비동기 통보인가 | **A** | F-07 AC 가 "전환 확인"이다. 확인 경로가 계약에 명시돼 있지 않다 |
| 2-5 | 전환 실패 시 원 경로 유지가 보장되는가 | **B** | 실패가 단절로 이어지면 우리 요청이 장애 원인이 된다 |

### 2-4. I-3 링크·장비 상태 통보 (F-08)

| # | 받아야 할 것 | 등급 | 없으면 |
|---|---|---|---|
| 3-1 | **Webhook 인가 폴링인가** (계약은 "또는"으로 열어 두었다) | **A** | 설계가 통째로 갈린다. Webhook 이면 **우리가 수신 엔드포인트를 공개**해야 하고 그 인증·방화벽이 새 과제다 |
| 3-2 | (Webhook 인 경우) 재전송 정책 · 서명 검증 방식 | **A** | 유실·위조를 못 막는다 |
| 3-3 | (폴링인 경우) 권장 주기와 변경분만 받는 방법 | **A** | 전량 폴링은 60초 AC 를 못 지키거나 SDN 을 때린다 |
| 3-4 | **"위치 매핑"을 누가 관리하는가** — 링크 ID ↔ 지리 좌표 | **A** | ★ **두 번째 최대 위험**. SDN 이 좌표를 주지 않으면 GuardianX 가 링크-좌표 대응표를 관리해야 하고, 그것은 **운영 데이터 관리 화면 신규**다. F-09 지도 표시와 F-13 정찰 제안이 여기 걸려 있다 |
| 3-5 | 상태값 열거 — UP/DOWN 외 "혼잡"의 판정 기준(임계 대역폭?) | **A** | "혼잡"을 재난 징후로 쓸지 말지가 갈린다 |
| 3-6 | "지정 지역" 을 어떻게 표현하는가 (링크 묶음? 행정구역?) | **A** | F-08 은 "지정 지역 통신 두절"을 만든다. 지역 정의가 없으면 이벤트를 만들 수 없다 |

### 2-5. I-4 제어 결과·감사 이력 (F-09·F-11)

| # | 받아야 할 것 | 등급 | 없으면 |
|---|---|---|---|
| 4-1 | **요청 ID 를 누가 만드는가** — GX 가 보내는가, SDN 이 발급하는가 | **A** | 요청과 결과를 못 잇는다. 그러면 감사로그가 반쪽이 되고 F-11 보고서의 "조치 이력"이 빈다 |
| 4-2 | 결과 통보 방식 — Push(Webhook)인가 조회(polling)인가 | **A** | I-3 과 같은 갈림 |
| 4-3 | 보관 기간 · 과거 이력 조회 가능 여부 | **B** | 보고서가 사후에 조치 이력을 못 넣으면 F-11 이 반쪽이다 |
| 4-4 | 처리 시각의 **시간대·형식**(UTC? KST? ISO8601?) | **A** | 30초·60초 AC 를 시간대 어긋난 값으로 재면 판정이 뒤집힌다 |

### 2-6. I-5 인증

| # | 받아야 할 것 | 등급 | 없으면 |
|---|---|---|---|
| 5-1 | 시험환경 자격증명 **발급 절차**(누구에게 요청하는가) | **A** | 연동 시험 불가 |
| 5-2 | 자격증명 **회전 주기·절차** | **B** | 만료 시 운영 중단 |
| 5-3 | 권한 범위(scope) — 조회만/제어까지 구분되는가 | **B** | 최소권한 원칙 적용 불가 |

> ⚠ **자격증명 값 자체는 이 문서에 적지 않는다.** D-204 · 계약 §4 I-5("키는 코드 외부 보관").
> 값은 비밀저장소에 넣고, 문서·코드·티켓에는 **참조 이름만** 적는다.
> 이 저장소는 실제로 운영 실키 53개가 커밋돼 있던 이력이 있다(W0-1b). 같은 사고를 반복하지 않는다.

## 3. 우리 쪽이 **미리 정해 둔** 설계 제약 (명세와 무관하게 지킨다)

명세를 기다리는 동안에도 이것들은 확정할 수 있다. 매핑서 v1.0 은 이 제약 위에 쓰인다.

1. **타임아웃 없는 외부 호출을 만들지 않는다.**
   `backend/common/external_http.py` 의 규약을 따르고 값은 `settings` 한 곳에 둔다.
   W0-17 이 타임아웃 없는 동기 호출 17건을 0으로 만들었다. 신규 어댑터가 그것을 되돌리지 않는다.
2. **SDN 고유 필드가 GuardianX 도메인 모델로 새어 들어가지 않는다.**
   어댑터 경계에서 변환한다. 계약 9조2항이 "타 SDN 교체 가능"을 요구하기 때문이고,
   그 요구는 **필드 이름 하나가 도메인에 박히는 순간 깨진다.**
3. **가이온의 책임은 요청·기록까지다**(계약 10조1항).
   AC 문장을 "SDN 이 이행했다"가 아니라 "요청이 나갔고 결과가 기록됐다"로 쓴다.
   SDN 이 이행하지 않은 것을 우리 결함으로 판정할 수 없게 하는 것이 이 문장의 목적이다.
4. **오류는 HTTP 상태로 낸다.** ★ 이것을 명시적으로 적는 이유가 있다 —
   이 저장소는 권한거부를 `200 + {"success": false}` 로 내보내던 구조를 가지고 있었고,
   그중 8개 라우트는 **거부 사실이 아예 소멸**해 조용히 성공처럼 보였다(W0-18 실측).
   신규 어댑터·F-05 는 그 전철을 밟지 않는다. 상세: `docs/contracts/api-error-and-auth.md`.
   같은 이유로 **C-4(에스비 측 오류 형식)를 A 등급으로 올렸다** — 상대방이 200 으로 실패를
   돌려주는 API 라면 우리 쪽에 판정 계층이 하나 더 필요하고, 그건 견적 항목이다.
5. **Mock 어댑터는 실기 어댑터와 같은 인터페이스를 구현한다.** 설정 한 줄로 갈아끼운다(D-212).

## 4. 명세 수령 후 채울 빈칸 (매핑서 v1.0 의 목차)

```
§A  엔드포인트 매핑표     I-1~I-5 × (에스비 경로·메서드 ↔ sdn-adapter 메서드)
§B  필드 매핑표           요청/응답 필드 ↔ GuardianX 도메인 필드 ↔ 변환 규칙
§C  식별자 대응 설계       StreamMonitor ↔ SDN 장비 식별자 (2-2 1-2 의 답에 따라 결정)
§D  링크-좌표 매핑 설계    (2-4 3-4 의 답에 따라 — 우리가 관리하면 신규 화면 필요)
§E  실패 3종 처리          무응답 / 거부 / 부분성공 × 재시도·기록·화면표시
§F  결과코드 사전          에스비 코드 → GuardianX 감사로그 코드
§G  Mock 서버 명세         시험용 응답 시나리오(정상·거부·지연·무응답)
§H  시험 시나리오          화재·침수·통신두절 3종 (계약 §5 6차 통합시험 대비)
```

## 5. 이 문서가 드러낸 **견적 밖 항목** 2개

명세를 받기 전에도 이미 보이는 것이 둘 있다. 둘 다 답에 따라 **신규 개발**이 된다.

| # | 조건 | 그러면 추가되는 일 |
|---|---|---|
| **R-1** | SDN 의 장비 식별자가 GuardianX 의 `StreamMonitor` 와 다른 체계일 때 (2-2 1-2) | 식별자 대응표 모델 + 관리 화면 + 초기 데이터 입력 절차 |
| **R-2** | SDN 이 링크의 지리 좌표를 주지 않을 때 (2-4 3-4) | 링크-좌표 대응표 모델 + 지도 기반 관리 화면. **F-09 지도 표시와 F-13 정찰 제안이 여기 종속** |

**두 항목은 명세 수령 즉시 확인해 대표에게 보고한다.** 나중에 발견하면 일정이 아니라 계약이 흔들린다.
