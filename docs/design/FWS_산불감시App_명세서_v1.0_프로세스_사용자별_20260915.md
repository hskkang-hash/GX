## 0. 한 장 요약

산불은 봄 두 달(3~4월)에 건수의 절반, 면적의 84%가 난다. 2025년 영남 산불(약 105,000ha · 사망 27명 이상)은 초동 30분과 대피 시각이 승패를 갈랐다. 2026년 2월 산림재난방지법이 시행되면서 대응단계가 3단계(초기대응 · 확산대응 1 · 2)로 바뀌고 헬기 골든타임이 30분으로 당겨졌으며, 지자체 기간제 인력은 산림재난대응단으로 통합됐다. 지자체 산림과는 이 새 체계를 **CCTV·감시원·드론·헬기·대피**를 한 화면에서 굴려야 하는데, 지금은 산림청 관제시스템(보고용)과 개별 AI-CCTV(탐지용)와 전화(지휘용)가 따로 논다.

GuardianX 산불감시 App은 그 셋을 한 흐름으로 잇는다 — **탐지(AI 연기·불꽃) → 2단 확인(감시원·드론) → 신고·초기대응(30분 시계) → 확산대응(단계 자동 제안·지휘 이양) → 대피(5h/8h 카운트다운·CBS 초안·앱 푸시) → 주불·잔불·뒷불·진화완료 → 조사·보고(산림청 입력 항목 1:1)**.

### 4.2 상태머신 — K1 대응 축 위의 산불 하위 상태

플랫폼 K1의 4값(미처리 → 접수 → 조치 중 → 종결)은 그대로 두고, 「조치 중」 아래에 산불 단계를 하위 상태로 둔다. 화면에는 처리 단계 1축 + 산불 단계 배지 하나만 보인다.

| K1 대응 축 | FWS 하위 상태 | 들어가는 조건 | 누가 | 나가는 전이 |
| --- | --- | --- | --- | --- |
| 미처리 | `detected` 탐지 | AI/신고 | 시스템 | → 확인 요청 |
| 접수 | `verifying` 확인 중 | 관제 「확인 요청」 | F3/관제 | → 산불 확정 / 오인 종결 |
| 종결(판정 오탐) | `false_alarm` 오인 | 감시원·드론 「아무것도 없음」 + 사유 | F1·F5 | 종결(K6 학습) |
| 조치 중 | `initial` 초기대응 | 산불 확정 · 신고 접수 시각 | F3 | → 확산 1 / → 주불 진화 |
| 조치 중 | `spread_1` 확산 1단계 | 면적·풍속·시간·시설 규칙 또는 F4 확정 | F4 | → 확산 2 / → 주불 진화 |
| 조치 중 | `spread_2` 확산 2단계 | 100ha·11m/s·48h·20동 · 지휘 시도지사 | F4(시도) | → 주불 진화 |
| 조치 중 | `main_out` 주불 진화 | 지휘권자 선언 | F4 | → 잔불 |
| 조치 중 | `mop_up` 잔불 정리 | 자동 | F2 | → 뒷불 감시 |
| 조치 중 | `ember_watch` 뒷불 감시 | F2 보고 | F2·F5 | → 진화완료 |
| 종결 | `extinguished` 진화완료 | 지휘권자 선언 | F4 | → 조사 |
| 종결 | `investigating` 조사 중 → `closed` | 조사반 배정 | F3 | 조사 종료 |

병행 상태: **대피 축**(없음 → 준비 8h → 즉시 5h → 대피 중 → 완료 → 해제) · **지휘 축**(시군구청장 → 시·도지사 → 산림청장 · 이양 시각·사유 기록).
