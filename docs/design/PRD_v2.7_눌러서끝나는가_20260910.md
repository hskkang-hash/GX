## 1. 술어 — 제품 전체에 건다
**「끝난다」 = 역할 있는 계정으로 눌렀다 → 네트워크 호출 ≥ 1 → 서버 상태가 바뀌었다(재조회로 확인) → 화면의 상태 칸이 바뀌었다.** 넷 중 하나가 없으면 ◐(그려짐) 또는 ○(없음). 토스트·모달이 떴는가는 「끝난다」의 조건이 아니다 — **상태 칸의 변화**가 조건이다(토스트는 죽을 수 있다 · 이번에 죽어 있었다).
게이트 `verify_click_completes`(신설 · 대장 QA-)가 이 술어를 잰다: 48흐름마다 「누르는 것 · 기대 호출 · 기대 상태 변화 · 기대 화면 문구」 4칸.

## 3. 셈법 v0.2
**FC** = Σ(48흐름 값) ÷ 48 · 값 {1 끝난다 · 0.5 그려짐(면·라우트 실재 · 끝은 안 봄) · 0 없음} · 흐름 목록 = `docs/agent/onboarding_48.md`(6 × 8). 역할 없는 계정·root·사진으로 잰 값은 무효. 페인포인트 18(GX-FCPR §1)은 FC의 분모가 아니라 **개선 우선순위 렌즈**로 남는다.
**PR** = GX-FCPR §2 15관문 그대로.
**CR** = 8조건(REVIEW §1) ÷ 8 · 값 {1·0.5·0} · ①URL ②계정 안전 ③U1 첫 근무일 ④U4 보고서 ⑤알림 실수신 ⑥SLA 실측 ⑦가격·계약·청구 ⑧감사 60초. GX-CR v0.1의 9항목은 ⑦의 하위로 접는다(이중 계상 금지).
**RC-1 문턱**: FC ≥ 70 · PR ≥ 80 · CR ≥ 75 · 상용 /100 ≥ 88.

## 5. Design Convention (이번 증분으로 못박는 셋 + 언어)
① **상태는 칸으로, 성공은 칸의 변화로** — 토스트·모달은 보조. ② **없음 · 오류 · 권한 없음 · 없는 사건은 다른 문장** — 표준 문구 4개(UX-31). ③ **한 화면에 우리말 아닌 글자 0** — 영문이 보이면 우리 층 화면이 아니다 → 숨긴다. **언어**: 이벤트→사건 · 스냅샷→현장 사진 · 구간 티켓→영상 구간 · 「실제 상황 / 오탐(잘못 감지)」 첫 1회 병기 · 코드 식별자·경로·계약 용어 0(v2.6 P0).
색·타이포·간격은 v2.6 §4.1과 `GX-COPY_v1.md` 그대로.

## 6. Coding Convention (이번 증분에서 드러난 것)
- 프런트: `main.tsx` 첫 줄에 React 19 패치 import(UX-24) · antd 정적 메서드(`Modal.confirm`·`message.*`)는 **상태 칸 변경과 함께만** 쓴다(UX-25) · 이미지는 `createObjectURL` + 해제 · 「다시 시도」 버튼은 반드시 호출을 낸다(죽은 버튼 0).
- 서버: 변경 메서드는 역할 관문을 통과한다(`access_gate` · SEC-20) · 4xx는 JSON·한국어 · 5xx 본문에 내부 0(`error_body`) · 404는 「없는 사건」으로 구분 가능한 코드.
- 게이트: `TARGET/AS/SOURCE` 3줄 · 앱의 자격으로 · 「누르면 끝나는가」는 촬영과 별개 게이트.

## 8. 대표께
- 술어를 고객 쪽으로 옮기자 세 수가 다 내려갔습니다(60/50/34 → 33/20/12.5). 제품이 아니라 잣대가 움직였고, 고객은 언제나 이 잣대로 셉니다.
- 새로 지을 기능은 없습니다 — 다섯 걸음은 전부 이미 있는 것을 잇는 일이고, import 한 줄이 그 첫 걸음입니다.
- 손 밖은 그대로 대표 결정 여섯입니다. 그중 **공개 URL(스테이징)**은 CR 조건 ①이자 세종·대표가 제품을 직접 열어 볼 유일한 길입니다.
