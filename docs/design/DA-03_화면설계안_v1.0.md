## 0. 이 문서가 고정하는 것 하나 — **"5상태"의 뜻**

계약 F-09 AC 원문: **"5상태(기본/로딩/빈/오류/권한없음) 정의, 이벤트 클릭→영상 3초 이내"**.

즉 5상태는 **재난 등급이 아니라 화면 상태**다. 재난 등급은 F-04 의 3종(주의·경계·심각)이다.
검수 기준 "5상태 100%"는 **모든 위젯이 다섯 상태를 전부 정의·구현했는가**를 묻는다.

| 상태 | 언제 | 기존 자산 | 신규 여부 |
|---|---|---|---|
| **기본** (data) | 정상 데이터 있음 | 전 위젯 구현됨 | — |
| **로딩** (loading) | 요청 진행 중 | `*Skeleton.tsx` 5종 실재 (`AbnormalSignsOverviewSkeleton` · `DailyProfileOverviewSkeleton` · `DroneStatusChartSkeleton` · `NotificationsSkeleton` · `WeatherInforSurveillanceSkeleton`) | **재사용** |
| **빈** (empty) | 요청 성공 · 데이터 0건 | 없음 | **신규** |
| **오류** (error) | 요청 실패 | 없음 | **신규** |
| **권한없음** (forbidden) | 403 | 없음 | **신규** |

**따라서 F-09 의 5상태 작업량은 "빈·오류·권한없음 × 위젯 수"다.** 로딩은 이미 있다.

### 0-1. ★ "오류"와 "권한없음"을 가르는 것은 **HTTP 상태**다 — 그런데 그것이 이 저장소의 약점이었다

W0-18 실측: 권한거부가 `200 + {"success": false}` 로 나가는 라우트가 281건,
`500` 으로 나가는 라우트가 7건, **거부 사실이 소멸해 `200 + {}` 로 나가는 라우트가 8건**이었다.
후처리 계층이 상태줄을 승격하지만 **기본값은 OFF**(`API_CONTRACT_PROMOTE_ERROR_STATUS=False`)다.

**화면 설계에 미치는 결과 3가지:**
1. 신규 위젯은 **`success` 필드와 HTTP 상태를 둘 다** 본다. 하나만 보면 상태를 잘못 그린다.
2. 프론트 무보호 호출 21곳(15파일)의 증상은 흰 화면이 아니라 **스피너 고착**이다(W0-18 §프론트 영향).
   즉 **로딩 상태가 오류 상태를 삼킨다.** → **모든 신규 위젯에 로딩 타임아웃을 건다**
   (기본 10초 초과 시 로딩 → 오류로 전이). 이것이 F-09 의 숨은 필수 요건이다.
3. F-05(신규 API)는 처음부터 올바른 HTTP 상태로 낸다 — 승격 계층에 기대지 않는다.

## 1. User Flow 5종 → 화면 전이

### Flow 1 — 관제요원 (주 사용자 · 상주 화면)

```
[알림 수신 F-10]  브라우저 푸시 / 목록 상단 배지
      │  클릭
      ▼
[T1 재난 대시보드 F-09]  지도 + 이벤트 목록 + 연계상태
      │  이벤트 카드 클릭          ◀── ★ 여기서 3초를 잰다 (§2-4)
      ▼
[T1-D 이벤트 상세 드로어]  스냅샷 → 라이브/녹화 영상 · 위치 · 신뢰도 · 규칙 판정 근거
      ├─ [확인]  status: new → confirmed
      ├─ [오탐]  status: new → rejected + 사유 (F-14 통계의 분자)
      ├─ [드론 정찰 제안 보기 F-13] ──▶ [승인 모달] ──▶ 프로파일 생성 (승인 없이는 비행 명령 미전송)
      └─ [종료]  status: → closed ──▶ [보고서 생성 F-11] ──▶ PDF
```
- 상주 화면이므로 **자동 갱신**이 기본이다. 갱신 중에는 스켈레톤을 다시 그리지 않는다
  (깜빡임이 관제를 방해한다) — 갱신은 **조용한 부분 갱신**, 최초 진입만 스켈레톤.
- `critical` + `new` 는 목록 최상단 고정(`DetectionEvent` 계약 §정렬 규칙).

### Flow 2 — 재난관제 관리자 (신설 역할 · 설정 화면 주 사용자)

```
[T9 관리자 설정 F-12]
   ├─ 위험구역        폴리곤 조회/지정 (지도는 *Unified 래퍼 재사용)
   ├─ 임계값          카메라별 수위 기준선 (F-02) · 탐지 신뢰도 하한
   ├─ 등급 규칙       F-04 규칙 JSON — 편집 → 검증 → 저장(무재기동 반영)
   ├─ 수신자 그룹     등급별 수신자 (F-10)
   ├─ SDN 연계 설정   엔드포인트·자격증명 **참조명**(값 미표시) · 연결 시험 버튼
   ├─ 역할 관리       "재난관제 관리자" 역할 부여/회수
   └─ 감사로그        설정 변경 이력 (읽기 전용)
        │
        └─▶ [T1 대시보드]에서 SDN 연계상태 확인 ──▶ [F-14 월간 오탐 리포트]로 임계값 재조정
```

### Flow 3 — 기관장/부서장 (읽기 전용)

```
[T1 대시보드 · 요약 프리셋]  ── 읽기 전용. 편집·확인·승인 버튼 자체가 렌더되지 않는다
      ├─▶ [이력 조회]        기간·유형·등급 필터
      ├─▶ [보고서 PDF F-11]
      └─▶ [통계 F-14]        월간 오탐률 추이
```
- ★ **버튼을 비활성(disabled)으로 두지 않고 아예 렌더하지 않는다.** 비활성 버튼은
  "권한이 있으면 되는데"라는 오해를 만들고, 클릭 시도가 서버까지 가서 403 로그를 오염시킨다.
- 다만 **서버 권한 검사는 그대로 건다.** 화면에서 감췄다는 사실은 보안 통제가 아니다.

### Flow 4 — 운영자 (에스비 1차 / 가이온 2차)

```
[테넌트 발급]  에스비가 고객사 group 생성 · 초기 관리자 계정 발급
     │
[장애 1차 대응 4영업시간]  에스비 ── 해결 못하면 ─▶ [에스컬레이션 2차 1영업일] 가이온
     │
[패치 적용] ──▶ [감사로그 점검]  설정 변경·권한 변경·제어 요청 전건
```
- ★ 이 Flow 의 화면 요구는 **테넌트 경계**다. 에스비 운영자가 A 고객 화면에서 B 고객 데이터를
  보면 그 순간 채널 신뢰가 끝난다. WP-2 가 이 Flow 의 전제다.

### Flow 5 — 외부 APP 개발자

```
[F-12 에서 API Key 발급]  ──▶ [OpenAPI 문서]  ──▶ [Webhook 구독 등록]  ──▶ [조회·확인 API]
```
- **F-05 하나로만 진입한다.** 내부 화면·내부 엔드포인트로 가는 경로를 UI 에 만들지 않는다.

## 2. T1 재난 관제 대시보드 (F-09)

### 2-1. 영역 구성

```
┌──────────────────────────────────────────────────────────────────────┐
│ ① 상단바   테넌트명 · 프리셋 선택(요원/관리자/기관장) · 연계상태 · 사용자 │
├───────────────────────────────────┬──────────────────────────────────┤
│                                   │ ④ 이벤트 목록                     │
│  ③ GIS 지도                        │    필터: 유형·등급·상태·기간       │
│     · 카메라 마커                   │    정렬: critical+new 최상단 고정  │
│     · 드론 마커                     │    카드: 유형 아이콘·등급색·시각·  │
│     · 이벤트 마커 (등급색)           │          위치·신뢰도·스냅샷 썸네일 │
│     · 위험구역 폴리곤                │                                  │
│     · ★ 네트워크 링크 상태            │  ─────── 카드 클릭 ───────▶ ⑤    │
│       (UP/혼잡/DOWN)                │                                  │
│                                   │                                  │
├───────────────────────────────────┴──────────────────────────────────┤
│ ② 요약 스트립  미처리 건수 · 등급별 건수 · 오늘 발생 추이 · 기상 · 드론 상태 │
└──────────────────────────────────────────────────────────────────────┘
                            ⑤ 이벤트 상세 드로어 (우측 슬라이드)
                               스냅샷 → 영상 · 규칙 판정 근거 · SDN 조치 이력(I-4)
                               [확인] [오탐] [드론 정찰 제안] [종료·보고서]
```

**재사용 대응** — 새로 만드는 것보다 옮겨 붙이는 것이 많다.

| 영역 | 기존 자산 | 처리 |
|---|---|---|
| ② 요약 스트립 | `AbnormalSignsOverview` · `DailyProfileOverview` · `DroneStatusChart` · `WeatherInfoSurveillance` | **재배치** |
| ③ 지도 | `SurveillanceMapDashboard` · `DetectionMarkersKakao/Google` · `today-profiles-polygon` | **재사용** + 네트워크 링크 레이어 **신규** |
| ④ 이벤트 목록 | `NotificationsList` (무한 스크롤·페이지네이션 훅 포함) | **확장** (필터·정렬·등급색) |
| ⑤ 상세 드로어 | 없음 | **신규** |
| ① 프리셋 | W3-1·W3-2 (3계층 프리셋) | **연결** — 새로 만들지 않는다 |

### 2-2. 등급 색 규약 (ISA-101)

| 재난등급 (F-04) | `DetectionEvent.severity` | 색 | 규칙 |
|---|---|---|---|
| 심각 | `critical` | **빨강** | **빨강은 이 등급 전용.** 다른 용도(삭제 버튼·필수 표시 등)에 빨강 금지 |
| 경계 | `warning` | 주황/황 | |
| 주의 | `info` | 청/회 | |

- 등급을 색으로만 구분하지 않는다 — **아이콘·라벨 텍스트를 함께** 낸다(색각 이상 대응).
- 상태(`new`/`confirmed`/`rejected`/`closed`)는 색이 아니라 **형태**(배지·취소선)로 구분한다.
  색을 두 축에 동시에 쓰면 관제 화면에서 판독이 무너진다.

### 2-3. 연계 상태 3표시 (계약 §2.2-2 장애격리)

상단바에 **"연계 정상 / 대기 / 끊김"** 을 항상 띄운다.

| 표시 | 판정 | 화면 동작 |
|---|---|---|
| 정상 | 최근 I-3/I-4 수신이 임계 시간 내 | 전 기능 |
| 대기 | 요청 전송 후 결과 미수신 | 해당 이벤트 카드에 "SDN 요청 중" 배지 |
| **끊김** | 임계 시간 초과 · 연속 실패 | ★ **GuardianX 기능은 계속 동작한다.** SDN 관련 표시만 "끊김"으로 낮추고 목록·영상·보고서는 정상 |

> 이것이 "일방 장애 시 타방 단독 동작"(계약 §2.2-2)을 사람이 눈으로 확인하는 자리다.
> 같은 성질을 스트리밍 서버에 대해서는 W0-17 이 이미 만들어 두었다
> (죽은 상태에서 목록 API 500→200, `stream_status:"unavailable"`) — **그 표시 규약을 그대로 쓴다.**

### 2-4. ★ "클릭 → 영상 3초" — 어디서 재는가

**측정 지점을 여기서 못박는다. 정하지 않으면 이 KPI 는 판정 불가다.**

```
t0 ── 사용자가 이벤트 카드를 클릭한 순간 (브라우저 클릭 이벤트 핸들러 진입)
   │
   ├── 드로어 열림 + 스냅샷 즉시 표시   ◀── 스냅샷은 이미 받아 둔 썸네일이다 (네트워크 왕복 0)
   │
   └── 영상 플레이어 마운트 → 스트림 연결 → 첫 프레임 디코드·페인트
t1 ── 첫 프레임이 화면에 그려진 순간 (video 요소의 첫 렌더 콜백)

AC-09② :  t1 - t0 ≤ 3.0초
```

**설계 결정 3개 — 이 셋이 3초를 만든다.**
1. **스냅샷을 먼저 그린다.** `DetectionEvent.snapshot_path` 는 이미 있다. 클릭 즉시 정지 이미지가
   뜨므로 사용자 체감 지연은 0 에 가깝다. 다만 **AC 판정은 영상 첫 프레임(t1)으로 한다** —
   스냅샷으로 3초를 통과했다고 주장하지 않는다.
2. **목록에 있는 동안 스트림을 미리 연결하지 않는다.** N개 카드에 대한 선연결은
   스트리밍 서버를 N배로 때린다. 대신 **카드 hover 시 프리커넥트 1건**만 허용한다.
3. **3초를 못 지키면 무엇을 보여줄 것인가**를 미리 정한다 —
   3초 경과 시 "영상 연결 지연" 안내 + 스냅샷 유지 + 재시도 버튼. **스피너 고착 금지**(§0-1).

**계측 방법**: 프론트에서 `t0`·`t1` 을 기록해 F-14 계측에 함께 적재한다.
검수 시 "재봤더니 빨랐다"가 아니라 **분포(p50/p95)** 로 보고한다.

### 2-5. 5상태 × 위젯 적용표 (검수 "5상태 100%"의 판정표)

| 위젯 | 기본 | 로딩 | 빈 | 오류 | 권한없음 |
|---|---|---|---|---|---|
| ② 요약 스트립 (4종) | 값 | Skeleton **재사용** | "오늘 발생 없음" | "집계를 불러오지 못했습니다" + 재시도 | 위젯 자체 미렌더 |
| ③ 지도 | 마커 | 지도 회색 + Skeleton | "표시할 대상 없음" 오버레이 | "지도를 불러오지 못했습니다" (지도 배경은 유지) | 미렌더 |
| ③ 네트워크 레이어 | 링크 상태 | — | 링크 정보 없음 | **"연계 끊김"으로 표시** (§2-3) | 미렌더 |
| ④ 이벤트 목록 | 카드 | Skeleton **재사용** | "조건에 맞는 이벤트가 없습니다" + 필터 초기화 | "목록을 불러오지 못했습니다" + 재시도 | 미렌더 |
| ⑤ 상세 드로어 | 상세 | Skeleton **신규** | — | "상세를 불러오지 못했습니다" | 드로어가 열리지 않음 |
| ⑤ 영상 | 재생 | 스냅샷 + 진행 표시 | "녹화 없음" | "영상 연결 지연" + 재시도 (§2-4) | 스냅샷만 표시 |

**규칙 2개**
- **"빈"과 "오류"를 같은 문구로 쓰지 않는다.** 데이터가 없는 것과 못 가져온 것은 다른 사실이고,
  관제요원의 다음 행동이 다르다(전자는 대기, 후자는 신고).
- **"권한없음"은 미렌더가 기본**이다(Flow 3 규칙). 단 화면 전체가 권한없음이면
  빈 화면 대신 **"이 화면에 접근할 권한이 없습니다 · 관리자 문의"** 한 장을 낸다.

## 3. T9 관리자 설정 (F-12)

### 3-1. 영역 구성 — 좌측 탭 7개

```
┌─────────────┬────────────────────────────────────────────────────┐
│ 위험구역     │  선택 탭의 편집 영역                                 │
│ 임계값       │                                                    │
│ 등급 규칙    │  ┌──────────────────────────────────────────────┐  │
│ 수신자 그룹  │  │  편집 폼 (AntD)                               │  │
│ SDN 연계     │  │                                              │  │
│ 역할 관리    │  │  [저장]  ← 저장 전 변경 요약 확인 모달          │  │
│ 감사로그     │  └──────────────────────────────────────────────┘  │
└─────────────┴────────────────────────────────────────────────────┘
```

### 3-2. 탭별 설계 요점

| 탭 | 핵심 | 주의 |
|---|---|---|
| 위험구역 | 폴리곤 조회·지정 | 지도는 `MapForRouteUnified` 래퍼만. **새 편집기를 만들지 않는다**(§0.4) |
| 임계값 | 카메라별 수위 기준선(F-02) · 신뢰도 하한 | 값 변경은 즉시 반영이 아니라 **저장 시점 반영** — 편집 중 값이 탐지에 새면 안 된다 |
| **등급 규칙** | F-04 규칙 JSON 편집 | ★ 아래 §3-3 |
| 수신자 그룹 | 등급별 수신자(F-10) | 심각 등급의 수신자 **0명 저장을 막는다** — 30초 AC 가 조용히 무력화된다 |
| SDN 연계 | 엔드포인트 · 자격증명 **참조명** · [연결 시험] | ★ **자격증명 값을 화면에 표시하지 않는다**(D-204). 마스킹이 아니라 **미조회**다 — 서버가 값을 응답에 담지 않는다 |
| 역할 관리 | "재난관제 관리자" 부여/회수 | 역할 판정은 `common/tenant_roles.py` 만 부른다. **레거시 `superuser` 역할은 이 화면에 등장하지 않는다** (회수 대상이다 · W0-16) |
| 감사로그 | 설정 변경 이력 | 읽기 전용. **이 화면에서 로그를 지울 수 없다** |

### 3-3. 등급 규칙(F-04) 편집 — 무재기동 반영을 화면이 떠받친다

```
[규칙 목록]  ──▶ [규칙 편집: JSON 에디터 + 폼 뷰 전환]
                   │
                   ├─ [검증]   문법·참조 무결성(구역 ID·수신자 그룹 ID 실재 여부) 검사
                   │            ✗ → 오류 위치 표시. 저장 버튼 비활성
                   │            ✓ → 저장 가능
                   ├─ [시험]   최근 이벤트 N건에 이 규칙을 적용하면 어떤 판정이 나오는가 (읽기 전용 미리보기)
                   └─ [저장]   변경 요약 확인 모달 → 저장 → **다음 이벤트부터 즉시 적용**
                                감사로그: 누가·언제·이전값→새값
```
- ★ **[시험] 이 이 화면의 핵심이다.** 규칙 하나가 알림 폭주나 알림 침묵을 만든다.
  저장 전에 결과를 보여주지 않으면 관리자는 운영 데이터로 실험하게 된다.
- **무재기동 반영 = 저장 즉시 다음 평가부터 적용.** 진행 중인 평가를 소급 변경하지 않는다.

### 3-4. 역할 5종 × 설정 항목 — 가시(V) / 편집(E) 매트릭스

`–` = 탭 자체가 렌더되지 않음

| 설정 항목 | 관제요원 | 재난관제 관리자 | 기관장/부서장 | 운영자 | 외부 APP 개발자 |
|---|---|---|---|---|---|
| 위험구역 | V | **E** | V | V | – |
| 임계값 | – | **E** | – | V | – |
| 등급 규칙 | V | **E** | V | – | – |
| 수신자 그룹 | – | **E** | V | – | – |
| SDN 연계 | – | V | – | **E** | – |
| 역할 관리 | – | V | – | **E** | – |
| API Key 발급 | – | – | – | **E** | (자기 키만 V) |
| 감사로그 | – | V | V | **V** | – |

**불변 규칙 3개**
1. **화면에서 감추는 것은 통제가 아니다.** 이 표는 UI 규칙이고, 같은 내용을 **서버가 다시 판정**한다.
   서버 판정은 `common/tenant_roles.py` 한 곳만 부른다 — 판정식을 화면 코드로 복사하지 않는다(D-212).
2. **성공·실패 모두 감사로그**에 남긴다. 차단된 시도를 기록하지 않으면 공격을 볼 수 없다.
3. 어떤 역할도 **자기 테넌트 밖** 설정을 보지 않는다. 운영자의 E 도 자기가 담당하는 테넌트 안이다.

### 3-5. T9 의 5상태

| 영역 | 빈 | 오류 | 권한없음 |
|---|---|---|---|
| 탭 목록 | — | — | 권한 없는 탭 **미렌더** (§3-4) |
| 편집 폼 | "아직 설정된 항목이 없습니다" + [추가] | "설정을 불러오지 못했습니다" + 재시도. **폼을 빈 값으로 그리지 않는다** (빈 값 저장 사고) | 폼 미렌더 |
| 저장 | — | 저장 실패 시 **입력값을 유지**하고 오류만 표시 | 403 시 "권한이 없습니다" — 폼 초기화 금지 |
| 감사로그 | "기록 없음" | "이력을 불러오지 못했습니다" | 미렌더 |

★ **오류 상태에서 폼을 빈 값으로 그리지 않는 것**이 T9 의 가장 중요한 5상태 규칙이다.
불러오기 실패를 "설정 없음"으로 그리면, 관리자가 저장을 눌러 **실제 설정을 빈 값으로 덮어쓴다.**

## 4. 공통 화면 규약

1. **신규 화면만 AntD.** 기존 화면을 AntD 로 개종하지 않는다(§0.4).
2. **지도는 `MapForRouteUnified` 래퍼만.** Kakao/Google 직접 호출을 신규 화면에 넣지 않는다.
3. **로딩 타임아웃 10초** — 초과 시 로딩→오류 전이(§0-1).
4. **응답 판정은 HTTP 상태 + `success` 필드 둘 다** 본다(§0-1).
5. **자동 갱신은 부분 갱신**. 갱신 때 스켈레톤을 다시 그리지 않는다.
6. **시각은 KST 표기 + 상대시간 병기**("14:32 · 3분 전"). I-4 의 처리 시각 시간대는 DA-02 확인 항목이다.
