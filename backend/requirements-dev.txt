#
# 왜 이 파일이 생겼나 [실측 2026-09-21 → 2026-09-22]
# ---------------------------------------------------
# 손 안 93절 중 **미측정 7절**이 「QA-07 커버리지 계열」이었고, 그 일곱이 회색이던
# 이유는 하나였다: **`pytest-cov` 가 이 이미지에 없다.** 도구가 없어서 못 잰 것을
# 「측정했더니 낮다」와 같은 색으로 두면, 무엇을 해야 색이 갈리는지 아무도 모른다
# (D-301 — 검사 못함 ≠ 0건 검사).
#
# 왜 `requirements.txt` 가 아니라 여기인가
# ----------------------------------------
# 커버리지 도구는 **운영 이미지에 들어갈 이유가 없다.** 운영이 안 쓰는 것을 운영
# 명세에 넣으면 배포되는 것이 늘고, 늘어난 것은 공격면이다. 시험 환경만 이 파일을 읽는다.
#
# 왜 해시까지 박는가 (D-387)
# --------------------------
# 판만 고정하면 「같은 이름의 다른 파일」이 들어올 수 있다. `--require-hashes` 는
# 받은 파일이 이 해시가 아니면 **설치를 거절한다** — 그래야 "깔았다"가 진술이 아니라
# 확인 행위가 된다(D-323 · `scripts/secret_scanner.lock.json` 과 같은 규약).
#
#     docker exec gx-shell pip install --require-hashes -r /repo/backend/requirements-dev.txt
#
# ⚠ 판을 올릴 때는 해시도 **같은 자리에서 함께** 갱신한다. 둘을 따로 고치면 lock 이 아니다.
#
# ⚠ [실측 2026-09-22] 아래 `coverage` 해시는 **cp311 · manylinux x86_64 휠**의 것이다.
#   다른 파이썬 판이나 다른 아키텍처에서는 이 해시로 설치되지 않는다 — 그것이 정상이고,
#   그때는 그 환경의 휠 해시를 **한 줄 더** 적는다(지우고 바꾸지 않는다).
#   컨테이너 실측: Python 3.11.14 · linux x86_64.
